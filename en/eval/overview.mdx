Comet has two evaluation-related systems that serve different purposes.

<p align="center">
  <img src="/assets/eval-overview-illustrations/01-two-eval-systems.png" alt="Xiaoyu separates comet eval release evidence from comet skill check run-completeness checks" width="800" />
</p>

| System | Purpose | Output |
| --- | --- | --- |
| `comet eval` | Measures Skill quality in task environments. | pass@k, pass^k, rubric scores, attribution, HTML report. |
| `comet skill check` | Checks whether an Engine Run is structurally complete. | Runtime check pass/fail for a specific run. |

Do not mix them. `comet eval` is release evidence. `comet skill check` is run-health evidence.

## Eval manifest

Generated Skills can include `comet/eval.yaml`. It declares the task set, profile, treatments, thresholds, and expected artifacts for a repository-local eval.

```bash
comet eval ./generated-skill/comet/eval.yaml --collect
comet eval ./generated-skill/comet/eval.yaml --html
```

## Profiles

| Profile | Use case |
| --- | --- |
| `generic` | Single-turn generic Skill smoke tests. |
| `comet-workflow` | Classic `/comet` workflows. |
| `authoring-skill` | `/comet-any` generated packages. |

## Recommended workflow

1. Run `--collect` first to discover tasks and catch setup issues without model calls.
2. Run the real eval with `--html`.
3. Inspect pass rates, dimension scores, and failure attribution.
4. Use passing evidence for publish readiness.
