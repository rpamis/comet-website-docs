`comet-handoff.mjs` bridges design and build. It creates a compact context package from accepted OpenSpec and design artifacts, then records a hash so later phases can detect drift.

## Why handoff exists

Design and implementation often happen in different sessions or after context compression. Handoff gives build a durable source of truth instead of relying on chat memory.

## Handoff contents

Typical handoff evidence includes:

- proposal and spec delta references;
- task list snapshot;
- design doc and implementation plan references;
- generated context package;
- hash of the source material.

## Drift detection

If the spec, tasks, or design change after handoff, the hash changes. Comet can then route the workflow back to design or ask for a decision before build proceeds.

## When it runs

Agents normally run handoff at the end of design before entering build. Users rarely need to call it directly.
