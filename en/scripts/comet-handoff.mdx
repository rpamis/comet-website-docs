---
title: 'comet handoff'
description: 'Inspect Classic handoff sources and optionally generate a Markdown view of the current original materials.'
---

Classic hands off original materials by default. `comet handoff` inspects an existing design handoff source and creates a Markdown view only when requested. It does not approve a proposal or advance an unconfirmed design.

## Inspect an existing handoff

```bash
comet handoff <change-name> design --write
```

During Design or Build, the command checks the current change and its original task's handoff reference. By default, it reports the formal source without copying a new reading view or recalculating file hashes.

If an SDK task has no design proposal yet, continue the original workflow so the Agent can prepare a concrete proposal and request confirmation. A handoff command cannot replace the proposal or user decision.

## Generate a reading view

```bash
comet handoff <change-name> design --write --full
```

The view is written to `.comet/handoff/design-context.md` in the current change. It includes available proposal, design, tasks, and delta Specs in full. Use the actual change directory returned by Runtime.

This view is for reading. Formal sources still define current requirements and task completion. After source edits, the Agent assesses the impact and regenerates the view only when useful.

## Existing projects and old commands

`off`, `beta`, and old derived files may remain as compatibility records; they no longer represent two hash-based handoff formats. `--hash-only` has been removed. File digests no longer determine whether documents are read or stages may advance.

The package retains the `comet-handoff.mjs` compatibility entry point. Use the public `comet handoff` command for normal operations. See [Context handoff and source reuse](/en/concepts/context-compression) and [Mid-workflow changes](/en/guides/mid-workflow-changes).
