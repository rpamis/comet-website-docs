`comet guard` is a stable phase check command. It will check the files, fields and validation evidence required for the current phase.

<Note>
  The commands on this page are called by the Agent behind the scenes. You do not run them yourself. In day-to-day work you just enter <code>/comet</code> in the conversation, answer the Agent's questions, or say "continue". This page is for troubleshooting in a terminal, writing scripts, or integrating another Agent platform.
</Note>

## Basic usage

```bash
comet guard <change-name> <phase>
comet guard <change-name> <phase> --apply
```

Without `--apply`, `comet guard` only checks conditions without modifying state, and you can also run it directly in a terminal. With `--apply`, it calls `comet state transition` to advance the phase after all checks pass; phase Skills invoke this form at the end of each phase.

## Common checks

- open: Whether the proposal, design, tasks, and delta spec are complete.
- design: Whether the Design Doc exists.
- build: Whether `build_mode`, `isolation`, `tdd_mode`, `review_mode`, and related fields meet constraints, plus running the automatically detected project build checks.
- verify: Whether the verification report and verification result are valid.
- archive: Whether verification has passed and final confirmation is recorded.

## Build checks

During the build phase, `comet guard` no longer reads `build_command` or `verify_command` configuration fields. Instead, it detects build commands from project files such as `package.json` (`npm run build`), Maven, or Cargo.

If `build_command` or `verify_command` remains in a change's `.comet.yaml`, `comet guard` rejects it as an unknown field. Put fixed team-level verification commands in your project's own scripts. When Comet cannot infer the entry point automatically, the Agent or CI script runs the command first and then records the evidence with `comet state record-check`; `comet guard` verifies that record.

<Warning>
  When guard fails, do not forcibly change the status to bypass it. Fix the missing evidence or return to the corresponding phase first.
</Warning>

<Note>
  The package still includes the <code>comet-guard.mjs</code> compatibility launcher, but Agent instructions, scripts, and terminal troubleshooting should prefer <code>comet guard</code>.
</Note>
