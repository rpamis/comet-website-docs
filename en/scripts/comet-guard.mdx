`comet-guard.mjs` protects the workflow from moving forward without required evidence. It validates phase-specific conditions and reports concrete blockers.

## Guarded phases

| Phase | Exit requires |
| --- | --- |
| open | proposal, spec delta, and tasks are present. |
| design | design artifacts and handoff evidence are current. |
| build | tasks are complete and configured build checks pass. |
| verify | verification report exists and branch/worktree status is handled. |
| archive | archive evidence confirms the change is closed. |

## What blocked means

A blocked result means Comet found missing or stale evidence. Fix the named artifact or check, then rerun the workflow. The guard should not partially update state when a required check fails.

## Build and verify commands

If the project config or workflow state defines build or verify commands, the guard can run them as part of the phase check. Command output becomes part of the evidence used to decide the next transition.

## Relationship to state

Guard validates whether a transition is allowed. State records the transition after the guard passes.
