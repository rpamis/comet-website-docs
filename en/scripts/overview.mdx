Comet used to rely on shell scripts. The current runtime ships Node.js `.mjs` launchers so the same workflow can run on Windows, macOS, and Linux without requiring Git Bash or WSL.

## Why move from `.sh` to `.mjs`

The shell implementation proved the workflow model, but it made Windows support fragile. Node launchers remove shell-path assumptions, improve JSON/YAML handling, and make runtime behavior easier to test.

## Script responsibilities

| Script area | Responsibility |
| --- | --- |
| state | Read and update `.comet.yaml` and runtime state. |
| guard | Enforce phase transitions and required evidence. |
| handoff | Package design/spec/task context and calculate hashes. |
| archive | Close accepted changes and preserve history. |
| routing | Classify `/comet` requests against the current project state. |

## How scripts cooperate

1. routing decides the intended action;
2. state reads the current workflow;
3. guard validates whether the transition is allowed;
4. handoff records evidence when moving from design to build;
5. archive closes the change after verification.

## Where to find runtime evidence

Look in `.comet/`, the active OpenSpec change directory, Superpowers artifacts, and archive output. These files are the recovery source after chat context is lost.
