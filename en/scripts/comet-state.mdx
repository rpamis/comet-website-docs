`comet-state.mjs` is the runtime interface for Comet workflow state. Agents should use Comet commands and installed Skill entrypoints instead of editing `.comet.yaml` directly.

## What it manages

| Area | Purpose |
| --- | --- |
| current workflow | change id, phase, mode, and archive status |
| transition events | allowed moves such as build complete or verify pass |
| user-readable fields | paths, verification report, branch status, timestamps |
| runtime boundary | keeps detailed checkpoints in `.comet/run-state.json` |

## Typical operations

State operations initialize a change, read fields, update approved metadata, validate entry conditions, and record transitions.

Most users interact through:

```bash
comet status
comet dashboard .
```

## Why not edit phase manually

Phase is part of a state machine. A transition should happen only after required artifacts and checks exist. Manual edits can make recovery ambiguous.

## Recovery role

After context compression or a new session, `/comet` uses state files to decide whether to start, resume, verify, archive, or ask for a user decision.
