---
title: 'Native command overview'
description: 'The public Native commands for creating, inspecting, selecting, progressing, recovering, and archiving a change.'
---

`comet native` is the Native Runtime command entry point. Most users only enter `/comet` or `/comet-native` in their Agent; the Skill follows the continuation returned by Runtime.

## Command overview

| Command                       | What it does                                                    |
| ----------------------------- | --------------------------------------------------------------- |
| `comet native init`           | Initialize or normalize Native project configuration            |
| `comet native root show/move` | Inspect or transactionally move the artifact root               |
| `comet native new`            | Create a change and prepare `current`, `branch`, or `worktree`  |
| `comet native show`           | Read the brief, Specs, and portable state                       |
| `comet native status`         | View the change, Loop, acceptance, checks, and next action (`--cursor` paginates, `--details` shows the full continuation) |
| `comet native select`         | Select ownership when several changes coexist                   |
| `comet native spec remove`    | Record a capability-removal intent                              |
| `comet native next`           | Confirm or recover a boundary and submit handoff/Verifier input |
| `comet native archive`        | Preview or execute Archive and workspace finish                 |
| `comet native check`          | Run the read-only Native verification check for a change        |
| `comet native doctor`         | Diagnose, migrate, and rebuild local Runtime                    |

The new Native flow no longer exposes `checkpoint`, `evidence`, or `receipt` commands; acceptance checks run during Verify and you can re-run them read-only at any time with `comet native check`. Results are stored in portable state and the user report.

## Create and inspect

```bash
comet native new add-user-avatar --isolation current
comet native status --json
comet native status add-user-avatar --details --json
comet native show add-user-avatar
```

`new` creates the brief, Specs, and `comet-state.yaml`; local execution lives under `.comet/runtime/native/`. `status` and `show` are read-only and do not switch selection as a side effect.

## Progress and Verify

`next` does not accept a self-reported pass. It confirms Shape, accepts or revises a Verify result, retries an allowed Verifier, or accepts the Runtime-defined handoff, check-plan, and Verifier response through `--runner-input`:

```bash
comet native next add-user-avatar --summary "Shape confirmed" --confirmed
comet native next add-user-avatar --summary "Current result accepted" --accept-result
comet native next add-user-avatar --summary "Implementation needs revision" --revise-implementation
comet native next add-user-avatar --summary "Acceptance criteria changed" --revise-requirements
comet native next add-user-avatar --runner-input <temporary-json-file>
```

Use `--accept-result`, `--revise-implementation`, and `--revise-requirements` for the user decision after Verify. `--confirmed` only confirms Shape or an explicit verifier-unavailable fallback; it does not accept a passing result. When the Verifier is unavailable, the two choices are:

```bash
comet native next add-user-avatar --summary "Retry verifier" --retry-verifier
comet native next add-user-avatar --summary "Accept degraded result" --confirmed
```

`--retry-verifier` keeps the current candidate and completed checks and starts a new acceptance attempt. For Supervisor parallel progress, `next` also accepts `--coordination-mode` and `--max-parallel` (default 2); recovery calls can guard stale responses with `--expected-state-version` / `--expected-action`.

Use `continuation.inputOptions.template` from `comet native status <name> --details --json` as the current input schema. Only the current Verifier can request checks through `request-checks`; a Builder self-report cannot enter Archive.

## Archive

Read the archive-ready continuation, then preview or execute as needed:

```bash
comet native archive add-user-avatar --dry-run
comet native archive add-user-avatar --confirmed
```

Archive applies complete target Specs, writes `verification.md`, moves the change, and cleans local Runtime; the normal path does not rerun Verify. For branch/worktree isolation, specify the delivery with `--finish keep|merge|push|pull-request` (the option semantics are described in [Archive and delivery](/en/native/archive-and-delivery)). For a capability conflict, choose the serial order first with `--serial-first`.

## Diagnose, migrate, and recover

```bash
comet native doctor
comet native doctor add-user-avatar
comet native doctor add-user-avatar --repair
```

`doctor --repair` only performs deterministic migration, transaction finalization, and local overlay rebuild. It does not rewrite requirements, Specs, or code. A missing `verification.md` does not block Shape/Build recovery; a wrong branch/worktree or mixed active/archive layout pauses and waits for you to resolve it.

The user-readable artifacts are the brief, Specs, `comet-state.yaml`, and `verification.md`. `.comet/runtime/native/` contains only local state, logs, locks, and transactions.
