`comet status` is the read-only daily recovery entry point. It lists Native, Classic, and unmanaged OpenSpec changes from the configured project, without changing selection or running checks as a side effect.

## Usage

```bash
comet status
comet status --json
```

For Native details, use:

```bash
comet native status <change-name> --details --json
```

## What Native status contains

Native v4 status comes from `comet-state.yaml` and includes:

- `schema`, `state_version`, `status`, `phase`, and `loop.stage`;
- `loop.iteration`, `loop.attempt`, stagnation/failure/execution-error counters, and bounded history;
- every acceptance item with its `passed`, `failed`, `blocked`, or `pending` reason;
- Builder handoff, Runtime checks, Verifier verdict, risks, and blockers;
- the next `continuation` action, plus whether the local overlay is running, interrupted, or absent.

Normal Native details do not require project scans, old receipts, or change-local Runtime files. `verification.md` is a user report generated from YAML and can be rebuilt when missing.

## Native JSON fragment

```json
{
  "schema": "comet.native.v4",
  "name": "avatar-upload",
  "status": "verify",
  "phase": "verify",
  "loop": { "stage": "verify", "iteration": 1, "attempt": 2 },
  "acceptance": { "passed": 3, "failed": 0, "blocked": 0, "pending": 0 },
  "continuation": { "action": "dispatch-verifier" }
}
```

Follow `continuation.commandArgs` and `inputOptions.template` from the current response. Do not add internal execution identity or result fields by hand.

## Select the current change

A project may have multiple active Native changes. `.comet/current-change.json` only selects which workflow/change owns the next write; it is not a one-change lock. Make ownership explicit with:

```bash
comet native select <change-name>
```

A branch/worktree mismatch, ambiguous target, unsynced code, or mixed active/archive layout returns `await-user` or `blocked` instead of guessing another change.

## Classic and OpenSpec

Classic changes keep their five phases, task progress, and Classic Runtime. Plain OpenSpec changes are not forced into a Comet state machine:

| Type           | State source                                            | Archive command when ready                       |
| -------------- | ------------------------------------------------------- | ------------------------------------------------ |
| Native         | portable `comet-state.yaml` plus optional local overlay | `comet native archive <change-name> --confirmed` |
| Classic        | `.comet.yaml` plus Classic Runtime                      | `comet archive <change-name>`                    |
| Plain OpenSpec | OpenSpec artifacts                                      | `openspec archive <change-name> -y`              |

When status reports a problem, follow its `continuation` first, then run:

```bash
comet native doctor <change-name>
```
