---
title: 'comet status'
description: 'View active changes, current phases, next commands, and recovery guidance.'
---

`comet status` is the first command to use for everyday recovery and troubleshooting.

## Basic usage

```bash
comet status
```

| Option   | Description              |
| -------- | ------------------------ |
| `--json` | Output structured status |

## What it tells you

- Whether project configuration sets Native or Classic as the default entry point; projects without root configuration show the Classic legacy fallback.
- Separate sections for Native changes, Classic changes, and plain OpenSpec changes.
- Native phase, approval, verification, selection, and next step.
- Classic workflow, phase, runtime mode, current step, and file-evidence status.
- Recovery guidance for missing evidence or malformed `.comet.yaml`.

## Reading mixed changes

A project can contain Native, Classic, and plain OpenSpec changes at the same time—even changes with the same name. `comet status` displays them in separate sections. It does not convert fields, merge state, or force a plain OpenSpec change into either Comet state machine.

| Change type           | State source                                        | Archive command when ready           |
| --------------------- | --------------------------------------------------- | ------------------------------------ |
| Native change         | `<artifact-root>/comet/changes/` and Native runtime | `comet native archive <change-name>` |
| Classic change        | `.comet.yaml` and Classic runtime evidence          | `comet archive <change-name>`        |
| Plain OpenSpec change | OpenSpec artifacts and task state                   | `openspec archive <change-name> -y`  |

Changes that have not passed verification, have invalid state, or still have incomplete tasks do not show a direct archive recommendation. Follow `next:` or the recovery guidance to restore the required evidence first.

## Multiple active Comet changes

With only one active Comet change, source writes can be attributed automatically. When multiple changes are active, select the current work target explicitly:

```bash
comet state select <change-name>
comet state current
```

Selection is bound to the current branch or worktree. After switching branches or worktrees, or after the target is archived, select again. Use `comet status` to review candidates; guards do not guess when the target is ambiguous.

## Recommended use

```bash
comet status
```

If the output looks abnormal, then run:

```bash
comet doctor
```
