---
title: 'Resume probe (comet resume-probe)'
description: 'Use project configuration to decide read-only whether the current request should resume Native or Classic, pausing on ambiguity or damage.'
---

The resume probe is a read-only step exposed as `comet resume-probe`. It first reads the project-root `comet.config.yaml` to select Native or Classic, then reads only that workflow's active changes, current phase, and the user request. Legacy projects without root configuration retain the Classic fallback. If configuration is malformed, the probe stops and requests repair instead of scanning the other workflow's directories.

It does not modify a change, advance a phase, choose between multiple changes, or execute the returned next command.

## Basic usage

```bash
comet resume-probe . --utterance "continue the login refactor"
```

Read the request from standard input:

```bash
echo "continue the login refactor" | comet resume-probe . --stdin --json
```

Common options:

| Option                    | Purpose                                                                                 |
| ------------------------- | --------------------------------------------------------------------------------------- |
| `--utterance <text>`      | Pass the user request to classify directly                                              |
| `--stdin`                 | Read the user request from standard input                                               |
| `--json`                  | Return stable structured output for agents, hooks, and automation                       |
| `--no-workflow-work`      | Mark the request as informational rather than workflow work                             |
| `--already-in-comet-flow` | Return `out_of_scope` when the turn is already inside Comet, avoiding duplicate routing |

## Understand the result

| `action`       | Meaning                                                                                                              | Next step                                                                                                    |
| -------------- | -------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| `auto_resume`  | One clear target exists and its state allows recovery                                                                | Enter the permanent entry point in `nextCommand`: `/comet-native` for Native or `/comet-classic` for Classic |
| `ask_user`     | The target is ambiguous, state is invalid, or a user decision is required                                            | Ask one question; do not choose a target or scan across workflows                                            |
| `out_of_scope` | The user opted out, the turn is already inside Comet, or the request is informational and unrelated to workflow work | Handle the request normally without entering Comet                                                           |
| `none`         | No active Comet change exists                                                                                        | Do not resume; invoke `/comet` explicitly to start new work                                                  |

JSON uses `comet.resume_probe.v2` and includes `workflow`, `skill`, `entrySource`, `reasonCode`, `candidates`, `changeName`, `phase`, `nextCommand`, and decision evidence. Native resumes from every phase through `/comet-native`; `comet native next` advances state and is not a recovery entry point. The v1 probe bundled with the Classic runtime remains compatible internally, while the top-level CLI returns v2.

## Cases that pause recovery

- Multiple active changes exist and the user request does not name a target.
- Multiple active changes exist without a valid selection or user-named target.
- An active change lacks valid state, or project configuration is malformed.
- The workflow is at plan-ready, verification failure, archive confirmation, or another user decision point.
- A request unrelated to existing changes, or an informational request, does not resume and returns `out_of_scope` instead.

For Native, uncommitted changes are recovery evidence and a reminder; they do not by themselves block a strong model from entering `/comet-native` and inspecting the worktree. Classic retains its worktree-attribution confirmation rules.

<Warning>
  <code>ask_user</code> is not an error. It means the evidence is insufficient or the workflow is
  waiting for a user decision. The caller should show the reason and ask the user instead of
  repeatedly running the probe.
</Warning>

## How it differs from other commands

| Command              | Purpose                                                                           |
| -------------------- | --------------------------------------------------------------------------------- |
| `/comet`             | Forward to `/comet-native` or `/comet-classic` according to project configuration |
| `comet resume-probe` | Perform a read-only recovery probe before entering a workflow                     |
| `comet status`       | View active changes, phases, evidence, and recommended next steps                 |
| `comet doctor`       | Diagnose installation, environment, or damaged state                              |
