---
title: "comet resume-probe "
description: "During long-term tasks, cross-session, or cross-device recovery, read-only determines whether the current natural language request corresponds to the existing Comet Change and helps the Agent re-enter the correct workflow. "
---

`comet resume-probe` mainly addresses the loss of workflow context in long-distance tasks: the user still wants to continue with a certain Comet Change, but the Agent is no longer aware that the current request belongs to Comet in the new context window, session, or device, and the user does not explicitly call `/comet` again. The recovery probe will read-only compare the user request with the existing active changes to determine whether to re-enter the corresponding Native or Classic workflow, avoiding the Agent from treating "continuing the previous login refactoring" as an ordinary new task after leaving Comet.

It first reads the `.comet/config.yaml` of the project to determine Native or Classic, and then only reads the active changes, current stage and user requests of this workflow. Old Classic projects without effective workflow configuration remain legacy fallback; When the configuration is damaged, stop and request repair without scanning another set of directories.

Recovery detection is only responsible for identification and routing. It will not modify the change, advance the phase, select multiple changes for the user, nor will it automatically execute the next command returned. The actual recovery is still accomplished by the Agent calling `/comet-native` or `/comet-classic` by pressing `nextCommand`.

## Why is it necessary to restore the detection

Long-distance tasks do not necessarily always remain in the same complete context. The following situations may all cause the Agent to forget that the current job was originally managed by Comet:

- The dialogue undergoes context compression, window switching, or starts a new session;
- When a user changes equipment, they continue to use the same warehouse and change.
- The new Agent can only see the disk status and the sentence "Continue with the previous work."
- The user naturally requested to continue the task, but did not enter `/comet` again.

The Comet recovery description written by the project initialization enables the Agent to invoke the recovery probe before processing such requests. The probe returns interpretable results based on configuration, active change, stage, selection, and request text: It provides the correct permanent Skill entry when the target is unique, asks only once when the target is unclear, and remains in the normal conversation when it is truly irrelevant.

<Note>
Restoring detection does not require users to remember an additional command. It is mainly called by agents and project recovery descriptions to bridge the gap between natural language continuation and the explicit <code>/comet</code> entry.
</Note>

## How does automatic detection occur

Users do not need to input `comet resume-probe`. Normal interaction still directly tells the Agent:

> Continue with the login refactoring just now.

`comet init` and `comet update` will write the recovery instructions into the project's Agent instruction file. When `ambient_resume` is enabled, the Agent will automatically run a read-only recovery probe before processing natural language requests that may be long-term tasks:

1. Read the project configuration to determine whether Native or Classic should be checked.
2. Compare user requests, active changes, current stage and selection;
3. When the target is unique, press `nextCommand` to re-enter the corresponding `/comet-native` or `/comet-classic`.
4. When the goal is ambiguous, only ask the user one question. When the request is irrelevant, handle it normally and do not enter Comet.

When explicitly calling `/comet`, it will directly enter the workflow according to the project configuration without relying on automatic detection. The ** non-Comet ** Skill or slash command explicitly invoked by the host does not trigger the recovery probe either - the task intent has been clearly defined by this call, and the Skill can be directly executed. If the project is set to `ambient_resume: false`, ordinary natural language requests will not trigger environmental awareness detection, but `/comet` is still available.

<Note>
For users, the recovery detection is automatic. The following CLI parameters are used for Agent, Hook, project instructions, and automation integration, and are not steps that must be manually executed before restoring tasks.
</Note>

## Reference for Agent and Automation Integration

An Agent or integrator can directly pass in requests:

```bash
comet resume-probe . --utterance "Continue with the login refactoring just now" --json
```

It can also be read from standard input:

```bash
echo "Continue with the login refactoring just now" | comet resume-probe . --stdin --json
```

|Options|Function|
| ------------------------- | ---------------------------------------------------------- |
| `--utterance <text>`      |Pass in the user requests that need to be classified directly|
| `--stdin`                 |Read the user request from the standard input|
| `--json`                  |Output stable structured results, suitable for agents, hooks and automation|
| `--no-workflow-work`      |Mark the current request as an information query and skip workflow advancement|
| `--already-in-comet-flow` |When it is already within the Comet process, return `out_of_scope` to avoid duplicate routing|

## How to understand the result

| `action`       |Meaning|Next step|
| -------------- | ------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| `auto_resume`  |There is a clear goal and the state allows for recovery|The Agent enters the permanent entry by pressing `nextCommand`: Native is `/comet-native`, and Classic is `/comet-classic`|
| `ask_user`     |The target is ambiguous, abnormal in status or must be determined by the user|Ask only one question and do not choose or scan across workflows by yourself|
| `out_of_scope` |The user clearly does not want to restore, is currently in Comet, or the request is merely an information query unrelated to workflow|Answer the current request normally and do not enter Comet|
| `none`         |There is no active Comet Change|Do not perform recovery; If you need to start a new job, you can explicitly run `/comet`|

JSON uses `comet.resume_probe.v2`, including `workflow`, `skill`, `entrySource`, `reasonCode`, `candidates`, `changeName`, `phase`, `nextCommand` and judgment evidence. Native restores at any stage through `/comet-native`. `comet native next` is a status advancement command, not a recovery entry. The internal v1 probe of Classic's built-in runtime remains compatible, but the top-level CLI returns v2.

## Under what circumstances will it definitely be suspended

- Multiple active changes, but the user request did not name the target.
- Multiple active changes without valid selection or user roll call.
- The active change lacks a valid status or the project configuration is damaged.
- Currently, it is at user decision points such as plan-ready, verification failure, and archive confirmation.
- When the request is not related to an existing change or is merely an information query, it will not be restored but will return `out_of_scope`.

The unsubmitted changes of Native are only used as recovery evidence and reminders, and will not separately block strong models from entering the `/comet-native` inspection site. Classic continues to retain the rule for confirming the ownership of the working tree.

<Warning>
  <code>ask_user</code>{' '}
This result indicates insufficient evidence or that the process is waiting for the user to make a choice, which is a normal pause state. The caller should present the reasons and ask the user. Repeated operation of the recovery detection fails to complete the required evidence.
</Warning>

## The difference from other commands

|Command|Purpose|
| -------------------- | ---------------------------------------------------- |
| `/comet`             |Forward to `/comet-native` or `/comet-classic` according to the project configuration|
| `comet resume-probe` |Perform a read-only recovery probe before entering the workflow|
| `comet status`       |View active change, stages, evidence and recommend next steps|
| `comet doctor`       |Diagnose installation, environmental or condition damage|
