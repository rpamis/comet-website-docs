---
title: 'Native CLI'
description: 'Initialize Native, manage changes, advance phases, archive specifications, and recover interrupted transactions.'
---

`comet native` is the single CLI facade for the Native workflow. It operates only on `comet.config.yaml` and the configured `<artifact-root>/comet/`; it does not read Classic or OpenSpec changes.

## Initialize and manage the artifact root

```bash
comet native init [--root <artifact-root>] [--language en|zh-CN]
comet native root show
comet native root move <artifact-root>
```

Examples:

```bash
# <project>/comet/
comet native init

# <project>/docs/comet/
comet native init --root docs --language en

# Transactionally move to <project>/artifacts/comet/
comet native root move artifacts
```

Existing configuration rejects a conflicting `init --root`. A root move progresses through `copying`, `ready`, and `switched`. While `pending_root_move` exists, ordinary Native write commands fail closed instead of guessing which tree to use.

## Change management

```bash
comet native new <change-name> [--language en|zh-CN]
comet native list
comet native show <change-name>
comet native status [<change-name>]
comet native select <change-name>
comet native spec remove <change-name> <capability>
comet native spec rebase <change-name> --summary <text>
```

`change-name` uses lowercase kebab-case. `new` creates default `<project>/comet/` configuration when absent. `show` returns change state, the brief, and proposed complete specifications. `status` returns the current phase, verification result, next command, and archive readiness. `select` writes only Native-owned selection state.

For added or replaced durable behavior, write the complete target specification to `changes/<change-name>/specs/<capability>/spec.md`. The runtime derives `create` or `replace` from canonical-spec existence and freezes the `base_hash` used for conflict checks. Use `spec remove` to delete a capability. Do not edit `spec_changes` in `change.yaml` manually. After a concurrent change causes a conflict, re-read and rewrite the complete target specification, then use `spec rebase` to refresh the baseline, return to Build, and clear the old verification conclusion.

## Progress and archive

```bash
comet native next <change-name> --summary <text> \
  [--confirmed] \
  [--artifact <project-relative-path>]... \
  [--no-code-reason <text>] \
  [--result pass|fail] \
  [--report <change-relative-path>]

comet native archive <change-name>
```

Evidence by phase:

| Current phase | Required condition                                                | Result                                          |
| ------------- | ----------------------------------------------------------------- | ----------------------------------------------- |
| Shape         | Complete brief, valid complete target specs, no blocking question | Enter Build and let the runtime record approval |
| Build         | Unblocked brief/specs plus an artifact or no-code reason          | Enter Verify                                    |
| Verify        | `--result` and a complete `--report`                              | pass enters Archive; fail returns to Build      |
| Archive       | Verify passed and canonical hashes still match                    | Update canonical specs and archive              |

Pass `--confirmed` during Shape or Build progression only when the user has just confirmed a decision that materially affects scope, user-visible behavior, compatibility, risk, or irreversibility. With no such decision, the runtime records implicit approval. No approval form can bypass a `[blocking]` question in `brief.md`.

`next` cannot replace `archive`. If another change already modified the same canonical spec, the command reports a conflict and preserves the active change. After re-reading the canonical specification and updating the complete target specification, run `spec rebase`. The runtime reopens Build under state control, and implementation, confirmation, and verification must run again.

## Diagnose and recover

```bash
comet native doctor [<change-name>]
comet native doctor [<change-name>] --repair --strategy continue
comet native doctor [<change-name>] --repair --strategy rollback
```

Doctor is non-mutating by default. Every ordinary phase transition first writes `runtime/transition.json`. If the process stops between Run state, `change.yaml`, trajectory, or checkpoint writes, the next `next` or `archive` idempotently continues that transition first. Use `doctor --repair --strategy continue` to recover it explicitly.

Explicit repair can also clear a selection that points to a missing change, remove a provably stale local lock, and continue or roll back an Archive or root-move transaction according to its journal. Ordinary phase transitions support only `continue` because their journal contains a deterministic before-and-after state. `rollback` remains available only for Archive or root-move transactions that still permit it.

Once Archive finalization starts, only continue is safe. When hashes cannot match either side of a transaction or root tree, doctor stops automatic recovery and preserves all data for manual judgment.

## JSON and exit codes

Every Native command supports `--json` and emits exactly one object:

```json
{
  "command": "status",
  "exitCode": 0,
  "data": {}
}
```

Failures add a structured `error`.

| Exit code | Meaning                                              |
| --------- | ---------------------------------------------------- |
| `0`       | Success                                              |
| `64`      | Invalid arguments or usage                           |
| `65`      | Invalid configuration, state, or artifacts           |
| `70`      | Unexpected internal failure                          |
| `73`      | Lock, transaction, concurrent hash, or root conflict |

## Hosts that expose only Skill files

If the host does not have the `comet` CLI, use the runtime shipped with `/comet-native` directly:

```bash
node <comet-native-skill-root>/scripts/comet-native-runtime.mjs <command> [options]
```

It uses the same arguments, output, and exit codes as `comet native`, without depending on OpenSpec, Superpowers, or any external Skill.
