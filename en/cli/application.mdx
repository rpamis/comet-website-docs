---
title: 'comet application'
description: 'Export, preview, install, distribute, upgrade, and selectively uninstall complete SDK workflow applications.'
---

`comet application` handles complete applications whose entry is `application.json`. It manages the application package, pinned dependencies, and platform Skill/Rule/Hook entries together.

## Commands

| Command                       | Purpose                                                               |
| ----------------------------- | --------------------------------------------------------------------- |
| `install <file>`              | Preview or confirm the current application's local installation       |
| `distribute <file>`           | Distribute an application to selected Comet platforms                 |
| `export <file> <destination>` | Export the complete package and pinned dependencies                   |
| `uninstall <id>`              | Preview and remove platform entries while retaining required versions |

## Preview and confirm

```bash
comet application distribute ./weekly-report/application.json --project . --platform codex --preview --json
```

Read the write targets, pinned content, capabilities, and conflicts. After the user confirms, continue with the hash returned by this preview:

```bash
comet application distribute ./weekly-report/application.json --project . --platform codex --confirmation-hash <current-preview-confirmation-hash> --json
```

Without a confirmation hash, distribution returns a preview by default. If the package, files, or configuration change, obtain and confirm a new preview.

| Option                       | Purpose                                                         |
| ---------------------------- | --------------------------------------------------------------- |
| `--project <dir>`            | Project associated with the installation; defaults to `.`       |
| `--platform <id>`            | Repeat to select platforms; `all` selects registered platforms  |
| `--scope project`            | Project installation; the default                               |
| `--scope user`               | User installation                                               |
| `--user-root <dir>`          | Use an isolated user application directory                      |
| `--preview`                  | Read the preview without installing                             |
| `--confirmation-hash <hash>` | Submit the confirmed current preview                            |
| `--upgrade`                  | Update platform entries and retain versions used by active Runs |
| `--json`                     | Return structured output                                        |

The preview describes platform installation capabilities. Resolve missing Hooks, required host activation, or unavailable Skill loading before proceeding. Successful file installation does not establish successful execution.

## Export

```bash
comet application export ./weekly-report/application.json ./exports/weekly-report --project . --json
```

Export retains the entry, modules, and pinned dependencies. Do not copy only `SKILL.md` or replace package modules without updating the identity and confirmation.

## Selective uninstall

```bash
comet application uninstall weekly-report --project . --platform codex --json
comet application uninstall weekly-report --project . --platform codex --confirmation-hash <current-uninstall-preview-hash> --json
```

Omitting platform selection removes all entries. Shared Rule/Hook entries, dependencies used by other applications, and required versions remain available.

After an interrupted uninstall, retry with the original platform selection and `--confirmation-hash` to continue the confirmed plan. Finish that uninstall before reinstalling. If an entry file has changed, resolve the conflict first and keep the original uninstall scope.

Use [comet runtime](/en/cli/runtime) for execution records and [comet creator](/en/cli/creator) for authoring.
