## Installation and initialization

<AccordionGroup>
  <Accordion title="Will comet init overwrite my existing configuration">
No. When an existing component is detected, `comet init` will allow you to choose to overwrite or skip it. hooks are non-destructive merging, keeping the hooks you already have. In the `--yes` mode, existing components are skipped by default. To force a refresh, use `--overwrite`.
  </Accordion>

## Status and Diagnosis

<AccordionGroup>
  <Accordion title="What happens if I say continue without entering /comet?">
Starting from 0.4.0-beta.4, installing or updating the generated project description will cause the Agent to run read-only recovery probes first. Recovery is only recommended when there is a clearly relevant active change that is not at the decision point. When there are multiple changes, unsubmitted alterations, or irrelevant requests, inquiries will be made first or normal responses will be given. It will not be forced into the workflow. For details, please refer to the [Restore Detection Command ](/en/cli/resume-probe)
  </Accordion>

<Accordion title="What's the difference between comet status and comet doctor">
`comet status` check the active change
The current stage and the next command are the first commands for daily recovery. `comet doctor`
Conduct a complete installation health check (Skill, script, working directory, change status), suitable for `status`
Troubleshooting when abnormal display occurs.
</Accordion>

<Accordion title="Should we take care of a doctor who warns">
`warn` is usually not blocking (such as when openspec CLI is not installed but the project does not depend on it), while `fail` is blocking (such as
(Skill missing, state corrupted) It is recommended to give priority to handling `fail`. For more details, see [comet]
  doctor](/en/cli/doctor)。
</Accordion>

  <Accordion title="Why does the Agent still show as unavailable when the CodeGraph index is normal">
CodeGraph CLI, project index, MCP registration and Agent effective capability are four independent states. If the CLI is installed and the index is up to date, it only indicates that the project data is ready. The corresponding Agent also needs to register a valid MCP pointing to the CodeGraph service before it will be displayed as "effective".

Run `comet doctor --json` and check `codegraph.cliStatus`, `indexStatus`, `mcpStatus`, `agents` and `effectiveForAgent`. Fix the missing links according to the actual diagnosis in the output. Do not skip the MCP check just because the index is normal.

  </Accordion>

  <Accordion title="The comet status display stage is incorrect">
First, run `comet doctor` to see if there are any abnormal `.comet.yaml` or missing evidence. After the repair, run status again. For the troubleshooting of abnormal status, please refer to [Status Damage and Recovery ](/en/guides/state-recovery)
  </Accordion>
</AccordionGroup>

## Upgrade and Uninstall

<AccordionGroup>
  <Accordion title="How can I upgrade to RC1">
Interactive updates can update the applicable npm packages and refresh the Skill, Rule, Hook, Runtime and managed configuration in the registered items. After completion, run "Doctor" to confirm the installation health

    ```bash
    comet update
    comet doctor
    ```

By default, `--current-project`, `--scope global` or `--json` only refresh assets and do not update npm packages. When using these limited modes and needing to upgrade the CLI simultaneously, explicitly add `--self-update`:

    ```bash
    comet update --current-project --self-update
    comet doctor
    ```

The Native Portable State, Supervisor, Personal Memory, Project Knowledge and platform adaptation of RC1 all rely on the Runtime and managed assets released with the version. Upgrading only the npm package without running `comet update` will cause the project to continue using the old assets.

  </Accordion>

<Accordion title="Will uninstalling delete my code or OpenSpec change">
No. `comet uninstall` only removes the skills, rules and hooks managed by Comet and keeps yours
OpenSpec change, design documents, implementation plans and project codes. For more details, see [comet]
  uninstall](/en/cli/uninstall)。
</Accordion>

  <Accordion title="Which one should be used, update or init">
After upgrading the version, refresh the Skill/ rule/script with `comet update`. `comet init` is used for the first installation or new platform. Both non-destructively retain user configuration.
  </Accordion>
</AccordionGroup>

## Skill, evaluation and command issuance

<AccordionGroup>
  <Accordion title="Which one should be used, comet skill or/Comet-any">
When creating reusable skills, it is preferred to use `/comet-any`, which will internally invoke the CLI backend. `comet skill` is a low-level tool, suitable for local debugging, advanced Skill execution, and package management. See comet skill](/en/cli/skill).
  </Accordion>

<Accordion title="What are the differences between comet eval and comet skill check">
`comet eval` assesses the product capabilities of a Skill and produces pre-release evidence. `comet skill check`
Check whether a certain Skill run is missing an artifact or status without generating release evidence. Publish readiness
Just `comet eval`. See comet eval](/en/cli/eval).
</Accordion>

  <Accordion title="Which one should be used, comet bundle or comet publish">
Ordinary users use `comet publish` (user Posting entry). `comet bundle` is an advanced backend that is only directly used for checking backend status, auditing, or automated integration. See [comet publish](/en/cli/publish).
  </Accordion>
</AccordionGroup>

## CI/CD

<AccordionGroup>
  <Accordion title="How to install non-interactively in CI">
Skip all prompts with `--yes --json`:

    ```bash
    comet init --yes --scope project --language zh --json
    ```

  </Accordion>

  <Accordion title="Can json output be stably parsed">
Yes. The JSON structure of `status` and `doctor` is part of the CLI contract. CI access control suggests that only the `fail` of `doctor` exit non-zero. For details, please refer to [CI/CD integration ](/en/guides/cicd-integration)
  </Accordion>
</AccordionGroup>
