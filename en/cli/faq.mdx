## Install and initialization

### Do I install globally or per project?

Install the CLI globally with npm, then use `comet init` inside each project that should use Comet.

### Should Skills be project-level or global?

Prefer project-level install for team repositories. Use global install for personal defaults across many projects.

## State and diagnostics

### When should I use `comet status`?

Use it when you need the current phase, change id, mode, archive state, or recovery hint.

### When should I use `comet doctor`?

Use it when platform files, Skill installation, hooks, or runtime assets look broken.

## Upgrade and uninstall

```bash
npm install -g @rpamis/comet@latest
comet update
```

## Skill, eval, and publish commands

Use `comet creator` for `/comet-any` recovery, `comet eval` for scoring, and `comet publish` for release readiness.
