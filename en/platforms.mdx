## Summary of Capabilities

### Rule format

Comet supports four rule formats:

|Format|Use the platform|
| --------- | -------------------------------------------------- |
| `md`      |The vast majority of platforms that support rules|
| `mdc`     |Cursor and Oh My Pi; Oh My Pi uses alway-apply MDC|
| `copilot` |Only GitHub Copilot|
| `dsh`     |Only DeepSeek Harness; Write to the managed `AGENTS.md` block|

### Hooks format

The 16 Hook platforms in the current list use 11 hook formats:

|Hook format|Write to the file|Use the platform|

| `qwen`        | `settings.json`                  | Qwen Code                          |
| `qoder`       | `settings.json`                  | Qoder                              |

## Choose project-level or global

|Installation scope|Suitable scenarios|Features|
| -------- | -------------------------------- | ------------------------------ |
| project  |Team projects, warehouse agreements, and the need to submit configurations|The configuration is written to the current project to facilitate collaboration|
| global   |Personal default environment, shared by multiple projects|The configuration is written to the user directory, making it more convenient to switch projects|

<Tip>
If you're not sure, install it at the project level first. It is the easiest for team members to see the same set of Comet behaviors.
</Tip>

## Installation mode: Copy vs symbolic link

After `comet init` and `comet update` select the platform, they will ask for "install mode". Starting from 0.4.0-beta.1, a new symlink mode has been added:

|"Mode"|"Behavior"|Suitable|
| ----------------------- | ---------------------------------------------------------------------------------------- | ------------------------------------------------------ |
|**Copy** (Copy, default)|Copy the skills, rules and scripts of each platform independently to the target directory|The traditional approach requires mutual isolation between platforms and cross-device synchronization (submitted to the warehouse)|
|"Symlink" (Symbolic link)|Link the Comet-managed skills within the existing `skills/` directory of the target platform and share the `.comet/skills/` central storage|Multi-platform development, save disk space, and want to update all platforms at once|

### The working mode of Symlink mode

After selecting Symlink, Comet no longer copies Comet Skill for each platform. Instead, it creates symbolic links for Comet Skill in the existing `skills/` directories of each platform, pointing to the central `.comet/skills/` of the project:

```text
.comet/skills/ ← Central storage (only one copy)
├── comet-open/
├── comet-design/
└── ...
.claude/skills/comet-* →.comet/skills/comet-* (symbolic link created by Comet)
.cursor/skills/comet-* →.comet/skills/comet-* (symbolic link created by Comet)
.agents/skills/comet-* →.comet/skills/comet-* (symbolic link created by Comet)
```

When running `comet update`, only the central storage needs to be updated, and it takes effect immediately on all platforms. The terminal summary will display `symlink created` or `symlink creation failed`.

<Warning>
Symbolic links rely on file system support. Some Windows
Configuration or synchronization tools (such as some cloud disks) may not handle symbolic links correctly. If you encounter any problems, roll back to {" "}
The <strong>Copy</strong> mode is fine.
</Warning>

<Note>
If the target platform already has its own <code>skills/</code> directory, Comet
The directory and the local/third-party skills within it will be retained, and only the links managed by Comet will be created or refreshed.
</Note>

<Note>
Which mode is chosen does not affect Comet's behavior; it only influences how files are landed on the disk. When submitting to the repository, Copy
The mode will generate real files; The Symlink pattern generates symbolic links (usually requiring each team member to {" "})
  <code>comet init</code>）。
</Note>

## General skills Registry Platform

Some AI coding platforms manage skills through the universal `skills` CLI registry. For these platforms (including OpenClaw, Hermes, etc.), install the Comet skill package directly using the common command:

```bash
npx skills add rpamis/comet
```

This command pulls the Comet skill package from the common skills registry and installs it to the location expected by the platform without the need for a global Comet installation. It can coexist with `comet init` without any conflict.

## hooks and executable capabilities

Some platforms support hooks. Comet will non-destructively merge the hook configurations it manages and retain the existing configurations of users.

If there are already plugins, hooks or other user Settings in the file, Comet will retain them. If the JSON cannot be parsed, the installation will explicitly fail and the original file will remain unchanged.

## Verification after installation (not mandatory

```bash
comet doctor
```

If the platform directory, Skill file, script or hooks are missing, `doctor` will provide a diagnosis. Run when an update is needed:

```bash
comet update
```
