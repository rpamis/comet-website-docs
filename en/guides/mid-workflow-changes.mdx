## Continue the current task after edits

Native and Classic retain your actual edits during Build, Verify, or before Archive. The current Agent checks their content and impact, then continues the original Run. Ordinary edits do not require a separate review session or a new change.

- Code or check inputs changed: keep valid work and refresh only affected or missing checks.
- Wording changed in a brief, Spec, Design Doc, or plan without changing its contract: compare it with the approved original, then retain approval and phase.
- Goals, acceptance criteria, approach, or approved scope materially changed: explain the change and impact, then handle the corresponding user decisions.
- Ordinary documentation changed after result acceptance but before delivery: review the impact, refresh affected checks, and continue the original Archive without repeating completed one-time operations.

The Agent follows Runtime guidance such as `comet edit-review observe`. Edits do not grant approval for new operations. Executing tasks or tasks with unknown results cannot simply be restarted.

The transition examples below cover explicit Classic rollback. For everyday edits, follow Runtime's current continuation. For Native acceptance, see [verification and repair](/en/native/verification-and-repair).

## Phase is not manually edited

Do not hand-edit `phase` to force progress. Use the workflow transition that matches the evidence.

## Available transition events

Typical events include proposal approval, design approval, build completion, verify pass, verify fail, archive completion, and preset upgrade.

## Scenario 1: edit spec during build

If the spec changes during build, Comet should detect drift and decide whether the current design still applies.

## Scenario 2: implementation is wrong and you want to rebuild

Use a verify-fail or explicit rollback path. Preserve evidence, then return to build with a clear reason.

In the normal flow, `branch_status` remains `pending`; do not write `handled` during re-verification. Archive records the confirmed delivery method.

## Scenario 3: verify passed but you want another check before archive

Use `archive-reopen` to return to Verify. It resets `branch_status` to `pending`; Archive only after the evidence is acceptable and you are ready for immediate remote delivery.

## Scenario 4: upgrade hotfix or tweak to full

Upgrade the preset to the full workflow when the work needs design, broader verification, or spec changes.

## Scenario 5: edit delta Specs during design

The Agent checks design edits against the original request and updates affected design and planning materials. Material changes to goals or approval scope require reconfirmation.

Classic uses original materials by default, without rebuilding a content hash. Generate a Markdown reading view only when needed, following the current Runtime instructions.

## Scenario 6: resume finds uncommitted changes

Inspect the worktree. Do not discard changes unless the user explicitly asks.

## Rollback reference

| Need               | Route                                    |
| ------------------ | ---------------------------------------- |
| Bad implementation | verify fail -> build                     |
| Spec drift         | build or verify -> design/open as needed |
| Preset got bigger  | preset -> full workflow                  |
| Extra checks       | stay in verify                           |
