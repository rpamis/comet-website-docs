---
title: 'Native Runtime protection and recovery'
description: 'Stage guards, task ownership, Agent checks, and recovery from interruption or blockers.'
---

Native uses stage guards, execution identities, and recoverable transactions to constrain workflow progress. The Agent interprets requirements, runs checks, and assesses edits. Runtime records user decisions, advances the original task, and handles Archive and delivery.

## Identify the owning change

`.comet/current-change.json` selects the current workflow and change. A project may enable several workflows, but each requirement belongs to one. Hook Router resolves ownership before calling that workflow's Guard.

When selection is missing and exactly one valid task exists, ownership may be inferred. Multiple candidates, damaged selection, or workspace mismatches require resolving the target first, without guessing from the default workflow. Use `comet native select <change-name>` when manual selection is needed.

## Stage-aware changes

- **Shape**: Prepare goals, the proposal, and acceptance criteria; implementation waits for your confirmation.
- **Build**: Implement in the task's workspace. Supervisor children write only in their own worktrees; the parent coordinates and submits results sequentially.
- **Verify**: Check the original request and every acceptance item. Return to Build before implementing a repair.
- **Archive**: Archive accepted results within the actual delivery decision, without expanding the approved scope.

Ordinary edits follow `native.document_writes`. The default preserves edits and lets the Agent assess their impact. Wording changes do not automatically revoke approval; requirement changes need reconfirmation, implementation changes revise the candidate, and check changes refresh affected or missing evidence. With `revert`, follow the Guard's rejection and recovery instructions. See [Continue after edits](/en/guides/mid-workflow-changes#continue-the-current-task-after-edits).

## Protection before observable writes

Hooks handle only events and paths supplied by the platform; they are not an operating-system sandbox. IDEs, background processes, and writes the platform does not expose may bypass immediate interception. Later Agent review and Runtime checks of ownership, workspace, and delivery still apply.

Enable or trust Hooks when the platform requires it. Installing a plugin does not itself grant Hook trust.

## Agent-run checks

Development commands and tests run through Agent platform tools. Record actual commands, working directories, results, and limitations. Runtime no longer manages these processes, binds PIDs, waits for stop receipts, or fingerprints project files to decide check reuse.

The Agent determines whether previous checks still apply to the current candidate and environment, retains valid results, and runs necessary verification. Passing tests does not complete acceptance: Verify still covers the original request and every acceptance item. Explicit independent-review requirements remain. See [Verification and repair](/en/native/verification-and-repair).

## Workspace writers and unfinished transactions

One writer maintains state per workspace; child worktrees isolate parallel work. Ordinary workflows no longer create coordination locks or require recovery of obsolete lock records.

Directory migration and Archive still check actual unfinished transactions. Resolve pending steps, uncertain directories, or workspace conflicts through the original transaction. Do not delete state or transaction records to bypass blockers.

## Paths and file ownership

Use Runtime-returned paths for formal documents and state. The relevant entry points still check directory moves, symbolic links, archive targets, and workspace ownership. Growing documents no longer hit built-in byte caps; read failures report actual errors rather than substituting old content.

Path and transaction checks do not mean Runtime snapshots ordinary edits. Do not reconstruct local state manually, alter execution identities, or copy another task's records.

## Recoverable Archive transactions

Archive preserves the original Run, accepted results, approved scope, and actual delivery progress. After interruption, inspect the original transaction and follow its recovery action. Do not repeat completed steps; reconcile unknown external results first.

Preserve the execution site when active and archive directories coexist, a transaction is damaged, a directory is busy, or tasks conflict. Spec updates and Git delivery still require checks. Creating another task cannot overwrite unfinished transactions. See [Archive and delivery](/en/native/archive-and-delivery).

## Resume the original task

Recovery continues the same change and Run. Formal documents and valid checkpoints support cross-device recovery. Local data is isolated by checkout and worktree; use Runtime's actual directory instead of assuming the legacy `.comet/runtime/native/` layout.

Keep waiting for an Agent task that is still running. A wait-tool timeout is not execution failure and does not justify duplicate dispatch. Record actual failure, loss, or unusable results before recovering through the original workflow. See [Task progress and recovery](/en/native/continuation-and-checkpoints).

## Read-only resume probes

`comet resume-probe` identifies the current selection and recoverable tasks without modifying a change or switching branches. Ambiguous ownership requires your choice; no matching task remains neutral. `ambient_resume: false` disables automatic probes for ordinary requests.

## Diagnosis and recovery

Follow the latest task and commands returned by Runtime. For diagnosis, inspect:

```bash
comet status
comet native status <change-name> --details --json
comet native doctor <change-name>
```

Return to the specified workspace when ownership mismatches. Read the latest action after an old command is rejected. Continue migrations and Archive through the returned recovery path. If no supported repair is available, preserve the execution site rather than assembling state manually.

Read the [Recovery playbook](/en/native/recovery-playbook).
