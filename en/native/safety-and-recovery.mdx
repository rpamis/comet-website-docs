The Skill guides the model, while Runtime puts important boundaries into state and files that can be checked. The responsibilities are separate: prose cannot replace a Runtime check, and Runtime cannot decide whether a test is meaningful.

## One write belongs to one change

Comet attributes observable writes to the selected workflow/change, giving each write to at most one Guard. `.comet/current-change.json` selects ownership for the current request but does not limit the number of active changes. A legacy global Hook without trusted project context stays neutral instead of applying another project's change.

This protects only writes the host exposes. A shell, IDE, background process, or platform without Hook visibility may not be attributed immediately; the next Runtime state check still rejects an inconsistent result and returns to Build, Shape, or the user.

## Portable state versus local Runtime

The cross-device boundary is `comet-state.yaml`, the brief, Specs, and the rebuildable `verification.md`. Together they record the phase, Loop, acceptance, handoff, required checks, Verifier verdict, blockers, and next action.

`.comet/runtime/native/` stores only local `state.json`, logs, short-lived locks, and transactions. When moving devices, when files are missing, or when an overlay version does not match, Runtime rebuilds from YAML; an old machine's execution state is never completion proof.

## Build and Verify boundaries

- A Builder submits a handoff and cannot write a passing verdict directly;
- Runtime executes required checks, and a non-zero exit or timeout cannot pass;
- a fresh Verifier must cover every A1…An item; missing, duplicate, and unknown items are rejected;
- Verify failure returns to Build, and the new implementation gets a new Verifier attempt;
- normal Archive does not rerun Verify; it applies Specs, writes the report, and moves the change;
- without an independent Verifier execution, the report and Dashboard show degraded assurance and Archive requires user confirmation.

## Context-aware recovery

`comet resume-probe` is read-only and inspects only the workflow selected by project defaults:

| Result         | Meaning                                                       |
| -------------- | ------------------------------------------------------------- |
| `auto_resume`  | One target is unambiguous and the request intends to continue |
| `ask_user`     | Several candidates exist or ownership is unclear              |
| `out_of_scope` | The request does not intend to enter a resumable workflow     |
| `none`         | No resumable change exists                                    |

When configuration is damaged, code is unsynced, the branch/worktree mismatches, or active/archive layout conflicts, the probe stops with a reason instead of scanning another workflow or guessing a directory. `ambient_resume: false` disables automatic probing for ordinary requests; explicit `/comet` is unaffected.

## Dashboard responsibility

Dashboard is read-only. It shows portable YAML phase, Loop, acceptance, checks, blockers, history, and user documents, adding a matching local overlay when available. It does not progress, repair, or Archive, and it does not expose raw logs or execution identity; all writes go through Native CLI/Runtime.
