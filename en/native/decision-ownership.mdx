---
title: "Which Decisions Need Your Confirmation"
description: "Understand how Native distinguishes investigable facts, user choices, and implementation choices, including the decisions that pause Shape."
---

Native only pauses at the actual user selection point: there are two or more reasonable options, and different choices will change the final result. The facts that can be ascertained in the warehouse are investigated by the Agent. The internal implementation method is determined by the Agent within the confirmed goals and constraints.

You confirm the goal, scope, default behavior, and acceptance criteria. The Agent chooses implementation methods within those boundaries.

## Three types of information, three processing methods

Shape will first determine who is responsible for each piece of information:

|Type|Processing method|Example|
| --- | --- | --- |
|Verifiable facts|The Agent is identified from the code, documentation, tools or runtime environment|Which image formats are supported by the current interface|
|User selection|It's up to you to confirm the final action|After the upload fails, should you keep the original avatar or clear it|
|Implementation selection|The Agent makes autonomous decisions within the confirmed boundaries|Which image processing library should be used|

A problem will only become a user's choice point when it simultaneously meets the following conditions:

- There are two or more reasonable and executable options;
- Different options will change the visible results for users, default behavior, failure results, scope, risks or irreversible impacts.
- Your requirements, formal specifications, project documents and project rules cannot provide reliable answers.

When there is only one legitimate solution, the Agent will explain the basis and proceed. When encountering an execution error or the absence of a secure next step, Native will report a block, allowing you to understand the current status and the required processing.

## Which questions do you need to choose

Take "Adding an avatar upload to the user profile page" as an example:

|It requires your choice.|Hand it over to the Agent|
| --- | --- |
|When the upload fails, should you keep the original avatar or clear it|Which HTTP client should be used|
|Whether users are allowed to delete their existing avatars|Should image cropping be placed on the front end or the back end|
|Maximum size and format restrictions for avatars|Where are the temporary files saved|
|Whether server-side compression is required|Should I use sharp or jimp|

The left side determines how the product works, while the right side influences the internal implementation. The Agent will handle the matters on the right during the implementation process and continuously meet the confirmed results.

## When providing PRD, files or links directly

When files, attachments, links or local paths constitute the source of requirements, Native reads the complete content and establishes source overriding:

- Record source units by title, paragraph, list, table, code block, example, constraint, link and boundary;
- Mark each source unit as `complete`, `partial` or `unavailable`;
- Map the content to be implemented to the complete target Spec and associate it with at least one acceptance ID;
- Categorize the background, non-target and content that has been replaced by new requirements respectively and explain the reasons.
- Retain the content that cannot be read, is only partially read, lacks mapping or still has ambiguity as `[blocking]`.

The source coverage is recorded in the **Scope** of `brief.md`. Block reading only changes the processing order and still overwrites the complete source in the end. The requirements summary can help understand the context, and the formal mapping is responsible for proving that each requirement has fallen within the scope of Spec and acceptance.

Materials used for troubleshooting, forensics, review or reference implementation shall be treated in accordance with their original purposes. When the purpose is not clear, Native will first confirm whether it constitutes a source of requirements.

## How does the question enter the clarification round

Native will first investigate the facts and then organize the issues based on the dependencies among the decisions. Each question explains the recommended plan and the actual impact of each option. `native.clarification_mode` decides whether to raise one question in each round or to raise all the questions that have been prepared for this round in a concentrated manner.

The complete rules for Sequential, Batch, issue number, and cross-session recovery can be found in [Sequential and Batch Clarification ](/en/native/clarification-modes)

## After confirmation, enter Build

After all user selection processing is completed, Native will summarize the goals, scope, key decisions, acceptance items, and non-goals, and ask you to confirm a complete understanding. The Runtime only allows change to enter the Build from Shape after receiving a clear confirmation. Sequential and Batch use the same confirmation access control.

For large-scale requirements, it will also be checked whether it is suitable to be split into Supervisor Changes. When multiple results can be independently implemented and verified, and there are clear dependencies or parallel values, Native will provide splitting suggestions for you to confirm the sub-tasks and advancement methods.

<Warning>
"Maintaining existing behavior" applies to results that already exist. The new behavior still requires clear semantics. Adjacent functions, dependency default values, and the principle of minimum modification can help the Agent form a recommended solution, and the final result is determined by your choice.
</Warning>

## The requirements change after the Build

- ** Implementation omission, requirements remain unchanged ** : Return to Build to fix.
- ** Changes in user-visible behavior or acceptance criteria ** : Return the Shape, update the formal requirements and reconfirm.
- ** The new requirement is irrelevant to the current demand ** : Create another change for it to keep the current range stable.
