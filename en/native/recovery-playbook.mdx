title: 'Recovery and troubleshooting'
description: 'Recover Native from portable state and handle cross-device moves, interrupted execution, branch mismatches, transactions, and archive conflicts.'
---

When a session is interrupted or an action fails, read the Runtime state first and follow its action. Native recovery uses `.comet/config.yaml`, the brief, Specs, `comet-state.yaml`, and the necessary local Runtime; it does not use chat memory or a Builder's self-report.

## Standard diagnostics

```bash
comet status
comet native status <change-name> --details --json
comet native doctor <change-name>
```

Check them in this order:

1. artifact root, enabled workflow, and clarification mode;
2. whether `status` can find the target change;
3. whether the current branch/worktree matches the change;
4. `status --details` for `status`, `phase`, Loop, acceptance, blockers, and continuation;
5. doctor output for migration residue, unfinished transactions, locks, or active/archive conflicts.

Do not edit YAML, selection, or `.comet/runtime/native/` by hand. If output is paged, follow its cursor or continuation instead of treating unseen acceptance items as absent.

## A change is not found on another device

Sync the project code, `.comet/config.yaml`, brief, Specs, and `comet-state.yaml`. Sync `verification.md` when present; a missing report can be rebuilt. On the target device run:

```bash
comet status
comet native status <change-name> --details --json
```

If the artifact root or branch/worktree does not match, fix the project context or choose the target explicitly. Do not create a second change or copy the same documents into two roots.

## Interrupted execution and missing local Runtime

`.comet/runtime/native/changes/<name>/state.json`, logs, and locks are local overlays. After a process termination, device move, or missing overlay:

1. run `comet native status <name> --details --json`;
2. let Runtime mark running work interrupted from YAML and rebuild a matching overlay;
3. if the change is in Shape or Build, continue that stage;
4. if it is in Verify, rerun the necessary interrupted checks according to continuation, then dispatch a new Verifier;
5. if it is `archive-ready`, reconfirm Verify before Archive; the normal Archive path does not rerun completed checks again.

## Migration and doctor

An older active change may contain change-local Runtime files, legacy state, or an old report. After `comet update`, run when needed:

```bash
comet native doctor <change-name> --repair
```

Migration carries forward only facts that can be established from the old brief, Specs, and state. An old passing conclusion never becomes a new v4 pass automatically. Unclear progress conservatively returns to Build or waits for the user. A new change should not use legacy-only repair strategies.

## Interrupted Archive and parallel conflicts

Archive can write Specs, update final YAML, generate the report, move the directory, and clean local Runtime in several steps. Re-running the same Archive command resumes its transaction; do not delete the transaction or edit the state to `done`. If active and archive directories both exist, or the transaction is missing after a partial move, doctor stops for explicit handling.

When two changes target the same capability, Archive returns a serial-order blocker. Choose which change goes first, then follow the new continuation; Runtime does not overwrite the other change's Spec automatically.

## Common states and responses

| Symptom                                 | Correct response                                                                                            |
| --------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| `await-user`                            | Read the blocker and `resolution_action`, show the choices, then continue after confirmation                |
| `blocked`                               | Resolve the damage, execution error, conflict, or stagnation; do not edit counters or fabricate a result    |
| branch/worktree mismatch                | Return to the correct checkout or have the user choose a new workspace; do not write in the wrong directory |
| Verify failure                          | Repair the failed acceptance/check, submit a new Builder handoff, and let a new Verifier review it          |
| Missing/stale report                    | Ask Runtime to rebuild it from YAML; do not copy a “pass” report by hand                                    |
| Legacy Runtime/receipt/evidence residue | Run update/doctor migration or inspect read-only; do not add it to a new change                             |
