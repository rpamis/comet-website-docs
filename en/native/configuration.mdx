Comet stores project-level configuration in `.comet/config.yaml` at the repository root. Running `comet init` generates sensible defaults that most projects do not need to change. Edit specific fields only when you want to customize the default workflow, document language, clarification cadence, document write policy, concurrency limit, memory or knowledge sources, or custom PR creation commands.

## Recommended Native configuration

A common configuration for a Native project looks like this:

```yaml
# Configuration format version, maintained automatically by Comet
schema: comet.project.v1
# /comet enters the Native workflow by default
default_workflow: native
# Workflows enabled in this project (native, classic, or both)
workflows:
  - native
# Enable read-only resume probing when continuing an old task in natural language
ambient_resume: true
# Support generating standalone HTML change walkthroughs (under Native, generated only on request)
change_walkthrough: true

# Personal memory (shared by Native and Classic)
memory:
  learning: true
  retrieval: true

# Project knowledge source
knowledge:
  provider: local

# Native core settings
native:
  # Root directory for changes, Specs, and verification reports: <artifact_root>/comet/
  artifact_root: docs
  # Document language for new changes (en | zh-CN)
  language: en
  # Clarification mode: batch (group per round) | sequential (one question per round)
  clarification_mode: batch
  # Archive confirmation: automatic (archive when safety checks pass) | required (confirm before archiving)
  archive_confirmation: automatic
  # Maximum real Verify failures allowed for one confirmed target
  max_verify_failures: 5
  # Concurrency limit for multi-session Supervisor child tasks
  max_parallel_children: 2
  # Ordinary document write policy outside Build: allow (keep and let Agent assess impact) | revert (strict block)
  document_writes: allow
```

<Tip>
  Use `comet init --workflow native` to generate your initial configuration and `comet update` to keep versions in sync. You can also adjust common options visually under **Settings → Comet configuration** in `comet dashboard`.
</Tip>

## Default workflow and natural-language resume

| Field | Default | Behavior |
| --- | --- | --- |
| `schema` | `comet.project.v1` | Configuration schema version. Do not edit manually. |
| `default_workflow` | Chosen during init | Determines whether `/comet` enters `native` or `classic` by default. |
| `workflows` | Chosen during init | Declares which workflows are enabled (`native`, `classic`, or both). |
| `ambient_resume` | `true` | When enabled, saying "continue the previous task" in chat triggers a read-only resume probe; set to `false` to disable. |

Changing `default_workflow` only affects routing for new entry points. It does not convert existing Native changes to Classic or migrate Classic changes to Native. To enable both workflows in the same project, run `comet init --workflow both`.

## Native core fields

| Setting | Allowed values / default | Effect |
| --- | --- | --- |
| `native.artifact_root` | Project-relative path; default `docs` | Sets the root directory for changes, Specs, and reports (`<artifact_root>/comet/`). |
| `native.language` | `en` \| `zh-CN`; default `en` | Sets the document language for new changes; existing changes keep the language recorded at creation. |
| `native.clarification_mode` | `batch` \| `sequential`; default `batch` | Controls whether Shape asks questions in batches or one at a time. See [Sequential and batch clarification](/en/native/clarification-modes). |
| `native.archive_confirmation` | `automatic` \| `required`; default `automatic` | Controls whether Native archives automatically after all Verify criteria pass. |
| `native.max_verify_failures` | Positive integer; default `5` | Maximum real Verify failures allowed for the same confirmed target before pausing for your decision. |
| `native.max_parallel_children` | Positive integer; default `2` | Child concurrency limit for multi-session Supervisor mode; single-session mode is always `1`. |
| `native.document_writes` | `allow` \| `revert`; default `allow` | Controls how ordinary document file writes are handled during Shape, Verify, and Archive. |

### Supervisor child concurrency

Adjust this under **Dashboard → Settings → Comet configuration → Native workflow**, or edit `native.max_parallel_children` directly:

- Slots count active children that have been dispatched and have not finished integration (including Build, Verify, and waiting for integration); the Runtime releases each slot automatically after integration finishes.
- Changes take effect on the next dispatch. If you lower the limit below the current active count, the system waits for in-flight children to finish integration before dispatching under the new limit without interrupting running tasks.
- The parent project always supplies this setting; configuration inside a child worktree does not override parent scheduling. See [Supervisor Change](/en/native/supervisor-change).
- Legacy compatibility mode (Compat) still supports a per-run `--max-parallel` override; Native SDK workflows always use `native.max_parallel_children`.

### Artifact root directory

`artifact_root: docs` maps to `<project>/docs/comet/`, and `artifact_root: .` maps to `<project>/comet/`. The path must remain inside the project root.

To migrate the artifact root in an existing project, do not edit the YAML or move folders by hand. Let the Agent handle it, or run the migration commands in your terminal (`show` displays the current root, `move` migrates to the target directory; if a migration is interrupted, recover with `comet native doctor --repair --strategy <continue|rollback>`):

```bash
comet native root show
comet native root move docs
```

### Archive confirmation (`native.archive_confirmation`)

- **`automatic`**: When Verify passes completely and all of the following hold—accepting verification is the only pending wait, no evidence waits are pending, and no `running` or `unknown` actions exist—the Runtime automatically accepts and proceeds to Archive.
- **`required`**: Pauses after all Verify criteria pass and waits for your explicit confirmation in conversation before archiving.

Note: `automatic` only determines whether to skip the extra confirmation before local archiving. It **never** executes Git merge, push, or PR creation without your consent.

### Verify failure limit (`native.max_verify_failures`)

Limits the maximum number of real Verify failures allowed for the same confirmed target (default `5`). When the limit is reached, the Native Loop pauses and lists prior failure records so you can decide whether to try a different approach, adjust requirements, or cancel the task instead of spending tokens in the wrong direction. Platform errors or missing external prerequisites pause and report directly—do not raise this limit to mask environment issues.

### Document write policy outside Build (`native.document_writes`)

- **`allow` (default)**: During Shape, Verify, and Archive, writes to ordinary Markdown, text, and LICENSE files under the repository root and `docs/`, `doc/`, `documentation/`, `.github/` (outside the Native artifact root) as well as `walkthrough.html` are treated as neutral edits. The original Run is preserved and the Agent inspects the diff to assess impact.
- **`revert`**: Switches back to strict interception so ordinary document writes outside Build are also rejected by the Hook Guard.

## Change walkthroughs

`change_walkthrough` is shared by Native and Classic and defaults to `true`. Under Native, `walkthrough.html` is generated **only when you explicitly request a visual change explanation** (comparing before/after behavior, expanding key code, and including optional diagrams; Verify syncs actual test results and Archive keeps the archived link). Routine tasks still finish with a concise text summary. To disable walkthroughs completely and save explanation tokens, set `change_walkthrough: false` at the top level of `.comet/config.yaml` (or turn it off in Dashboard settings).

## Personal memory (`memory`)

`memory` is shared by Native and Classic, with both switches enabled by default:

| Field | Description |
| --- | --- |
| `memory.learning` | Allows automatically recording reusable personal development preferences and collaboration lessons when tasks finish. |
| `memory.retrieval` | Allows automatically retrieving and injecting relevant personal memory during related tasks. |

To read existing memories without automatically adding new ones, set `learning: false` and `retrieval: true`.

## Project knowledge (`knowledge`)

`knowledge.provider` defaults to `local`. In addition to the built-in code and documentation corpus, you can append project-internal Markdown globs via `include` (forward slashes, staying within the project root) and adjust per-file and total corpus size limits:

```yaml
knowledge:
  provider: local
  local:
    include:
      - docs/architecture/**/*.md
      - packages/*/README.md
    max_file_mb: 1
    max_total_mb: 32
```

If your team already operates a remote RAG knowledge service, switch to `remote` (must use HTTPS, with HTTP allowed only for `localhost` and loopback addresses; specify an environment variable name in `token_env` rather than putting a token in plaintext; `timeout_ms` range is `100`–`30000` milliseconds):

```yaml
knowledge:
  provider: remote
  remote:
    endpoint: https://knowledge.example.com
    token_env: COMET_KNOWLEDGE_TOKEN
    scope: engineering
    timeout_ms: 5000
```

## Hook write allowlist (`hook.allow_paths`)

Shared by Native and Classic, defaulting to an empty array. If your project has custom hooks or scripts that must write to a dedicated directory during protected phases, allowlist those directories here (project-relative directories using forward slashes `/`):

```yaml
hook:
  allow_paths:
    - .my-hook-output
    - docs/team-notes
```

<Warning>
  Do not add business source-code directories to `allow_paths`, or you will bypass Shape, Verify, and Archive write protections. `.comet/`, the Native artifact directory, and the Classic artifact directory are always protected by workflow rules and cannot be exempted via `allow_paths`.
</Warning>

## Custom pull request creation command (`native.finish.pull_request`)

By default, choosing "push and create PR" calls `gh pr create --fill`. If your team repository enforces custom PR templates, titles, or required fields, plug in a repository script via `native.finish.pull_request` while Comet continues handling commits, pushes, existing-PR checks, branch verification, and recovery:

```yaml
native:
  finish:
    pull_request:
      provider: repository-command
      command: [pwsh, -NoProfile, -File, scripts/comet-create-pr.ps1]
      timeout_ms: 120000
```

Configuration constraints:

- `provider` currently supports only `repository-command`.
- `command` must be a non-empty argument array; the first element must be an executable on `PATH` or a project-relative path (absolute paths are not allowed).
- `timeout_ms` defaults to `120000` milliseconds (2 minutes) with a maximum of `600000` milliseconds (10 minutes).
- The script starts in the project root, receives `comet.native.pull-request-finish-input.v1` JSON on stdin, and returns `comet.native.pull-request-finish-result.v1` JSON on stdout.
- GitHub CLI (`gh`) must still be installed and authenticated locally so Comet can independently verify remote branch and PR status.
