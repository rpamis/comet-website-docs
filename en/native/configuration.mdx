Native and Classic share the project-level `.comet/config.yaml`. After Native is enabled, this file no longer contains only four Classic defaults. It also owns `/comet` entry routing, enabled workflows, and automatic recovery, while Native-specific settings live under the `native` namespace.

## Complete example

A project with both Native and Classic enabled can use:

```yaml
schema: comet.project.v1
default_workflow: native
workflows:
  - native
  - classic
ambient_resume: true

native:
  artifact_root: docs
  language: en
  clarification_mode: sequential
  # Auditable project scope and bounded work budget for Native content snapshots.
  snapshot:
    # Included project-relative paths; supports *, **, and ?.
    include:
      - '**/*'
    # Explicitly exclude data or generated output outside the implementation scope.
    exclude: []
    # Maximum files captured by one snapshot.
    max_files: 10000
    # Maximum total content bytes hashed by one snapshot.
    max_total_bytes: 268435456
    # Maximum snapshot duration in milliseconds.
    max_duration_ms: 60000

classic:
  language: en
  context_compression: off
  review_mode: standard
  auto_transition: true
```

Shared fields control entry and recovery. `native.*` affects only Native, and `classic.*` affects only new Classic changes. Sharing one configuration file does not merge their state machines, change directories, or Guards.

## Shared entry fields

| Field              | Values / default             | Purpose                                                                                                             |
| ------------------ | ---------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| `schema`           | `comet.project.v1`           | Current structured project configuration version; managed by Comet                                                  |
| `default_workflow` | `native` \| `classic`        | Permanent Skill entered when the user invokes `/comet`                                                              |
| `workflows`        | `native`, `classic`, or both | Workflows enabled and installed for this project; must include the default                                          |
| `ambient_resume`   | `true` (default) \| `false`  | Whether the agent automatically runs the read-only resume probe for ordinary natural-language continuation requests |

`default_workflow` controls entry only; it does not migrate existing changes. `workflows` is not an installer. Do not enable a workflow only by editing YAML. Use `comet init . --workflow native|classic|both` so its Skills, Rule, and Hook Router are installed.

## Native fields

| Field                             | Values / default                              | Purpose                                                                                  |
| --------------------------------- | --------------------------------------------- | ---------------------------------------------------------------------------------------- |
| `native.artifact_root`            | Project-relative path; default `docs`         | Locates specs, changes, archive, and runtime under `<artifact-root>/comet/`              |
| `native.language`                 | `en` \| `zh-CN`; default `en`                 | Language for briefs, specs, and reports of newly created Native changes                  |
| `native.clarification_mode`       | `sequential` \| `batch`; default `sequential` | Ask one upstream question per round, or ask every currently answerable question together |
| `native.snapshot.include`         | Project-relative globs; default `["**/*"]`    | Paths included in the baseline and later current snapshots                               |
| `native.snapshot.exclude`         | Project-relative globs; default `[]`          | Versioned data or generated output explicitly outside the implementation scope           |
| `native.snapshot.max_files`       | Positive integer; default `10000`             | Maximum files captured by one snapshot                                                   |
| `native.snapshot.max_total_bytes` | Positive integer; default `268435456`         | Maximum total file-content bytes hashed by one snapshot                                  |
| `native.snapshot.max_duration_ms` | Positive integer; default `60000`             | Maximum time allowed for one snapshot capture                                            |

`artifact_root: .` maps to `<project>/comet/`; `artifact_root: docs` maps to `<project>/docs/comet/`. For an existing Native project, do not edit the field and move files manually. Use the transactional command:

```bash
comet native root show
comet native root move docs
```

Change the default language for future changes with:

```bash
comet native init --language en
```

Existing changes keep the language written when they were created.

`clarification_mode` changes only how product questions are organized. It does not add a phase or change the shared write safeguards or caller stop points. Sequential asks one most-upstream decision per round, while Batch asks every currently answerable decision in the round. Both modes require final shared-understanding confirmation before Build. Switching modes does not clear `[blocking]` questions already saved in the brief. Resolve the current question first, then let Native compute the next round under the new mode.

### Content snapshot scope and budgets

Native establishes baselines with streaming SHA-256 over actual file content. It does not use Git object hashes or Git LFS pointers as ordinary file identities. A Git project may use Git to enumerate tracked and non-ignored untracked files, but Git is only the selection provider. A non-Git project uses the physical-tree provider with the same content semantics.

Native normalizes `include` and `exclude`, then persists the policy and its hash in the new change's `baseline-manifest.json`. Build, Verify, and check keep using that baseline scope, so changing project configuration mid-change cannot hide implementation changes. Resource budgets are not file-content identity: you can raise `max_files`, `max_total_bytes`, or `max_duration_ms` as the repository grows without switching to Git hashes.

#### Pattern matching rules

Every pattern is relative to the project root and uses `/`:

- `*` matches characters within one directory level;
- `**` may cross directory levels;
- `?` matches one character other than `/`;
- absolute paths, backslashes, empty patterns, and `..` are rejected;
- `!pattern` is not supported; put exclusions under `exclude`.

A path enters the snapshot only when it matches at least one `include` and no `exclude`, so exclude wins. Patterns are deduplicated, sorted, and normalized before Runtime stores the baseline policy.

`.gitignore` and `exclude` operate at different layers. The Git provider uses `.gitignore` to decide which untracked files enter its candidate set. Native policy records the scope a change explicitly promises to observe. A non-Git provider has no Git-ignore semantics, so explicit excludes for large generated output and data preserve the same intent across providers.

#### Choosing scope and budgets

Define the deliverable boundary before optimizing capture:

- If a file belongs to implementation or verification scope, raise the total-byte and duration budgets so Runtime can hash it completely.
- If large data or generated output is outside implementation scope, exclude it explicitly and retain that policy in the baseline audit record.
- If you are unsure whether a file is relevant, keep it included and inspect the actual limit and affected path reported by Runtime.

Typical projects should start with the complete default scope:

```yaml
native:
  snapshot:
    include:
      - '**/*'
    exclude: []
    max_files: 10000
    max_total_bytes: 268435456
    max_duration_ms: 60000
```

A monorepo should include the target application, shared dependencies, relevant tests, and root build-identity files:

```yaml
native:
  snapshot:
    include:
      - 'apps/web/**'
      - 'packages/ui/**'
      - 'packages/config/**'
      - 'package.json'
      - 'pnpm-lock.yaml'
      - 'pnpm-workspace.yaml'
    exclude:
      - 'apps/web/dist/**'
      - 'apps/web/coverage/**'
    max_files: 20000
    max_total_bytes: 536870912
    max_duration_ms: 90000
```

A large repository can keep a broad include while explicitly excluding heavy content outside the deliverable:

```yaml
native:
  snapshot:
    include:
      - '**/*'
    exclude:
      - 'data/generated/**'
      - 'artifacts/benchmarks/**'
      - 'dist/**'
      - 'coverage/**'
      - '.cache/**'
    max_files: 50000
    max_total_bytes: 1073741824
    max_duration_ms: 120000
```

Do not include only the source directory you expect to edit. Shared packages, root configuration, lockfiles, and migration scripts also belong in scope when build, test, or runtime behavior depends on them. Do not exclude source, tests, or delivery configuration merely to make capture pass; that disconnects the implementation scope from real risk.

When capture exceeds a budget, `comet native new` still fails closed and removes the incomplete change. Its diagnostic reports the effective limits, policy hash, affected paths, configuration location, and supported fixes instead of returning only a generic action.

See [Native FAQ](/en/native/faq#content-snapshots-and-implementation-scope) for copy-ready scenarios and troubleshooting answers.

<Warning>
  <code>native.pending_root_move</code> is a machine-managed recovery field for an interrupted root
  move, not a user setting. Run <code>comet native doctor</code> instead of editing or deleting it.
</Warning>

## Classic fields

Classic Runtime reads these defaults from the `classic:` block in `.comet/config.yaml` and snapshots them into a new change's `.comet.yaml`:

| Field                 | Values                            | Default    |
| --------------------- | --------------------------------- | ---------- |
| `language`            | `en` \| `zh-CN`                   | `en`       |
| `context_compression` | `off` \| `beta`                   | `off`      |
| `review_mode`         | `off` \| `standard` \| `thorough` | `standard` |
| `auto_transition`     | `true` \| `false`                 | `true`     |

These fields do not change Native methodology. Native has no context compression, review mode, or cross-Skill phase-transition setting.

## Common configurations

### Native only

```yaml
schema: comet.project.v1
default_workflow: native
workflows:
  - native
ambient_resume: true
native:
  artifact_root: docs
  language: en
  clarification_mode: sequential
  snapshot:
    include: ['**/*']
    exclude: []
    max_files: 10000
    max_total_bytes: 268435456
    max_duration_ms: 60000
```

### Both workflows, with Classic as the default

```yaml
schema: comet.project.v1
default_workflow: classic
workflows:
  - native
  - classic
ambient_resume: true
native:
  artifact_root: docs
  language: en
  clarification_mode: batch
  snapshot:
    include: ['**/*']
    exclude: []
    max_files: 10000
    max_total_bytes: 268435456
    max_duration_ms: 60000
classic:
  language: en
  context_compression: off
  review_mode: standard
  auto_transition: true
```

### Disable automatic recovery for ordinary requests

```yaml
ambient_resume: false
```

This disables ambient probing for natural-language continuation requests only. Explicit `/comet` still follows `default_workflow`.

## Migrating legacy Classic configuration

For entry routing, an older file containing only top-level `language`, `context_compression`, `review_mode`, and `auto_transition` still uses `legacy-fallback` and enters Classic. It does not guess Native. Classic Runtime no longer reads those top-level defaults directly.

When you run `comet init` or `comet update`, Comet migrates the old top-level values into `classic:`, preserves values already set explicitly in the new block, and removes the legacy fields. Use `comet init . --workflow native` or `--workflow both` when enabling Native instead of assembling the two configurations manually.
