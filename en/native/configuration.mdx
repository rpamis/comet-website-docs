title: 'Native configuration'
description: 'Configure the /comet default route, enabled workflows, recovery probing, and Native artifact root, language, clarification mode, and archive confirmation.'
---

Native and Classic share one project-level `.comet/config.yaml`. It selects the workflow for `/comet`, records enabled workflows, and holds each workflow's defaults. New Native changes do not need a project-wide scan scope.

## Complete example

```yaml
schema: comet.project.v1
default_workflow: native
workflows:
  - native
  - classic
ambient_resume: true

native:
  artifact_root: docs
  language: en
  clarification_mode: batch
  archive_confirmation: automatic
  max_verify_failures: 5

classic:
  language: en
  context_compression: off
  review_mode: standard
  auto_transition: true

# hook:
#   allow_paths:
#     - src
```

Shared fields govern entry and recovery. `native.*` affects only Native and `classic.*` affects only new Classic changes. The two workflows keep separate directories and state.

## Shared entry fields

| Field              | Values / default             | Purpose                                |
| ------------------ | ---------------------------- | -------------------------------------- | ------------------------------------------------------------------------------- |
| `schema`           | `comet.project.v1`           | Configuration version managed by Comet |
| `default_workflow` | `native`                     | `classic`                              | Default `/comet` entry                                                          |
| `workflows`        | `native`, `classic`, or both | Workflows enabled for this project     |
| `ambient_resume`   | `true` (default)             | `false`                                | Whether natural-language continuation requests run the read-only recovery probe |

`default_workflow` controls entry only; it does not migrate existing changes. Adding `native` to YAML does not install the Skill. Install or refresh it with:

```bash
comet init --workflow native|classic|both
comet update
```

## Hook write allowlist

`hook.allow_paths` lists the project-relative directories the Agent may write during guarded phases. It is a write policy shared by Native and Classic, and it is empty by default.

When unset, writes inside the project (outside artifact areas) follow each workflow's phase rules: Native allows implementation writes only during Build, and Classic applies its own phase and guard rules. Adding a directory to `hook.allow_paths` lets writes to that directory and its subdirectories pass through directly, bypassing the phase check — a typical use is allowing implementation code directories (such as `src/`, `apps/web/`) to be modified in any phase, avoiding rollbacks or blocks outside Build.

```yaml
hook:
  allow_paths:
    - src
    - apps/web
```

Notes:

- Paths must be project-relative, `/`-separated, one directory per item; matching is by prefix, so `src` covers every file under `src/`.
- The following areas are always protected and cannot be allowed through this setting: `.comet` (Runtime state), the Native artifact root (for example `docs`), and the Classic openspec and superpowers roots. They always follow their own write rules.
- Out-of-bounds or malformed paths are reported by `comet doctor`.

## Native fields

| Field                         | Values / default                      | Purpose                                                       |
| ----------------------------- | ------------------------------------- | ------------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| `native.artifact_root`        | Project-relative path; default `docs` | User documents under `<artifact-root>/comet/`                 |
| `native.language`             | `en`                                  | `zh-CN`; default `en`                                         | Language for new change briefs, Specs, and reports                                    |
| `native.clarification_mode`   | `batch`                               | `sequential`; new projects default to `batch`                 | Ask all currently answerable questions in a round, or one upstream question per round |
| `native.archive_confirmation` | `automatic`                           | `required`; default `automatic`                               | Whether to wait for one explicit confirmation after Verify                            |
| `native.max_verify_failures`  | Positive integer; default `5`         | Maximum implementation-failure iterations for one requirement |

### Change the artifact root

`artifact_root: .` maps to `<project>/comet/`, and `docs` maps to `<project>/docs/comet/`. For an existing project, do not edit YAML and move directories by hand:

```bash
comet native root show
comet native root move docs
```

### Change language and clarification mode

Language affects only changes created afterward; existing changes keep the language recorded at creation. Batch is the default for new projects, but you can choose explicitly:

```yaml
native:
  language: en
  clarification_mode: sequential
```

Both modes investigate discoverable facts and require confirmation of the complete shared understanding before Build. Switching modes does not remove `[blocking]` questions already in the brief.

### Archive confirmation and failure cap

`automatic` continues to Archive after Verify passes; `required` waits for one explicit confirmation. `max_verify_failures` limits implementation-failure iterations. Runtime execution errors and semantic blockers return `await-user` or `blocked` instead of being bypassed by editing counters.

## Upgrading an older project

Older versions may leave `native.snapshot`, change-local Runtime files, old receipts, or evidence documents. They are not configuration fields or acceptance inputs for a beta17 change. `comet update` and `comet doctor` handle the migration; do not add these fields to make a new Verify pass and do not copy old Runtime files by hand.

## Common configurations

### Native only

```yaml
schema: comet.project.v1
default_workflow: native
workflows:
  - native
ambient_resume: true
native:
  artifact_root: docs
  language: en
  clarification_mode: batch
  archive_confirmation: automatic
  max_verify_failures: 5
```

### Disable the automatic recovery probe for ordinary requests

```yaml
ambient_resume: false
```

This disables the read-only probe for natural-language continuation only; an explicit `/comet` still follows `default_workflow`.
