---

You just need to tell Comet what results you want to achieve and confirm the decisions that truly affect product behavior. Comet will save the requirements and acceptance criteria in the project, prepare the workspace, advance the implementation and independent acceptance, and then complete the archiving.

Native is suitable for Fable 5, GPT-5.6 and strong models of the same level. It does not stipulate how the model must plan or write code, but it does not take a "done" statement from the model as delivery evidence.

## Before starting

- Node.js 22 or later
- Git
- [A supported AI coding platform](/en/platforms)

## Start a Native change in three steps

<Steps>
  <Step title="Install and initialize Comet">
Run in the project root directory:

    ```bash
    npm install -g @rpamis/comet
    comet init --workflow native
    ```

Initialization installs the skills and rules required by Native. Platforms that support Hook will also install a unified Router. Project configuration will be saved in
`.comet/config.yaml`, the new Native documentation is placed by default in `docs/comet/`.

  </Step>

  <Step title="Tell Comet what you want to achieve">
Open Agent and enter: In the project

    ```text
comet adds the ability to upload avatars to user profile pages
    ```

`/comet` will read the project configuration and enter Native. It is the Skill entry point in the Agent, not a terminal command.

When creating a change, you can continue to use the current directory or let Comet create a branch or worktree. When parallel processing is explicitly required,
Comet uses an independent worktree to isolate tasks.

  </Step>

  <Step title="Confirm the target and then let Comet move forward">
Native will first investigate the facts that can already be determined in the repository, and only ask for decisions that would still change the scope, default behavior, compatibility, or risks. You confirm the goal
After non-target and non-acceptance criteria are set, Comet will continue to implement, inspect, independently accept and archive, without the need for you to manually switch phases.
  </Step>
</Steps>

## What Comet manages

- ** Prepare and bind the workspace ** : Create or reuse branches and worktrees, and return to the correct directory when restoring; Stop writing when the workspaces do not match to prevent the code from falling into the wrong directory.
- ** Continuously advance the workflow ** : The model is responsible for investigation and implementation, and the Runtime determines the current stage and the next step. It is paused only when a user decision or blockage occurs.
- ** Independent judgment of completion ** : The Runtime first runs the necessary checks, and then the new read-only Verifier checks the results against the acceptance criteria; Once a gap is found, return to Build with a clear problem to fix it.
- ** Continue from the break ** : Requirements, schedules and acceptance conclusions are saved in the project files. After changing Windows, sessions or compressing the context, there is no need to restate the background.
- ** Load relevant records ** : After enabling Personal Memory and Project Knowledge, Comet selects relevant personal preferences and project knowledge for the current task instead of loading all historical content.

The main path of Native has only four stages:

```mermaid
flowchart LR
  S["Shape\n confirm the target"] --> B["Build\n implementation and inspection"]
  B --> V["Verify\n independent acceptance"]
  V -->|"Through| A["Archive\n Archiving and delivery"]
  V -->|Discover the gap| B
```

## Resume after interruption

After reopening the project, enter: in the Agent

```text
/comet continues
```

Comet will re-read change, workspace binding, and Next, and continue from the stable breakpoint. When the code, branches or worktree do not match, it will stop to explain the problem and will not silently move to another directory to advance.

To quickly view the current stage, you can run `comet status`; To view Change, tasks, acceptance and workspace progress in a browser, you can use it
[`comet dashboard`](/en/dashboard/overview). When installation or status is abnormal, run `comet doctor` again for troubleshooting.

```bash
comet status      # View all changes and the current stage
comet dashboard   # View the detailed progress in the browser
comet doctor      # Check the installation, configuration and status
```

## What will you get after it's completed

In addition to the implementation code, the project will also leave behind a readable requirements brief, complete target Specs, workflow status, and verification reports. The next Agent can continue working from these files without relying on the original conversation or having to guess "where exactly was done last time".
