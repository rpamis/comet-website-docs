---
title: 'Task progress and interruption recovery'
description: 'Find the next step for a Native change and resume the same task after a session interruption, workspace switch, or device change.'
---

After a session interruption, have the Agent continue the same change. The Runtime keeps the current stage, user decisions, and task results in the Run. Check the workspace and pending action first, then follow the latest command response.

## Inspect progress and the next step

Return to the change's workspace and run `comet native status <change-name> --json`. If you don't know the name, use `comet native status --json` to list changes in the current workspace. If the change uses a separate Git worktree, switch to that worktree before querying. Add `--details` to a named query for the complete record of actions and decisions.

Use `status` to inspect the change. The Agent follows the next step from the response and uses the new response after each operation. If the state changed, query it again before submitting a decision. If the response supplies a state version, expected action, or proposal identifier, keep those arguments in the confirmation command.

| `continuation.mode` | Current situation | How to proceed |
| --- | --- | --- |
| `execute` | The next action is ready. | The Agent runs the returned operation in the specified workspace. |
| `ask` | The workflow is waiting for your input. | Review the current proposal and confirm it, request a revision, or provide missing information. |
| `wait` | The original task was claimed and has yet to return a result. | Check or wait for the original task, then submit its result with the original claim. |
| `reconcile` | The Runtime needs an outcome confirmed or a blocker resolved. | Inspect the original task, path, or transaction as directed, then follow the returned recovery action. |
| `done` | The workflow has ended. | Check the final state. If the change was archived, verify the agreed Git delivery. |

## Resume a task that was running

In the new session, check whether the original task was claimed and whether the original execution session is still running. After a wait tool times out, check progress on the original platform. If the task is still running, keep waiting for that execution. If it has ended, retrieve its actual result and submit it with the original claim.

If the outcome is unknown, inspect the original execution and any files or external results it produced before repeating an operation that may have already taken effect. Follow the Runtime's next step for failure or retry after confirming the task failed, was lost, timed out during execution, or ended without a usable result. See [SDK failure recovery and unknown results](/en/sdk/recovery).

## Restore a missing local Run

If the local records are missing, inspect the diagnostics with `comet native doctor <change-name> --json`. The Runtime can restore the original Run using a valid checkpoint in `comet-state.yaml` and the accompanying materials. Run the recovery command returned by Doctor. If the checkpoint is missing or materials disagree, preserve the workspace and check the available original records.

Before changing devices, stop workflow activity on the original device and synchronize the current code, `comet-state.yaml`, `brief.md`, relevant Specs, referenced artifacts, and project configuration. The checkpoint preserves recorded progress. Recover unsynced code from the original workspace. Check the original task for any unknown outcomes. An active Supervisor child also requires handling its child and integration worktrees separately. See [Native Runtime components](/en/native/runtime) and [Supervisor Change](/en/native/supervisor-change) for storage and recovery boundaries.

## Recover interrupted archiving

If Archive is still running in the background, wait for the original command to return. If the command was interrupted, inspect current status and diagnostics, then follow the Runtime's instructions to resume the original archive transaction. After archiving, independently check whether the Git commit, push, or pull request was completed. See [Archive and delivery](/en/native/archive-and-delivery).
