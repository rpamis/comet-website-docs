title: 'Native walkthrough'
description: 'Run an avatar-upload requirement through Shape, Build, Verify, and Archive, and see the fresh Verifier and Loop in action.'
---

This walkthrough takes “add avatar upload to the user profile page” through all four Native stages and shows a failed acceptance item returning to Build before a new Verifier passes it.

## Start with a requirement

```text
/comet add avatar uploads to the user profile page
```

`/comet` enters `/comet-native` from project configuration. The Skill reads existing changes and `.comet/config.yaml`; when the target is unambiguous, it creates a new change.

## Shape: make the behavior clear

The Agent investigates the current profile page, upload endpoint, image formats, and error handling, then asks only decisions that change product behavior:

- avatar size and format limits;
- whether a failed upload keeps or clears the old avatar;
- whether cropping and preview are required.

After confirmation, the change contains `brief.md`, complete target Specs, and `comet-state.yaml`. New projects default to Batch, asking every question whose prerequisites are settled in a round.

## Build: implement and hand off

The Agent chooses its implementation and test method, edits source and test files, and submits a Builder handoff. The handoff lists what was implemented and what Runtime/Verifier should inspect; it is not a final pass declaration.

## Verify: checks and a fresh Verifier

Runtime resolves A1…An from the brief and Specs and runs necessary checks, for example:

```text
pnpm test --filter profile
pnpm lint
```

The check runs once, logs locally, and keeps a summary in state. Runtime then dispatches a fresh read-only Verifier. Suppose the first Verifier finds A3: a failed upload does not preserve the old avatar.

Runtime returns the change to Build:

```text
status: build
loop.iteration: 2
next: repair A3, then submit a new Builder handoff
```

After the repair, a new Verifier reviews every A1…An. It cannot submit only A3 or reuse the first failed execution.

## Archive: only archive work remains

When all items pass, Runtime writes `verification.md`, applies the canonical Specs, and moves the change. Normal Archive does not rerun checks or require users to inspect local logs. With `archive_confirmation: required`, the Skill waits for one explicit confirmation before the move.

The archived user-readable result is the brief, Specs, `comet-state.yaml`, and `verification.md`; the change's local execution directory under `.comet/runtime/native/` is cleaned up.

## Continue after an interruption

If Verify is interrupted, enter `/comet continue` again or run:

```bash
comet native status avatar-upload --details --json
```

Runtime recovers the iteration, acceptance, and continuation from YAML. A missing local overlay is rebuilt. A code or branch/worktree mismatch waits for an explicit user action instead of silently using another directory.
