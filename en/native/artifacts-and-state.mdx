---
title: 'Native artifacts and state'
description: 'Understand Native user documents, portable recovery state, and the responsibilities of local Runtime files.'
---

Native keeps documents users need to read and sync in the change directory, while execution details live in the project Runtime. You normally only read the brief, Specs, `comet-state.yaml`, and `verification.md`; do not create or edit Runtime files by hand.

## Project layout

The default layout is:

```text
<project>/
  .comet/
    config.yaml
    current-change.json
    runtime/native/
      changes/<change-name>/state.json
      logs/
      locks/
      transactions/
  docs/comet/
    specs/
    changes/
      <change-name>/
        brief.md
        comet-state.yaml
        specs/<capability>/spec.md
        verification.md
    archive/
      YYYY-MM-DD-<change-name>/
```

`native.artifact_root` may point to another project-relative directory such as `artifacts/comet/`. `.comet/config.yaml` and `.comet/current-change.json` remain project-level boundaries. `.comet/runtime/native/` is Runtime-owned and normally ignored; it should not be copied into a change or presented as user documentation.

## The user-readable files

### `brief.md`

The brief records the goal, scope, non-goals, confirmed user decisions, open questions, acceptance examples, and verification expectations. It is the Shape working document that users can read and edit as requirements evolve.

### `specs/<capability>/spec.md`

Each Spec describes the complete behavior of a capability after Archive. Archive applies a declared `create`, `modify`, or `remove`: create a new Spec, replace its full contents, or delete it only through the controlled capability path. If parallel changes target the same capability, Runtime stops for an archive-order decision instead of overwriting automatically.

### `comet-state.yaml`

This is the stable, portable recovery state. It records the current phase and status, Loop iteration/attempt, every acceptance item and result, the Builder handoff, required-check summaries, the Verifier verdict, blockers, bounded history, and the next action. A new Agent reads it first and follows the continuation without relying on the previous chat session.

### `verification.md`

Runtime generates this user report from state. It contains the actual checks, per-item acceptance results, risks, limitations, and conclusion. It is a rebuildable presentation file, not an authoritative transition input; if it is missing or stale, Runtime can rebuild it from `comet-state.yaml`.

## Local Runtime

`.comet/runtime/native/` stores the local execution overlay, logs, short-lived locks, and recoverable transactions. It may be absent after moving to another device or cleaning local files; Runtime rebuilds it from the synced YAML and never treats a copied `state.json` as portable truth. Logs are useful for command diagnostics but do not replace `verification.md`.

`.comet/current-change.json` only selects which workflow/change owns the next write; it does not limit a project to one active change. Status is read-only. When ownership must be explicit, use `comet native select <change-name>`.

## Cross-device recovery

Sync the project code, `.comet/config.yaml`, the brief, Specs, and `comet-state.yaml`. If a report already exists, sync `verification.md` too, but a missing report must not prevent Shape or Build recovery. On the target device, verify the artifact root and the branch/worktree, then run:

```bash
comet status
comet native status <change-name> --details --json
comet native doctor <change-name>
```

An in-flight local check is treated as interrupted. A previous Verify or `archive-ready` result is reconfirmed according to Runtime recovery rules; copying an old `state.json` never makes Archive safe by itself. Unsynced code, a mismatched branch, or a mixed active/archive layout stops with an explicit user action.

## After Archive

A successfully archived change keeps only user-readable brief, Specs, `comet-state.yaml`, and `verification.md` artifacts. Its per-change local execution directory under `.comet/runtime/native/` is cleaned up. Machine files left by an older version are handled only by migration or the read-only legacy adapter and are not inputs to a new Native flow.
