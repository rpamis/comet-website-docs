<Tip>
Call <code>/comet-any</code> in the Agent to start. The flow prompts for confirmation, evaluation, release, and distribution steps.
</Tip>

`/comet-any` (also known as **Skill Creator**) is Comet's single entry point for creating, optimizing, and composing reusable Skills. This page gives you the shortest path to get started. For the internal model, continue to [Advanced topics](#advanced-topics).

<Warning>
Combining any Skill remains an experimental feature. Subsequent versions may undergo significant refactoring of processes, command interfaces, product structures, and release access control, and may also remove or replace some capabilities. It is recommended to first try it out in non-critical projects and review the changelog before upgrading Comet.
</Warning>

## Use cases

- I want to condense a recurring process in the team into a reusable Skill, eliminating the need to re-describe it each time.
- Want to add, replace or close certain links on the basis of the classic five stages of `/comet`.
- I want to organize the existing but scattered skills into standard Skill packages that are assessable, releasable and distributable.

## What do you need to prepare first

1. Comet has been installed. Run `comet doctor` to confirm that the CLI is normal. If not installed yet, see [Installation and Update ](/en/guides/install-and-update)
2. ** An Agent platform that supports Skill **, such as Claude Code, Codex, Cursor, etc. `/comet-any` is a Skill called on these platforms and is not an independent terminal command.
3. Optional project-level preferences. On first use, `/comet-any` scans available platforms and recommends defaults. You can skip this step or [prepare preferences in advance](#optional-prepare-a-preference-file).

<Note>
<code>/comet-any</code> is the only entry point that <strong> users need to remember. </strong>. When you need to check the recovery status, use <code>comet creator</code>. After entering the release, use <code>comet Publisher </code>. For daily use, there is no need to directly run <code>, COMET bundle</code>.
</Note>

## Create the main line

```text
/ Comet-any create → comet eval verify → comet creator status/next See Next → review/approve/run → distribute
```

Call `/comet-any` to start. After an interruption, run `comet creator next <name>` for the suggested action or `comet creator status <name>` for readiness, blockers, and evidence.

## Step 1: Call /comet-any and describe the target

Enter: In the Agent platform

```text
/comet-any
```

Then describe the Skill you want to create. The more specific the description, the higher the quality of the generated Skill. A good description should at least include: what to do, how many steps to take, and for whom to reuse. For example:

```text
Please create a PR review assistant.
It needs to first clarify the review scope, then formulate the inspection plan, and finally carry out the code review.
Finally, it is required to verify the evidence before completion.
The goal is to be reused by the team, not just for the current task.
```

## Step 2: Select the starting point

`/comet-any` will allow you to choose one from three starting points. This is the first layer of choice of Skill Creator, which determines the entire generation method:

|Starting point|Skill Creator Intent|Meaning|Typical scenarios|
| --- | --- | --- | --- |
|"Five-stage customization based on Comet's existing Skill.| `customize-comet` |Make incremental adjustments on the classic five stages|I want to add a review process to `/comet` and require the use of component libraries|
|** Create a brand-new workflow Skill**| `new-skill` |Create a brand-new workflow from the target description|Establish a team-specific process|
|** Organize existing skills **| `upgrade-existing` |Organize the existing skills into standard packages that can be released|Standardize the scattered skills|

Whichever starting point you choose, `/comet-any` compiles the target into the same **Workflow Contract**, composed of Workflow Nodes, Skill Bindings, Required Skill Calls, Output Schemas, Guardrails, and Handoffs. See the [Skill Creator overview](/en/skill-creator/overview#workflow-contract-a-common-model-for-all-paths).

<Warning>
  When you choose <strong>five-phase customization based on an existing Comet Skill</strong>, <code>/comet</code> is a <strong>protected boundary</strong>. You cannot replace the implementation of control nodes (<code>open</code>/<code>execute</code>/<code>verify</code>/<code>archive</code>). You can only <strong>add Required Skill Calls, augment nodes, or disable optional nodes</strong>.
</Warning>

## Step 3: Confirm the combination plan (Skill Creator Confirmation page)

`/comet-any` will read the real skills in the project, compile the target into a **Workflow Contract**, generate a ** combination scheme **, and then ** pause for your confirmation **. This page is called the "Skill Creator Solution Confirmation Page "and it is a key checkpoint in the entire process. It will display:

- What type of Skill (Skill Creator Intent) are you working on and what are your goals
- Which nodes should be retained, which Required Skill calls should be added, which node implementations should be replaced, and which optional nodes should be closed
- What cannot be done (for example, replacing the control node will be rejected)
- The responsibilities of each node, the implementation Skill, the skills that must be called, and the Output Schema
- Workflow Contract type (`comet-five-phase-overlay`/`workflow-kernel`) and Output Schemas list
- Are there any missing or ambiguous candidates that you need to handle
- What executable disclosures will scripts/hooks bring
- Which files will be generated

You need to make one of the three choices:

1. ** Confirm Generation ** - Write the plan into draft and continue generating.
2. ** Modify the plan ** - Regenerate the plan after adjusting the goals, preferences or candidates.
3. "Cancel" - Do not write any status.

<Tip>
If <code>/comet-any</code> prompts that there are candidate <strong> missing </strong> or there are multiple sources of <strong> from </strong>, it will definitely pause and ask you - it will never choose for you or silently ignore it. Just select the source as prompted. This is a hard and fast rule, not an optional behavior.
</Tip>

## Step 4: Evaluation

After confirmation, `/comet-any` generates the Skill package. Then evaluate whether it meets the standards. This is the "mandatory evidence" before release, not an optional step:

```bash
# Low-cost discovery pre-checking (without consuming model calls)
comet eval ./generated-skill/comet/eval.yaml --collect

# 2. Conduct real evaluations and generate browsable HTML reports
comet eval ./generated-skill/comet/eval.yaml --html
```

Open the `Report path` printed from the CLI and confirm that the assessment has passed. For detailed environmental preparation and report interpretation, please refer to [Evaluate Any Skill](/en/eval/quickstart)

<Info>
<strong>Prerequisite</strong>: To run <code>comet eval</code>, install <code>uv</code>, Python 3.11+, and Docker, then set <code>ANTHROPIC_API_KEY</code> (or <code>ANTHROPIC_AUTH_TOKEN</code>). See <a href="/en/eval/quickstart#what-you-need-before-running">Evaluation quickstart · What you need before running</a>.
</Info>

## Step 5: Release and distribution

After the assessment is passed, check the release readiness and release:

```bash
# View the complete readiness and blocking items
comet creator status my-skill --project . --json

# Just want to know what to run next
comet creator next my-skill --project . --json

# Generate review summaries (see Readiness/Blockers/Evidence)
comet publish review my-skill --platform claude --json

# Manually approve the current version
comet publish approve my-skill --reviewer alice --json

# "Publish
comet publish run my-skill --platform claude --json
```

Before distribution to the platform, it will first force a preview run. Only after confirmation will it be truly written.

```bash
# Forced preview (no files will be written)
comet publish distribute my-skill --platform claude --scope project --preview --json

# After confirming that the preview is correct, distribute it in reality
comet publish distribute my-skill --platform claude --scope project --json
```

The complete publish status chain and access control can be found at [Publish and Distribute Skill](/en/skill-creator/publishing)

<Tip>
  <code>/comet-any</code> also advances these steps and asks for your confirmation at each one. The commands above are an{' '}
  <strong>optional manual path</strong> for troubleshooting or automation.
</Tip>

## Optional: Prepare preference files

The first time you use it, `/comet-any` will scan the platform skills and recommend default preferences. You can also directly create a preference file and tell it which skills to prioritize for reuse. Save to `.comet/skill-preferences.yaml`:

```yaml
# .comet/skill-preferences.yaml
version: 1
mode: advisory

prefer:
  - brainstorming
  - writing-plans
  - requesting-code-review
  - verification-before-completion

require:
  - verification-before-completion

policies:
  missing: ask
  ambiguous: ask
  deviation: explain
  scripts: disclose
  hooks: disclose
```

For the complete field meanings, please refer to [Skill Preferences and real source ](/en/skill-creator/preferences)

## Q&A

<AccordionGroup>
  <Accordion title="What's the difference between /comet-any and /comet">
<code>/comet</code> is used to complete a project change. <code>/comet-any</code> is used to create, optimize or organize reusable skills.

If you want to create features, fix bugs or modify project code, use <code>/comet</code>. If you want to condense a set of processes into reusable skills or add team rules on the basis of the five stages of <code>/comet</code>, use <code>/comet-any</code>.
  </Accordion>

  <Accordion title="Do I need to understand words like Workflow Node and Output Schema">
It is not necessary for ordinary use. You only need to look at what is done at each step on the solution confirmation page, which skills will be called, and which capabilities will be added or disabled.

When doing deep customization or reviewing the product, then refer to [Overview of Skill Creator ](/en/skill-creator/overview)
  </Accordion>

  <Accordion title="What should I do if I stop halfway through">
Tell the Agent, "Continue the previous Skill creation." <code>/comet-any</code> first attempts to <strong>restore the current authoring state</strong>, showing its name, status, next step, and blocker so you can choose what to continue. See [The complete Skill creation workflow · Resume the interrupted process](/en/skill-creator/workflow#resume-the-interrupted-process).
  </Accordion>

  <Accordion title="Will the products be distributed automatically">
No. After <code>/ Comet-any </code> is released, it will ask you if you want to distribute it, and <strong> will first show a preview of </strong>. It will only be truly written into the platform after your confirmation. Preview is a mandatory step and cannot be skipped.
  </Accordion>

  <Accordion title="I don't want to run the eval and publish commands myself">
You can call only <code>/comet-any</code> throughout the process. It will proactively advance the evaluation and release and ask for your confirmation at each step. The commands listed on this page are to help you understand the process, facilitate troubleshooting or perform automation integration.
  </Accordion>
</AccordionGroup>
