title: 'Quickstart: Comet Any'
description: 'Compose a goal and actual local Skills into an SDK Skill application with stage artifacts, validation, and recovery.'
---

Invoke `/comet-any` in your Agent and describe the workflow you want to reuse. The Agent investigates actual Skills and writes the entry, business rules, and validators. SDK assembles the confirmed plan into an application you can run and install.

## Prepare the goal and Skills

Install Comet and run `comet doctor` to check the environment. Current Creator host options are Codex and Claude Code. Analysis requires actual Skill loading and handoff capabilities.

Describe inputs, steps, artifacts, validation, and user decisions. For example:

```text
/comet-any
Compose local research and report Skills into a project weekly-report workflow.
First collect accepted tasks, then generate a draft and check that every conclusion has a source.
The report must contain “Completed this week” and “Risks and next steps” sections.
Missing reports or incomplete sources must prevent publication.
Write the final publication file only after the user confirms the actual report.
```

Without explicit Skill paths, the Agent investigates candidates and handles missing or ambiguous matches. Names do not establish capabilities; actual content, scripts, and resources must be read.

## Confirm the composition type

| Type                       | Suitable goals                                                                                  |
| -------------------------- | ----------------------------------------------------------------------------------------------- |
| Native extension           | Retain Native's Builder, independent Verifier, and Archive; add business work at allowed points |
| Classic composition        | Retain full, hotfix, or tweak; add or replace Skills that meet stage requirements               |
| Standalone SDK application | Declare a workflow and validation for reports, research, content production, or other tasks     |

The Agent explains its recommendation and boundaries. Actual steps, dependencies, and outputs go into the same plan.

## Read the complete plan

Before confirming, inspect the complete `SKILL.md`, business Rule, dependency Skills, execution steps, required files, business validators, failure paths, and host capabilities.

You can approve, revise, or reject. The decision binds to the current plan. Changes to content, goals, or dependencies require confirmation again.

## Validation and optional Eval

After SDK compiles the pinned package, Creator checks normal and abnormal artifacts in a temporary project. It must detect missing files, empty files, incorrect content, digest changes, and declared business failures.

After local checks pass, choose model Eval, retry, revision, or an explicit skip. Skipping Eval does not skip local checks or mark the application as validated by a model or host.

## Confirm the installation preview

The preview shows the complete package's export directory, platform Skill entries, Runtime dependencies, Rule/Hook configuration, conflicts, and capability limitations. Targets are written only after you confirm the current preview.

The complete package export and platform entry occupy separate locations. Use [comet application](/en/cli/application) to distribute the application to other projects, user directories, or platforms.

## Continue after interruption

Retain the original authoring name. Invoke `/comet-any` in the same project to continue, or inspect current state:

```bash
comet creator list --project . --json
comet creator status weekly-report --project . --json
comet creator next weekly-report --project . --json
```

`next` executes local machine steps and stops when a host Action or user decision is required. Check operations whose results are unknown before proceeding. Do not create another workflow to repeat installation or publication.

Dashboard's **Comet Any** page shows authoring, application Runs, artifacts, and evidence. It remains read-only; user decisions and progress still use the original Agent or CLI.
