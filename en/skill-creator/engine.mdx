title: 'Execution, rules, and business checks'
description: 'Understand SDK Actions and approvals, and the responsibilities of business Rules, platform Hooks, and artifact validators.'

The entry Skill tells the Agent how to perform business work. SDK Runs save actual steps, Actions, decisions, and results. Platform integration associates the current application with file tool events.

## Business content and execution protocol

The Agent writes complete `SKILL.md` content and business Rules from the goal: how to organize inputs, which files each stage must produce, and how to check conclusions and sources.

SDK appends the execution protocol and general protection rules to this content, then assembles a pinned Runtime. The protocol requires reading the current Run, claiming the current Action, reporting its original result, and waiting for user decisions. Text claiming that work is “approved” cannot replace an actual Wait decision.

## Rule / Hook responsibilities

Distribution installs shared platform Rule/Hook entries while retaining unrelated user configuration. On platforms with Hook support, attributable file writes go to the current workflow for checking. The preview describes unsupported capabilities or capabilities that need activation.

Shared protection rules check the current Action, approval, and write scope. They do not infer business conditions such as “all report sources must be present” from Skill text alone, and do not provide an operating system sandbox.

## Business validator responsibilities

Stage artifact contracts require actual files, content, structure, and digests. Business validators check additional domain conditions. The authoring Agent writes and pins them; Creator validates them with normal and abnormal samples.

```text
Execute Skill → Check actual artifacts → Check business conditions → Accept current result → Allow dependent work to continue
```

Missing files, failed business conditions, or files modified after completion prevent downstream work from proceeding on the original evidence. See [stage artifacts and business validation](/en/sdk/artifact-validation) for configuration.

## Host execution and unknown results

The host must actually load declared Skills, complete required handoffs, and call tools under current authorization. Missing capabilities cannot be silently removed or reported as executed.

If reporting is interrupted after dispatch, retain the original Action, attempt, and claim credentials, then check the actual result. Repeating work after files were written, messages sent, or publication completed can create additional side effects.

## Observation does not advance execution

Dashboard shows saved steps, decisions, execution attempts, artifacts, and evidence. It does not approve proposals or advance Runtime. Decision options in the interface explain what the current Wait supports; the original host still obtains and submits actual decisions.
