---
title: 'Skill preferences and actual sources'
description: 'Express project composition preferences and inspect actual Skills, capabilities, and dependencies before confirming a plan.'
---

`.comet/skill-preferences.yaml` expresses which Skills the project prefers and how to handle missing Skills, ambiguity, scripts, and Hooks. Without this file, you can still describe a goal directly to `/comet-any`.

## Configuration example

Replace these names with Skills your project actually uses:

```yaml
version: 1
mode: advisory
prefer:
  - team-research
  - team-report
require:
  - team-verification
policies:
  missing: ask
  ambiguous: ask
  deviation: explain
  scripts: disclose
  hooks: disclose
```

| Field      | Authoring requirement                                                               |
| ---------- | ----------------------------------------------------------------------------------- |
| `prefer`   | Actual Skills to consider first                                                     |
| `require`  | Skill requirements the plan must address                                            |
| `mode`     | `advisory` expresses suggestions; `strict` expresses stricter selection constraints |
| `policies` | How to explain missing Skills, ambiguity, deviations, and executable content        |

A preference file does not create missing Skills or grant tool, network, or file-write permissions.

## Confirm actual content

The Agent reads matching `SKILL.md` files, scripts, and resources, then explains their inputs and outputs, user interaction, business checks, and recovery. Similar names do not make Skills interchangeable.

Check every actual dependency's source, purpose, and scope in the plan. Explain same-name candidates, missing required capabilities, or substitute implementations and obtain a decision first.

## Continue with pinned content

After confirmation, the application pins the actual content used and its adaptation contracts. Subsequent dependency changes cannot silently replace the original plan. Restore original dependencies or revise and confirm the plan again.

The Agent still authors the complete entry Skill and business Rule. Preferences cannot replace their content or [stage artifact validation](/en/sdk/artifact-validation).
