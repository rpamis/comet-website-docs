---
title: 'Install and distribute SDK Skill applications'
description: 'Confirm the complete package and platform write plan before installing, upgrading, or selectively uninstalling application entries.'
---

After Comet Any passes local validation, it presents the complete package export and formal installation preview. SDK writes targets only after you confirm the current preview. Applications do not need their own installation scripts.

## What to inspect before installation

| Preview item               | What to check                                                                   |
| -------------------------- | ------------------------------------------------------------------------------- |
| Complete package           | Application identity, version, entry, modules, and pinned dependencies          |
| Export directory           | Where the application package is actually saved                                 |
| Platform entries           | Which Skills will be installed in this project or user directory                |
| Rule / Hook                | Shared entries to write, platform support, and configuration needing activation |
| Conflicts and capabilities | Existing file conflicts and host loading, handoff, and execution capabilities   |
| Evidence                   | Separate local validation, model Eval, and host validation results              |

Platform entries and the complete package export directory are managed separately. Copying only entry `SKILL.md` does not install the complete application and dependencies.

## Distribute to other platforms

Run in the project that needs the installation:

```bash
comet application distribute ./weekly-report/application.json --project . --platform codex --preview --json
```

Read the preview and obtain confirmation, then use the confirmation hash it returned:

```bash
comet application distribute ./weekly-report/application.json --project . --platform codex --confirmation-hash <current-preview-confirmation-hash> --json
```

Use `--platform all` for registered platforms or repeat `--platform` for multiple platforms. Use `--scope user` for user installation. The preview defines platform capabilities; successful entry installation does not establish that all host capabilities are active.

## Upgrade and uninstall

Add `--upgrade` for an upgrade and confirm the current preview again. SDK updates platform entries while retaining older versions needed by active Runs.

Uninstall previews by default. Use `--platform` to remove only selected entries, then confirm before execution. Selective uninstall does not arbitrarily delete shared Rule/Hook entries, dependencies, or required versions.

```bash
comet application uninstall weekly-report --project . --platform codex --json
```

## Interrupted installation

For partial writes or unknown results, check the original Action and target files before recovering along the original Run. File or configuration drift invalidates the original preview approval.

See [comet application](/en/cli/application) for command options. Inspect actual execution records and evidence in [Dashboard](/en/dashboard/overview)'s Comet Any workspace.
