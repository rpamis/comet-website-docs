description: 'Choose composition types, understand business checks, inspect evidence, and recover unfinished authoring.'
---

<AccordionGroup>
  <Accordion title="When should I use /comet or /comet-any?">
    `/comet` enters Native or Classic according to project configuration to complete requirement
    changes. `/comet-any` turns a goal and existing Skills into a reusable SDK Skill application.
  </Accordion>
  <Accordion title="Do I need to write SDK code myself?">
    With Comet Any, the authoring Agent investigates actual dependencies and writes business
    content, execution ports, and validators. Focus on the goal, complete plan, validation, and
    installation preview. Read the [SDK documentation](/en/sdk/overview) to integrate a platform or
    write an application yourself.
  </Accordion>
  <Accordion title="Who generates the Skill, business Rule, and Hook?">
    The Agent writes the complete entry Skill and business Rule. SDK appends the execution protocol,
    pins dependencies, and assembles Runtime. Formal distribution installs shared platform Rule/Hook
    entries. Business validators check actual business conditions; general protection rules do not
    replace them.
  </Accordion>
  <Accordion title="Can execution continue if a stage did not produce its required file?">
    When required artifacts have declared contracts, SDK checks actual files, content, and digests.
    Missing or empty files or failed business conditions prevent acceptance of a successful result.
    Dependent work cannot proceed on that evidence.
  </Accordion>
  <Accordion title="Does skipping model Eval skip local checks?">
    No. Local validation of normal and abnormal artifacts must pass. Skipping model Eval keeps an
    explicit skip record and does not produce a model pass or actual host validation result.
  </Accordion>
  <Accordion title="Does successful installation mean business validation passed?">
    Installation, local contract validation, model Eval, and actual host validation are recorded
    separately. Successful installation establishes that written entries and dependencies meet the
    installation plan. It does not establish execution on every platform, business sample, or
    external operation.
  </Accordion>
  <Accordion title="Do I need to create a new workflow after interruption?">
    First read `comet creator status` and `next` with the original authoring name. Retain the
    original Run, Actions, and current user Wait. Reconcile dispatched operations with unknown
    results before proceeding; do not create another workflow to repeat installation or publication.
  </Accordion>
  <Accordion title="Why can I not click approval options in Dashboard?">
    Comet Any's workspace is for read-only observation. The original Agent obtains user decisions
    and submits them through the current Wait. Dashboard does not take over Runtime progress.
  </Accordion>
</AccordionGroup>
