## What's Changed [0.4.0-beta.1] - 2026-06-27

### Highlights

- Rebuilt the classic workflow runtime on cross-platform Node entrypoints.
- Added structured intent routing for `/comet` so status, recovery, presets, and full workflow entry are easier to distinguish.
- Added Skill Creator surfaces for `/comet-any`, `comet creator`, bundle drafting, review, and publish preparation.
- Added a shared Skill evaluation harness with reports, scoring, and runtime attribution.
- Added the read-only dashboard for active and archived changes.

### Added

- `comet dashboard` for local project inspection.
- `comet creator` commands for inspecting and resuming Skill Creator state.
- `comet eval` support for local manifests and Skill paths.
- Bundle and publish command surfaces for advanced Skill distribution workflows.
- Runtime state separation between human-readable workflow state and machine-managed checkpoints.

### Changed

- Replaced shell-centered workflow launchers with Node `.mjs` entrypoints.
- Updated platform installation logic for Skills, rules, hooks, and generic registries.
- Clarified preset routing for hotfix and tweak work.
- Moved user-facing Skill composition language toward `comet creator` and `/comet-any`.

### Fixed

- Improved Windows behavior by removing Git Bash or WSL as runtime requirements.
- Improved workflow recovery after context compression and interrupted sessions.
- Tightened transition and handoff behavior around spec drift.

### Removed

- Removed the old assumption that core workflow control must run through Bash scripts.

### Security

- Preserved explicit executable capability disclosure for hooks and generated Skill packages.
