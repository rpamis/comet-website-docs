`.comet/config.yaml` is a project-level configuration, with a global copy. This page only covers the Classic related parts: the shared entry field and the default values of `classic.*`. The meaning of the `native.*` field can be found in [Native Configuration ](/en/native/configuration)

The following text uses `<classic-root>` to represent the current Classic OpenSpec root directory: The default for new projects is `docs/openspec/`, and for projects that retain the old layout, it is `openspec/`. The actual location is determined by `classic.artifact_layout`. For details, please refer to [Project File structure ](/en/guides/project-structure)

## Complete example

When two sets of workflows are enabled simultaneously and Chinese is selected, project-level installation will generate a similar configuration (from the Classic perspective, only shared fields and `classic:` blocks are concerned) :

```yaml
schema: comet.project.v1
default_workflow: classic
workflows:
  - native
  - classic
ambient_resume: true

classic:
  artifact_layout: docs
  language: zh-CN
  context_compression: off
  review_mode: standard
  auto_transition: true
```

## Shared entry field

|Configuration item|Allowable value|Meaning|
| ------------------ | -------------------------- | ----------------------------------------------------- |
| `schema`           | `comet.project.v1`         |The current structured project configuration version is managed by Comet|
| `default_workflow` | `native` \| `classic`      |By default, `/comet` enters which set of permanent skills|
| `workflows`        |`native`, `classic` or both|The workflow that the project has enabled; The default workflow must be included|
| `ambient_resume`   | `true` \| `false`          |Whether to allow the Agent to automatically run the recovery probe for ordinary natural language continuation requests|
| `hook.allow_paths` | Project-relative directory list (empty by default) | Directories the Agent may write during protected phases; matching uses path prefixes and cannot unlock protected artifact areas. See [Allowing Hook writes](#allowing-hook-writes). |

<Note>
Modifying <code>default_workflow</code> only changes the entry of <code>/comet</code> without migrating any changes.
</Note>

### Hook write release

`hook.allow_paths` is a shared write release policy: when it is empty by default, writes within the project (outside the product area) are determined according to the Classic's own phase and guard rules. After configuration, writes to the matching directory and its subdirectories will be directly allowed. A typical application is to enable the implementation code directory (such as `src/`) to be modified at any stage, avoiding triggering interception during non-coding phases.

```yaml
hook:
  allow_paths:
    - src
    - apps/web
```

The openspec and superpowers product roots of `.comet` (Runtime state) and Classic are always protected and cannot be released through this configuration. Path out-of-bounds or format errors will report an error during the `comet doctor` check.

## "Classic field"

`artifact_layout` is the project-level directory selection. The remaining four items will be snapshots to `.comet.yaml` of the new Classic change when it is created:

|Configuration item|Allowable value|Default value|Meaning|
| ----------------------------- | --------------------------------- | ----------------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| `classic.artifact_layout`     | `legacy` \| `docs`                |The default is `docs`; When upgrading, it was detected that the root directory `openspec/` already existed, so it was added to `legacy`|Select the OpenSpec root directory: `openspec/` or `docs/openspec/`|
| `classic.language`            | `en` \| `zh-CN`                   |The Skill language mapping selected by `comet init`; `--yes` defaults to `en`|The main language for controlling workflow products such as OpenSpec, Superpowers, verification reports, and archived instructions|
| `classic.context_compression` | `off` \| `beta`                   | `off`                                                             |Control the context compression during the handover from design to build. For details, please refer to [Context Compression mechanism ](/en/concepts/context-compression)|
| `classic.review_mode`         | `off` \| `standard` \| `thorough` |`standard` (full workflow default)|Control the intensity of code review. For details, please refer to [Code Review Mechanism ](/en/concepts/review-mode)|
| `classic.auto_transition`     | `true` \| `false`                 | `true`                                                            |Whether the next stage Skill is automatically called after the stage is advanced. For details, please refer to [Automatic Propulsion mechanism ](/en/concepts/auto-transition)|

</Note>

### The difference between product language and Skill language

The "Skill language" in `comet init` will determine whether to install the Chinese or English version of Comet Skill. The product language of Classic is written in `classic.language`:

|init selection|Installed Skill| `classic.language`   |
| --------------------------- | ------------ | -------------------- |
| `English` / `--language en` |English Skill| `en`                 |
|`Chinese`/`--language zh`|"Chinese Skill"| `zh-CN`              |

When creating a new Classic change later, Comet will snapshot the project-level `classic.language` to `<classic-root>/changes/<name>/.comet.yaml`. OpenSpec proposal, design, tasks, Superpowers Design/Plan, verification report and archive description are all based on this snapshot as the output language.

<Warning>
Project-level and change-level language values only accept <code>en</code> or <code>zh-CN</code>. <code>zh</code> is only used for {' '}
<code>comet init - language zh</code> CLI options, not <code>.com et/config yaml</code> legal values.
</Warning>

## Configuration priority

The following priorities only describe the Classic `language`, `context_compression`, `review_mode` and `auto_transition`:

```text
change level.comet.yaml field > Environment variables > Project level.comet/config.yaml > Global language default > Built-in default values
```

|Hierarchy|Explanation|Setting method|
| --------------------------- | ------------------------------------------------------------- | ------------------------------------------------------------------- |
|"change grade `.comet.yaml`|Highest priority. change is created from a project configuration snapshot and then flows through `/comet`|Written by the Skill of the `/comet` stage|
|Environmental variable|It only takes effect when the change-level field is empty and is suitable for CI/CD temporary overwriting| `export COMET_AUTO_TRANSITION=true` / `export COMET_LANGUAGE=zh-CN` |
|Project-level `.comet/config.yaml`|Fallback when the change level is empty and the environment variable is not set|Handwritten or generated by init|
|Global `~/.comet/config.yaml`|Only provide cross-project default for `language`; Project configuration priority|Global init/update generation|
|Default value|Finally, go back|See the table above|

## Detailed Explanation of auto_transition

Whether the next Skill is automatically called after the control phase of `auto_transition` advances.

|value|"Behavior"|
| -------------- | ------------------------------------------------------------------------------- |
|`true` (Default)|After guard advances `phase`, it outputs `NEXT: auto` and automatically invokes the next stage Skill|
| `false`        |After guard advances `phase`, it outputs `NEXT: manual`, prints the HINT, and you can manually run the next Skill|

<Warning>
<strong> phase advance must occur </strong> - guard <code> - updated <code>phase</code>{' '} apply</code> always
The field is independent of <code>auto_transition</code>. <code>auto_transition</code> only affects whether the next one is automatically called
"Skill. User decision points (confirming proposals, choosing execution methods, etc.) regardless of <code>auto_transition</code>{' '}
Anything can block.
</Warning>

Environment variable coverage (only effective when the change level is empty) :

```bash
export COMET_AUTO_TRANSITION=true
```

## Environmental variable

|Environmental variable|Purpose|Applicable scenarios|
| --------------------------- | ----------------------------------------------- | ------------------------------------ |
| `COMET_LANGUAGE`            |Overwrite language (effective when the change level is empty)|CI/CD or temporarily specify the product language of the new change|
| `COMET_AUTO_TRANSITION`     |Overwrite auto_transition (effective when the change level is empty)|CI/CD or temporary overwrite|
| `COMET_CONTEXT_COMPRESSION` |Override context_compression (effective when the change level is empty)|Temporarily test the compression mode|
| `COMET_REVIEW_MODE`         |Override the default resolution (resolver layer) of review_mode|Temporarily designate the review mode|
| `COMET_FORCE_PHASE`         |When `=1` is used, direct `set phase` is allowed (an escape hatch for state repair and troubleshooting only)|Status repair and troubleshooting|
| `COMET_OPENSPEC`            |Specify the openspec CLI path (default `openspec`)|Customize the installation location of OpenSpec|

<Note>
  <code>COMET_LANGUAGE</code>、<code>COMET_AUTO_TRANSITION</code>、<code>COMET_FORCE_PHASE</code>、
<code>COMET_OPENSPEC</code> are environment variables available to users. <code>COMET_CONTEXT_COMPRESSION</code> and {' '}
<code>COMET_REVIEW_MODE</code> exists in the parsing layer but is not officially recorded in the user documentation. It is mainly used internally and for testing.
</Note>

## How to configure

### Configure the default values of the project

Editor: `.comet/config.yaml`

```yaml
schema: comet.project.v1
default_workflow: classic
workflows:
  - native
  - classic
ambient_resume: true
classic:
  language: zh-CN
  context_compression: beta
  review_mode: thorough
  auto_transition: true
```

When submitted to the repository, new changes for team members will use these default values.

### Temporary coverage (environment variable)

```bash
export COMET_LANGUAGE=zh-CN
export COMET_AUTO_TRANSITION=false
```

Affect the current session and do not modify the file.
