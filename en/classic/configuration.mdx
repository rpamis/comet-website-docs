`.comet/config.yaml` is a project-level configuration, with a global copy. This page only covers the Classic related parts: the shared entry field and the default values of `classic.*`. The meaning of the `native.*` field can be found in [Native Configuration](/en/native/configuration)

The following text uses `<classic-root>` to represent the current Classic OpenSpec root directory: The default for new projects is `docs/openspec/`, and for projects that retain the old layout, it is `openspec/`. The actual location is determined by `classic.artifact_layout`. See [Project File structure](/en/guides/project-structure) for details.

## Change walkthroughs

Classic generates `walkthrough.html` at Build completion by default. Verify updates actual results on the same page, and Archive retains existing pages. Set `change_walkthrough: false` at the project configuration's top level to disable extra explanation and rendering. See [shared configuration](/en/native/configuration#change-walkthroughs).

## Complete example

When two sets of workflows are enabled simultaneously and Chinese is selected, project-level installation will generate a similar configuration (from the Classic perspective, only shared fields and `classic:` blocks are concerned):

```yaml
schema: comet.project.v1
default_workflow: classic
workflows:
  - native
  - classic
ambient_resume: true

classic:
  artifact_layout: docs
  language: zh-CN
  context_compression: off
  review_mode: standard
  auto_transition: true
```

## Shared entry field

| Configuration item | Allowable value                                    | Meaning                                                                                                                                                                             |
| ------------------ | -------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `schema`           | `comet.project.v1`                                 | The current structured project configuration version is managed by Comet                                                                                                            |
| `default_workflow` | `native` \| `classic`                              | By default, `/comet` enters which set of permanent skills                                                                                                                           |
| `workflows`        | `native`, `classic` or both                        | The workflow that the project has enabled; The default workflow must be included                                                                                                    |
| `ambient_resume`   | `true` \| `false`                                  | Whether to allow the Agent to automatically run the recovery probe for ordinary natural language continuation requests                                                              |
| `hook.allow_paths` | Project-relative directory list (empty by default) | Directories the Agent may write during protected phases; matching uses path prefixes and cannot unlock protected artifact areas. See [Allowing Hook writes](#allowing-hook-writes). |

<Note>
  Modifying <code>default_workflow</code> only changes the entry of <code>/comet</code> without
  migrating any changes.
</Note>

### Hook write release

`hook.allow_paths` is a shared write release policy: when it is empty by default, writes within the project (outside the artifact area) are determined according to the Classic's own phase and guard rules. After configuration, writes to the matching directory and its subdirectories will be directly allowed. A typical application is to enable the implementation code directory (such as `src/`) to be modified at any stage, avoiding triggering interception during non-coding phases.

```yaml
hook:
  allow_paths:
    - src
    - apps/web
```

`.comet` (Runtime state) and the OpenSpec and Superpowers artifact roots of Classic are always protected and cannot be released through this configuration. Path out-of-bounds or format errors will report an error during the `comet doctor` check.

## Classic fields

`artifact_layout` is the project-level directory selection. The remaining four items will be snapshots to `.comet.yaml` of the new Classic change when it is created:

| Configuration item            | Allowable value                   | Default value                                                                                                                           | Meaning                                                                                                                                                                        |
| ----------------------------- | --------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `classic.artifact_layout`     | `legacy` \| `docs`                | The default is `docs`; When upgrading, it was detected that the root directory `openspec/` already existed, so it was added to `legacy` | Select the OpenSpec root directory: `openspec/` or `docs/openspec/`                                                                                                            |
| `classic.language`            | `en` \| `zh-CN`                   | The Skill language mapping selected by `comet init`; `--yes` defaults to `en`                                                           | The main language for workflow artifacts such as OpenSpec, Superpowers, verification reports, and archived instructions                                             |
| `classic.context_compression` | `off` \| `beta`                   | `off`                                                                                                                                   | Control the context compression during the handover from design to build. See [Context Compression mechanism](/en/concepts/context-compression) for details.      |
| `classic.review_mode`         | `off` \| `standard` \| `thorough` | `standard` (full workflow default)                                                                                                      | Control the intensity of code review. See [Code Review Mechanism](/en/concepts/review-mode) for details.                                                          |
| `classic.auto_transition`     | `true` \| `false`                 | `true`                                                                                                                                  | Whether the next stage Skill is automatically called after the stage is advanced. See [Automatic Propulsion mechanism](/en/concepts/auto-transition) for details. |

<Note>
  Classic project defaults snapshot when creating the new change to <code>.com et. The yaml</code>;
  Subsequent modifications will not retrospectively change the existing changes.
</Note>

<Warning>
  Changing <code>classic.artifact_layout</code> only changes the directory Comet reads; it does not
  move existing artifacts. When you switch layouts for an existing project, first run{' '}
  <code>comet classic root move docs --dry-run</code> to check the current state, conflicts, and
  blocking items, then run <code>comet classic root move docs --apply</code> to migrate.
</Warning>

### The difference between artifact language and Skill language

The "Skill language" in `comet init` will determine whether to install the Chinese or English version of Comet Skill. The artifact language of Classic is recorded in `classic.language`:

| init selection              | Installed Skill | `classic.language` |
| --------------------------- | --------------- | ------------------ |
| `English` / `--language en` | English Skill   | `en`               |
| `Chinese`/`--language zh`   | "Chinese Skill" | `zh-CN`            |

When creating a new Classic change later, Comet will snapshot the project-level `classic.language` to `<classic-root>/changes/<name>/.comet.yaml`. OpenSpec proposal, design, tasks, Superpowers Design/Plan, verification report and archive description are all based on this snapshot as the output language.

<Warning>
  Project-level and change-level language values only accept <code>en</code> or <code>zh-CN</code>.{' '}
  <code>zh</code> is only used for <code>comet init - language zh</code> CLI options, not{' '}
  <code>.com et/config yaml</code> legal values.
</Warning>

## Configuration priority

The following priorities only describe the Classic `language`, `context_compression`, `review_mode` and `auto_transition`:

```text
change-level .comet.yaml field > environment variables > project-level .comet/config.yaml > global language default > built-in default
```

| Hierarchy                          | Description                                                                                               | How it is set                                                      |
| ---------------------------------- | --------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------- |
| Change-level `.comet.yaml`         | Highest priority. The change is created from a project configuration snapshot and then runs through `/comet` | Written by the `/comet` stage Skill                                 |
| Environment variable               | Applies when the change-level field is empty; suits temporary overrides in CI/CD                           | `export COMET_AUTO_TRANSITION=true` / `export COMET_LANGUAGE=zh-CN` |
| Project-level `.comet/config.yaml` | Used when the change-level field is empty and no environment variable is set                              | Written by hand or generated by init                                |
| Global `~/.comet/config.yaml`      | Provides a cross-project default for `language` only; project configuration takes precedence              | Generated by global init and update                                 |
| Built-in default                   | Used when nothing else is set                                                                             | See the table above                                                 |

## Detailed Explanation of auto_transition

Whether the next Skill is automatically called after the control phase of `auto_transition` advances.

| Value            | Behavior                                                                                                          |
| ---------------- | ----------------------------------------------------------------------------------------------------------------- |
| `true` (Default) | After guard advances `phase`, it outputs `NEXT: auto` and automatically invokes the next stage Skill              |
| `false`          | After guard advances `phase`, it outputs `NEXT: manual`, prints the HINT, and you can manually run the next Skill |

<Warning>
  <strong>Phase advancement always executes</strong>: Running the guard command with <code>--apply</code> always updates the <code>phase</code> state, regardless of whether <code>auto_transition</code> is enabled or disabled. <code>auto_transition</code> only controls whether the subsequent Skill is invoked automatically. At required human decision points (such as confirming proposals or selecting execution modes), the workflow always pauses and waits for your input.
</Warning>

Environment variable override (only effective when the change level is empty):

```bash
export COMET_AUTO_TRANSITION=true
```

## Environment variables

| Environment variable        | Purpose                                                                                      | Applicable scenarios                                                       |
| --------------------------- | -------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| `COMET_LANGUAGE`            | Override `language` (effective when unset at change level)                                   | CI/CD pipelines or temporarily setting the artifact language for new changes |
| `COMET_AUTO_TRANSITION`     | Override `auto_transition` (effective when unset at change level)                            | CI/CD pipelines or temporary override                                      |
| `COMET_CONTEXT_COMPRESSION` | Override `context_compression` (effective when unset at change level)                         | Temporarily testing compression mode                                       |
| `COMET_REVIEW_MODE`         | Override default `review_mode` resolution (resolver layer)                                   | Temporarily specifying review mode                                         |
| `COMET_FORCE_PHASE`         | When `=1`, allows direct `set_phase` (an escape hatch for state repair only)                  | State repair and troubleshooting                                          |
| `COMET_OPENSPEC`            | Specify custom `openspec` CLI path (default `openspec`)                                      | Custom OpenSpec installation paths                                         |

<Note>
  <code>COMET_LANGUAGE</code>, <code>COMET_AUTO_TRANSITION</code>, <code>COMET_FORCE_PHASE</code>,
  <code>COMET_OPENSPEC</code> are environment variables available to users.{' '}
  <code>COMET_CONTEXT_COMPRESSION</code> and <code>COMET_REVIEW_MODE</code> exists in the parsing
  layer but is not officially recorded in the user documentation. It is mainly used internally and
  for testing.
</Note>

## How to configure

### Configure the default values of the project

Editor: `.comet/config.yaml`

```yaml
schema: comet.project.v1
default_workflow: classic
workflows:
  - native
  - classic
ambient_resume: true
classic:
  language: zh-CN
  context_compression: beta
  review_mode: thorough
  auto_transition: true
```

When submitted to the repository, new changes for team members will use these default values.

### Temporary coverage (environment variable)

```bash
export COMET_LANGUAGE=zh-CN
export COMET_AUTO_TRANSITION=false
```

Affect the current session and do not modify the file.
