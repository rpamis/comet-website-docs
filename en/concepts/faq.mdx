---
title: "FAQ"
description: "Common questions about Comet classic Spec mode, routing, recovery, presets, and Skill boundaries."
---

<AccordionGroup>
  <Accordion title="Should I call /comet or a phase command directly?">
    Use `/comet` by default. It reads repository state and routes to the correct phase. Direct phase commands are for manual control or debugging.
  </Accordion>
  <Accordion title="Does Comet rely on chat history to recover?">
    No. It recovers from `.comet.yaml`, OpenSpec artifacts, Design Docs, Plans, and runtime evidence files.
  </Accordion>
  <Accordion title="When should I use hotfix?">
    Use hotfix for existing bugs that do not introduce new capabilities, public APIs, schema changes, or architecture changes.
  </Accordion>
  <Accordion title="When should I use tweak?">
    Use tweak for bounded medium changes that fit one OpenSpec change and can be built through OpenSpec apply.
  </Accordion>
  <Accordion title="Can I edit .comet.yaml by hand?">
    You can read it, but do not advance phases by hand. Use guard `--apply` or `comet-state transition`.
  </Accordion>
  <Accordion title="Do project Skills override built-ins?">
    Yes. Project Skills in `.comet/skills/` have priority. Invalid overrides fail closed instead of falling back silently.
  </Accordion>
</AccordionGroup>
