`review_mode` controls how much automatic review Comet performs during build and verify.

<Note>
  <code>review_mode</code> controls only <strong>automatic</strong> in-workflow review. You can
  also invoke <code>/comet-review</code> at any time for a read-only, on-demand review of the
  current change; it is independent of <code>review_mode</code> and does not advance the workflow.
  See [Skill types and purpose](/en/concepts/skills).
</Note>

Verify records review and verification evidence but does not handle branch delivery. A passing Verify transition keeps `branch_status: pending`; Archive records `handled` only after the user confirms immediate remote delivery.

## Mode selection

| Mode       | Behavior                                | Use when                               |
| ---------- | --------------------------------------- | -------------------------------------- |
| `off`      | No automatic review dispatch.           | Hotfixes or very small local work.     |
| `standard` | Default review depth for full workflow. | Normal feature work.                   |
| `thorough` | More exhaustive review.                 | High-risk changes or public contracts. |

Project defaults live at `classic.review_mode` in `.comet/config.yaml`; each Classic change snapshots the value into `.comet.yaml`.

## Presets

Hotfix and tweak default to `off` to keep lightweight paths lightweight. You can raise the mode before verify when risk warrants it.
