---
title: 'Context handoff and source reuse'
description: 'How Classic reuses formal materials between Design and Build, with an optional reading view.'
---

Classic reads current OpenSpec materials directly during Design, Build, and recovery. The Agent selects the proposal, design, tasks, and delta Specs relevant to the task, without copying a full context package or recalculating file hashes for each handoff.

## Handoff sources

- `proposal.md`: goals, scope, and motivation.
- `design.md`: existing design decisions.
- `tasks.md`: the implementation plan and progress.
- `specs/*/spec.md`: requirement changes and acceptance scenarios.

Execution always relies on formal materials as the authoritative baseline. An Agent summary can help restore context, but it cannot replace source documents or user confirmation of the technical design. After documents are modified, assess the actual impact first and update the design and plan as needed, rather than continuing solely from an outdated summary.

## Compatible off and beta settings

`classic.context_compression` retains `off` and `beta` for compatibility. Both now use formal sources without generating the old hash indexes or requiring a matching `handoff_hash` to advance. Old derived files may remain, but recovery uses the same task's formal sources and actual progress.

These settings no longer select between truncated summaries and hash references. Do not infer a fixed Token saving from them.

## A single reading view

If you want the current materials in one Markdown document, ask the Agent to follow the current Runtime instructions:

```bash
comet handoff <change-name> design --write --full
```

The view contains original source content. It does not replace formal materials, the design proposal, or approval. Routine progress does not require manually generating it. See [comet handoff](/en/scripts/comet-handoff).

## Continue after interruption

Ask the Agent to continue the original task. It checks the stage, unresolved decisions, and actual work before reading the necessary sources. `--hash-only` has been removed; regenerating a hash is not a recovery prerequisite.
