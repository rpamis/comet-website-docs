Comet is an agent workflow and Skill harness for AI coding tools. It has four connected surfaces:

- **Classic Spec mode**: `/comet` routes product work through proposal, design, implementation, verification, and archive.
- **CLI**: `comet init`, `status`, `doctor`, `dashboard`, and advanced Skill commands give you deterministic local control.
- **Skill Creator**: `/comet-any` composes any set of Skills into a reusable, reviewable Skill bundle.
- **Skill Eval**: `comet eval` measures Skill behavior with tasks, rubrics, pass metrics, reports, and failure attribution.

## What you can do with Comet

Use Comet when a task needs memory across turns, recoverable state, and explicit evidence.

| Need | Comet surface |
| --- | --- |
| Turn an idea into an implemented change | `/comet` classic Spec workflow |
| Resume after context loss or a new session | `.comet.yaml` plus run-state evidence |
| Compose several Skills into one reusable Skill | `/comet-any` and `comet creator` |
| Decide whether a Skill improved | `comet eval` reports and scorecards |
| Inspect project progress without editing files | `comet dashboard` |

## How it differs from a prompt

A prompt describes behavior. Comet gives that behavior a filesystem contract.

- Work has a current phase, current change id, artifacts, checks, and archive history.
- The agent can recover by reading files instead of relying on chat memory.
- Phase transitions are guarded by deterministic scripts.
- Design and implementation evidence are linked by handoff hashes.
- Skill bundles can be evaluated, reviewed, and published.

## What installation adds

`comet init` installs Comet Skills, rules, and hooks where each selected platform expects them. It also creates project configuration under `.comet/` and, when you start a workflow, creates `.comet.yaml` as the human-readable workflow state.

The current runtime uses Node.js entrypoints. You do not need Git Bash or WSL on Windows.
