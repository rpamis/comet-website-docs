Comet Dashboard is a locally hosted, visual developer console. When running long-horizon tasks in your terminal, Dashboard gives you full visibility into the execution process: track Classic and Native change progress, verify evidence chains, manage personal memory and project knowledge, and trace Comet Any authoring pipelines alongside Eval benchmarks.

<DashboardWebsiteDemo language="en" />

The interactive demo runs on built-in sample data. It does not read your local project or perform actual evaluations, installations, or exports. To use it in real development, start the local Dashboard in your project.

## Start the local Dashboard

Run the following command in your project root:

```bash
comet dashboard
```

The service binds to local `127.0.0.1:4321` by default and automatically opens the console in your default browser. Common options include:

- `--port <port>`: Specify a custom port (e.g. `comet dashboard --port 5000`);
- `--no-open`: Start the background web service without automatically launching a browser window.

For all options and configuration details, see [comet dashboard command reference](/en/cli/dashboard).

<Tip>
  **Recommended workflow: Dual-screen development**
  In day-to-day coding, keep your IDE or terminal on your primary display running `/comet`, and keep Dashboard open on a secondary display. As the Agent modifies files, executes automated tests, and advances through Verify stages, you can observe state transitions and watch test assertions turn green in real time without digging through terminal logs.
</Tip>

## Classic and Native Change Explorer

The Change Explorer synchronizes live with change states stored on your local disk. You can inspect the current stage, recommended next steps, automated check outcomes, and Git diff summaries at a glance.

> The Dashboard adheres to a read-only safety design: all code modifications, stage advancement approvals, verification fallbacks, and final archives remain strictly under your control in the Agent terminal. Dashboard never modifies code or forces state transitions autonomously.

| Console Area | Core Functionality |
| --- | --- |
| Metrics Cards | Toggle between active and archived views, filter by running or failed states, and drill down into tasks, acceptance criteria, or Git diff details |
| Changes Explorer | Browse active, archived, or all changes with smooth infinite scrolling |
| Details Panel | Inspect execution steps, physical artifact evidence chains, and next-step guidance |
| Status Sidebar | Verify breakpoint recovery checkpoints, blocking factors, bound workspaces, and Git branch details |

### Workspaces and Supervisor Collaboration Tracking

- **Git Worktree Mapping**: Clearly displays the isolated branch and physical directory bound to each change, preventing accidental operations in the wrong workspace.
- **Supervisor Tree View**: For complex composite tasks, the tree expands all child tasks, visually presenting dependency topologies, individual acceptance results, and integration progress.
- **Archive Prompts**: When all acceptance criteria for a change have passed and meet delivery thresholds, the Details panel highlights the change for archival and displays the corresponding terminal command.

## Personal Memory and Project Knowledge Management

Dashboard provides an intuitive card-based UI for managing Personal Memory and Project Knowledge, eliminating the friction of CLI lookups:

- **Personal Memory**: Hierarchically presents Core Profiles, Collaboration Policies, and Personal Episodes. Click any card to edit its content online, toggle its scope (global or project-specific), correct inaccuracies, or forget items with one click, and review 7-day context injection hit rates.
- **Project Knowledge**: Structurally organizes Project Models (directory architectures, module topologies, and technical facts) alongside Project Policies (design decisions, stable patterns, and engineering conventions).
- **Interactive Retrieval Simulation**: Enter a simulated task description in the Project Knowledge page to preview matched knowledge cards, ranking scores, and exact `whyApplied` trigger reasons to tune your rules.
- **Project Memory**: Centrally browse, search, and prune Markdown experience snippets recorded by agents after task completions.

## Evaluation with Eval

Under **New Evaluation**, select a local Skill or SDK application, verify the Agent platform, model configuration, and testing budget, then launch local evaluation with a single click.

- **Live Execution Monitor**: The Details panel synchronizes live evaluation stages, active test cases, terminal logs, and coverage metrics.
- **Reports and Failure Attribution**: Automatically generates interactive HTML reports upon completion, displaying multi-dimensional Rubric scores, `pass@k` metrics, and root-cause failure attribution.
- **Rerun and Baseline Management**: Rerun failed test cases with one click, download complete execution bundles, and maintain default evaluation baselines under **Settings → Eval**.

For comprehensive guides, see [Evaluate SDK Applications](/en/eval/applications) and [Eval Quickstart](/en/eval/quickstart).

## Comet Any Authoring and Run Tracking

Select an authoring goal or application on the left to inspect pinned release versions and execution runs in the center, and view detailed step outputs and physical artifacts on the right.

- **Full Authoring Traceability**: Completely records requirements analysis, plan confirmation, local validation, optional Eval benchmarks, and installation states.
- **Application Run Streams**: Displays real-world task execution streams after application installation, strictly isolated from authoring logs.
- **Application Distribution and Export**: Select a pinned application version in the local Dashboard and click **Distribute / Export**:
  - **Install to Agent Platforms**: Select supported platforms (such as Claude Code, Codex, etc.) and toggle project-level or global installation;
  - **Version Upgrade Preview**: Compare file diffs before upgrading; active running tasks continue unaffected on their pinned versions;
  - **Export Distribution Packages**: Export standalone packages with pinned dependencies, clean of internal execution history.

All code adoption and final submissions remain confirmed by you in the Agent terminal. For authoring walkthroughs, see [Comet Any Quickstart](/en/skill-creator/getting-started).

## Runtime Performance and Change Trace Observability

### Runtime Performance Dashboard

Open **Observability → Runtime Performance** to view local task execution efficiency metrics:

- **Multi-Dimensional Filters**: Toggle between All, Native, or Classic views, and filter by the last hour, 24 hours, 7 days, or all time.
- **Core Quality Metrics**: Command call frequencies, overall success rates, sub-second fast response ratios, check pass rates, and P50 / P95 latencies.
- **Hotspots and Error Distribution**: Sort high-frequency commands by call volume or cumulative duration, observe nonzero exit codes, and drill down into slow execution logs.
- **Runtime Health**: Real-time monitoring of resident background services, memory consumption, and uptime using lightweight queries without extra daemon processes.

### Change Execution Traces

Open **Observability → Change Traces** and expand the Gantt tree structure to inspect task lifecycles:

- **Fine-Grained Node Tracing**: Covers action execution, guard checks, context retrieval, awaiting confirmation, and automatic retries. Click nodes to inspect timestamps, retry counts, and outputs.
- **Smooth Gantt Bars**: Active nodes display pulsing animations; duration calculations automatically merge parallel spans and deduct human wait times.
- **Automatic Synchronization**: Silently syncs every 15 seconds, preserving current node selections and expanded tree states without UI flicker.

## Artifact Previews, Themes, and Settings

- **Full Artifact Previews**: Read complete Markdown documents, JSON, and structured artifacts with full-screen reading modes and table-of-contents navigation. Logs and reports support one-click downloads.
- **Appearance and Themes**: Toggle light or dark themes and scale interface font sizes under **Settings → Appearance**; preferences persist across projects in the local browser.
- **Updates and Maintenance**: The sidebar displays current versions and update badges for upgrading the CLI; the project selector flags invalid paths and allows safe removal from the index without touching local project files.
