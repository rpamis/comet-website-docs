Dashboard provides Classic, Native, Comet Any, Eval, personal memory, and project knowledge workspaces for the same project. Select a feature in the sidebar and switch project, language, or theme at the top.

<DashboardWebsiteDemo />

The demo uses sample data. It does not read your project or perform actual evaluations, installations, or exports. Select a completed application and click **Distribute / export** to explore the configuration options. Start the local Dashboard to perform these operations.

## Start the local Dashboard

```bash
comet dashboard
```

The service binds to local `127.0.0.1` on port `4321` by default. Use `--port <port>` to choose a port or `--no-open` to start only the service. See [comet dashboard](/en/cli/dashboard) for all options.

## Classic and Native

Select a change to inspect its stage, task or acceptance progress, next-step guidance, artifacts, and Git summary. These workspaces remain read-only; progress, validation, and archiving still use the original workflow.

| Area             | Purpose                                                                                                                        |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| Statistics cards | Switch between active and archived records, filter execution or failure status, and open task, acceptance, or Git file details |
| Changes Explorer | Browse active, archived, or all changes, and scroll to load more                                                               |
| Details          | Inspect steps, current evidence, and next steps                                                                                |
| Status sidebar   | Check recovery, blockers, workspace, and Git information                                                                       |

Native status statistics cover all active changes. Archived totals appear separately. Archive-ready status remains visible on individual changes and in next-step guidance.

Registered Git worktrees retain their branch or directory association. Expand Supervisor children to inspect acceptance, dependencies, and archive records. Read failures provide diagnostics and retry options instead of being treated as zero records.

## Comet Any

Select an authoring goal or application on the left, inspect the current pinned version and Run in the center, and read selected steps or execution records on the right.

**Authoring** shows proposals, user waits, local validation, optional Eval, and installation records. **Application Runs** show actual tasks after installation. These records are saved separately; evidence from one version cannot replace another version's evidence.

Inspect steps, execution attempts, artifacts, and version evidence, open saved child workflows, or follow evidence to a linked Eval. Returning preserves the original Any record and reading position.

### Distribute or export a completed application

In the local Dashboard, select a completed creation or a pinned application version and click **Distribute / export**. The application contents must match that version's record. Historical archives are available for viewing only.

| Operation                       | Configuration and result                                                                                                                                                                                                                     |
| ------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Install to Agents               | Select one or more Agent platforms supported by Comet and choose project or user scope. You can enter a custom root directory. Project scope defaults to the current project; leaving the user root empty uses the current user's directory. |
| Upgrade an installed version    | Enable the upgrade option and preview the installation changes. Active runs continue using their pinned versions.                                                                                                                            |
| Export the complete application | Enter a destination directory that does not yet exist to export the application and its pinned Skill dependencies. Run records are excluded from the package.                                                                                |

Click **Preview** first, review the version, destination directories, and files to be written, then confirm installation or export. Changing platforms, directories, or other options requires a new preview. Changes to the application contents also require renewed confirmation.

The original Agent obtains and submits user decisions. Dashboard does not directly approve proposals or advance Runs. See [Comet Any](/en/skill-creator/getting-started) for authoring.

## Eval

In **New evaluation**, choose a Skill or SDK application target, review the Agent, model, configuration, and budget, then start local execution. Details show live stages, the current case, logs, reports, and coverage.

Filter the run list by status and baseline. You can stop executions you started, retry failed items with the original cases, download complete logs and reports, and manage applicable default baselines.

Common settings are saved in **Settings → Eval**. New runs reuse defaults and can override them for that run. Models, paths, or hosts that did not execute remain unverified. See [evaluate SDK applications](/en/eval/applications).

## Memory and project knowledge

Pages show current records, history, retrieval sources, and evidence separately. Management operations update the corresponding storage. Agents still write project memory through `comet knowledge remember`.

In settings, **Built-in service** uses Comet capabilities on the current device. **External service** calls compatible memory or knowledge APIs. **API examples** beside the endpoint show the corresponding requests and responses. The Token field takes an environment variable name; do not enter a model API endpoint directly.

## Runtime performance

Open **Observability → Runtime performance** and select All, Native, or Classic to inspect command counts, latency P50/P95, failure rates, Git calls and time, recent command latency, and slow records. Click a chart point or command name to inspect that record. Check executions are counted separately; reusing a check does not count as a new execution.

Statistics use newly recorded local activity for this workspace over the last 7 days. Storage retains up to 10,000 records and reads the latest 5,000, with a notice when the sample is truncated. Command handling time excludes CLI startup and model thinking, and does not represent the time an Agent takes to complete a whole task. Help, Hooks, and Dashboard previews are excluded. History from before the upgrade is not reconstructed.

## Artifacts, refresh, and updates

Preview Markdown, JSON, and structured artifacts. Logs and reports retain download links. The page sanitizes untrusted HTML content.

Refresh preserves the selected record, forms, and reading position. Initial reads show structured placeholders; background updates retain existing content. Light and dark themes and English and Chinese use the same navigation state and respect the system's reduced-motion preference.

The sidebar shows the running version and available updates. Confirm the project scope before updating. The dialog shows CLI/npm output, failures, and retries; reopen it after closing to inspect progress.
