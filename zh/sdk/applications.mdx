---

Workflow Application 把工作流与实际执行内容绑定在一个包中。包记录应用身份、入口 Skill、执行模块、真实依赖及其摘要，宿主据此加载和执行。

希望由 Agent 创作完整业务内容时，使用 [Comet Any](/zh/skill-creator/getting-started)。需要自行编写和接入应用时，从下面的本地报告样板开始。

## 最小应用包

在项目内创建独立的 `local-report/` 目录，保存三份文件。

`application.json`：

```json
{
  "schema": "comet.workflow.application.v1",
  "id": "local-report",
  "version": "1",
  "base": "standalone",
  "runtimeVersion": "0.5.0",
  "entrySkill": "SKILL.md",
  "module": "application.mjs",
  "skills": [],
  "bindings": []
}
```

`application.mjs`：

```js
export { createReportApplication as createApplication } from '@rpamis/comet/applications';
```

`SKILL.md`：

```markdown
---
name: local-report
description: 生成需要用户审批后才能发布的本地报告。
---

# 本地报告

使用 application.json 启动 report-publishing@1，提供 title、body 和 sources。
保存 Run ID，执行当前动作，展示实际草稿并等待用户决定。
批准后执行本地发布；结果未知时先核对原动作，不重新派发。
```

样板的 `draft` 与 `sources` 可以并行完成，`compose` 在两者完成后生成实际 Markdown 草稿。父流程展示草稿、路径和摘要，等待用户选择。它验证声明的报告格式与本地文件发布；来源事实核验或外部部署应另行声明验证与授权。

## 通过 SDK 加载

```js
import path from 'node:path';
import { loadWorkflowApplication } from '@rpamis/comet/applications';

const application = await loadWorkflowApplication({
  file: path.resolve('local-report/application.json'),
  projectRoot: process.cwd(),
});
console.log(application.identity);
```

应用包必须位于独立目录，不能把整个项目连同运行状态作为包根。加载器核对实际文件、身份和固定依赖；同一版本内容发生变化时会拒绝继续使用原身份。

加载应用会执行其模块，接入前应审查模块与依赖来源。固定摘要用于核对内容，不提供代码沙箱。

## 通过 CLI 运行

将每次请求保存为 JSON 文件，再调用 [comet runtime](/zh/cli/runtime)：

```bash
comet runtime dispatch --application-file ./local-report/application.json --project-root . --request start.json --json
```

`start.json`：

```json
{
  "operation": "start",
  "runId": "report-1",
  "workflow": { "id": "report-publishing", "version": "1" },
  "input": {
    "title": "项目周报",
    "body": "本周完成了三个已验收任务。",
    "sources": ["本地任务记录"]
  }
}
```

后续使用 `--application local-report` 和同一 Run ID 查询、执行或恢复。读取实际返回的子 Run、Action 和 Wait ID；不要根据步骤名称猜测它们。

## 接入真实 Skill

`inspectApplicationSkill` 读取实际目录，`adaptApplicationSkill` 将内容审查、能力、输入输出、副作用和恢复条件形成适配契约。依赖按内容固定，不会在运行途中悄悄换成新文件。

使用 `createApplicationSkillExecutor` 接入宿主的实际 Skill 调用、能力检查和授权。加载过 Skill、宿主声明完成、机器验证通过、独立评审通过分别记录，前一层不能替代后一层。

分发与升级见 [comet application](/zh/cli/application)。应用评估见 [评估 SDK 应用](/zh/eval/applications)；必需文件与业务条件见 [阶段产物验收](/zh/sdk/artifact-validation)。
