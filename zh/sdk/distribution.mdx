本地报告应用已经通过验证，你希望团队成员通过平台入口调用它。分发完整应用包，让工作流、入口 Skill、规则与固定依赖一起安装。

先按 [Workflow Application](/zh/sdk/applications) 准备 `local-report/application.json`。本页使用 Comet CLI；完整选项见 [comet application](/zh/cli/application)。

## 预览安装

```bash
comet application distribute ./local-report/application.json --project . --platform codex --preview --json
```

检查返回结果中的安装路径、平台能力、冲突和确认摘要。默认使用项目级范围；需要用户级入口时显式设置 `--scope user`。缺少 Agent 平台执行或 Hook 能力时，先处理预览指出的问题。

预览读取目标与当前内容，不写入安装文件。即使应用方案已经批准，安装仍需要对当前目标单独确认。

## 确认并安装

用户确认预览后，将返回的确认摘要替换到命令中：

```bash
comet application distribute ./local-report/application.json --project . --platform codex --confirmation-hash <本次预览确认摘要> --json
```

包内容或目标配置变化后，旧摘要失效，需要重新预览。安装后按返回提示激活平台能力，再启动原应用验证入口和实际输出。文件写入成功不等于真实 Skill 已运行。

## 导出给另一台设备

```bash
comet application export ./local-report/application.json ./exports/local-report --project . --json
```

导出包含完整包及固定依赖。接收者审查模块与依赖来源后，在自己的目标项目重新预览和确认安装。不要只发送 `SKILL.md`，否则缺少流程定义、执行模块与验收条件。

## 升级应用

修改业务内容后创建新应用版本，通过同样的预览流程增加 `--upgrade`。确认后平台入口指向新版本，活动 Run 仍保留它使用的旧版本。

应用身份、版本和内容应保持一致。不要在原版本目录直接替换 Skill 或执行模块，再要求旧 Run 使用新内容续跑。

## 移除平台入口

```bash
comet application uninstall local-report --project . --platform codex --json
```

先检查卸载预览，再用返回的 `--confirmation-hash` 提交。共享 Rule/Hook、其他应用的依赖和仍需使用的版本继续保留。只移除某个平台时明确传入 `--platform`。
