open 阶段负责把用户目标变成可执行 change。它调用 OpenSpec skill 探索需求、创建 artifacts，并初始化 Comet 状态。

## 调用的 skill

| Skill | 用途 | 何时调用 |
| --- | --- | --- |
| `openspec-explore` | 探索问题空间、澄清需求 | Step 1，立即执行，不可跳过 |
| `openspec-new-change` | 创建 change 骨架 | Step 2，立即执行，不可跳过 |

<Warning>
  完整工作流默认<strong>不加载</strong> <code>openspec-propose</code>（一次性生成全部 artifacts）。只有用户明确要求时才允许。Comet 用标准产物循环逐个生成。
</Warning>

## 产物

```text
openspec/changes/<name>/
├── .openspec.yaml
├── .comet.yaml          # Comet 状态（comet-state init）
├── proposal.md          # Why + What
├── design.md            # How（高层）
├── tasks.md             # 任务清单
└── specs/<capability>/spec.md   # delta spec
```

## 完整步骤

### Step 0：输出语言约束

传递用户请求语言给 OpenSpec 的所有提问和产物。恢复已有 change 时保持既有主语言。

### Step 1：探索想法与需求澄清

加载 `openspec-explore`，围绕以下内容持续提问，直到形成澄清摘要：

- 目标、非目标
- 范围边界（涉及/不涉及的模块、用户、平台、数据）
- 关键未知项（假设、风险、依赖）
- 验收场景草案（核心场景 + 边界场景）

不得把一次问答视为足够澄清。

### Step 1a：PRD 拆分预检（停顿点）

如果输入是大型 PRD 或澄清摘要包含多个独立能力，触发拆分预检。详见[五阶段停顿点和用户选择点](/zh/concepts/decision-points)。

### Step 1b：需求澄清完成确认（停顿点）

展示澄清摘要，等待用户确认。确认前不创建任何 artifact。

### Step 1c：change 名称确认（停顿点）

推荐 2-3 个 kebab-case 英文名，让用户选择或自行输入。名称必须是 kebab-case 英文。

### Step 2：创建 change 结构

加载 `openspec-new-change`。按标准产物循环逐个生成 proposal → design → tasks：

1. 刷新状态：`openspec status --change "<name>" --json`
2. 获取指令：`openspec instructions <proposal|design|tasks> --change "<name>" --json`
3. 读取 `dependencies`、遵循 `template` 和 `instruction`、应用 `context`/`rules` 约束（不复制到 artifact）、写入 `resolvedOutputPath`
4. 每个 artifact 后刷新状态确认

然后初始化 Comet 状态：

```bash
node "$COMET_STATE" init <name> full
```

### Step 3：入口状态验证

```bash
node "$COMET_STATE" check <name> open
```

### Step 4：内容完整性检查

逐个确认三个文件存在且非空：proposal（背景/目标/范围）、design（架构决策/选型/数据流）、tasks（任务描述）。

### Step 5：用户审视确认（停顿点）

展示三个文档摘要，等待用户确认。

### 退出

```bash
node "$COMET_GUARD" <change-name> open --apply
```

full workflow 推进到 `phase: design`；hotfix/tweak 推进到 `phase: build`。

## 何时进入

- 项目里没有活跃 change
- 用户明确要创建新变更
- `.comet.yaml` 缺失，需要补齐

## 幂等性

open 阶段所有操作可安全重复。如果 `.comet.yaml` 已处于 `phase: open` 且三个产物都已存在，跳过已完成步骤。

## 常见问题

<AccordionGroup>
  <Accordion title=".comet.yaml 缺失怎么办">
    不要用 `/opsx:new` 绕过。重新运行 `/comet`，让它通过 `/comet-open` 补齐状态。
  </Accordion>
  <Accordion title="change 名称有什么限制">
    必须是 kebab-case 英文（小写字母、数字、连字符）。中文或非合规名称会被转换并回显确认。
  </Accordion>
  <Accordion title="openspec instructions 失败了怎么办">
    立即停止 artifact 创建并报告 OpenSpec 错误。不得回退为硬编码文档结构，那会绕过项目规则。
  </Accordion>
</AccordionGroup>
