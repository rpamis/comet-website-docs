## 启动

在项目根目录运行：

```bash
comet dashboard
```

Dashboard 默认在 `http://localhost:4321` 启动并打开浏览器。使用 `--port <端口>` 修改端口，使用 `--no-open` 只启动服务。

<Info>
  服务只绑定 <code>127.0.0.1</code>，不会对外暴露，也不会修改项目文件。
</Info>

## Classic 与 Native

左上角的 **Classic / Native** 开关决定当前工作区。两种视图共用 Change Explorer、详情区、状态侧栏和产物预览，但不会混在一起展示。

|                  | Classic                                      | Native                                              |
| ---------------- | -------------------------------------------- | --------------------------------------------------- |
| 生命周期         | open → design → build → verify → archive     | Shape → Build → Verify → Archive                    |
| 主要信息         | 任务、产物、Verify、风险和 Git               | Loop、验收、检查、阻塞、恢复和用户产物              |
| 活跃与归档       | 支持                                         | 支持                                                |
| 修改或推进 Change | 不支持                                       | 不支持                                              |

选择一个 Change 后，可以查看当前阶段、任务或验收进度、下一步、风险和相关产物。完整诊断仍以 `comet status` 或 `comet native status --details` 为准。

## Supervisor Change 与 Git worktree

Dashboard 会扫描当前仓库已经注册的 Git worktree，并保留每个工作区的分支或目录标签。

Native Supervisor Change 会显示子 Change 的完成进度。展开父 Change 后，可以选择某个 child，查看它的阶段、工作区、依赖和验收状态。Dashboard 只负责发现和展示，不会创建 worktree、推进任务或执行验证。

## 产物预览

点击已生成的产物，会打开 Markdown 预览抽屉。预览支持：

- 标题、列表、表格、任务列表和代码高亮；
- Mermaid 图；
- `.comet.yaml`、handoff 和 checkpoint 的结构化表格；
- Classic 与 Native 的用户可读产物。

超过 256 KiB 的内容会被截断并标记。产物内容会在渲染前清洗，不能通过 HTML 或 Mermaid 执行脚本。

## 主题、刷新与演示数据

- 使用顶部工具栏切换亮色或暗色主题；选择保存在当前浏览器中。
- Dashboard 每 30 秒自动刷新，也可以点击工具栏立即刷新。
- 在地址后添加 `?demo` 可以加载演示数据，不读取真实 Change：

```text
http://localhost:4321/?demo
```

## 使用边界

Dashboard 不会推进、修复、验证或归档 Change，也不会暴露绝对路径、原始日志和本机 Runtime 文件。所有状态变更仍由 `/comet`、`/comet-native` 和对应 CLI 完成。

如果某个工作流采集失败，Dashboard 会显示错误，不会把失败伪装成空工作区，也不会阻止另一种工作流继续显示。
