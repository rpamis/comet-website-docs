欢迎使用 **Comet** (`@rpamis/comet`)。Comet 提供了两套相互独立、支持从中断中恢复的开发工作流：Native 与 Classic。

## 两条工作流怎么选

- **Native**：面向**强编码模型**，专注于确认需求边界、明确目标规格、检查任务状态并保存验收证据，由 Agent 自主选用你的本地 Skill 参与实现，按 Loop 驱动的交付流程推进
- **Classic**：集成 [OpenSpec](https://github.com/Fission-AI/OpenSpec) 与 [Superpowers](https://github.com/obra/superpowers)，保留完整的五阶段治理，适合希望按固定节拍推进方案设计、任务计划、TDD 测试与代码审查的团队，经典 SDLC 流程驱动

项目根目录 `.comet/config.yaml` 中的 `default_workflow` 决定了 `/comet` 转发到哪个入口；`/comet` 严格遵从项目配置，不会猜测你的任务模式。

**新项目默认使用 Native**。通常只有以下三种情况需要选择 Classic：

- 团队/个人使用非旗舰模型（如 20B/30B 级别），希望通过阶段性任务拆解来规避长会话截断导致的遗忘问题；
- 项目需要 OpenSpec/Superpowers 式的完整阶段治理；
- 项目中已有 Classic 历史记录，或者正在使用 OpenSpec 与 Superpowers。

| 我的情况                                               | 用哪套             |
| ------------------------------------------------------ | ------------------ |
| 新项目，尚未初始化                                     | **Native**（默认） |
| 采用云端旗舰模型，非本地私有化 20B/30B/小尺寸模型                                     | Native |
| 不确定怎么选，想先使用一条可中断恢复的工作流       | Native             |
| 团队需要严格的方案设计、TDD 测试与代码审查阶段治理     | Classic            |
| 项目已有 Classic 历史记录，或正在配合 OpenSpec + Superpowers | Classic            |

两套工作流相互独立，也可以在同一个项目中同时启用，分别维护各自的 change；每次调用 `/comet` 只会进入对应的一套流程。默认工作流在初始化时直接写入项目配置，后续即便全局默认值发生变更，也不会影响已激活的项目。完整对比请参考 [Native 还是 Classic](/zh/native/native-vs-classic)，初始化配置项请参考 [comet init](/zh/cli/init)。

完整安装指引与创建第一个 change 请参考 [快速开始](/zh/quickstart)。

## AI 原生文档

你可以通过 MCP 将 Comet 官方文档站直接接入你的 Agent，在日常对话中实时检索最新文档。

### 在 Claude Code 中使用

```bash
claude mcp add --transport http docs-comet --scope user https://docs.comet.rpamis.com/mcp
```

### 在 Codex CLI 中使用

```bash
codex mcp add docs-comet --url https://docs.comet.rpamis.com/mcp
```

### 在 Cursor / Antigravity 中使用

```json
{
  "mcpServers": {
    "docs-comet": {
      "url": "https://docs.comet.rpamis.com/mcp"
    }
  }
}
```

### 在 VS Code 中使用

```json
{
  "servers": {
    "docs-comet": {
      "url": "https://docs.comet.rpamis.com/mcp"
    }
  }
}
```
