欢迎使用 **Comet** (`@rpamis/comet`)。Comet 为 AI 编码任务提供两套相互独立、支持中断恢复的需求工作流：Native 与 Classic。

## 两条工作流怎么选

- **Native** 面向**强编码模型**，提供详细需求、完整目标规格、状态检查和验证证据，但不规定固定计划、TDD 或审查方法；
- **Classic** 连接 [OpenSpec](https://github.com/Fission-AI/OpenSpec) 与 [Superpowers](https://github.com/obra/superpowers)，保留完整的五阶段治理，适合需要流程固定安排设计、计划、TDD 与审查的团队。

项目根目录 `.comet/config.yaml` 的默认工作流决定 `/comet` 转发到哪一个入口；`/comet` 只读取项目配置，不根据任务大小猜模式。

**新项目默认 Native**。只有两种情况需要选 Classic：

- 需要 OpenSpec/Superpowers 式的完整阶段治理；
- 项目里已有 Classic 状态，或正在使用 OpenSpec 与 Superpowers。

| 我的情况 | 用哪套 |
| --- | --- |
| 新项目，尚未初始化 | **Native**（默认）|
| 不确定怎么选，想先跑通一条可中断恢复的流程 | Native |
| 需要固定的计划、TDD、审查等阶段治理 | Classic |
| 项目已有 Classic 状态，或正在用 OpenSpec + Superpowers | Classic |

两套工作流相互独立，可以在同一个项目里同时启用（`comet init --workflow both`），各自管理各自的 change；一次 `/comet` 调用只会进入其中一套。默认值在初始化时固化到项目配置，已激活项目不会因全局默认值变化而被改写。逐项对比见 [Native 还是 Classic](/zh/native/native-vs-classic)，初始化选项见 [comet init](/zh/cli/init)。

完整安装与第一个 change 见 [快速开始](/zh/quickstart)。

## AI 原生文档

你可以通过 MCP 把 Comet 文档站直接接入到你的 Agent，对话时可按需检索最新文档内容。

### 在 Claude Code 中使用

```bash
claude mcp add --transport http docs-comet --scope user https://docs.comet.rpamis.com/mcp
```

### 在 Codex CLI 中使用

```bash
codex mcp add docs-comet --url https://docs.comet.rpamis.com/mcp
```

### 在 Cursor / Antigravity 中使用

```json
{
  "mcpServers": {
    "docs-comet": {
      "url": "https://docs.comet.rpamis.com/mcp"
    }
  }
}
```

### 在 VS Code 中使用

```json
{
  "servers": {
    "docs-comet": {
      "url": "https://docs.comet.rpamis.com/mcp"
    }
  }
}
```
