---

`comet uninstall` 专注于干净、安全地剥离由 Comet 框架托管安装的组件，完好保留开发者原有的业务代码、自定义 Git Hook 脚本及非 Comet 配置。

## 基本用法

```bash
cd your-project
comet uninstall
```

常用选项参数：

| 参数选项 | 说明 |
| --- | --- |
| `--force` | 跳过确认提示，直接执行静默卸载 |
| `--scope <scope>` | 仅卸载指定作用域的资产：支持 `project`（当前项目）或 `global`（全局环境） |
| `--json` | 输出机器可读的结构化 JSON 卸载报告 |
| `--current-project` | 严格仅卸载当前项目级资产（单项目作用域） |
| `--all-projects` | 批量卸载项目全局索引账本中登记的全部项目级安装 |

## 典型使用示例

交互式安全卸载：

```bash
comet uninstall
```

仅移除当前项目级资产：

```bash
comet uninstall --scope project
```

自动化脚本非交互式静默卸载：

```bash
comet uninstall --force --json
```

批量移除所有已在册的项目级安装：

```bash
comet uninstall --all-projects --force --json
```

## 按需解绑特定工作流

若当前安装目标同时激活了 Native 与 Classic 双工作流，交互式卸载会引导你按需选择是仅注销其中单套体系，还是全量卸载。若仅剥离其中之一，另一套工作流及其共享配置文件会被完好保留，无需二次重装。

在选择移除 Classic 工作流时，系统还会单独询问是否连同 OpenSpec 或 Superpowers 专属 Skill 一并卸载。这两项默认保持未选中状态，杜绝误删你在其他场景下仍在依赖的工具链。在非交互自动化模式下（`--force` 或 `--json`），系统同样采取保守策略，不擅自删除配套的三方 Skill。

## 细粒度控制卸载生效范畴

当全局索引中登记了多个项目时，交互式 `comet uninstall` 会主动询问是仅处理当前工程还是批量操作所有已登记工程。追加 `--json`、`--force` 或显式 `--current-project` 默认安全限定在当前项目范围；跨工程全局卸载必须显式传入 `--all-projects`。在编写自动化运维脚本时，建议始终显式声明范围参数。

`--all-projects` 禁止与 `--scope global` 或 `--current-project` 产生参数冲突。当本地索引非空但仅需清理全局主目录资产时，可通过如下指令安全绕过项目选择：

```bash
comet uninstall --scope global --current-project
```

批量卸载会按工程维度逐一汇总回显执行结果。若某个工程内部的受控文件因系统权限受阻未能安全移除，该工程在报告中会如实标红报错并保留索引，不虚夸为已成功完成。

## 清理失效孤儿项目的索引登记

当某个工程的目录在本地已被直接删除后，你可以在任意终端目录下传入原实际路径，安全注销其在全局索引中的残留账本：

```bash
comet uninstall "<已删除项目的原路径>" --scope project --current-project
```

确认后系统仅纯粹剔除索引中的僵尸条目，不尝试向原路径执行任何写操作，亦不波及其他正常在册的项目。`--all-projects` 同样具备清理失效项目索引的能力，但会同时批量处理仍在磁盘上的正常工程；若仅需精准剔除单条失效记录，显式传入原实际路径最为安全。Web 控制台同样提供了可视化的失效条目清理入口，详见 [Dashboard 概览](/zh/dashboard/overview#项目切换与缺失项目)。

<Warning>
  执行 Comet 卸载操作<strong>严格仅移除受 Comet 清单管辖的 Skill 文件、规则规约、Hook 钩子与托管配置切片</strong>。系统不会触碰你的 OpenSpec change 业务文档、架构设计方案、实施拆解计划、验证报告以及业务源码，更不会误删任何无关的第三方开发者 Skill。
</Warning>
