---
title: "comet uninstall"
description: "安全移除 Comet 安装的 Skill、规则和 hooks，同时保留用户自定义配置。"
---

`comet uninstall` 只移除 Comet 托管的文件，并保留你自己的 hooks 与非 Comet 配置。

## 基本用法

```bash
cd your-project
comet uninstall
```

| 选项                | 说明                           |
| ------------------- | ------------------------------ |
| `--force`           | 跳过确认提示                   |
| `--scope <scope>`   | 仅卸载 `project` 或 `global`   |
| `--json`            | 输出 JSON                      |
| `--current-project` | 只卸载当前项目级安装           |
| `--all-projects`    | 卸载项目索引中的所有项目级安装 |

## 示例

交互式卸载：

```bash
comet uninstall
```

仅移除项目级安装：

```bash
comet uninstall --scope project
```

非交互式：

```bash
comet uninstall --force --json
```

批量移除所有已登记的项目级安装：

```bash
comet uninstall --all-projects --force --json
```

## 选择要移除的工作流

如果同一个安装目标同时启用了 Native 和 Classic，交互式卸载会让你选择删除其中一个或两个工作流。只删除其中一个时，另一个工作流和共享配置会继续保留，不需要重装。

选择移除 Classic 时，你还可以单独决定是否连同 OpenSpec 或 Superpowers Skill 一起移除。这两项默认不勾选，目的是避免误删仍在使用的配套能力。自动化模式下（`--force` 或 `--json`）也不会自动移除这些配套 Skill。

## 选择卸载范围

项目索引里有已登记项目时，交互式 `comet uninstall` 会询问只处理当前项目，还是处理所有已登记项目。`--json`、`--force` 或显式 `--current-project` 只处理当前项目；要跨项目卸载，必须显式使用 `--all-projects`。自动化脚本建议始终明确范围参数。

`--all-projects` 不能与 `--scope global` 或 `--current-project` 同时使用。项目索引非空时，如仅卸载全局安装，应显式绕过项目范围选择：

```bash
comet uninstall --scope global --current-project
```

批量卸载会逐项目汇总结果。某个项目的 Comet 文件无法安全移除时，该项目会保留失败状态和索引记录，不会被错误标记为已完成。

<Warning>
  卸载 Comet 只移除 Comet 管理的 Skill、规则、hooks 和配置片段，不会删除你的
  OpenSpec
  change、设计文档、实施计划、验证报告或项目代码，也不会删除无关的第三方 Skill。
</Warning>
