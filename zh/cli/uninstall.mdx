`comet uninstall` 用来移除 Comet 安装的组件，保留你原有的业务代码、自定义 Git Hook 脚本和其他非 Comet 的配置。

## 基本用法

```bash
cd your-project
comet uninstall
```

常用选项：

| 选项 | 说明 |
| --- | --- |
| `--force` | 不询问，直接卸载 |
| `--scope <scope>` | 卸载范围：`project`（当前项目）或 `global`（全局环境） |
| `--json` | 输出结构化的 JSON 结果 |
| `--current-project` | 只卸载当前项目的资产 |
| `--all-projects` | 卸载索引中登记的所有项目 |

## 常用示例

交互式卸载：

```bash
comet uninstall
```

只移除当前项目的资产：

```bash
comet uninstall --scope project
```

脚本里不询问地卸载：

```bash
comet uninstall --force --json
```

批量移除所有已登记的项目：

```bash
comet uninstall --all-projects --force --json
```

## 只卸载其中一套工作流

如果当前项目同时启用了 Native 和 Classic，交互式卸载会让你选择只移除其中一套，还是全部移除。只移除一套时，另一套工作流和共享配置都会保留，不需要重新安装。

移除 Classic 时，系统会单独问你是否连同 OpenSpec 或 Superpowers 的 Skill 一起卸载。这两项默认不勾选，避免误删你在其他地方还在用的工具。非交互模式（`--force` 或 `--json`）下也一样，不会自动删除第三方 Skill。

## 控制卸载范围

全局索引里登记了多个项目时，交互式 `comet uninstall` 会问你是只处理当前项目，还是处理所有已登记的项目。加 `--json`、`--force` 或 `--current-project` 时默认只处理当前项目；要跨项目卸载必须加 `--all-projects`。写脚本时建议始终写明范围。

`--all-projects` 不能与 `--scope global` 或 `--current-project` 一起用。索引非空、但只想清理全局主目录的资产时，用下面的命令跳过项目选择：

```bash
comet uninstall --scope global --current-project
```

批量卸载会按项目分别输出结果。某个项目里的文件因为权限问题删不掉时，报告中会标出这个项目并保留它的索引记录，不会显示成已完成。

## 清理已删除项目的索引

项目目录已经被直接删除后，可以在任意目录下传入它原来的路径，把索引里的记录清掉：

```bash
comet uninstall "<已删除项目的原路径>" --scope project --current-project
```

确认后系统只会删掉索引里的这条记录，不会向原路径写任何东西，也不影响其他正常登记的项目。`--all-projects` 也能清理失效记录，但会同时处理磁盘上仍然存在的项目；只想去掉一条失效记录时，传入原路径更稳妥。Dashboard 里也有清理失效条目的入口，见 [Dashboard 概览](/zh/dashboard/overview#项目切换与缺失项目)。

<Warning>
  卸载<strong>只移除 Comet 清单里的 Skill 文件、规则、Hook 和 Comet 自己写入的配置</strong>。系统不会动你的 OpenSpec 变更文档、设计文档、实施计划、验证报告和业务源码，也不会删除无关的第三方 Skill。
</Warning>
