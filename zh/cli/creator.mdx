日常创作建议在 Agent 对话中直接使用 [Comet Any](/zh/skill-creator/getting-started)。需要查看运行状态、从中断处恢复，或在脚本和 Agent 平台中集成时，使用 `comet creator`。

## 核心子命令

| 命令形式 | 用途 |
| --- | --- |
| `start <name>` | 按目标描述启动一次可恢复的创作流程。 |
| `list` | 列出当前项目的全部创作记录。 |
| `status <name>` | 查看当前运行状态、待执行动作、等待确认项和验收证据。 |
| `next <name>` | 自动推进本地可执行步骤，遇到需要 Agent 执行或用户确认时停下。 |
| `dispatch <name>` | 认领待执行动作、回传执行结果，或提交用户确认决定。 |
| `guide` | 查看首次使用说明、偏好配置指引和中断恢复说明。 |
| `candidates` | 扫描当前项目中可复用的已有 Skill。 |

所有子命令都支持 `--project <dir>` 和 `--json` 参数。

## 启动创作并查看状态

```bash
comet creator start weekly-report --project . --host codex --goal "整理已验收任务，生成周报并检查来源；用户确认后发布本地文件" --install-target .comet/creator/exports/weekly-report --json
comet creator status weekly-report --project . --json
comet creator next weekly-report --project . --json
```

`--host` 指定目标 Agent 平台，可选 `codex` 或 `claude-code`。`--install-target` 指定完整应用包的导出目录，不要填成平台的普通 Skill 入口目录。

可选追加 `--eval-config <file>` 指定评测配置文件。模型 API Key 由本机或 Agent 平台环境变量提供，不会写入配置文件、应用包或评测报告。

## Agent 平台操作与用户确认回传

Agent 平台通过 JSON 请求文件向当前创作流程提交操作：

```bash
comet creator dispatch weekly-report --project . --request request.json --json
```

| 请求操作类型 | 必须携带的字段 |
| --- | --- |
| `claim`（认领动作） | 当前 Run ID、Action ID、执行器 ID、会话标识、`claimToken` 和平台能力清单。 |
| `record-outcome`（回传结果） | 对应动作的认领令牌、输出内容和生成的文件路径。 |
| `resolve-wait`（提交确认） | 当前 Wait ID、方案校验摘要、选项编号和用户决定。 |

调用前先用 `status` 获取最新的版本号和状态，不要猜测 Action 或 Wait ID。代码分析动作由 `creator-host` 执行器运行，目标平台需要具备 `skill-load`（加载 Skill）和 `handoff`（任务交接）能力。

提交用户确认时，所选决定必须在当前 Wait 声明的选项范围内。等待期间如果修改了方案、规则或依赖，旧方案的确认会失效，不能沿用到新版本。

## 中断恢复

`next` 只推进本地已就绪的步骤，不会替 Agent 执行外部操作，也不会代替用户确认。产物缺失或业务校验不通过时，流程按返回的重试、修订或拒绝路径处理；跳过模型 Eval 不会绕过本地检查。

如果动作已派发但结果未回传，先向原执行端核对实际文件和状态，确认后再回传结果。完整流程见 [创作、验收与安装](/zh/skill-creator/workflow)，应用运行与分发见 [comet runtime](/zh/cli/runtime) 和 [comet application](/zh/cli/application)。
