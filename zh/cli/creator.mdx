---

日常创作从 [Comet Any](/zh/skill-creator/getting-started) 开始。`comet creator` 提供同一创作过程的命令行入口，用于状态检查、恢复及宿主集成。

## 子命令

| 命令              | 用途                                     |
| ----------------- | ---------------------------------------- |
| `start <name>`    | 用自然语言目标启动可恢复创作             |
| `list`            | 列出项目中的创作记录                     |
| `status <name>`   | 读取当前 Run、Action、Wait 与证据        |
| `next <name>`     | 执行本地步骤，直到需要宿主动作或用户决定 |
| `dispatch <name>` | 领取动作、回传真实结果或提交当前用户决定 |
| `guide`           | 读取首次使用、偏好与恢复指引             |
| `candidates`      | 调查可用于创作的 Skill 候选              |

子命令支持 `--project <dir>` 与 `--json`。

## 启动并读取状态

```bash
comet creator start weekly-report --project . --host codex --goal "整理已验收任务，生成周报并检查来源；用户确认后发布本地文件" --install-target .comet/creator/exports/weekly-report --json
comet creator status weekly-report --project . --json
comet creator next weekly-report --project . --json
```

`--host` 可选择 `codex` 或 `claude-code`。`--install-target` 是完整应用包的项目内导出目录，不是平台 Skill 入口目录。

可选 `--eval-config <file>` 指向 Eval 配置 JSON。模型凭据来自执行环境，不写入这个配置、包或报告。

## 宿主动作与用户决定

请求保存在 JSON 文件中：

```bash
comet creator dispatch weekly-report --project . --request request.json --json
```

| 请求操作         | 宿主需要保留的事实                                               |
| ---------------- | ---------------------------------------------------------------- |
| `claim`          | 当前 Run、Action、执行端口、真实会话、稳定 claimToken 与实际能力 |
| `record-outcome` | 同一动作与领取凭据、真实结果和实际产物                           |
| `resolve-wait`   | 当前 Wait ID、提案摘要、唯一决定 ID 与实际用户选择               |

先读取 `status` 返回的实际身份与当前状态，不根据创作名称猜测 Action 或 Wait ID。分析动作使用配置的 `creator-host` 端口，并要求实际的 `skill-load`、`handoff` 能力。

审批只能提交当前待处理 Wait 支持的选择。改方案、正文或依赖后，旧提案批准不能继续使用。

## 恢复

`next` 不会替宿主执行未知操作，也不会代替用户批准。缺少必需产物或业务验收失败时，按当前返回的重试、修订或拒绝路径处理；模型 Eval 的 skip 不绕过本地检查。

已经派发但结果未知时，先核对原动作和真实文件，再回报。完整机制见 [创作、验收与安装](/zh/skill-creator/workflow)。应用运行和分发分别使用 [comet runtime](/zh/cli/runtime) 与 [comet application](/zh/cli/application)。
