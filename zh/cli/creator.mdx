title: "comet creator"
description: "查看、恢复和推进 /comet-any Skill Creator 的创建状态。"
---

`comet creator` 是 `/comet-any` 的用户 CLI 表面。它负责列出可恢复的 Skill Creator 流程、查看 readiness、给出唯一下一步，并暴露必要的创作命令。

普通用户仍然从 `/comet-any` 开始。只有流程中断、你想看状态，或需要自动化某一步时，才直接运行 `comet creator`。

## 它和 publish 的区别

| 命令 | 负责什么 | 什么时候用 |
| --- | --- | --- |
| `comet creator` | 创建、恢复、候选解析、方案确认、生成和 authoring lane | `/comet-any` 流程还没进入发布，或你要查下一步 |
| `comet publish` | review、approve、publish、distribute | eval 证据就绪后，准备发布和分发 |
| `comet bundle` | 高级后端 | 审计、排障、平台编译调试 |

推荐主线是：

```text
/comet-any 创建 -> comet eval 验证 -> comet creator status/next -> comet publish review/approve/run -> comet publish distribute --preview -> comet publish distribute
```

## 子命令

| 命令 | 用途 | 必需参数 |
| --- | --- | --- |
| `comet creator list` | 列出可恢复的 Skill Creator candidate | - |
| `comet creator status <name>` | 查看 readiness、blocker、warning 和 evidence | `<name>` |
| `comet creator next <name>` | 打印单个推荐下一步 | `<name>` |
| `comet creator guide` | 查看首次使用向导、偏好和可恢复流程摘要 | - |
| `comet creator candidates` | 发现可用于组合的 Skill 候选 | - |
| `comet creator propose <name>` | 预览 Skill Creator 方案，不写状态 | `<name>`、`--file` |
| `comet creator init <name>` | 用确认后的 plan 初始化或更新状态 | `<name>`、`--file` |
| `comet creator resolve <name>` | 解决缺失或歧义候选 | `<name>`、`--candidate` |
| `comet creator authoring-plan <name>` | 查看生成 Skill 的创作 lane 计划 | `<name>` |
| `comet creator authoring-record <name>` | 记录某个创作 lane 的输出 | `<name>`、`--lane`、`--file` |
| `comet creator generate <name>` | 从已确认 metadata 生成 Skill 包 | `<name>` |

所有子命令都支持 `--project <dir>` 和 `--json`。

## 常用恢复命令

```bash
# 列出可恢复流程
comet creator list --project . --json

# 查看完整状态、readiness 和证据
comet creator status review-helper --project . --json

# 只看下一步该做什么
comet creator next review-helper --project . --json
```

`comet creator next` 的文本输出会包含当前状态、所在阶段、推荐动作、推荐命令、原因，以及这一步是否需要用户确认。

```text
Next step for review-helper
Status: draft
Current step: needs-eval
Action: Run repository eval for the generated Skill
Command: comet eval ./generated-skill/comet/eval.yaml --quick --html
Reason: Current draft hash is missing passing eval evidence
Requires confirmation: no
```

## 方案和生成命令

这些命令通常由 `/comet-any` 在内部调用。你只有在自动化或排障时才需要手工运行。

```bash
# 首次使用向导
comet creator guide --project . --json

# 发现候选 Skill
comet creator candidates --project . --json

# 预览组合方案，不写状态
comet creator propose review-helper --file ./plan.json --json

# 用户确认方案后写入状态
comet creator init review-helper --file ./plan.json --confirmed-proposal --json

# 解决歧义候选
comet creator resolve review-helper --candidate review-flow --source ./skills/review-flow --json

# 忽略缺失候选，需要写明原因
comet creator resolve review-helper --candidate optional-helper --ignore-missing --reason "not needed for this workflow" --json

# 生成 Skill 包
comet creator generate review-helper --json
```

<Warning>
  不要绕过方案确认页直接生成。<code>/comet-any</code> 必须先展示 Skill Creator 方案确认页，等你确认后才写入 draft。
</Warning>

## authoring lane 命令

生成的 Skill 不是薄模板。`/comet-any` 会用 authoring lane 写入口正文、节点指导、脚本契约、参考文件和评审证据。

```bash
# 查看 quick 或 full 创作计划
comet creator authoring-plan review-helper --depth quick --json
comet creator authoring-plan review-helper --depth full --json

# 记录某个 lane 的输出
comet creator authoring-record review-helper --lane skill-core --file ./lane-output.json --json
```

如果生成物里还保留 `AUTHORING PENDING` 标记，readiness 会出现 `[authoring]` blocker。你需要完成对应 lane，并记录输出后再继续 eval 和发布。
