`comet application` 用于管理以 `application.json` 为入口的工作流应用，包括导出应用包、预览安装、分发到各 Agent 平台、升级和卸载。

## 核心子命令

| 命令形式 | 用途 |
| --- | --- |
| `install <file>` | 预览或确认在本地安装当前应用。 |
| `distribute <file>` | 将应用分发并安装到指定的 Agent 平台。 |
| `export <file> <destination>` | 导出包含应用入口和已锁定依赖的完整分发包。 |
| `uninstall <id>` | 预览并移除指定平台的入口，保留其他平台和运行中任务仍需使用的版本。 |

## 先预览再安装或分发

```bash
comet application distribute ./weekly-report/application.json --project . --platform codex --preview --json
```

命令会先检查写入路径、已锁定的依赖、平台能力和文件冲突。确认预览后，带上预览返回的确认摘要（`--confirmation-hash`）执行写入：

```bash
comet application distribute ./weekly-report/application.json --project . --platform codex --confirmation-hash <本次预览确认摘要> --json
```

未提供确认摘要时，命令默认只做预览，不写入文件。只要应用包、目标文件或配置有变化，旧摘要就会失效，需要重新生成预览。

| 选项参数 | 说明 |
| --- | --- |
| `--project <dir>` | 目标项目根目录（默认 `.`）。 |
| `--platform <id>` | 目标平台标识；可重复传入多个平台，或用 `all` 选择全部已登记平台。 |
| `--scope project` | 项目级安装（默认）。 |
| `--scope user` | 用户级安装。 |
| `--user-root <dir>` | 自定义用户级应用存储目录。 |
| `--preview` | 只输出预览报告，不写入文件。 |
| `--confirmation-hash <hash>` | 提交当前预览的确认摘要，允许执行写入。 |
| `--upgrade` | 升级平台入口，同时保留运行中任务正在使用的旧版本。 |
| `--json` | 输出 JSON 格式结果。 |

各 Agent 平台的可用能力以预览检查结果为准。如果预览提示缺少 Hook、需要手动开启权限或无法加载 Skill，先补齐这些配置；文件写入成功不代表应用已验证可用。

## 导出完整应用包

```bash
comet application export ./weekly-report/application.json ./exports/weekly-report --project . --json
```

导出结果包含应用主入口、执行模块和所有已锁定的 Skill 依赖。不要只手动复制单个 `SKILL.md`，也不要直接替换包内文件；修改内容后需要重新生成并确认应用包。

## 选择性卸载

```bash
comet application uninstall weekly-report --project . --platform codex --json
comet application uninstall weekly-report --project . --platform codex --confirmation-hash <本次卸载预览摘要> --json
```

不传 `--platform` 时，默认卸载该应用在全部 Agent 平台上的入口。共享的全局 Rule/Hook、其他应用共用的依赖，以及历史版本都会保留。

卸载中途如果中断，传入相同的平台参数和 `--confirmation-hash` 重试即可继续完成。建议先完成未结束的卸载，再执行全新安装。如果入口文件被手动修改过，先处理冲突再继续卸载，避免误删。

运行时调度见 [comet runtime](/zh/cli/runtime)，创作流程见 [comet creator](/zh/cli/creator)。
