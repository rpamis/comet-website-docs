<Note>
  以 `application.json` 为入口的完整 SDK 应用，由 Agent 平台通过 [comet runtime](/zh/cli/runtime) 调度、用
  [comet application](/zh/cli/application) 安装和分发。本页讲的是单个底层 Skill 包和 Engine 的命令。
</Note>

`comet skill` 用来管理底层 Skill 包和 Engine Run。它可以按显式目录、`.comet/skills/` 下的项目级覆盖或内置 Skill 找到目标，能管理本地 Skill 包，也能查看 Engine Run 的运行状态。

要从零创作可复用的 Skill，用对话里的 [`/comet-any`](/zh/skill-creator/overview)。`comet skill run` 和 `comet skill continue` 适合单步调试 Engine Run。

<Note>
  只想把本地开发的 Skill 引入当前项目时，用 <code>comet skill add</code> 和 <code>comet skill show</code> 就够了。Engine Run 的调试和自检属于进阶用法。
</Note>

## 平台 Skill 与项目 Skill

- **平台 Skill**：由 `comet init` 或 `comet update` 安装到 `.claude/skills/`、`.agents/skills/` 等平台目录，Agent 客户端可以直接把它当斜杠命令用。
- **项目 Skill**：由 `comet skill add` 安装到当前项目的 `.comet/skills/<name>/`，供 Comet Engine 按名称解析依赖，不会出现在客户端的命令列表里。

两者用途不同。日常用 `/comet` 推进变更时，多数情况不需要维护项目 Skill。只有要引入自定义引擎 Skill、用同名覆盖内置 Skill，或单步调试 Engine Run 时，才需要本页的命令。

## 常用操作

| 想做什么 | 命令 | 说明 |
| --- | --- | --- |
| 安装本地 Skill | `comet skill add ./my-skill --project .` | 复制到当前项目的 Skill 目录 |
| 查看 Skill 来源和元数据 | `comet skill show my-skill --project .` | 确认实际加载的是哪个文件 |
| 单步调试一次 Engine Run | `comet skill run my-skill --change ./changes/demo` | 调试用，不是日常创建入口 |
| 继续待处理的动作 | `comet skill continue ...` | 提交外部执行结果，或恢复中断的 Run |
| 触发运行时检查 | `comet skill check ...` | 只检查指定 Run 声明的检查项 |

## 子命令

| 命令 | 作用 |
| --- | --- |
| `comet skill add <path>` | 把本地 Skill 加入当前项目的 Skill 目录 |
| `comet skill show <skill>` | 查看 Skill 的内容、来源和元数据 |
| `comet skill run <skill>` | 启动一次 Engine Run |
| `comet skill continue` | 提交待处理动作的结果，或继续运行 Run |
| `comet skill check` | 检查当前 Run 的运行时检查项 |

所有子命令都支持 `--json`。

## 通用选项

| 选项 | 说明 | 适用子命令 |
| --- | --- | --- |
| `--project <dir>` | 项目根目录，默认为 `.` | 全部 |
| `--json` | 输出结构化的 JSON | 全部 |
| `--overwrite` | 覆盖项目里已有的同名 Skill | `add` |
| `--change <dir>` | 绑定对应的 OpenSpec change 目录（与 `--run-id` 互斥） | `run`、`continue`、`check` |
| `--run-id <id>` | 把运行状态存到 `.comet/runs/<run-id>`（与 `--change` 互斥） | `run`、`continue`、`check` |
| `--confirm <ref>` | 放行受安全守卫保护的敏感动作，可多次传入；输出提示需要确认时，带上对应引用重新运行 | `run`、`continue` |
| `--status <succeeded\|failed>` | 提交动作的最终执行结果 | `continue` |
| `--summary <text>` | 执行结果的文字摘要（指定 `--status` 时必填） | `continue` |
| `--artifact <key=value>` | 提交产物键值对（配合 `--status` 使用） | `continue` |
| `--state <key=value>` | 提交内部状态键值对（配合 `--status` 使用） | `continue` |
| `--upgrade <skill>` | 用新版本 Skill 原地升级当前 Run | `continue` |
| `--scope <progress\|step\|completion>` | 检查范围，默认 `progress` | `check` |

<Info>
  <code>--change</code> 与 <code>--run-id</code> 不能同时使用，一次 Run 只能绑定其中一种。
  <code>--change</code> 绑定某个 OpenSpec change 目录，<code>--run-id</code> 则把状态单独放在 <code>.comet/runs/&lt;run-id&gt;</code> 下。
</Info>

## 管理 Skill 包

### add：添加 Skill

```bash
comet skill add ./my-skill --project .
comet skill add ./my-skill --project . --overwrite
```

命令会把本地 Skill 复制到 `.comet/skills/<name>`，不用软链接，而是先写入临时目录再重命名，并保留备份。项目里的 Skill 以同名方式**覆盖内置 Skill**。如果覆盖包格式不合法，系统直接报错停止，不会退回使用内置版本。

### show：查看元数据

```bash
comet skill show my-skill --project .
```

输出包括 Skill 的名称、契约版本、来源、根目录路径、内容哈希（Hash）、步骤定义（steps）、守卫规则（guardrails）和运行时检查项。

## Skill 的查找顺序

Engine 解析 Skill 时按下面的顺序查找，命中就停止：

1. **explicit（显式指定）**：直接传入已存在的目录路径时，直接加载。路径不存在就报错，不再继续查找。
2. **project（项目内）**：查找 `<projectRoot>/.comet/skills/<selector>`，**优先于内置 Skill**，团队可以用它完全接管同名逻辑。
3. **builtin（内置）**：查找系统内置的 `assets/skills/<selector>`。
4. **都没找到**：按**失败关闭（fail closed）**处理，直接报错，不会自动改用其他来源。

<Warning>
  Skill 名称必须符合正则 <code>^[A-Za-z0-9][A-Za-z0-9._-]*$</code>。用项目 Skill 覆盖内置 Skill 时，如果项目 Skill 本身格式有问题，系统会直接报错，不会降级使用内置版本，避免用了有问题的旧逻辑还不知道。
</Warning>

## Run 的运行过程

### run：启动

```bash
# 绑定某个 OpenSpec change 目录
comet skill run my-skill --change ./changes/demo

# 或指定全局唯一的 run-id
comet skill run my-skill --run-id demo-run --project .
```

启动时 Engine 依次做这些事：

1. 检查并拒绝自适应的变体包（目前还不支持）；
2. 防止重复启动：同一个目录下只允许有一个进行中的 Run；
3. **生成不可变快照**：把 Skill 完整快照存到 `.comet/skill-snapshots/<hash>/`，并把哈希写入 Run 的 `skillHash`；
4. 初始化状态：`currentStep = entry`，`status = running`；
5. 在审计日志里追加 `run_started` 事件；
6. 决定第一步：解析入口步骤、组装第一个动作、经过安全守卫检查，把动作记为待处理（pending action），状态设为 `status = waiting`。

### continue：提交结果或恢复

提交执行结果：

```bash
comet skill continue --change ./changes/demo --status succeeded --summary "Done" --artifact report=report.md
```

```bash
comet skill continue --run-id demo-run --project . --status succeeded --summary "代码已全部实现"
```

只查看状态或让 Engine 重新决定下一步（不带执行结果）：

```bash
comet skill continue --change ./changes/demo
```

把已暂停的 Run 升级到新版 Skill：

```bash
comet skill continue --change ./changes/demo --upgrade my-skill --project .
```

升级有前提条件：当前没有未处理的待处理动作，Skill 包名称一致，编排方式兼容，且当前步骤在新版本中仍然存在。升级成功后，审计日志里会追加 `state_migrated` 事件。

<Warning>
  <code>--upgrade</code> 不能与 <code>--status</code>、<code>--summary</code>、<code>--artifact</code> 或 <code>--state</code> 一起用。<code>--summary</code>、<code>--artifact</code> 和 <code>--state</code> 必须与 <code>--status</code> 一起传。
</Warning>

### check：按需检查

```bash
comet skill check --change ./changes/demo --scope completion
```

```bash
comet skill check --run-id demo-run --project . --scope completion
```

`--scope` 可以是 `progress`、`step` 或 `completion`，默认 `progress`。命令会按 `comet/checks.yaml` 中声明的规则逐项检查。

<Warning>
  <code>comet skill check</code> 只检查某一次 Run 的步骤是否完整，不等于评测 Skill 的整体能力。要评估 Skill 的表现，用 <a href="/zh/cli/eval">comet eval</a>。详见 <a href="/zh/eval/runtime">Runtime check 规范</a>。
</Warning>

## Run 状态存在哪里

Run 的运行状态由 Engine 维护，**不要手动编辑**。只有 `run_id` 会同步到你可以直接读的 `.comet.yaml` 中。

| 模式 | 状态位置 | 特点 |
| --- | --- | --- |
| `change` | `<changeDir>/.comet/` | 绑定 OpenSpec change 目录，一个目录只有一个 Run |
| `standalone` | `<projectRoot>/.comet/runs/<runId>/` | 独立的 Run，用 runId 定位，可以同时存在很多个 |

change 或 run 目录里包含这些文件：

| 文件 | 内容 |
| --- | --- |
| `.comet/run-state.json` | 运行状态：当前步骤、待处理动作、生命周期状态 |
| `.comet/pending-action.json` | 等待 Agent 平台处理的待处理动作详情 |
| `.comet/trajectory.jsonl` | 追加写入的操作审计日志，不要修改 |
| `.comet/context.md` | 当前注入给 Agent 的上下文快照 |
| `.comet/artifacts.json` | 步骤产出的中间结果和最终产物的索引 |

所有文件读写都限制在 change 或 run 目录内，会拦截绝对路径、`~`、Windows 盘符和 `..` 路径穿越。写入时先写临时文件再重命名，避免断电导致文件损坏。

## 终端输出的提示

以文本模式运行 `comet skill` 时，终端末尾会打印当前的 `Pending action` 和下一步 `Next:`。

`run` 的输出示例：

```text
Run: demo-run
Status: paused
Current step: collect-evidence
Pending action: 4f3a9c1d7e2b8056 (tool, step collect-evidence)
Runtime checks: 1
Next: complete the pending action, then run comet skill continue
```

`check` 没通过时，会提示怎么修：

```text
Next: record the missing artifact/state and rerun comet skill check
```
