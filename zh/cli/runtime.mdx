---
title: 'comet runtime'
description: '通过 JSON 请求启动、读取、执行和恢复 SDK 应用的 Run。'
---

`comet runtime dispatch` 接收请求文件并返回结构化结果。宿主可以在不同进程间保留同一个 Run，接着处理当前动作，或继续等待用户决定。

## 调用方式

首次使用完整包：

```bash
comet runtime dispatch --application-file ./local-report/application.json --project-root . --request start.json --json
```

后续使用应用身份和原 Run：

```bash
comet runtime dispatch --application local-report --project-root . --request request.json --json
```

不要把当前应用的 Run 交给另一个应用身份，也不要另建 Run 来重复完成外部操作。

## 常用请求

| operation         | 用途                                    |
| ----------------- | --------------------------------------- |
| `start`           | 固定工作流版本和输入，启动 Run          |
| `inspect`         | 读取保存的状态、动作和等待              |
| `next`            | 根据依赖与当前状态准备下一步            |
| `execute`         | 通过已配置的端口执行当前 pending Action |
| `claim`           | 领取当前动作，交由宿主执行              |
| `record-outcome`  | 回传原动作的实际结果                    |
| `resolve-wait`    | 提交当前审批决定                        |
| `record-evidence` | 提交声明的实际证据                      |
| `retry`           | 在允许的失败恢复路径中重试              |

开始请求包含 `runId`、工作流 `id/version` 与业务 `input`。Action 和 Wait 请求使用读取到的真实身份，不猜测或复用过期提案。

## 执行与等待

```json
{
  "operation": "execute",
  "runId": "<原 Run ID>",
  "actionId": "<当前 pending Action ID>",
  "executorId": "<已配置的执行端口 ID>"
}
```

输出经过 Schema、业务验证器和应用产物契约检查。`completed` 表示声明的执行路径已经走完，还应读取实际业务结果，例如报告可能已发布，也可能沿拒绝分支结束。

## 接入边界

JSON 请求不会自行加载未注册的宿主能力，也不会获取用户授权。凭据由宿主执行上下文提供，不放入请求文件或持久化结果。

外部结果未知时先查询原执行者与外部系统，再根据证据回传或重试。详见 [SDK 恢复](/zh/sdk/recovery)。完整报告样板见 [Workflow Application](/zh/sdk/applications)。
