---
title: 'comet runtime'
description: '通过 JSON 请求启动、查看、推进和恢复 SDK 应用的运行实例（Run）。'
---

`comet runtime dispatch` 接收 JSON 请求并返回执行结果，允许 Agent 平台跨进程继续同一个运行实例（Run）、推进步骤或等待用户确认。

## 调用方式

首次启动时传入应用包路径：

```bash
comet runtime dispatch --application-file ./local-report/application.json --project-root . --request start.json --json
```

后续调用复用已注册的应用标识和原 Run ID：

```bash
comet runtime dispatch --application local-report --project-root . --request request.json --json
```

不要把某个应用的 Run ID 传给另一个应用，也不要新建 Run 重复执行已产生外部副作用的操作。

## 常用操作类型（operation）

| 操作指令 | 说明 |
| --- | --- |
| `start` | 按当前工作流版本和输入参数启动新的 Run。 |
| `inspect` | 读取当前保存的状态、待执行动作和等待确认项。 |
| `next` | 按步骤依赖计算下一步待执行动作。 |
| `execute` | 通过已配置的执行器运行当前待执行动作。 |
| `claim` | 认领当前动作，交由指定 Agent 平台执行。 |
| `record-outcome` | 回传外部动作的执行结果和状态。 |
| `resolve-wait` | 提交当前等待确认项的用户决定。 |
| `record-evidence` | 提交步骤声明的测试或执行证据。 |
| `retry` | 按流程允许的恢复路径重试失败步骤。 |

启动请求中需要包含 `runId`、工作流 `id/version` 和输入参数 `input`。推进 Action 或提交 Wait 决定时，必须使用 `inspect` 返回的最新 ID，不要猜测或复用过期方案。

## 动作执行与结果校验

执行指令示例如下：

```json
{
  "operation": "execute",
  "runId": "<原 Run ID>",
  "actionId": "<当前待执行 Action ID>",
  "executorId": "<已配置的执行器 ID>"
}
```

所有输出都会经过 Schema、业务验证器和产物约束检查。状态显示 `completed` 仅代表已按声明的分支执行结束，仍需检查实际业务结果（例如任务可能是沿拒绝分支正常结束，而非已发布）。

## 安全与恢复边界

JSON 请求本身不会加载未注册的平台能力，也不会绕过权限检查。敏感凭据应由 Agent 平台环境提供，不要写进请求文件，也不会保存到运行状态中。

调用外部服务后如果结果未回传，先向原执行端或外部系统核对状态，确认后再补传证据或重试。详见 [SDK 恢复协议](/zh/sdk/recovery) 和 [Workflow Application 指南](/zh/sdk/applications)。
