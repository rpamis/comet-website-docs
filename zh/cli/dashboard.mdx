`comet dashboard` 在本机启动一个浏览器控制台。

侧边栏可以切换 Classic、Native、Comet Any、Eval、个人记忆和项目知识六个工作区；顶部可以切换多个项目、手动刷新和切换语言；在 **设置 → 外观** 里可以改浅色/深色主题和字号。

查看工作流是只读的，不会推进阶段或修改 change；在知识管理里编辑个人记忆和项目知识卡片时，改动会保存到对应的存储。

<Info>
  本页是 <code>comet dashboard</code> 的命令行参考。想了解界面布局、产物分类和截图，见 <a href="/zh/dashboard/overview">Dashboard 总览</a>。
</Info>

## 快速上手

在项目根目录运行：

```bash
comet dashboard
```

默认在 `http://localhost:4321` 启动服务，并自动打开浏览器。终端会输出：

```text
Comet Dashboard running at http://localhost:4321
Press Ctrl+C to stop.
```

按 `Ctrl + C` 停止服务。

## 命令行参数

```bash
comet dashboard [path] [options]
```

| 选项 | 说明 |
| --- | --- |
| `[path]` | 项目路径，默认为当前目录 `.` |
| `--port <port>` | 监听端口，默认 `4321`；端口被占用时自动往后找 |
| `--no-open` | 只启动服务，不打开浏览器 |
| `--json` | 只在终端打印一次当前项目的 JSON 快照后退出，不启动服务 |

<Info>
  <code>--port</code> 指定的端口被占用时，系统会往后找下一个可用端口，最多试 50 次。传 <code>--port 0</code> 由操作系统分配一个空闲端口。端口必须是 0–65535 之间的整数。
</Info>

### 脚本和远程调试

在 CI/CD 里不需要常驻服务，只打印一次 JSON 快照：

```bash
comet dashboard . --json
```

在远程开发机上（如 SSH 或 VS Code Remote），指定端口并且不打开浏览器：

```bash
comet dashboard . --port 4399 --no-open
```

## Comet Any 与 Eval

Comet Any 模块按阶段展示创作过程和应用安装情况，可以查看每一步的动作、方案决定、重试次数、阶段产物和三类验证证据；查看过程不会推进 Runtime。Eval 模块可以启动评测、用甘特图看进度、读日志、重跑失败的用例，以及维护基准结果。用法见 [Dashboard 总览](/zh/dashboard/overview)。

## 数据来源

Classic 工作区按 `classic.artifact_layout` 的配置读取 `docs/openspec/changes/` 或旧版的 `openspec/changes/`，并从对应的 `changes/archive/` 读取已归档的变更。Native 工作区按 `.comet/config.yaml` 里配置的 Native 产物根目录读取。

两条数据链路都只读，互不影响：例如 Native 数据读取出错时，Classic 的状态仍能正常显示。界面一次只显示一套工作流，切换视图不会改变项目状态。

Changes 列表分页加载，选中某条记录后才读取完整的大文档。读取大文件时界面不会跳动，失败时提供重试入口；项目很大时向下滚动会自动加载更早的页面。

### 识别已登记的 Git worktree

Dashboard 会扫描当前 Git 仓库登记的所有 worktree，把每个 worktree 当作独立的变更来源。列表会标出对应的分支名或 worktree 路径，其他目录里的 change 不会被算到当前目录下。

```bash
comet dashboard .
```

Native 视图里，相互独立的 change 是顶层条目；Supervisor 复合任务可以展开成树，查看每个子任务的状态、所属分支和完成比例。点击父级或子任务，右侧会显示详情，整个过程只读。

### Native 变更看板

Native 工作区可以按“活跃 / 已归档 / 全部”筛选。数据来自 Native Runtime、归档预检和冲突检测：

- 当前阶段：Shape / Build / Verify / Archive
- 验证证据是否最新、是否满足归档条件
- continuation 中的下一步，以及是否在等你决定
- 自动检测到的问题和可疑代码（finding code）
- 可能存在的业务语义冲突和相关联的变更
- 需求简报、能力 Spec 和验证报告的 Markdown 预览
- 最近的检查点、下一步动作和执行时间线
- capability 的改动范围、验收项覆盖情况和代码改动关系
- 缺陷修复状态与当前工作区的 Git 状态

Native 面板只展示与交付相关的证据，不暴露内部的哈希值、Runtime 路径或未过滤的二进制日志；只读面板不提供修改状态或强制归档的按钮。所有写操作和阶段推进都由 `comet native` 命令完成。

指定 `--json` 时，如果当前项目启用了 Native 工作流，输出里会包含结构为 `comet.dashboard.native.v2` 的 `native` 字段。

### Classic 变更看板

布局上的几个特点：

- 窄屏下展开左侧列表，中间内容仍限制在浏览器视口内，不会横向溢出。
- 展开或关闭产物预览时会记住原来的滚动位置，连续看多份报告不用反复上下找。
- 已归档的 change 显示为完成状态，不会给出“重新验证”这类无意义的建议。
- 归档变更引用的设计文档、实施计划和验证报告会从项目根目录的 `docs/superpowers/` 中查找，随时可以在线查看。

#### 项目信息

- 项目名称、绝对路径、状态生成时间；
- 统计：进行中的 change 数、已归档数、verify 失败数、未完成任务数、工作区未提交文件数；
- Git 状态：当前分支、HEAD 哈希、未提交文件列表和最近的提交。

#### 变更信息

- 变更名称、状态（活跃/归档）、存储路径、最近更新时间；
- 工作流类型和当前**阶段**（open/design/build/verify/archive），用甘特条显示；
- 任务完成情况（已完成/总数、待办清单、各章节进度），用环形图显示；
- 产物按**来源**分组（OpenSpec / Superpowers / Comet），并标注状态（已就绪 / 未就绪 / 无需生成）；
- 核心产物是否齐全（proposal、design、tasks、plan、verifyReport、cometYaml），支持在线预览（单文件最大 256 KiB，显示文件大小和时间）；
- 验证结果（pending/pass/fail/unknown）和摘要；
- **下一步建议**（仅活跃 change）：建议的命令和判断依据；
- 风险项列表，按 info/warning/error 分级，并给出可执行的处理建议。

#### 常见风险码

| 风险码 | 原因 |
| --- | --- |
| `MISSING_COMET_YAML` | change 目录下缺少 `.comet.yaml` 状态文件 |
| `UNKNOWN_PHASE` | 阶段字段损坏，无法识别当前阶段 |
| `TASKS_MISSING` | 缺少 `tasks.md` 任务清单 |
| `TASKS_INCOMPLETE` | 任务清单里还有没勾选的项 |
| `VERIFY_FAILED` | 验收没通过，有失败的测试 |
| `VERIFY_PENDING` | 代码已提交，但还没跑完 Verify |
| `ARTIFACT_MISSING` | 缺少进入下一阶段必需的文件 |
| `ARCHIVE_METADATA_MISSING` | 归档元数据或时间记录不完整 |
| `GIT_DIRTY` | （项目级）工作区有未提交的改动 |

## 自动刷新与主题

界面每 **30 秒**自动刷新一次，也可以点顶部按钮手动刷新。支持按名称搜索变更，并提供活跃、已归档、全部的快速切换。产物预览使用经过安全过滤的 Markdown 渲染。

点 **设置 → 外观** 可以切换浅色或深色主题。第一次访问时跟随系统设置，手动选择后立即生效，并在当前浏览器里跨项目记住；同一页面还能调整全局字号。详见 [Dashboard 总览 · 产物、刷新与更新](/zh/dashboard/overview#产物、刷新与更新)。

## 演示模式

在访问地址后加 `?demo` 会载入内置的演示数据，不读取本地项目：

```text
http://localhost:4321/?demo
```

## 安全设计

- 服务只绑定本机环回地址 `127.0.0.1`，不向局域网或公网开放端口。
- 静态资源服务做了路径穿越（Directory Traversal）防护。
- 产物在线预览单文件上限 256 KiB，超出部分标记为 `truncated` 折叠显示。
- 展开和关闭产物预览时会保持滚动位置，关闭后回到原来查看的位置。
