`comet dashboard` 启动一个**本地只读**的浏览器仪表盘。它在同一个快照中提供 Classic/OpenSpec 与 Native 数据，并通过左上角的工作流选项互斥显示两个工作区。

它**只读**，不会修改任何文件，可以随时安全启动。

## 快速开始

在含有change的项目根目录运行：

```bash
comet dashboard
```

默认会在 `http://localhost:4321` 启动并自动打开浏览器。终端会显示：

```text
Comet Dashboard running at http://localhost:4321
Press Ctrl+C to stop.
```

## 命令选项

```bash
comet dashboard [path] [options]
```

| 选项            | 说明                                       |
| --------------- | ------------------------------------------ |
| `[path]`        | 项目路径（默认 `.`）                       |
| `--port <port>` | HTTP 端口（默认 `4321`，被占用时自动递增） |
| `--no-open`     | 不自动打开浏览器                           |
| `--json`        | 打印一次快照后退出（不启动服务器）         |

<Info>
  <code>--port</code> 被占用时会自动向上找可用端口（最多重试 50 次）。<code>--port 0</code>{' '}
  让系统自动分配。端口必须是 0–65535 的整数，否则报错。
</Info>

### 脚本 / CI 用法

不启动服务器，只打印一次 JSON 快照：

```bash
comet dashboard . --json
```

指定端口且不自动打开（适合远程开发）：

```bash
comet dashboard . --port 4399 --no-open
```

## 仪表盘能看到什么

Classic 工作区依据 `classic.artifact_layout` 读取 `docs/openspec/changes/` 或保留旧布局的 `openspec/changes/`，并从对应的 `changes/archive/` 读取归档 change。Native 工作区依据 `.comet/config.yaml` 读取配置的 Native artifact root。两部分都**只读、尽力而为**；Native 采集失败不会阻止 Classic 快照返回。浏览器中一次只显示所选工作流，切换不会改变项目状态。

### Native change

Native 工作区通过“活跃 / 已归档 / 全部”筛选显示 change。状态数据直接来自 Native Runtime 的 projection、归档预检和冲突雷达：

- phase：Shape / Build / Verify / Archive
- 验证证据新鲜度与归档就绪状态
- continuation 状态与是否需要用户决定
- 结构化 finding code
- 明确冲突与可能重叠的关联 change
- 需求简报、变更 Spec 和验证报告的 Markdown 预览
- 最近 checkpoint、下一步动作与进展时间
- capability 变更范围、Acceptance 覆盖和实现范围汇总
- Repair 状态与项目 Git 摘要

单次快照最多显示 32 个 Native change；每个 change 最多显示 8 个 finding code、8 个冲突关联、8 个 capability 和 8 个用户产物。Native 工作区只投影 checkpoint 与 evidence 的有界汇总，不会暴露 hash、Runtime 路径、原始 evidence 或其他内部状态文件，也不提供推进、修复和归档按钮。完整信息和写操作请使用 [Native CLI](/zh/cli/native)。

使用 `--json` 时，同一快照会在可用时包含 schema 为 `comet.dashboard.native.v1` 的 `native` 字段；项目未启用 Native 时省略该字段。

### Classic change

0.4.0-beta.4 对日常查看体验做了以下调整：

- 左侧 Changes Explorer 显示时，中间 change 工作区仍限制在浏览器视口内，不会把页面横向撑出屏幕。
- 打开或关闭 artifact preview 会保留原列表的滚动位置，连续检查多个产物时不必反复定位。
- 已归档 change 显示为完成状态，不再建议重新进入 verify。
- 归档 change 引用的 Design Doc、Plan 和验证报告会从项目根的 `docs/superpowers/` 正确解析，归档后仍可预览。

#### 项目级信息

- 项目名称、路径、生成时间
- 汇总：活跃 change 数、归档数、verify 失败数、任务未完成数、脏文件数
- Git 快照：分支、HEAD、脏文件列表、最近提交

#### 每个 change

- 名称、状态（活跃/归档）、路径、更新时间
- 工作流和**阶段**（open/design/build/verify/archive）——以生命周期步进条展示
- 任务完成度（completed/total、未完成项、各 section）——以环形图展示
- artifact **按来源分组**（OpenSpec / Superpowers / Comet），每组内显示存在性状态（已生成/未生成/无需生成）
- artifact 存在性（proposal、design、tasks、plan、verifyReport、cometYaml）+ 内容预览（最大 256 KiB，含文件大小和更新时间元数据）
- verify 结果（pending/pass/fail/unknown）和摘要
- **下一步**（仅活跃 change）：推荐的 slash 命令和原因
- 风险项（info/warning/error 级别 + 恢复建议）

#### 风险码

| 风险码                     | 含义                         |
| -------------------------- | ---------------------------- |
| `MISSING_COMET_YAML`       | change 缺少 `.comet.yaml`    |
| `UNKNOWN_PHASE`            | 阶段无法识别                 |
| `TASKS_MISSING`            | 缺少 tasks 文件              |
| `TASKS_INCOMPLETE`         | 任务未完成                   |
| `VERIFY_FAILED`            | verify 失败                  |
| `VERIFY_PENDING`           | verify 待跑                  |
| `ARTIFACT_MISSING`         | 缺少关键 artifact            |
| `ARCHIVE_METADATA_MISSING` | 归档元数据缺失               |
| `GIT_DIRTY`                | （项目级）工作区有未提交改动 |

## 自动刷新与主题

前端每 **30 秒**自动刷新一次，也有手动刷新按钮、搜索框和标签页（活跃/归档/全部）。artifact 抽屉带一个简易 Markdown 渲染器。

顶部工具栏右侧有**亮色/暗色主题切换**按钮：首次访问按系统偏好（`prefers-color-scheme`）选择，手动切换后持久化到 `localStorage`。详见 [Dashboard 总览 · 主题切换](/zh/dashboard/overview#主题切换：亮色-暗色)。

## 演示模式

在 URL 加 `?demo` 可以加载演示数据（不读真实 change），方便预览界面：

```text
http://localhost:4321/?demo
```

## 安全

- 服务器只绑定 `127.0.0.1`（localhost），不对外暴露。
- 静态文件服务有路径穿越防护。
- artifact 预览有大小限制（256 KiB，超出标记 `truncated`）。
- artifact 抽屉打开时保留页面滚动位置；关闭后回到打开前的位置。
