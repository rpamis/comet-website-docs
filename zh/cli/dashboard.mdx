`comet dashboard` 用于一键启动本机的浏览器可视化控制台。

你可以通过侧边栏切换 Classic、Native、Comet Any、评估 Eval、个人记忆与项目知识六大工作区；顶部支持多项目切换、即时刷新与多语言，在 **设置 → 外观** 中可定制浅色/深色主题与字体大小。

查阅工作流严格保持只读，绝不会擅自推进状态机或篡改 Change；在知识管理模块中在线编辑个人记忆与项目知识卡片，则会精准持久化更新底层的物理存储。

<Info>
  本页属于 <code>comet dashboard</code> 的命令行调用参考。若想全面了解控制台的视觉布局、产物归类逻辑、任务环形图及完整截图，请参阅 <a href="/zh/dashboard/overview">Dashboard 全景总览</a>。
</Info>

## 快速上手

在包含变更的项目根目录下执行：

```bash
comet dashboard
```

默认会在本地 `http://localhost:4321` 启动服务并自动弹出系统默认浏览器。终端将清晰打印：

```text
Comet Dashboard running at http://localhost:4321
Press Ctrl+C to stop.
```

敲击 `Ctrl + C` 即可随时安全终止本地 Web 服务。

## 命令行参数一览

```bash
comet dashboard [path] [options]
```

| 选项参数 | 说明 |
| --- | --- |
| `[path]` | 指定目标项目物理路径（默认使用当前目录 `.`） |
| `--port <port>` | 指定 HTTP 监听端口（默认为 `4321`；若端口被占用会自动递增寻址） |
| `--no-open` | 仅启动后台 Web 服务，禁止自动弹出系统浏览器 |
| `--json` | 仅在终端打印一次当前项目的状态 JSON 快照并即刻退出（不启动 Web 服务器） |

<Info>
  当 <code>--port</code> 指定的端口已被其他程序占用时，系统会自动向上寻找下一个可用端口（最多重试 50 次）。传入 <code>--port 0</code> 则允许操作系统完全动态分配空闲端口。端口参数必须为 0–65535 范围内的有效整数。
</Info>

### 脚本与远程调试用法

在 CI/CD 流水线中，无需启动常驻服务，仅打印一次格式化 JSON 快照：

```bash
comet dashboard . --json
```

在远程开发机（如 SSH 或 VS Code Remote）中，指定固定端口且静默启动：

```bash
comet dashboard . --port 4399 --no-open
```

## Comet Any 与 Eval 评测体系

Comet Any 模块清晰分层呈现全生命周期创作轨迹与固化的生产应用流水，可深度透视原子步骤、架构决议、执行重试轮次、阶段产物以及三类权威验证证据；观测过程绝不越权强推底层 Runtime。Eval 模块支持在线拉起评测执行、全景追踪进度甘特图、查阅详细日志报告、一键重跑失败用例并维护全局基准线。详细使用技巧请参考 [Dashboard 全景总览](/zh/dashboard/overview)。

## 控制台透视能力与数据拓扑

Classic 工作区严格依循 `classic.artifact_layout` 配置解析 `docs/openspec/changes/` 或旧版 `openspec/changes/`，并从对应的 `changes/archive/` 载入已归档变更。Native 工作区则依照 `.comet/config.yaml` 中绑定的 Native 产物根目录读取数据。

两条数据链路均以纯只读模式进行非侵入式采集，且容错相互隔离：例如即使本地 Native 数据采集发生抖动，Classic 的状态快照依然能够正常回显。界面单次聚焦呈现单一工作流视图，切换视图绝不会对项目物理状态产生任何副作用。

Changes 资源管理器默认按页轻量加载变更列表，唯有在选中特定条目后方拉取完整的底层大文档。在加载大体积详情期间，前端会稳妥保持当前视图不闪烁，若读取失败提供重试入口；项目规模庞大时平滑向下滚动即可自动加载历史页。

### 自动识别登记的 Git worktree

Dashboard 会自动扫描当前 Git 仓库登记的所有 worktree，并将每个物理 worktree 作为完全独立的变更来源予以呈现。列表中会醒目标记对应的 Git 分支名或 worktree 绝对路径，来自外部隔离目录的 Change 绝不会被错位归入当前主目录中。

```bash
comet dashboard .
```

在 Native 视图下，平行的独立 Change 展现为顶层根条目；Supervisor 复合任务支持一键展开折叠树，层级化透视各子任务（child）的实时状态机、分支归属与完工百分比。点击父级复合变更或具体子任务均可在右侧展开专属详情，全链路严格保持只读。

### Native 变更看板

Native 工作区支持通过“活跃 / 已归档 / 全部”三态维度筛选变更。所有指标直接由 Native Runtime 状态聚合器、归档预检模块及冲突检测中枢提供权威支撑：

- 核心阶段展示：Shape / Build / Verify / Archive
- 验证客观证据链新鲜度与归档准入就绪态
- continuation 调度水位及是否亟需人工介入裁决
- 结构化的自动化代码异味与隐患代码（finding code）
- 潜在的业务语义冲突与关联重叠变更告警
- 需求简报、系统能力 Spec 及验证报告的高清 Markdown 预览
- 最近断点检查点（checkpoint）、下一步行动指令与执行时间线
- Capability 变更范围、验收用例覆盖矩阵与代码改动拓扑
- 缺陷修复状态与当前工作区 Git 物理状态摘要

Native 面板仅提炼展示面向业务交付的关键证据汇总，绝不直接对外暴露内部敏感哈希值、私有 Runtime 物理路径或未清洗的二进制流水，亦严禁在只读面板上越权提供直接篡改状态或强行归档的操作按钮。一切写操作与阶段流转均由命令行 `comet native` 完成。

在指定 `--json` 参数时，若当前项目激活了 Native 工作流，输出的数据包中会自动包含契约为 `comet.dashboard.native.v2` 的 `native` 属性块。

### Classic 变更看板

经典模式的排版特性如下：

- 即使在窄屏下展开左侧资源列表，中间内容区依然严格自适应约束在浏览器视口内，绝不发生横向异常溢出。
- 展开或关闭产物抽屉预览时，前端完整锁定原列表的滚动进度，连续审查多份报告无需反复上下翻找。
- 已归档的历史 change 明确呈现为完工终态，绝不给出重复进入验证等无意义建议。
- 归档变更所引用的 Design Doc 设计方案、实施 Plan 及验证报告均能从项目根目录的 `docs/superpowers/` 中精准逆向解析，永久支持在线完整查阅。

#### 项目级宏观信息

- 项目名称、物理绝对路径、状态生成时间戳；
- 统计大盘：活跃 change 数、历史归档总数、verify 失败报警数、待办任务缺口及工作区脏文件计数；
- Git 实时快照：当前分支、HEAD 哈希、未提交脏文件列表与最近提交日志。

#### 变更级微观信息

- 变更名称、生命周期状态（活跃/归档）、存储路径、最近更新时间；
- 工作流类型与核心**阶段**（open/design/build/verify/archive）——以直观的甘特步进条呈现；
- 任务执行达标率（已完成数/总数、待办项清单、分章节进度）——以可视化环形图渲染；
- 产物按**物理来源结构化分组**（OpenSpec / Superpowers / Comet），各组清晰展示状态标记（已就绪/未就绪/无需生成）；
- 核心产物完备度（涵盖 proposal、design、tasks、plan、verifyReport、cometYaml）并支持在线实时预览（单文件最大放宽至 256 KiB，附带文件体积与时间戳）；
- 验证裁决终态（pending/pass/fail/unknown）及精炼摘要；
- **下一步行动指引**（仅限活跃 change）：推荐的 Slash 触发命令与判定依据；
- 风险项诊断大盘（依 info/warning/error 级别分类展示，并附带可执行自愈建议）。

#### 常见风险码速查

| 风险码 | 核心诱因与排障定性 |
| --- | --- |
| `MISSING_COMET_YAML` | 该 change 目录下丢失了核心的 `.comet.yaml` 状态机文件 |
| `UNKNOWN_PHASE` | 阶段字段损坏，当前所处阶段无法被状态机识别 |
| `TASKS_MISSING` | 缺失关键的 `tasks.md` 实施任务拆解文档 |
| `TASKS_INCOMPLETE` | 任务清单中尚存未勾选通过的未竟项 |
| `VERIFY_FAILED` | 阶段验收未通过，存在失败测试项 |
| `VERIFY_PENDING` | 代码实现已提交，但尚未跑通最终 Verify 验收 |
| `ARTIFACT_MISSING` | 缺失流程准入所必需的关键技术产物 |
| `ARCHIVE_METADATA_MISSING` | 归档元数据或时间戳索引不完整 |
| `GIT_DIRTY` | （项目级）当前工作区存在尚未提交的散落代码改动 |

## 自动静默同步与多主题配置

前端每隔 **30 秒**自动静默拉取一次最新数据，并支持点击顶部手动刷新按钮。支持按关键词全文检索变更名称，并提供活跃、已归档及全量的快速 Tab 切换。产物抽屉内置经过安全清洗的高性能 Markdown 渲染引擎。

点击 **设置 → 外观**，即可在可视化主题卡片中自由切换浅色或深色主题。首次访问自动遵循操作系统的系统偏好，手动选择后即刻生效，并在当前浏览器中跨项目持久封存；同页面还支持平滑缩放全局字体大小。详见 [Dashboard 全景总览 · 产物、刷新与更新](/zh/dashboard/overview#产物、刷新与更新)。

## 独立演示沙盒模式

在本地访问地址后追加 `?demo` 即可无感载入内置的标准演示样本数据（完全不触碰本地真实业务代码），便于对外展示或体验交互：

```text
http://localhost:4321/?demo
```

## 安全设计

- 本地服务器严格且仅绑定于本机环回地址 `127.0.0.1`（localhost），绝不向局域网或公网私自暴露端口。
- 内置静态资源分发服务具备坚固的路径穿越（Directory Traversal）攻击防护。
- 产物在线预览设有单文件 256 KiB 的安全防爆上限（超出部分友好标记为 `truncated` 折叠展示）。
- 产物抽屉展开与关闭实行严密的视口视差保护，关闭后精准归位至点击前的原始浏览行，杜绝跳动。
