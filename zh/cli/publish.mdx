---
title: 'comet publish'
description: '把关、正式批准、发布固化及分发由 /comet-any 生成的 Skill 发布候选制品（Publish Candidate）。'
---

`comet publish` 统领 Skill Bundle 的质量评审、人工核准、正式发布与多平台分发。完整 SDK 工作流应用请使用 [comet application](/zh/cli/application)；若发布目标为 `application.json`，请勿套用本页的 Bundle 指令流。

<Info>
  <code>comet publish</code> 是面向日常发布交付推荐的高级命令，高度精简了繁琐参数并自带端到端的就绪门禁检查；而 <code>comet bundle</code> 则提供偏底层的裸机包编译能力，主要服务于深度安全审计或底层排障。
</Info>

## 核心子命令

| 命令形式 | 核心用途与能力 | 必填核心参数 |
| --- | --- | --- |
| `comet publish review <name>` | 生成面向发版前的多维就绪度评审摘要大盘 | `<name>`、`--platform` |
| `comet publish approve <name>` | 针对当前哈希快照的候选制品签署人工批准授权 | `<name>`、`--reviewer` |
| `comet publish run <name>` | 将已获批准的候选制品正式固化发布为不可变 Bundle | `<name>`、`--platform` |
| `comet publish distribute <name>` | 将已发布的 Bundle 安全分发并部署至指定 Agent 平台 | `<name>`、`--platform` |

全量子命令均原生支持追加 `--json` 输出结构化数据。

<Note>
  <code>comet publish</code> 刻意未设立 reject 子命令。<code>approve</code> 是面向人类开发者唯一的核准授权入口，内部会自动写入标准已核准（approved）审计账本。若确需正式驳回，请调用底层高级命令 <code>comet bundle review &lt;name&gt; --reject --reviewer &lt;name&gt;</code>。
</Note>

标准的发布生命周期严格依照 `review（评审）` → `approve（批准）` → `run（固化）` → `distribute（分发）` 四步推进。客观评测得分、源码快照指纹与目标 Agent 平台的能力要求共同裁决 Bundle 是否达到就绪（Readiness）标准。

## 端到端实战完整用例

```bash
# 1. 深度查验全景就绪状态（Readiness）与潜在阻塞项
comet creator status review-helper --project . --json

# 2. 探查当前推荐执行的下一步动作
comet creator next review-helper --project . --json

# 3. 编译并生成目标平台的预发布评审摘要大盘
comet publish review review-helper --platform claude --json

# 4. 人工正式签署发版授权
comet publish approve review-helper --reviewer alice --json

# 5. 正式固化发布已获批的候选制品
comet publish run review-helper --platform claude --json

# 6. 安全分发预演（强制前置门禁）
comet publish distribute review-helper --platform claude --scope project --preview --json

# 7. 执行分发
comet publish distribute review-helper --platform claude --scope project --json
```

## 通用选项参数

| 选项参数 | 详细语义与影响 |
| --- | --- |
| `--project <dir>` | 指定目标项目根目录（默认值为 `.` 当前工作区） |
| `--json` | 输出机器可读的标准结构化 JSON 报文 |
| `--platform <id>` | 目标 Agent 平台标识符（支持多次指定绑定多个平台） |
| `--scope <project\|global>` | 分发生效范围（项目局部或全局用户主目录） |
| `--reviewer <name>` | 签署审批责任人的唯一名称标识（执行 `approve` 时为必填项） |
| `--locale <locale>` | 指定发布制品的语言区域偏好 |
| `--overwrite` | 强制覆写已存在的历史发布候选（用于 `run`）或已有分发（用于 `distribute`） |
| `--preview` | 纯只读拉取分发预览报告，不执行写操作 |
| `--confirm-executables` | 显式放行对包内可执行脚本或 Hook 的安全权限披露 |
| `--skip-capability <cap>` | 显式跳过可选（optional）扩展能力（支持多次传入） |

## 仅探查下一步动作：comet creator next

`comet creator status` 会输出详尽的底层状态机大盘。若你**仅希望快速获悉当下该敲哪条命令**，可直接运行 `comet creator next`，系统会智能推导并直接组装好下一步推荐命令，完全无需开发者翻阅复杂的底层数据：

```bash
comet creator next review-helper --project . --json
```

终端文本回显直观精炼：

```text
Next step for review-helper
Status: draft
Current step: review
Action: request-review
Command: comet publish review review-helper --platform claude --json
Reason: Current draft hash is missing review approval
Requires confirmation: yes
```

追加 `--json` 参数时，将返回面向脚本消费的结构化契约：

| 契约字段 | 核心业务语义 |
| --- | --- |
| `status` / `currentStep` | 当前候选制品的生命周期状态及所处步骤 |
| `nextStep.action` / `nextStep.label` | 建议触发动作的规范分类及人类可读标签 |
| `nextStep.command` | **已填好完整参数、可直接在终端粘贴执行的命令** |
| `nextStep.reason` | 系统做出该项调度的核心推导依据 |
| `nextStep.requiresUserConfirmation` | 标明该动作是否属于必须由人类确认的敏感节点（如审批、分发） |
| `preferenceDrift.changed` | 标明项目的 Skill 偏好规则在本次流程启动后是否发生了意外漂移 |

<Tip>
  <code>comet creator next</code> 专为遭遇外部打断的 <code>/comet-any</code> 流程自愈而生：它将底层状态机的内部动作映射为一条即开即用的标准指令。若检测到<strong>偏好漂移</strong>（<code>preferenceDrift.changed === true</code>），在 <code>advisory</code> 建议模式下会给出警告，而在 <code>strict</code> 严格模式下则会直接阻断推进，由开发者抉择是继续旧方案还是重新生成。
</Tip>

## 强安全红线：分发预览为必经前置门禁

正式分发前，**必须先跑通预览（preview）**：

```bash
comet publish distribute review-helper --platform claude --scope project --preview --json
```

预览报告会详尽披露：

- 拟部署文件的详细清单及目标实际路径；
- 目标平台不受支持的能力项列表；
- 潜在的可执行脚本安全披露；
- 明确标注 `No files were written`（未写入任何文件）。

只有在开发者充分审查预览结论后，才可移除 `--preview` 标志执行真实的分发。

## 处理可执行脚本披露与能力代沟

若目标平台涉及加载外部 Hook 或本地 Shell 脚本等敏感可执行能力，必须显式追加确认：

```bash
comet publish distribute review-helper --platform claude --scope project --confirm-executables --json
```

若目标平台缺失某些可选特性，且开发者明确确认放弃这些增强能力：

```bash
comet publish distribute review-helper --platform claude --scope project --skip-capability <capability> --json
```

| 平台能力类型 | 缺失代沟处置准则 |
| --- | --- |
| 必需能力（required）缺口 | **直接取消在该平台上的分发**，禁止强行跳过 |
| 可选能力（optional）缺口 | 必须由开发者在命令行中**显式声明跳过（skip）** |
| Hook 与脚本执行披露 | 必须由开发者**明确授权确认**后方被允许分发落地 |

包内的 `hooks/*.yaml` 遵循 **Comet portable hook descriptor（可移植 Hook 描述符规范）**，在 `comet publish distribute` 编译并映射至目标平台的原生配置后方正式激活生效。
