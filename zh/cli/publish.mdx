---
title: 'comet publish'
description: '评审、批准、发布并分发 /comet-any 生成的 Skill 发布候选（Publish Candidate）。'
---

`comet publish` 负责 Skill Bundle 的评审、批准、发布和分发。完整的 SDK 工作流应用请用 [comet application](/zh/cli/application)；如果发布目标是 `application.json`，不要照搬本页的 Bundle 命令。

<Info>
  <code>comet publish</code> 是日常发布用的命令，参数比底层命令少，自带发布前的检查；<code>comet bundle</code> 提供底层的包编译能力，主要用于安全审计和排查编译问题。
</Info>

## 子命令

| 命令 | 作用 | 必填参数 |
| --- | --- | --- |
| `comet publish review <name>` | 生成发布前的评审摘要 | `<name>`、`--platform` |
| `comet publish approve <name>` | 对当前哈希对应的候选签署批准 | `<name>`、`--reviewer` |
| `comet publish run <name>` | 把已批准的候选发布为不可变的 Bundle | `<name>`、`--platform` |
| `comet publish distribute <name>` | 把已发布的 Bundle 分发到指定 Agent 平台 | `<name>`、`--platform` |

所有子命令都支持 `--json`。

<Note>
  <code>comet publish</code> 没有 reject 子命令。<code>approve</code> 是人工批准的唯一入口，执行后会写入批准记录。要正式驳回，用底层命令 <code>comet bundle review &lt;name&gt; --reject --reviewer &lt;name&gt;</code>。
</Note>

发布按 `review`（评审）→ `approve`（批准）→ `run`（发布）→ `distribute`（分发）四步进行。客观评测得分、源码快照哈希与目标平台的能力要求，共同决定 Bundle 是否达到发布就绪状态（readiness）。

## 完整示例

```bash
# 1. 查看发布就绪状态和阻塞项
comet creator status review-helper --project . --json

# 2. 查看系统建议的下一步
comet creator next review-helper --project . --json

# 3. 编译并生成目标平台的评审摘要
comet publish review review-helper --platform claude --json

# 4. 人工批准
comet publish approve review-helper --reviewer alice --json

# 5. 发布已批准的候选
comet publish run review-helper --platform claude --json

# 6. 分发预览（正式分发前必须执行）
comet publish distribute review-helper --platform claude --scope project --preview --json

# 7. 执行分发
comet publish distribute review-helper --platform claude --scope project --json
```

## 通用选项

| 选项 | 说明 |
| --- | --- |
| `--project <dir>` | 项目根目录，默认为 `.` |
| `--json` | 输出结构化的 JSON |
| `--platform <id>` | 目标 Agent 平台，可多次传入绑定多个平台 |
| `--scope <project\|global>` | 分发范围：项目目录或全局用户目录 |
| `--reviewer <name>` | 审核人名称，执行 `approve` 时必填 |
| `--locale <locale>` | 发布产物的语言 |
| `--overwrite` | 覆盖已有的发布候选（`run`）或已有分发（`distribute`） |
| `--preview` | 只生成分发预览，不写入文件 |
| `--confirm-executables` | 确认包内可执行脚本或 Hook 的权限 |
| `--skip-capability <cap>` | 跳过指定的可选能力，可多次传入 |

## 查看下一步：comet creator next

`comet creator status` 会输出完整的状态。如果你**只想快速知道接下来该执行哪条命令**，运行 `comet creator next`，它会直接给出组装好的命令：

```bash
comet creator next review-helper --project . --json
```

终端输出类似：

```text
Next step for review-helper
Status: draft
Current step: review
Action: request-review
Command: comet publish review review-helper --platform claude --json
Reason: Current draft hash is missing review approval
Requires confirmation: yes
```

加 `--json` 时返回这些字段：

| 字段 | 含义 |
| --- | --- |
| `status` / `currentStep` | 当前候选的状态和所处步骤 |
| `nextStep.action` / `nextStep.label` | 建议执行的动作及其显示名称 |
| `nextStep.command` | **已填好完整参数、可直接在终端执行的命令** |
| `nextStep.reason` | 给出这个建议的原因 |
| `nextStep.requiresUserConfirmation` | 该动作是否需要你确认（如审批、分发） |
| `preferenceDrift.changed` | 项目的 Skill 偏好规则在流程启动后有没有变化 |

<Tip>
  <code>comet creator next</code> 用于 <code>/comet-any</code> 流程被中断后继续：它把内部状态对应的动作整理成一条可直接执行的命令。如果检测到<strong>偏好变化</strong>（<code>preferenceDrift.changed === true</code>），<code>advisory</code> 模式下会给出警告，<code>strict</code> 模式下会阻止继续，由你决定沿用原方案还是重新生成。
</Tip>

## 分发前必须先预览

正式分发前，**必须先跑通预览（preview）**：

```bash
comet publish distribute review-helper --platform claude --scope project --preview --json
```

预览会列出：

- 将要部署的文件清单和实际目标路径；
- 目标平台不支持的能力；
- 包内可执行脚本的权限说明；
- 明确标注 `No files were written`，表示没有写入任何文件。

确认预览结果后，去掉 `--preview` 执行真正的分发。

## 可执行脚本与平台能力缺口

目标平台需要加载外部 Hook 或本地 Shell 脚本时，必须显式确认：

```bash
comet publish distribute review-helper --platform claude --scope project --confirm-executables --json
```

目标平台缺少某些可选能力，且你确认放弃时：

```bash
comet publish distribute review-helper --platform claude --scope project --skip-capability <capability> --json
```

| 能力类型 | 处理方式 |
| --- | --- |
| 必需能力（required）缺失 | **不在该平台分发**，不能跳过 |
| 可选能力（optional）缺失 | 需要你在命令中**显式跳过** |
| Hook 与脚本执行 | 需要你**明确确认**后才会分发 |

包内的 `hooks/*.yaml` 遵循 **Comet 的 Hook 描述格式（portable hook descriptor）**，`comet publish distribute` 会把它编译并转换成目标平台的配置，之后才会生效。
