title: "comet init"

---

`comet init` 是安装入口。它会检测平台、安装或更新组件，并把 Comet Skill 部署到目标位置。

## 基本用法

```bash
comet init [path]
```

常用选项：

| 选项 | 说明 |
| --- | --- |
| `--yes` | 非交互模式，自动安装缺失组件并跳过已有组件 |
| `--scope <scope>` | 安装范围：`project` 或 `global` |
| `--language <lang>` | Skill 语言：`zh` 或 `en` |
| `--skip-existing` | 跳过已有组件 |
| `--overwrite` | 覆盖 manifest 管理的文件 |
| `--json` | 输出 JSON |

## 推荐命令

项目级中文安装：

```bash
comet init --scope project --language zh
```

CI 或脚本环境：

```bash
comet init --yes --scope project --language zh --json
```

## 初始化后检查

```bash
comet doctor
```

如果缺少平台目录、Skill 文件或脚本，先修复这些问题再开始 `/comet`。

## 安装摘要怎么看

`comet init`（和 `comet update`）按平台输出每个组件的安装状态。Skill/脚本复制是这样展示的：

```text
Comet -> claude: installed (12 files) -> .claude/skills/comet
Comet -> claude: skipped (alreadyExists)
Comet -> opencode: failed (12 files, 1 failed) -> .opencode/skills/comet
```

| 状态 | 含义 |
| --- | --- |
| `installed` | 全部文件复制成功 |
| `skipped` | 已存在（未指定 `--overwrite`） |
| `failed` | 有文件复制失败 |

<Warning>
  从 0.4.0-beta.1 起，<strong>部分失败的安装不再被掩盖成成功</strong>。如果某个平台有文件复制失败（例如 <code>comet-hook-guard.mjs</code> 没装上），该平台会标记 <code>failed</code> 并带失败计数（如 <code>failed (12 files, 1 failed)</code>）——而不是把半安装状态报告为成功。缺 <code>comet-hook-guard.mjs</code> 会静默破坏 phase guard，所以这类失败必须先修。重跑 <code>comet init</code> 或 <code>comet update</code> 补齐缺失文件。
</Warning>
