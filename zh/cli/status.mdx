title: "comet status"
description: "查看活跃 change、当前阶段、下一步命令和恢复提示。"
---

`comet status` 是日常恢复和排障的第一条命令。

## 基本用法

```bash
comet status
```

| 选项 | 说明 |
| --- | --- |
| `--json` | 输出结构化状态 |

## 它会告诉你什么

- 当前有哪些活跃 change，以及它们是 Comet 管理还是普通 OpenSpec change。
- Comet change 的 workflow、phase、runtime mode、current step 和文件证据状态。
- 每个 change 的推荐下一步；只有满足条件的条目才显示归档建议。
- Classic runtime mode 和 current step。
- 缺失证据或畸形 `.comet.yaml` 的恢复提示。

## 混合 change 怎么看

一个项目可以同时存在 Comet 管理的 change 和普通 OpenSpec change。`comet status` 会分别标识，不会把普通 OpenSpec change 套进 Comet 的五阶段状态机。

| 类型 | 状态来源 | 就绪时的归档方式 |
| --- | --- | --- |
| Comet change | `.comet.yaml` + Classic 运行时证据 | `comet archive <change-name>` |
| 普通 OpenSpec change | OpenSpec artifacts 和任务状态 | `openspec archive <change-name> -y` |

未通过验证、状态异常或任务未完成的 change 不会显示可直接归档的建议。先按 `next:` 或恢复提示补齐证据。

## 多个 active Comet change

只有一个 active Comet change 时，源码写入可以自动归属。多个 change 同时活跃时，先明确选择当前工作目标：

```bash
comet state select <change-name>
comet state current
```

选择会绑定当前 branch/worktree。切换分支、worktree 或目标已归档后，需要重新选择；`comet status` 可用于核对候选 change，守卫不会在歧义状态下猜测。

## 推荐使用场景

```bash
comet status
```

如果输出显示异常，再运行：

```bash
comet doctor
```
