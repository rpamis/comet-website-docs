---
title: 'comet update'
description: '升级 Comet npm 包和配套的运行资产，可以只更新当前项目、全局配置，或所有已登记的项目。'
---

`comet update` 用来刷新已安装的 Comet Skill、Rule、Hook、Runtime 和恢复说明。它默认先把对应的 Comet npm 包升级到最新版本，再刷新资产文件。只想修复损坏的文件时，加 `--skip-self-update` 跳过 npm 安装。

不加 `--language` 时，更新会保留各安装目录原有的中英文设置；需要换语言时才指定。

## 基本用法

```bash
comet update
```

常用选项：

| 选项 | 说明 |
| --- | --- |
| `--json` | 输出本次升级的结构化 JSON 结果 |
| `--language <lang>` | 改变 Skill 语言，`zh`（中文）或 `en`（英文） |
| `--scope <scope>` | 只刷新指定层级：`project`（当前项目）或 `global`（全局环境） |
| `--platform <id>` | 只刷新指定平台，或项目自定义的平台 |
| `--current-project` | 只刷新当前工作目录所属的项目 |
| `--all-projects` | 更新索引中登记的所有项目 |
| `--self-update` | 强制更新 npm 包（默认已开启） |
| `--skip-self-update` | 只刷新本地资产，不检查也不更新 npm 包 |
| `--yes` | 批量更新时不询问，使用 Copy 模式并跳过可选的集成 |
| `--target-version <ver>` | 升级到指定版本，不允许降级 |
| `--classic-layout <ly>` | 项目里 `openspec/` 与 `docs/openspec/` 同时存在时，指定登记哪个：`legacy` 或 `docs` |

## 更新范围

如果本机的全局索引里已经登记过项目，交互式运行 `comet update` 时会先问你更新范围：

- **All indexed projects**：按顺序更新所有已登记的项目；
- **Current project only**：只更新当前目录所在的项目。

在脚本里调用时，默认范围更保守：

| 调用方式 | 实际范围 |
| --- | --- |
| 交互式终端调用（索引非空） | 弹出选项，由你选择 |
| 加 `--json` | 默认只处理当前项目 |
| 加 `--current-project` | 只处理当前项目 |
| 加 `--all-projects` | 处理所有已登记的项目 |
| 加 `--scope global` | 在单目标模式下只更新用户级全局资产 |

`--all-projects` 不能与 `--scope global` 或 `--current-project` 一起用。指定 `--scope global` 时固定按单目标模式更新用户级全局资产，不会进入 `--all-projects` 批量项目更新或弹出全部项目选择；默认会一并更新对应的全局 npm 包，只想刷新全局模板文件时加 `--skip-self-update`。

```bash
# 只更新当前项目
comet update --current-project

# 更新所有已登记的项目
comet update --all-projects

# 只刷新全局模板文件，不更新 npm 包
comet update --scope global --skip-self-update

# 只刷新当前项目里指定平台的资产，不更新 npm 包
comet update --current-project --platform claude --skip-self-update

# 一并更新对应的全局 npm 包
comet update --scope global --self-update
```

批量更新时，每个项目的执行结果会分别输出。npm 安装失败、路径没有权限、配置文件解析出错，都会计入该项目的失败；只要有项目失败，整体结果就不算成功。索引里记录的项目路径已经不存在时，系统会自动清掉这条记录。

`--platform` 用于某个 Agent 平台缺组件，或只想刷新团队自建平台的情况。指定后不影响其他正常平台；不指定时处理当前范围内所有已绑定的平台。

写 CI 流水线时一定要加 `--json`、`--current-project` 或 `--all-projects`。Comet 不会根据是否运行在非 TTY 环境中去猜范围，缺这些参数时仍会尝试等待交互输入。

## npm 包的更新规则

单项目模式包括显式 `--current-project`、加 `--json`、索引为空时的默认调用，以及显式 `--scope global`。这些场景默认先把对应的 Comet npm 包升级到最新稳定版，再刷新资产文件；包装在项目内还是全局，会按当前安装位置决定。加 `--skip-self-update` 就只刷新静态文件。

批量模式会按顺序检查每个项目依赖的包，同一个全局包在一次执行中只更新一次。只想批量同步规则文件时，加 `--skip-self-update`。可以用 `--target-version <version>` 升到指定版本，但不允许降级。

更新时会比较完整的 SemVer 版本号（包括 RC 标签）。远端候选版本低于当前版本时，系统拒绝执行。正式写入前，Comet 会先在沙盒临时目录里试装候选版本，检查版本号、`workflow resolve` 和 Native 核心命令是否正常；验证不通过就不改动当前项目。安装中途出错时，系统会尝试回滚到原来的版本，并把本次更新标记为未完成（incomplete）。

## 什么时候需要更新

- 在全局或项目里升级了 `@rpamis/comet` 之后；
- `comet doctor` 提示本地 Skill 或脚本版本与 CLI 不一致时；
- 需要在项目里切换中英文 Skill 时；
- 团队核心仓库同步了新的项目级 Comet 配置规范时。

## Native 与 Classic 的更新边界

与 `comet init` 一致，`comet update` 遵循以下边界：

- **Native 项目**：刷新 Comet 自带的 Skill 和 Runtime、统一的工作流 Rule、Hook Router 和自然语言恢复说明，固定使用 Copy 模式；不创建 `.comet/skills/`，也跳过 CodeGraph 和 Classic 专属文件。发现旧版留下的符号链接时，会安全解除并换成真实副本，不会顺着链接写回去；共享目录里有你自定义的 Skill 时，系统保留原样，不会覆盖。
- **Classic 与全局目标**：保留你原来选的部署方式（Copy 或 Symlink）和依赖配置。Symlink 模式下会重建指向 `.comet/skills/` 的软链接。
- **项目共享配置**：`.comet/config.yaml` 按字段合并，保留跨工作流配置和你自定义的参数；Native 更新不会删除已有的 Classic 文件，调整默认入口也不等于搬迁数据。
- **自然语言恢复说明**：`ambient_resume` 控制两套工作流共用的只读恢复探测；设为 `false` 时，更新会移除对应的恢复检查点说明，其他自定义规则保持不变。

`comet update` 不会改动 OpenSpec、Superpowers 或其他第三方 Skill 的内部文件；平台原有的 `skills/` 目录会保留，Symlink 模式只维护 Comet 自己创建的链接，不碰本地或第三方的脚本。

## 日常更新流程

```bash
# 拉取最新 npm 包并刷新当前项目的资产
comet update --current-project

# npm 包已就绪，只同步本地规则文件
comet update --current-project --skip-self-update

# 最后检查一遍环境和平台状态
comet doctor
```
