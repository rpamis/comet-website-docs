---
title: 'comet update'
description: '全自动升级 Comet npm 核心包及配套运行时资产，支持精准更新当前工程、全局配置或全量已纳管项目。'
---

`comet update` 专门一键刷新已安装的 Comet Skill 技能包、Rule 规范、Hook 钩子、Runtime 运行时以及系统托管的恢复说明规约。在单项目更新与批量模式下，系统默认会优先将对应的 Comet npm 全局或本地包升级至最新版本，随后同步刷新资产文件文件。若仅需修复文件损坏，可通过追加 `--skip-self-update` 灵活跳过 npm 安装阶段。

若未显式指定 `--language` 参数，更新流程会自动识别并保留各安装目录既有的中英文语言偏好；仅在需要切换多语言时方需显式指定。

## 基本用法

```bash
comet update
```

常用选项参数：

| 参数选项 | 说明 |
| --- | --- |
| `--json` | 输出单次标准化的结构化 JSON 升级报告 |
| `--language <lang>` | 显式覆写 Skill 语言，支持 `zh`（中文）或 `en`（英文） |
| `--scope <scope>` | 仅刷新指定层级的资产目标：支持 `project`（当前项目）或 `global`（全局环境） |
| `--platform <id>` | 仅刷新指定的受支持平台或项目自定义平台 |
| `--current-project` | 严格仅刷新当前工作目录所绑定的项目工程 |
| `--all-projects` | 批量遍历并更新项目索引中登记的全部项目工程 |
| `--self-update` | 显式强制执行 npm 包自更新（默认已处于开启状态） |
| `--skip-self-update` | 仅刷新本地资产文件，跳过 npm 包版本检查与更新 |
| `--yes` | 免交互执行批量项目更新，默认采用 Copy 模式并自动跳过可选的新集成 |
| `--target-version <ver>` | 升级锁定至指定的精确版本号（严格拦截版本降级操作） |
| `--classic-layout <ly>` | 当项目中 `openspec/` 与 `docs/openspec/` 并存时，显式指定登记哪个布局：`legacy` 或 `docs` |

## 科学选定更新影响范围

当本机的全局索引账本中已登记过项目时，交互式执行 `comet update` 会首先向你确认升级范围：

- **All indexed projects**：依照拓扑依序批量更新所有已登记的工程；
- **Current project only**：严格仅针对当前终端所在的单项目实施更新。

在自动化脚本调用中，系统采取更为安全保守的默认策略：

| 触发调用范式 | 默认生效范围 |
| --- | --- |
| 常规交互式终端调用（且索引非空） | 弹出交互选择框，由人类二选一 |
| 追加 `--json` 参数 | 默认安全锁定为当前单项目 |
| 显式声明 `--current-project` | 严格仅限定当前单项目 |
| 显式声明 `--all-projects` | 批量调度全局所有已登记项目 |
| 显式声明 `--scope global` | 仅针对单项目模式下的全局共享资产目标 |

`--all-projects` 禁止与 `--scope global` 或 `--current-project` 产生参数冲突。显式指定 `--scope global` 默认采用单项目模式锁定全局资产，不会突兀进入批量全量流程；该模式默认会连带更新全局 npm 包，若仅需刷新全局模板资产，请追加 `--skip-self-update`。

```bash
# 严格仅更新当前单个项目
comet update --current-project

# 批量迭代升级所有已在册的项目级安装
comet update --all-projects

# 仅刷新全局模板资产，不触碰底层 npm 包
comet update --scope global --skip-self-update

# 仅刷新当前项目中的指定平台资产，跳过 npm 更新
comet update --current-project --platform claude --skip-self-update

# 显式联动更新对应的全局 Comet npm 核心包
comet update --scope global --self-update
```

在批量更新模式下，系统会独立统计并打印每个工程的执行结果。无论是 npm 安装失败、目标路径权限受阻还是配置文件解析异常，均会归入该项目的失败统计，任一项目失败时，整体结果不会标记为成功。若索引中记录的工程路径在磁盘上已不存在，系统会自动清理该条失效索引。

`--platform` 适用于单个 Agent 平台环境缺失组件、或仅希望针对团队自建平台进行资产刷新的精准维护场景。传入后不改动其他正常平台；省略时则处理当前作用域下的全量已绑定目标。

自动化 CI 流水线请务必显式追加 `--json`、`--current-project` 或 `--all-projects`。Comet 不会根据是否运行在非 TTY 管道中来猜测执行范围，缺少上述参数时仍会尝试进入交互等待。

## npm 自动化版本升级防线

单项目模式涵盖显式 `--current-project`、追加 `--json`、索引为空时的默认调用以及显式 `--scope global`。上述场景默认会优先将对应的 Comet npm 包升级至最新稳定版，随后刷新资产文件；包管理位置依据当前是项目私有还是全局安装自适应决定。追加 `--skip-self-update` 即可纯粹刷新静态资产。

全量项目模式默认按序校验每个工程所依赖的包；同一个全局包在单次执行中仅会触发一次更新。若仅需批量同步规则文件，传入 `--skip-self-update` 即可。可通过 `--target-version <version>` 锁定升级至特定的发版版本号，但系统严格拒绝逆向降级操作。

自更新算法会比对完整的 SemVer 语义化版本号（包含预发布 RC 标签）。若远端候选版本低于当前已安装版本，系统拒绝执行。在正式写入前，Comet 会在沙盒临时隔离目录中先行试装候选版本，在受限的时间窗口内核验版本号、`workflow resolve` 及 Native 核心命令的健全性；一旦候选验证受阻，当前工程代码完好保持原样。若安装遭遇异常中断，系统会自动尝试回滚至先前的精确版本，并将本次更新标记为未完成（incomplete）。

## 推荐运行场景

- 在全局或局部完成 `@rpamis/comet` 版本迭代后；
- `comet doctor` 明确警告本地 Skill 或脚本版本存在跨代脱节时；
- 需要在项目内全局切换中文与英文版 Skill 时；
- 团队核心仓库同步了最新的项目级 Comet 配置规范时。

## Native 与 Classic 的更新隔离机制

与 `comet init` 保持完全一致的严谨契约，`comet update` 贯彻以下边界：

- **针对 Native 项目**：全量刷新 Comet 原生 Skill/Runtime、统一工作流 Rule、Hook Router 路由钩子及自然语言恢复规约，并强制采用 Copy 拷贝模式；不创建 `.comet/skills/`，亦主动跳过 CodeGraph 与 Classic 专属资产。若检测到旧版遗留的符号链接，系统会安全解绑并转为本地真实副本，不沿链接逆向写回；若共享目录中包含非受控的自定义 Skill，系统完整保护现场并拒绝粗暴覆写。
- **针对 Classic 与 Global 目标**：严谨尊重既有的部署模式选择（Copy 或 Symlink）及依赖规范。在 Symlink 模式下自动重建指向 `.comet/skills/` 的软链接。
- **项目共享配置智能合并**：`.comet/config.yaml` 实行字段级智能合并，完整保留跨工作流配置及用户的自定义参数；Native 更新不擅自删除既有的 Classic 文件，调整默认入口亦不代表触发了破坏性的数据迁移。
- **自然语言恢复说明**：`ambient_resume` 开关统筹双流共用的只读恢复探测规则；若配置为 `false`，更新过程会自动剥离对应的恢复检查点说明，但完好保留其他用户自定义规则。

`comet update` 不越权干预 OpenSpec、Superpowers 或其他第三方 Skill 的内部文件；已有 Agent 平台的原生 `skills/` 目录会被绝对尊重，Symlink 模式仅打理受 Comet 纳管的链接，不触碰本地或第三方的既有脚本。

## 推荐日常升级操作流

```bash
# 标准化：自动拉取最新 npm 核心并刷新当前工程资产
comet update --current-project

# 轻量化：底层包已就绪，仅快速同步本地规则文件
comet update --current-project --skip-self-update

# 终验：运行健康自检，确认各平台和环境的检查均通过
comet doctor
```
