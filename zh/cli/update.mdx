---
title: "comet update"
description: "更新 Comet npm 包和已安装的 Comet Skill 文件。"
---

`comet update` 用于刷新已安装的 Comet Skill、规则和脚本。它适合版本升级后同步项目或全局安装。

## 基本用法

```bash
comet update
```

| 选项 | 说明 |
| --- | --- |
| `--json` | 输出 JSON |
| `--language <lang>` | 覆盖自动检测到的 Skill 语言，`zh` 或 `en` |
| `--scope <scope>` | 仅更新 `project` 或 `global` |
| `--current-project` | 只更新当前项目级安装 |
| `--all-projects` | 更新项目索引中的所有项目级安装 |

## 选择更新范围

如果项目索引中已有项目级安装，交互式 `comet update` 会让你选择：

- **All indexed projects**：依次更新所有已登记项目。
- **Current project only**：只更新当前工作目录对应的项目。

自动化调用采用更保守的默认值：

| 调用方式 | 默认范围 |
| --- | --- |
| 普通交互式调用，且索引中有项目 | 询问当前项目或所有已登记项目 |
| `--json` | 当前项目 |
| 显式 `--current-project` | 当前项目 |
| 显式 `--all-projects` | 所有已登记项目 |

`--all-projects` 不能与 `--scope global` 或 `--current-project` 同时使用。项目索引非空时，更新全局安装应同时传入 `--current-project`，避免进入项目范围选择：

```bash
# 只更新当前项目
comet update --current-project

# 批量更新所有已登记的项目级安装
comet update --all-projects

# 更新全局安装，不进入项目范围选择
comet update --scope global --current-project
```

批量模式会分别记录每个项目的结果。npm 包更新、安装目标检查或配置读取失败都会计入对应项目的失败汇总，不会被报告为全部成功。已不存在、且能安全确认不再有项目级安装的索引条目会被清理。

自动化脚本应显式使用 `--json`、`--current-project` 或 `--all-projects`。Comet 不会根据“是否由脚本启动”自动推断范围；没有这些选项且索引非空时，命令仍会进入交互式范围选择。

## 什么时候运行

- 升级 `@rpamis/comet` 后。
- `comet doctor` 提示 Skill 或脚本版本不一致。
- 切换中文或英文 Skill。
- 团队更新了项目级 Comet 配置。

## 安装模式和配置合并

和 `comet init` 一样，`comet update` 会：

- 询问**安装模式**（Copy 复制 / Symlink 符号链接），选择 Symlink 时会重建符号链接到 `.comet/skills/`。详见 [支持的平台 · 安装模式](/zh/platforms#安装模式：复制-vs-符号链接)。
- 对 `.comet/config.yaml` 做**字段级合并**：保留你的现有值、补齐缺失字段、刷新注释、保留自定义字段。终端提示 `项目配置已合并 (.comet/config.yaml)`。

已有平台 `skills/` 目录会被保留。Symlink 模式只刷新 Comet 管理的链接，不删除本地或第三方 Skill。

## 推荐流程

```bash
comet update
comet doctor
```
