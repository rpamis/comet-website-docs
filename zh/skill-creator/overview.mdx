Comet Any 将业务流程做成完整 SDK Skill 应用。应用包含可阅读的入口与业务规则，也包含管理执行、批准、产物和恢复的 Runtime。

## 谁编写什么

| 参与者     | 负责的内容                                                                  |
| ---------- | --------------------------------------------------------------------------- |
| 创作 Agent | 调查真实 Skill，编写完整入口、业务 Rule、执行端口、业务验证器和验收样例     |
| SDK        | 装配实际流程，固定内容与依赖，追加执行协议，保存 Run 并检查动作、批准和产物 |
| 执行宿主   | 加载真实 Skill、交接任务、调用工具、获取用户决定与核对外部结果              |
| 分发入口   | 预览并安装平台 Skill、共享 Rule/Hook 及 Runtime 依赖                        |

SDK 的通用执行协议不能代替业务正文。比如“报告必须包含来源”应同时出现在业务要求和实际验证条件中，不能只写一句提示语就假定已经强制执行。

## 应用由什么组成

完整包以 `application.json` 为入口，固定应用身份、版本、入口 Skill、执行模块及真实 Skill 依赖。创作方案必须包含完整 `SKILL.md` 和 `rules/workflow-guard.md`，可提供实际引用的 Markdown 资源。

平台安装入口引用这个固定包。普通文件安装成功、Skill 已加载、某次动作完成、机器验收通过和真实宿主验证是分别记录的事实。

## 三种组合类型

**Native 扩展**在允许的候选、父任务、子任务或集成检查位置增加工作。原 Builder、独立 Verifier、用户批准及归档约束保留。

**Classic 组合**使用 full、hotfix、tweak 领域工厂，在必要文档和阶段授权约束内增加或替换 Skill。

**独立应用**声明自己的工作流图、Schema、状态、分支、并行与子流程。它的验收由自己的契约定义，例如本地报告的拒绝分支可以正常结束，但并不表示已经发布。

三种类型的完整实践分别见 [定制 Native](/zh/skill-creator/native-customization)、[定制 Classic](/zh/skill-creator/classic-customization) 和 [组合任意 Skill](/zh/skill-creator/standalone-composition)。

## 确认后固定哪些内容

提案展示完整正文、实际步骤、依赖、输出条件、失败路径与能力限制。批准针对整份提案，不能由正文摘要或旧批准代替。

编译后使用固定内容。文件或依赖漂移时，保留当前记录并恢复原内容，或修订方案后取得新的确认。

## 阶段文件为什么能阻止推进

应用声明实际步骤对应的必需产物及内容要求，并由业务验证器核对领域条件。SDK 检查真实文件与摘要，缺失或不满足条件时，阶段结果不能作为成功证据，下游工作也不能沿过期证据推进。

完整说明见 [阶段产物与业务验收](/zh/sdk/artifact-validation)。日常使用从 [快速上手](/zh/skill-creator/getting-started) 开始；需要自行接入执行平台时阅读 [SDK 总览](/zh/sdk/overview)。
