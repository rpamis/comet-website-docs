---
title: '用 Any 定制 Native 工作流'
description: '把团队 Skill 加入 Native 的实现指导和候选审查，并保留原有独立验收与归档条件。'
---

你的团队使用 Comet Native 开发功能，希望 Builder 遵循团队规范，并在候选实现通过检查后增加安全审查。用 `/comet-any` 将这些要求做成单独的 Native 扩展应用，安装后通过该应用的入口使用。

本教程以“认证接口安全审查”为例。你会准备实际 Skill、确认扩展方案、验证报告与失败路径，再安装并试运行。创作 Agent 负责适配和编写应用，你不需要先写 SDK 代码。

## 确定要改变什么

| 你希望定制的内容                             | 应如何表达                                                    |
| -------------------------------------------- | ------------------------------------------------------------- |
| Builder 使用团队的实现约定。                 | 增加指导内容，说明适用范围与必须遵循的规则。                  |
| 每个候选增加安全审查。                       | 添加绑定当前候选的检查步骤、报告和业务验证器。                |
| Supervisor 的 child 或集成结果也要检查。     | 指明检查 child、parent 或 integration，不复用普通候选的结果。 |
| 完全替换 Builder、独立 Verifier 或归档规则。 | 当前 Native 扩展不提供这种替换。原职责和批准条件保留。        |

这里的“修改”指你创建的扩展应用改变执行指导和追加工作。默认 `/comet-native` 入口不会因为安装了扩展就自动变成另一套流程。不要手工改安装目录里的核心 Skill 或生成 Runtime。

## 1. 准备团队 Skill

先完成 [Comet 安装](/zh/quickstart)，用 `comet doctor` 检查环境。在支持 Creator 的 Codex 或 Claude Code 宿主中准备实际 Skill。

本例假设项目中已有：

```text
team-skills/
  implementation-guide/
    SKILL.md
  auth-security-review/
    SKILL.md
    references/checklist.md
```

这些是示例路径，替换为你的实际目录。实现指导至少说明认证代码的输入校验、错误响应和测试约定。安全审查 Skill 应能读取候选改动，并给出结论、发现和依据；名字包含“安全”不代表它已经具备这些能力。

如果审查依赖测试命令、网络服务或额外工具，提前说明。工具不可用时应报告阻塞，不能把“没有发现问题”作为默认结果。

## 2. 向 Any 描述扩展目标

在项目 Agent 会话中输入：

```text
/comet-any
把本次创作命名为 native-team-review，创建 Native 扩展应用。
读取 ./team-skills/implementation-guide 和 ./team-skills/auth-security-review 的真实内容。
实现指导用于当前项目的认证接口开发，不替换 Native Builder。
在普通 Native 候选的检查通过后增加安全审查，绑定本次候选和正式需求。
审查必须覆盖输入校验、权限判断、敏感信息和失败响应。
生成 reports/auth-security-review.md，包含“审查范围”“结论”“发现”“依据”。
未检查项、缺少依据或尚有未解决的阻塞问题时，不得判定审查通过。
审查不通过时回到当前候选的修复流程，新候选重新审查。
保留 Native 的独立 Verifier、用户决定和 Archive 条件。
先展示完整方案、本地验收样例及 Codex 项目级安装预览，等我分别确认。
```

Agent 会调查这些依赖，说明哪些内容作为指导、哪些作为执行检查，以及宿主缺少什么能力。若 Skill 输出不符合要求，让 Agent 在方案中说明适配方式，或先修订你维护的 Skill。

## 3. 检查候选审查方案

确认方案时重点核对以下内容：

| 项目     | 本例应该看到什么                                                |
| -------- | --------------------------------------------------------------- |
| 基础流程 | Native 扩展，保留原实现、检查、独立验收和归档。                 |
| 执行位置 | 普通候选使用 candidate 范围；不自动覆盖 Supervisor 的全部工作。 |
| 审查输入 | 当前候选、正式需求、实际改动与可读取的检查结果。                |
| 指导用途 | Builder 阅读团队约定，不让指导 Skill 代替独立验证。             |
| 实际报告 | 固定的项目内报告路径，必需章节和真实内容。                      |
| 业务条件 | 每项要求有检查状态与依据，未检查或有阻塞问题时失败。            |
| 失败处理 | 原工作区保留，修复后用新候选重新检查。                          |

要求 Agent 展示完整入口 Skill、业务规则和验证条件，再作出决定。只看到“增加安全检查”的一句摘要，还不能确认它会检查哪些代码、什么情况下阻止后续工作。

如果你的项目使用 Supervisor，补充说明是审查每个 child、父候选还是合并后的集成结果。不同范围分别声明输入和报告，不能把一个 child 的通过记录当成整个父任务的验收。

## 4. 验证报告与修复路径

Creator 会编译固定应用，并在临时项目检查产物。为这个例子要求至少以下样例：

| 样例                                 | 预期行为                                   |
| ------------------------------------ | ------------------------------------------ |
| 全部要求已检查，有依据且无阻塞问题。 | 报告通过扩展验收，进入原 Native 后续步骤。 |
| 章节齐全，但权限检查没有依据。       | 业务验证器拒绝；不能只检查章节是否存在。   |
| 报告缺失、为空或摘要不符。           | 文件检查拒绝。                             |
| 原候选变更，仍提交旧报告。           | 旧审查不能作为新候选的通过证据。           |

本地验收通过证明声明的检查能工作，不证明真实安全审查 Skill 的判断质量。选择模型 Eval 时，加入一项含认证缺陷的候选样例，观察它是否发现问题并走到修复路径。没有执行的模型与真实宿主仍保持未验证，见 [应用评估](/zh/eval/applications)。

## 5. 安装并使用定制入口

本例将完整应用包导出到 `.comet/creator/exports/native-team-review/`。安装预览还会列出平台入口、固定依赖和 Rule/Hook；具体目录以返回结果为准。检查是否会覆盖现有入口，以及宿主是否需要激活能力，再确认安装。

在目标平台加载预览中列出的新入口 Skill，输入一个小的认证需求，例如：

```text
使用已安装的 native-team-review 应用，为登录接口增加输入长度校验。
本次验收包括超长输入被拒绝、错误响应不泄露内部信息，以及安全审查报告有实际依据。
```

使用应用入口名以实际安装结果为准。创建这个业务任务后，先完成 Native 的需求确认，再由原 Run 进入实现、检查和扩展审查。你应能查看本次候选的安全报告，发现问题时保留代码并修复；扩展通过后仍要完成原独立验收和用户决定。

Dashboard 的 **Comet Any** 查看创作记录与应用运行；关联的 Native 记录可查看需求、候选与原验收进度。观察页面不能代替批准或推进。

## 6. 修改指导或继续中断任务

创作中断时先读取同一记录：

```bash
comet creator status native-team-review --project . --json
comet creator next native-team-review --project . --json
```

若实际创作名不同，替换命令中的名称。`next` 在宿主动作或用户决定处停下，不会自行完成安全审查或批准。

安装后想增加审查项或修改团队指导，向 Any 指出原应用包和需要改变的要求，准备并确认新版本。已经开始的业务 Run 保留原固定版本；不要在原版本目录替换 Skill 后要求它按新内容继续。完整升级与恢复说明见 [安装与分发](/zh/skill-creator/publishing)。
