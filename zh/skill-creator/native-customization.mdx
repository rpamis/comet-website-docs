---
title: '用 Comet Any 定制 Native 工作流'
description: '把团队 Skill 加入 Native 的实现指导和候选审查，并保留原有独立验收与归档条件。'
---

你的团队使用 Comet Native 开发功能，希望 Builder 遵循团队规范，并在候选实现通过检查后增加安全审查。用 `/comet-any` 可以把这些要求打包成独立的 Native 扩展应用，安装后通过该应用的入口使用。

本教程以“认证接口安全审查”为例：准备本地 Skill、确认扩展方案、验证报告与失败路径，再安装并试运行。创作 Agent 负责适配和编写应用，你不需要先写 SDK 代码。

## Native 哪些地方可定制

你可以直接告诉 Comet Any“想在哪里增加什么工作”，由它选择扩展范围并生成方案。下表列出当前支持的位置；括号中的范围名称供核对方案时参考，不需要手动编写 SDK 配置。

| 定制位置 | 可以怎么定制 | 需求示例 | 保留的条件 |
| --- | --- | --- | --- |
| Builder 的实现指导 | 增加团队规范、方法或领域知识。 | “认证接口按团队约定处理错误和测试。” | Builder 仍负责原实现任务，不替换其职责。 |
| 普通 change 的候选检查通过后（`candidate`） | 追加当前候选的审查或业务检查。 | “候选增加安全审查，报告无阻塞问题才能继续。” | 保留原有检查、独立 Verifier 和当前候选绑定。 |
| Supervisor 父候选检查通过后（`parent`） | 追加父任务整体的审查。 | “核对所有子任务是否覆盖父需求。” | 不能用单个子任务的通过结果代替父级验收。 |
| Supervisor 子任务检查通过后（`child`） | 为每个子任务追加专门检查。 | “涉及接口的子任务都生成兼容性报告。” | 检查绑定该子任务的候选和工作区。 |
| Supervisor 集成检查通过后（`integration`） | 追加对合并后集成结果的检查。 | “合并后检查跨模块接口和端到端行为。” | 不替换原集成检查，不使用合并前结果。 |
| 新增步骤的产物与验收 | 定义必需报告、业务条件和通过标准。 | “权限审查项必须逐条给出依据，未检查项不能通过。” | 原 Native 验收要求继续生效。 |
| 新增检查的失败处理 | 说明何时阻塞，以及如何修复和重验。 | “审查失败回到当前候选修复，再检查新候选。” | 沿 Native 的恢复路径处理，保留原记录。 |
| Shape、原独立 Verifier、用户批准和 Archive | 当前不支持直接替换或任意插入步骤。 | “取消独立验收，直接归档”不在可定制范围内。 | 原需求确认、独立验收、批准和归档约束保留。 |

`candidate` 用于普通 change，`parent`、`child`、`integration` 用于 Supervisor 的对应节点。可以组合多个范围，但每个范围都要有自己的输入和验收依据。这些扩展位置对应流程中的固定节点，不能在任务中途随时手动触发。

这里的“定制”指创建独立的扩展应用来补充执行指导和检查步骤。默认 `/comet-native` 入口不会因为安装了扩展就变成另一套流程。不要手动修改安装目录里的核心 Skill 或生成的 Runtime 文件。

## 1. 准备团队 Skill

先完成 [Comet 安装](/zh/quickstart)，并用 `comet doctor` 检查环境。在支持的 Agent 平台（如 Codex、Claude Code）中准备本地 Skill。

本例假设项目中已有以下目录：

```text
team-skills/
  implementation-guide/
    SKILL.md
  auth-security-review/
    SKILL.md
    references/checklist.md
```

以上为示例路径，使用时替换为你的项目目录。实现指导应至少说明认证代码的输入校验、错误响应和测试约定；安全审查 Skill 应能读取候选代码改动，并给出结论、发现和依据。仅仅在名称里包含“安全”，并不代表它已经具备审查能力。

如果审查依赖测试命令、网络服务或额外工具，请提前说明。工具不可用时应报错阻塞，不能把“没有发现问题”作为默认结果。

## 2. 向 Comet Any 描述扩展目标

在项目 Agent 会话中输入：

```text
/comet-any
把本次创作命名为 native-team-review，创建 Native 扩展应用。
读取 ./team-skills/implementation-guide 和 ./team-skills/auth-security-review 的内容。
实现指导用于当前项目的认证接口开发，不替换 Native Builder。
在普通 Native 候选的检查通过后增加安全审查，绑定本次候选和正式需求。
审查必须覆盖输入校验、权限判断、敏感信息和失败响应。
生成 reports/auth-security-review.md，包含“审查范围”“结论”“发现”“依据”。
未检查项、缺少依据或尚有未解决的阻塞问题时，不得判定审查通过。
审查不通过时回到当前候选的修复流程，新候选重新审查。
保留 Native 的独立 Verifier、用户决定和 Archive 条件。
先展示完整方案、本地验收样例及 Codex 项目级安装预览，等我分别确认。
```

Agent 会读取这些依赖，说明哪些内容用作实现指导、哪些用作审查步骤，以及当前平台是否缺少所需能力。如果某个 Skill 的输出不符合要求，可以让 Agent 在方案中说明适配方式，或先修改你维护的 Skill。

## 3. 检查候选审查方案

确认方案时重点核对以下内容：

| 检查项 | 本例应该看到什么 |
| --- | --- |
| 基础流程 | Native 扩展，保留原实现、检查、独立验收和归档。 |
| 执行位置 | 普通候选使用 `candidate` 范围，不自动覆盖 Supervisor 的全部流程。 |
| 审查输入 | 当前候选、正式需求、代码改动与可读的检查结果。 |
| 指导用途 | Builder 阅读团队规范，但不让指导 Skill 代替独立验证。 |
| 输出报告 | 明确的项目内报告路径、必需章节和内容要求。 |
| 业务条件 | 每项要求都有检查状态和依据，未检查或有阻塞问题时失败。 |
| 失败处理 | 保留原工作区，修复后对新候选重新检查。 |

请让 Agent 展示完整的入口 Skill、业务规则和验证条件后再确认。只看“增加安全检查”这样一句摘要，无法判断它会检查哪些代码、什么情况下会拦截后续步骤。

如果你的项目使用 Supervisor，需要补充说明要审查的是每个子任务、父候选还是合并后的集成结果。不同范围应分别声明输入和报告，不能把单个子任务的通过记录当成整个父任务的验收。

## 4. 验证报告与修复路径

Comet Any 会编译出锁定依赖的应用包，并在临时项目中检查产物。本例建议至少覆盖以下用例：

| 用例 | 预期行为 |
| --- | --- |
| 全部要求已检查，有依据且无阻塞问题。 | 报告通过扩展验收，进入原 Native 后续步骤。 |
| 章节齐全，但权限检查没有依据。 | 业务验证器拒绝；不能只检查章节标题是否存在。 |
| 报告缺失、为空或校验摘要不匹配。 | 文件检查拒绝。 |
| 候选代码已修改，仍提交旧报告。 | 旧审查不能作为新候选的通过依据。 |

本地验收通过只说明声明的校验逻辑能正常运行，不代表安全审查 Skill 在真实模型下的判断质量。如果选择运行模型 Eval，建议加入一个包含认证缺陷的候选样例，观察它能否发现问题并进入修复流程。未测试的模型和平台会保持未验证状态，详见 [应用评估](/zh/eval/applications)。

## 5. 安装并使用定制入口

本例将完整应用包导出到 `.comet/creator/exports/native-team-review/`。安装预览会同时列出平台入口、已锁定的依赖和共享 Rule/Hook，具体路径以预览结果为准。确认不会覆盖现有入口，并核对目标平台是否需要手动开启 Hook 或相关配置后再安装。

在目标平台加载预览中列出的新入口 Skill，输入一个小型认证需求试运行，例如：

```text
使用已安装的 native-team-review 应用，为登录接口增加输入长度校验。
本次验收包括超长输入被拒绝、错误响应不泄露内部信息，以及安全审查报告有具体依据。
```

入口名称以安装结果为准。发起任务后，先完成 Native 的需求确认，再按流程进入实现、检查和扩展安全审查。你可以查看本次候选的安全报告；发现问题时保留代码并修复；扩展审查通过后，仍需完成原有的独立验收和用户决定。

在 Dashboard 的 **Comet Any** 页面可以查看创作记录和应用运行进度，在关联的 Native 页面可以查看需求、候选和原验收状态。Dashboard 仅用于查看进度，确认和推进仍需在 Agent 对话或命令行中完成。

## 6. 修改指导或从中断处恢复

创作中途中断时，用原名称查看状态并继续：

```bash
comet creator status native-team-review --project . --json
comet creator next native-team-review --project . --json
```

如果创作名称不同，替换为你的实际名称。`next` 在需要 Agent 平台执行操作或等待用户决定时会停下，不会代替你完成安全审查或批准。

安装后如果想增加审查项或调整团队规范，向 Comet Any 指出原应用包和改动要求，生成并确认新版本。已经启动的任务会继续沿用旧版本，不要直接去旧版本目录里覆盖 Skill 文件。完整升级与恢复说明见 [安装与分发](/zh/skill-creator/publishing)。
