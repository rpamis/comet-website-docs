在 Agent 中调用 `/comet-any`，描述你希望复用的工作流。Agent 调查真实 Skill，编写入口、业务规则和验证器；SDK 将确认的方案装配成可运行、可安装的应用。

## 准备目标与 Skill

先安装 Comet，运行 `comet doctor` 检查环境。当前 Creator 宿主选项为 Codex 和 Claude Code，执行分析时需要实际的 Skill 加载与交接能力。

描述目标时写清输入、步骤、产物、验收和用户决定。例如：

```text
/comet-any
把本地调研和报告 Skill 组合成项目周报流程。
先整理已验收任务，再生成报告初稿，随后检查每条结论是否有来源。
报告必须包含“本周完成”和“风险与下一步”两节。
缺少报告或来源不完整时不能进入发布。
用户确认实际报告后，才写入最终发布文件。
```

没有明确 Skill 路径时，Agent 会调查候选并处理缺失或歧义。Skill 名称不能证明能力，需阅读实际正文、脚本和资源。

全局安装 Comet 并初始化项目后即可创作，不需要再在业务项目中执行 `npm install @rpamis/comet`。Comet 会为编译和安装准备所需 Runtime 依赖；已存在的冲突依赖会保留，并提示先修复。

## 确认组合类型

| 类型          | 适合的目标                                                               |
| ------------- | ------------------------------------------------------------------------ |
| Native 扩展   | 保留 Native 的 Builder、独立 Verifier 和 Archive，在允许位置增加业务工作 |
| Classic 组合  | 沿用 full、hotfix 或 tweak，增加或替换符合阶段要求的 Skill               |
| 独立 SDK 应用 | 为报告、调研、内容生产等任务声明自己的流程与验收                         |

Agent 会说明推荐类型及其边界。组合后的实际步骤、依赖和输出会进入同一份方案。

## 阅读完整方案

确认前检查完整 `SKILL.md`、业务 Rule、依赖 Skill、执行步骤、必需文件、业务验证器、失败路径和宿主能力。

你可以批准、修订或拒绝。决定绑定当前方案；改正文、目标或依赖后，需要重新确认。

## 验收与可选 Eval

SDK 编译固定包后，Creator 在临时项目中检查正常与异常产物。缺失、空文件、内容不符、摘要变化，以及声明的业务异常都必须能识别出来。

本地检查通过后，你可以选择模型 Eval、重试、修订或明确跳过。跳过 Eval 不会跳过本地检查，也不会把应用标记为经过模型或宿主验收。

## 确认安装预览

预览会展示完整包导出目录、平台 Skill 入口、Runtime 依赖、Rule/Hook 配置、冲突和能力限制。确认当前预览后才写入目标。

完整包导出位置与平台入口是两处位置。应用可以通过 [comet application](/zh/cli/application) 再分发到其他项目、用户目录或平台。

## 中断后继续

保留原创作名称，在同一项目调用 `/comet-any` 继续，或读取当前状态：

```bash
comet creator list --project . --json
comet creator status weekly-report --project . --json
comet creator next weekly-report --project . --json
```

`next` 执行本地机器步骤，并在需要宿主动作或用户决定时停下。已经发生但结果未知的操作先核对现场，不能另起流程重复安装或发布。

Dashboard 的 **Comet Any** 页面可查看创作过程、应用运行、产物和证据。流程观测保持只读，用户决定和推进仍在原 Agent／CLI 中完成；就绪应用可在分发面板预览并确认安装或导出。
