---
title: 'Comet Any 常见问题'
description: '选择组合类型、理解业务校验、查看验收证据以及恢复未完成的创作。'
---

<AccordionGroup>
  <Accordion title="什么时候用 /comet，什么时候用 /comet-any？">
    `/comet` 按项目配置进入 Native 或 Classic 模式，用于完成日常开发中的需求变更。`/comet-any`
    用于把你的目标和本地已有 Skill 组合成可复用的 SDK 工作流应用。
  </Accordion>
  <Accordion title="我需要自己编写 SDK 代码吗？">
    使用 Comet Any 时不需要。创作 Agent 会读取本地已有 Skill，帮你写好入口说明、业务规则和校验逻辑；你只需要确认目标、完整方案、验收样例和安装预览。如果需要自行接入平台或用代码构建应用，请阅读
    [SDK 文档](/zh/sdk/overview)。
  </Accordion>
  <Accordion title="Skill、业务 Rule 和 Hook 是谁生成的？">
    创作 Agent 负责编写完整的入口 Skill 和业务 Rule。SDK 负责补充执行协议、锁定依赖并打包可运行应用；正式分发时会安装平台共享的
    Rule/Hook。业务校验由业务验证器完成，通用的共享保护规则不能代替它。
  </Accordion>
  <Accordion title="某一阶段没有生成指定文件，能继续吗？">
    不能。只要该阶段声明了必需的输出文件，SDK 就会检查文件是否存在、内容是否非空以及是否通过业务校验；任意一项不通过，流程都会拦截，不会进入下一步。
  </Accordion>
  <Accordion title="跳过模型 Eval 会跳过本地检查吗？">
    不会。本地的正常和异常用例验收必须全部通过。选择跳过模型 Eval
    后，系统会明确记录跳过状态，不会标记为模型测试通过或 Agent 平台实测通过。
  </Accordion>
  <Accordion title="应用安装成功就代表业务验收通过吗？">
    不代表。文件安装、本地自动验收、模型 Eval 和 Agent
    平台实测的结果会分开记录。安装成功只说明入口和依赖已按预览计划写入，不能代表所有平台配置、业务样本或外部操作都已经验证。
  </Accordion>
  <Accordion title="中断后要重新创建吗？">
    不需要。用原来的名称运行 `comet creator status` 和 `comet creator next`，系统会保留之前的进度和待确认项。如果中断前有已经发出的安装或发布操作，先核对实际结果，不要新建流程重复执行。
  </Accordion>
  <Accordion title="为什么 Dashboard 的批准选项不能直接点击？">
    Dashboard 在这里只负责展示进度和证据，不负责推进流程。真正的确认和审批需要回到原来的 Agent 对话或命令行里提交。
  </Accordion>
</AccordionGroup>

开始创作见 [快速上手](/zh/skill-creator/getting-started)，完整流程见 [创作、验收与安装](/zh/skill-creator/workflow)，平台分发见 [安装与分发](/zh/skill-creator/publishing)。
