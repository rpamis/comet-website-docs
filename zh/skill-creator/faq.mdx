---
title: 'Comet Any 常见问题'
description: '选择组合类型、理解业务检查、查看证据并恢复未完成的创作。'
---

<AccordionGroup>
  <Accordion title="什么时候用 /comet，什么时候用 /comet-any？">
    `/comet` 按项目配置进入 Native 或 Classic，用于完成项目中的需求变更。`/comet-any`
    用于把目标和已有 Skill 创作成可复用的 SDK Skill 应用。
  </Accordion>
  <Accordion title="我需要自己编写 SDK 代码吗？">
    使用 Comet Any 时，创作 Agent
    调查实际依赖并编写业务正文、执行端口和验证器。你重点阅读目标、完整方案、验收和安装预览。自行接入平台或编写应用时，阅读
    [SDK 文档](/zh/sdk/overview)。
  </Accordion>
  <Accordion title="Skill、业务 Rule 和 Hook 是谁生成的？">
    Agent 编写完整入口 Skill 与业务 Rule。SDK 追加执行协议、固定依赖并装配
    Runtime；正式分发时会安装平台共享的
    Rule/Hook。业务验证器检查实际业务条件，通用保护规则不代替它。
  </Accordion>
  <Accordion title="某一阶段没有生成指定文件，能继续吗？">
    对必需产物声明了契约后，SDK 检查实际文件、内容和摘要。缺失、空文件或不满足业务条件时，SDK
    不接受成功回报，依赖工作不能沿这份证据推进。
  </Accordion>
  <Accordion title="跳过模型 Eval 会跳过本地检查吗？">
    不会。本地正常与异常产物验收必需通过。选择跳过模型 Eval
    会保留明确的跳过记录，不会产生模型通过或真实 Agent 平台验证结果。
  </Accordion>
  <Accordion title="应用安装成功就代表业务验收通过吗？">
    安装、本地契约验收、模型 Eval 和真实 Agent
    平台验证分别记录。安装成功证明写入的入口与依赖满足安装计划，不能证明所有平台、业务样本或外部操作都已执行。
  </Accordion>
  <Accordion title="中断后要重新创建吗？">
    先使用原创作名称读取 `comet creator status` 和 `next`。保留原
    Run、动作和当前用户等待。已派发但结果未知的操作先核对，不另建流程重复安装或发布。
  </Accordion>
  <Accordion title="为什么 Dashboard 的批准选项不能直接点击？">
    Comet Any 工作区用于只读观测。用户决定由原 Agent 获取并通过当前 Wait 提交，Dashboard 不接管
    Runtime 的推进权。
  </Accordion>
</AccordionGroup>

开始创作见 [快速上手](/zh/skill-creator/getting-started)，完整过程见 [创作、验收与安装](/zh/skill-creator/workflow)，平台分发见 [安装与分发](/zh/skill-creator/publishing)。
