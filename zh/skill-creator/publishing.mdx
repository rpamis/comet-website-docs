Comet Any 本地验收通过后，会先展示应用包导出路径和正式安装预览。只有确认当前预览后，SDK 才会写入目标目录；应用本身不需要单独编写安装脚本。

## 安装前核对哪些内容

| 预览内容 | 需要核对的事情 |
| --- | --- |
| 完整应用包 | 应用标识、版本、入口、执行模块与已锁定的依赖。 |
| 导出目录 | 应用包保存在本地的哪个路径。 |
| 平台入口 | 本项目或用户目录会写入哪些 Skill 入口。 |
| Rule / Hook | 写入的共享规则入口、平台支持情况和需要手动开启的配置。 |
| 冲突与能力 | 是否与现有文件冲突，目标平台是否支持加载 Skill、任务交接和执行工具。 |
| 验收证据 | 本地验收、模型 Eval 和 Agent 平台实测各自的结果。 |

平台入口与完整应用包导出目录分开存放。不要只手动复制单个入口 `SKILL.md`，否则应用缺少执行模块和已锁定的依赖无法正常运行。

## 分发到其他平台

在需要安装的项目中运行预览命令：

```bash
comet application distribute ./weekly-report/application.json --project . --platform codex --preview --json
```

核对预览并确认后，带上它返回的确认摘要执行写入：

```bash
comet application distribute ./weekly-report/application.json --project . --platform codex --confirmation-hash <本次预览确认摘要> --json
```

传入 `--platform all` 可分发到全部已登记平台，也可以重复 `--platform` 同时指定多个平台；用户级安装使用 `--scope user`。平台实际能力以预览检查结果为准，入口写入成功不代表平台上的 Hook 或权限都已开启。

## 升级与卸载

升级时添加 `--upgrade` 并重新确认当前预览。SDK 会更新平台入口，正在运行中的任务会继续使用旧版本，不受影响。

卸载默认先展示预览。传入 `--platform` 可只移除指定平台的入口，确认后执行；选择性卸载不会删除共享 Rule/Hook、其他应用共用的依赖，以及运行中任务仍需保留的版本。

```bash
comet application uninstall weekly-report --project . --platform codex --json
```

## 安装中断处理

安装中途中断或不确定是否写入完成时，先核对目标文件，再从原记录恢复。如果期间文件或配置有改动，之前的预览确认会失效，需要重新预览并确认。

命令参数见 [comet application](/zh/cli/application)。生成后的运行记录和验收证据可在 [Dashboard](/zh/dashboard/overview) 的 **Comet Any** 页面查看。
