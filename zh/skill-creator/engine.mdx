入口 Skill 告诉 Agent 如何完成业务工作，SDK 运行记录（Run）保存每一步的状态、用户决定和结果，平台集成则把当前工作流和文件写入事件关联起来。

## 业务内容与执行协议

Agent 会根据你的目标编写完整的 `SKILL.md` 和业务 Rule，说明输入如何整理、各阶段必须产出哪些文件，以及如何校验结论与来源。

SDK 会在这些内容后面自动补充执行协议和通用保护规则，打包成完整的可运行应用。执行协议规定了如何读取当前运行记录、获取待执行动作、回传执行结果和等待用户确认。在 Prompt 里写“已经批准”不能代替用户实际的确认操作。

## Rule 与 Hook 的作用

分发应用时会安装平台共享的 Rule/Hook，同时保留你原有的其他配置。在支持 Hook 的平台上，当前工作流范围内的文件写入会先经过规则检查；如果平台不支持或需要手动开启 Hook，会在安装预览里提前提示。

共享保护规则负责检查当前步骤、审批状态和允许写入的目录范围。它不会仅凭 Skill 文字自动推导“报告来源必须齐全”这类业务条件，也不是操作系统级沙箱。

## 业务验证器的作用

阶段产物检查确保文件真实存在、内容非空且校验摘要一致，业务验证器则进一步核对具体的业务条件。验证器由创作 Agent 编写并随应用包锁定，在本地验收阶段通过正常和异常样例检验。

```text
执行 Skill → 检查输出文件 → 运行业务验证器 → 接受当前结果 → 允许后续步骤继续
```

只要文件缺失、业务校验失败，或完成后文件被修改，流程就不会沿原证据进入下游步骤。详细配置见 [阶段产物与业务验收](/zh/sdk/artifact-validation)。

## Agent 平台执行与中断核对

Agent 平台必须加载声明的 Skill、完成必要的上下文交接，并按现有权限调用工具。如果平台缺少某项能力，不能把步骤静默跳过或冒称已经执行。

如果动作已派发但在回传结果前中断，系统会保留原有的动作记录和认领标识。恢复前先检查文件是否已写入、消息是否已发出或外部发布是否已生效，避免重复执行造成重复写入或重复发布。

## Dashboard 只提供查看，不推进流程

Dashboard 用于展示已保存的步骤、用户决定、执行尝试、输出文件和验收证据，不会自行批准方案或推进流程。页面上列出的选项仅说明当前等待点支持哪些操作，实际确认仍需回到原来的 Agent 对话或命令行中提交。
