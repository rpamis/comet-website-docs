---
title: 'Skill 偏好与真实来源'
description: '表达项目的组合偏好，并在方案确认前检查实际 Skill、能力和依赖。'
---

`.comet/skill-preferences.yaml` 声明项目希望优先复用哪些 Skill，以及如何处理缺失、歧义、脚本和 Hook。没有这个文件，也可以直接向 `/comet-any` 描述目标。

## 配置示例

把示例中的名称替换为项目实际使用的 Skill：

```yaml
version: 1
mode: advisory
prefer:
  - team-research
  - team-report
require:
  - team-verification
policies:
  missing: ask
  ambiguous: ask
  deviation: explain
  scripts: disclose
  hooks: disclose
```

| 字段       | 对创作的要求                                       |
| ---------- | -------------------------------------------------- |
| `prefer`   | 优先考虑的真实 Skill                               |
| `require`  | 必须在方案中处理的 Skill 要求                      |
| `mode`     | `advisory` 表达建议，`strict` 表达更严格的选择约束 |
| `policies` | 如何解释缺失、歧义、偏离及可执行内容               |

偏好文件不会替你创造缺失的 Skill，也不会授予工具、网络或文件写入权限。

## 确认实际内容

Agent 需要阅读匹配的 `SKILL.md`、脚本和资源，说明它能提供什么输入输出、用户交互、业务检查及恢复方式。名称相近不代表可以互换。

方案中检查每个实际依赖的来源、用途与范围。有同名候选、缺少必需能力或需要替代实现时，先说明并取得决定。

## 固定后继续执行

确认后，应用使用固定下来的真实内容与适配契约。后续依赖变化不能悄悄替换原方案；恢复原依赖，或修订方案并重新确认。

完整的入口 Skill 与业务 Rule 仍由 Agent 创作。偏好文件不能代替这些正文，也不能代替 [阶段产物验收](/zh/sdk/artifact-validation)。
