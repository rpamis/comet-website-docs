---
title: 'Skill 偏好与依赖检查'
description: '配置项目优先复用的 Skill，并在确认方案前核对依赖内容、能力和冲突。'
---

`.comet/skill-preferences.yaml` 用于声明项目希望优先复用哪些 Skill，以及遇到缺失、同名歧义、脚本和 Hook 时的处理方式。没有这个文件，也可以直接用 `/comet-any` 描述目标。

## 配置示例

将示例中的名称替换为你的项目实际使用的 Skill：

```yaml
version: 1
mode: advisory
prefer:
  - team-research
  - team-report
require:
  - team-verification
policies:
  missing: ask
  ambiguous: ask
  deviation: explain
  scripts: disclose
  hooks: disclose
```

| 字段 | 说明 |
| --- | --- |
| `prefer` | 优先考虑复用的本地 Skill。 |
| `require` | 方案中必须处理的 Skill 列表。 |
| `mode` | `advisory` 表示优先参考、允许偏离并说明原因；`strict` 表示严格按配置选择，不满足时暂停询问。 |
| `policies` | 定义遇到 Skill 缺失（`missing`）、同名冲突（`ambiguous`）、偏离偏好（`deviation`），以及 Skill 内含脚本（`scripts`）或 Hook（`hooks`）时的处理方式（例如询问用户或提前披露）。 |

偏好配置只是选择约束，不会凭空创建缺失的 Skill，也不会授予工具、网络或文件写入权限。

## 核对 Skill 的具体内容

Agent 会读取匹配的 `SKILL.md`、脚本和参考文件，说明它支持的输入输出、用户交互、业务检查和恢复方式。名称相近的 Skill 并不意味着可以互相替换。

确认方案时，需要核对每个依赖的来源、用途和使用范围。如果存在同名候选、缺少必需能力或需要改用替代实现，Agent 会先说明情况并等你决定。

## 确认后锁定依赖

方案确认后，应用会锁定所选 Skill 的具体内容和输入输出约定。如果后续依赖文件被改动，系统不会自动替换，需要恢复原文件或修订方案后重新确认。

完整的入口 Skill 与业务 Rule 仍由 Agent 编写。偏好配置文件不能代替这些正文，也不能代替 [阶段产物验收](/zh/sdk/artifact-validation)。
