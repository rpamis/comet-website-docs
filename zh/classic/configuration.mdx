`.comet/config.yaml` 是项目级配置文件，保存在仓库根目录。本文专门介绍与 Classic 相关的配置项：包括全局共享入口字段以及 `classic.*` 专属配置。关于 `native.*` 的配置项说明，请参考 [Native 配置](/zh/native/configuration)。

下文用 `<classic-root>` 表示当前 Classic OpenSpec 的根目录：新项目默认是 `docs/openspec/`，保留旧版布局的项目为 `openspec/`。具体存储路径由 `classic.artifact_layout` 决定，详见 [项目文件结构](/zh/guides/project-structure)。

## 变更讲解（Walkthrough）

在 Classic 模式下，系统默认会在 Build 阶段结束时生成变更讲解页 `walkthrough.html`，Verify 阶段会在该页面实时同步验证结果，并在 Archive 阶段归档保存。如果你不需要生成变更讲解页面，可在项目顶层设置 `change_walkthrough: false` 予以关闭，详见 [共享配置说明](/zh/native/configuration#变更说明)。

## 完整配置示例

当项目中同时启用两套工作流并选用中文时，项目初始化后会生成类似如下的配置（在 Classic 视角下只需关注共享字段与 `classic:` 块）：

```yaml
schema: comet.project.v1
default_workflow: classic
workflows:
  - native
  - classic
ambient_resume: true

classic:
  artifact_layout: docs
  language: zh-CN
  context_compression: off
  review_mode: standard
  auto_transition: true
```

## 共享入口字段

| 配置项             | 允许值                     | 详细说明                                                                                                    |
| ------------------ | -------------------------- | ----------------------------------------------------------------------------------------------------------- |
| `schema`           | `comet.project.v1`         | 当前结构化项目配置版本，由 Comet 统一管理                                                                   |
| `default_workflow` | `native` \| `classic`      | `/comet` 默认进入哪套工作流                                                                                 |
| `workflows`        | `native`、`classic` 或两者 | 项目已启用的工作流列表；必须包含当前默认工作流                                                              |
| `ambient_resume`   | `true` \| `false`          | 是否允许 Agent 对“继续之前的工作”等自然语言请求自动执行上下文恢复探测                                       |
| `hook.allow_paths` | 项目相对目录列表（默认空） | 在受保护阶段允许 Agent 写入的项目相对路径（基于前缀匹配；核心受保护区域无法放行）。详见 [Hook 写入放行](#hook-写入放行) |

<Note>
  修改 <code>default_workflow</code> 仅会改变 <code>/comet</code> 的默认分发入口，绝不会自动迁移或修改任何既有的 change。
</Note>

### Hook 写入放行策略

`hook.allow_paths` 是全局共享的文件写入放行策略：默认为空时，项目内（产物区之外）的所有文件写入均受 Classic 自身阶段守卫的严格管控；配置之后，匹配该目录及其子路径的写操作将被直接放行。常见的使用场景是允许实现代码目录（例如 `src/`）在任意阶段都能随时修改，避免在非编码阶段误触发拦截：

```yaml
hook:
  allow_paths:
    - src
    - apps/web
```

请注意：`.comet`（Runtime 状态目录）以及 Classic 的 OpenSpec 与 Superpowers 产物根目录永远受到底层强保护，无法通过此配置绕过。若配置路径超出项目边界或格式错误，`comet doctor` 会明确报错提示。

## Classic 专属配置项

`artifact_layout` 为项目全局生效的目录规范；其余四项配置会在创建新的 Classic change 时，作为初始快照写入该 change 目录下的 `.comet.yaml`：

| 配置项                        | 允许值                            | 默认值                                                            | 详细说明                                                                                     |
| ----------------------------- | --------------------------------- | ----------------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| `classic.artifact_layout`     | `legacy` \| `docs`                | 默认为 `docs`；旧项目升级时若检测到既有 `openspec/` 则保留为 `legacy` | 指定 OpenSpec 产物根目录：`openspec/` 或 `docs/openspec/`                                    |
| `classic.language`            | `en` \| `zh-CN`                   | 根据 `comet init` 时选择的语言映射；使用 `--yes` 时默认为 `en`    | 控制 OpenSpec、Superpowers、验证报告、归档说明等工作流产物的输出语言                         |
| `classic.context_compression` | `off` \| `beta`                   | `off`                                                             | 控制 design → build 交接时的上下文压缩策略。详见 [上下文压缩机制](/zh/concepts/context-compression) |
| `classic.review_mode`         | `off` \| `standard` \| `thorough` | `standard`（完整 full 流程的默认值）                              | 控制代码审查的严格程度。详见 [代码审查机制](/zh/concepts/review-mode)                         |
| `classic.auto_transition`     | `true` \| `false`                 | `true`                                                            | 阶段守卫通过后，是否自动唤起下一个阶段的 Skill。详见 [自动推进机制](/zh/concepts/auto-transition) |

<Note>
  Classic 的项目默认值仅在创建新 change 时快照固化到该 change 的 <code>.comet.yaml</code> 中；后续修改项目配置不会追溯影响已经存在的历史 change。
</Note>

<Warning>
  切勿手动直接修改 <code>classic.artifact_layout</code>，这只会更改 Comet 的读取路径而不会搬迁物理文件。若已有项目需要平滑切换目录布局，请先运行 <code>comet classic root move docs --dry-run</code> 检查依赖与冲突，再执行 <code>comet classic root move docs --apply</code> 正式迁移。
</Warning>

### 产物语言与 Skill 语言的关系

在运行 `comet init` 时，向导提示选择的“Skill 语言”决定了安装中文还是英文版本的 Comet Skill；而 Classic 产物的语言则保存在 `classic.language` 中：

| 初始化时的选项              | 实际安装的 Skill | `classic.language` |
| --------------------------- | ---------------- | ------------------ |
| `English` / `--language en` | 英文 Skill       | `en`               |
| `中文` / `--language zh`    | 中文 Skill       | `zh-CN`            |

后续创建新的 Classic change 时，Comet 会将项目级的 `classic.language` 复制到 `<classic-root>/changes/<name>/.comet.yaml`。OpenSpec 的 proposal、design、tasks，以及 Superpowers 架构设计、执行计划、验证报告和归档说明，均以该份快照作为正文语言标准。

<Warning>
  项目级和 change 级的语言字段仅接受 <code>en</code> 或 <code>zh-CN</code>。命令行参数 <code>zh</code> 仅在 <code>comet init --language zh</code> 时作为缩写传参，切勿直接写入 <code>.comet/config.yaml</code>。
</Warning>

## 配置生效优先级

对于 Classic 的 `language`、`context_compression`、`review_mode` 与 `auto_transition` 配置项，Comet 按以下严格优先级解析：

```text
change 级 .comet.yaml 字段 > 环境变量 > 项目级 .comet/config.yaml > 全局 language 默认值 > 内置默认值
```

| 层级                        | 说明                                                          | 配置方式                                                            |
| --------------------------- | ------------------------------------------------------------- | ------------------------------------------------------------------- |
| change 级 `.comet.yaml`     | 最高优先级。change 创建时继承自项目配置，后续由工作流阶段流转维护 | 由 `/comet` 阶段 Skill 自动读写                                     |
| 环境变量                    | 仅在对应 change 的字段未指定时生效，非常适合 CI/CD 流程动态覆盖 | 例如 `export COMET_AUTO_TRANSITION=true` 或 `export COMET_LANGUAGE=zh-CN` |
| 项目级 `.comet/config.yaml` | 当 change 级未配置且无环境变量覆盖时的基准配置                | 手动编辑或由 `comet init` 自动生成                                  |
| 全局 `~/.comet/config.yaml` | 仅为 `language` 提供跨项目默认兜底；项目级配置始终优先        | 由全局 `comet init` / `update` 自动写入                             |
| 内置默认值                  | 最终兜底默认策略                                              | 参见上方参数表格                                                    |

## auto_transition 机制详解

`auto_transition` 用于控制当前阶段的守卫检查通过后，是否自动链式调用下一个阶段的 Skill：

| 设定值         | 具体产品行为                                                                      |
| -------------- | --------------------------------------------------------------------------------- |
| `true`（默认） | 守卫通过并推进 `phase` 状态后，系统输出 `NEXT: auto`，并由 Agent 自动进入下一阶段 |
| `false`        | 守卫推进 `phase` 状态后，系统输出 `NEXT: manual` 并打印提示信息，等待你手动输入下一阶段命令 |

<Warning>
  <strong>阶段推进本身必定会执行</strong>：守卫命令运行 <code>--apply</code> 时，始终会更新 <code>phase</code> 状态，这与 <code>auto_transition</code> 的开闭无关。<code>auto_transition</code> 仅决定是否自动唤起后续 Skill。而在需要人工确认的关键决策点（如确认方案、选择执行模式等），无论该选项如何设置，流程均会正常暂停等待你确认。
</Warning>

通过环境变量覆盖（仅在 change 自身未设置时生效）：

```bash
export COMET_AUTO_TRANSITION=true
```

## 环境变量一览

| 环境变量                    | 具体作用                                           | 常见适用场景                         |
| --------------------------- | -------------------------------------------------- | ------------------------------------ |
| `COMET_LANGUAGE`            | 覆盖 `language`（change 级为空时生效）             | CI/CD 或临时指定新 change 的产物语言 |
| `COMET_AUTO_TRANSITION`     | 覆盖 `auto_transition`（change 级为空时生效）      | CI/CD 或临时覆盖                     |
| `COMET_CONTEXT_COMPRESSION` | 覆盖 `context_compression`（change 级为空时生效）  | 临时测试压缩模式                     |
| `COMET_REVIEW_MODE`         | 覆盖 `review_mode` 默认解析（resolver 层）         | 临时指定审查模式                     |
| `COMET_FORCE_PHASE`         | `=1` 时允许直接 `set_phase`（仅用于状态修复与排障） | 状态修复排障                         |
| `COMET_OPENSPEC`            | 指定 openspec CLI 路径（默认 `openspec`）          | 自定义 OpenSpec 安装位置             |

<Note>
  <code>COMET_LANGUAGE</code>、<code>COMET_AUTO_TRANSITION</code>、<code>COMET_FORCE_PHASE</code> 与 <code>COMET_OPENSPEC</code> 为面向用户的正式环境变量。<code>COMET_CONTEXT_COMPRESSION</code> 和 <code>COMET_REVIEW_MODE</code> 位于解析层，主要供内部调试与测试框架使用。
</Note>

## 常见配置方式

### 配置项目全局默认值

直接编辑项目根目录下的 `.comet/config.yaml`：

```yaml
schema: comet.project.v1
default_workflow: classic
workflows:
  - native
  - classic
ambient_resume: true
classic:
  language: zh-CN
  context_compression: beta
  review_mode: thorough
  auto_transition: true
```

将该文件提交到 Git 仓库后，所有团队成员新建的 change 都会自动沿用这套标准规则。

### 临时环境变量覆盖

```bash
export COMET_LANGUAGE=zh-CN
export COMET_AUTO_TRANSITION=false
```

此方式仅对当前终端会话生效，不会更改仓库中的任何物理文件。
