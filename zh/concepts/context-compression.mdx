---
title: '上下文交接与原文复用'
description: '了解 Classic 如何在 design 与 build 之间复用正式材料，以及需要集中阅读时如何生成可读视图。'
---

Classic 在 design、build 与恢复任务时直接读取当前 OpenSpec 正式材料。Agent 根据本次任务选择需要的 proposal、design、tasks 与 delta Specs，不再为了阶段交接复制一份完整上下文或重新计算文件 hash。

## 交接哪些内容

- `proposal.md`：目标、范围和动机。
- `design.md`：已有的设计约定。
- `tasks.md`：实现计划和完成进度。
- `specs/*/spec.md`：本次需求变化与验收场景。

正式材料仍是当前要求的依据。Agent 摘要可以帮助恢复上下文，不能替代源文档或用户对方案的确认。修改后先判断实际影响，必要时更新方案与计划，不能凭旧摘要继续。

## off 与 beta 的兼容设置

`classic.context_compression` 的 `off` 和 `beta` 保留为兼容配置。当前交接都使用正式材料，不再生成旧的 hash 索引，也不要求 `handoff_hash` 匹配后才进入下一阶段。旧项目中的派生文件可以保留，但恢复时仍以同一任务的正式来源和实际进度为准。

两种配置不再代表旧版“截断摘要”与“hash 引用”的差别，不应据此预估固定的 Token 节省比例。

## 需要集中阅读时

如果希望把当前材料放在一个 Markdown 文件中阅读，可以让 Agent 按当前 Runtime 的指引生成可读视图：

```bash
comet handoff <change-name> design --write --full
```

视图汇集当前原文，不替代正式材料、设计提案或批准。日常推进不需要手工生成，见 [comet handoff](/zh/scripts/comet-handoff)。

## 中断后继续

直接告诉 Agent 继续原任务。Agent 核对当前阶段、未完成决定和实际工作，按需读取原始材料。`--hash-only` 已移除，不要用重新生成 hash 作为恢复前提。
