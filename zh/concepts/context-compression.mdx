title: '上下文交接与原文复用'
description: '解析 Classic 如何在 design 与 build 阶段直接复用权威文档，以及需要汇总阅读时如何生成集成视图。'
---

Classic 在进行方案设计（design）、编码实现（build）以及断点恢复时，均直接读取最新的 OpenSpec 权威材料。Agent 根据当前具体任务按需加载 proposal、design、tasks 与增量 Specs，不再为了跨阶段交接而强行复制一份冗余的上下文镜像，也无需重新计算文件 Hash。

## 交接材料包含哪些内容

- `proposal.md`：核心目标、变更范围与最初动机。
- `design.md`：既定的架构共识与技术选型约定。
- `tasks.md`：具体的实施计划与逐项任务完成进度。
- `specs/*/spec.md`：本次需求涉及的接口/能力变更规范及验收测试用例。

所有执行环节均以原始权威文档为准。Agent 生成的中间摘要仅作为快速唤醒记忆的辅助线索，绝不能取代原始文档，更不能替代用户对架构方案的正式确认。需求或方案修改后，必须先行评估改动影响，必要时同步修正计划，切勿盲目依赖过时的旧摘要。

## off 与 beta 的兼容设置说明

`classic.context_compression` 的 `off` 与 `beta` 当前仅保留用于向下兼容。现在的交接链路直接读取正式材料，不再生成旧版的文件 Hash 索引，也不会要求强制校验 `handoff_hash` 才放行到下一阶段。旧版本项目中残留的衍生缓存文件可以安全保留，但在恢复时始终以当前任务的正式材料和物理代码进度为准。

这两项兼容配置不再代表旧版中“截断摘要”与“Hash 引用”的区别，无需据此预估固定的 Token 节省率。

## 需要集中汇总阅读时

如果你希望把当前变更的所有材料汇集到一个统一的 Markdown 文件中通读，可以让 Agent 运行如下命令生成只读的汇总视图：

```bash
comet handoff <change-name> design --write --full
```

该命令仅用于将分散的原文汇集为方便人类阅读的视图，不能替代原始材料或架构方案的正式确认。在日常工作流推进中完全无需手动执行此命令，详见 [comet handoff 脚本](/zh/scripts/comet-handoff)。

## 中断后如何继续

只需在对话中直接告诉 Agent 继续当前任务。Agent 会自动核对当前所处阶段、尚未敲定的决策项以及当前实际代码进度，按需重新读取原始文档。原有的 `--hash-only` 参数已正式废弃，切勿将重新生成 Hash 作为恢复的前置条件。
