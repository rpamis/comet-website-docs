title: '上下文交接与原文复用'
description: '介绍 Classic 如何在 design 与 build 阶段直接复用正式文档，以及需要汇总阅读时如何生成集成视图。'
---

Classic 在方案设计（design）、编码实现（build）和断点恢复时，都直接读取最新的 OpenSpec 正式文档。Agent 根据当前任务按需加载 proposal、design、tasks 和增量 Specs，不再为了跨阶段交接而复制一份冗余的上下文镜像，也无需重新计算文件 Hash。

## 交接材料包含哪些内容

- `proposal.md`：核心目标、变更范围与最初动机。
- `design.md`：既定的架构共识与技术选型约定。
- `tasks.md`：具体的实施计划与逐项任务完成进度。
- `specs/*/spec.md`：本次需求涉及的接口/能力变更规范及验收测试用例。

所有执行环节都以原始的正式文档为准。Agent 生成的中间摘要只作为帮助快速回忆的辅助线索，不能取代原始文档，更不能替代你对架构方案的正式确认。需求或方案修改后，必须先评估改动的影响，必要时同步修正计划，不要依赖过时的旧摘要。

## off 与 beta 的兼容设置说明

`classic.context_compression` 的 `off` 和 `beta` 现在只为向下兼容而保留。现在交接时直接读取正式文档，不再生成旧版的文件 Hash 索引，也不再要求校验 `handoff_hash` 才放行到下一阶段。旧版本项目中残留的衍生缓存文件可以放心保留，但恢复时始终以当前任务的正式文档和代码进度为准。

这两项兼容配置不再代表旧版中“截断摘要”与“Hash 引用”的区别，无需据此预估固定的 Token 节省率。

## 需要集中汇总阅读时

如果你希望把当前变更的所有材料汇总到一个 Markdown 文件里通读，可以让 Agent 运行下面的命令，生成只读的汇总视图：

```bash
comet handoff <change-name> design --write --full
```

这条命令只用于把分散的原文汇集成便于阅读的视图，不能替代原始文档，也不能替代对架构方案的正式确认。日常工作流中不需要手动运行这条命令，详见 [comet handoff 脚本](/zh/scripts/comet-handoff)。

## 中断后如何继续

只需在对话中告诉 Agent 继续当前任务。Agent 会自动核对当前所处阶段、尚未敲定的决策项和实际代码进度，按需重新读取原始文档。原有的 `--hash-only` 参数已废弃，不要把重新生成 Hash 作为恢复的前置条件。
