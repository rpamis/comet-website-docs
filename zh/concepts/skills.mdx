Comet 的核心能力都以 **Skill** 的形式提供。一个 Skill 就是一个独立目录：`SKILL.md` 写清楚它做什么、按什么步骤做，旁边可以带脚本、参考文档和校验文件。安装之后，它要么变成平台里的斜杠命令（例如 `/comet-native`），要么被 Comet Engine 按名称调用。

正常使用只需要 `/comet`，不需要理解这些机制。这一页回答三个问题：Skill 从哪来、装在哪、谁发现它——供你想定制、安装或排查时查阅。

## 三种来源

按"怎么来的、装到哪里"，Comet 里的 Skill 分三种：

| 来源               | 怎么来的                       | 装到哪里                 | 怎么被使用                                 |
| ------------------ | ------------------------------ | ------------------------ | ------------------------------------------ |
| 内置工作流 Skill   | `comet init` / `comet update`  | 平台目录（如 `.claude/skills/`） | 平台直接发现，显示为斜杠命令         |
| 项目 Skill         | `comet skill add`              | `.comet/skills/<name>`    | Comet Engine 按名称解析，不进平台目录      |
| 生成的 Skill       | `/comet-any` 创作并发布        | Bundle draft 目录         | 评估发布后分发，装成项目 Skill 或平台 Skill |

<Note>
  最常混淆的是前两种：<strong>平台 Skill</strong>（<code>comet init</code> 装到{' '}
  <code>.claude/skills/</code> 等平台目录）由 AI 平台直接发现并变成斜杠命令；<strong>项目 Skill</strong>（
  <code>comet skill add</code> 装到 <code>.comet/skills/</code>）是 Comet Engine 自己的 Skill
  池，不直接暴露给平台，而是在运行时按名称解析。
</Note>

## 项目 Skill：覆盖和扩展内置能力

项目 Skill 是安装到项目内 `.comet/skills/<name>/` 目录的 Skill 包：

- **位置**：`.comet/skills/<name>/`，和 `.comet/config.yaml` 同级，属于项目本身，可以提交到 Git。
- **发现顺序**：Engine 解析 Skill 名称时按 **explicit（显式路径）→ project（项目 Skill）→ builtin（内置 Skill）** 查找，项目 Skill 优先于内置 Skill。
- **不直接进平台**：它们不会自动变成斜杠命令。

| 用途              | 说明                                                                                      |
| ----------------- | ------------------------------------------------------------------------------------------ |
| 覆盖内置 Skill    | 在 `.comet/skills/` 放一个同名 Skill，Engine 优先用它。团队统一调整流程时有用。           |
| 安装额外 Skill    | `/comet-any` 生成的 Skill 或社区 Skill 可以装到这里，让 Engine 运行它们。                 |
| 项目内共享        | 提交到 Git 后，团队成员 clone 仓库就有同一套 Skill。                                      |

安装命令：

```bash
comet skill add ./my-skill --project .
```

这会把 `./my-skill` 目录校验、计算 hash 后复制到 `.comet/skills/<metadata.name>/`。已存在时需要 `--overwrite`。安装拒绝符号链接，保证 Skill 包内容是真实的。

<Warning>
  项目 Skill 按名称覆盖内置 Skill 时，如果项目 Skill 无效（校验失败），Engine 会
  <strong>直接失败</strong>
  而不是回退到内置。这避免"你以为在用自定义版本，实际静默用了内置"的问题（fail-closed，而非静默降级）。
</Warning>

## Skill 管理命令

`comet skill` 提供一整套本地 Skill 工具：

| 命令                   | 作用                                                            |
| ---------------------- | --------------------------------------------------------------- |
| `comet skill add`      | 安装 Skill 包到 `.comet/skills/`                                |
| `comet skill show`     | 查看 Skill 来源、结构、hash、步骤、guardrails 和 runtime checks |
| `comet skill run`      | 启动高级 deterministic Engine Run                               |
| `comet skill continue` | 提交 pending action 结果或恢复 Run                              |
| `comet skill check`    | 运行 Engine Run 的 runtime checks                               |

## 按需代码审查：/comet-review

`/comet-review` 对当前选中的 Comet change（Native 或 Classic）执行一次**手动触发的只读代码审查**：对照实现 diff 和已有证据，按优先级报告正确性、安全、边界和覆盖问题。

它不属于任何阶段，也不替代 Build 或 Verify 的验证：

- 整个调用保持只读——不修改文件、不推进阶段、不更新状态或验证报告，也不修复发现的问题；
- 独立于 `review_mode`：`review_mode` 控制流程内的自动审查策略，`/comet-review` 只代表你手动触发的单次审查，调用时也不会读取或修改当前 change 的 `review_mode`；
- 审查结果不是 Verify 通过，“没有发现问题”也不等于测试已经通过。

## 用 /comet-any 创建可复用 Skill

`/comet-any`（Skill Creator）是普通用户创建或优化 Skill 的主入口。你只需要描述想创建的工作流，它会：

1. 读取项目级偏好 `.comet/skill-preferences.yaml`。
2. 用 `find-skill` 解析**真实本地 Skill 内容**——不靠名字推测能力。
3. 展示 Skill Creator 确认页，列出每个 Skill 的来源、hash、角色和调用顺序，等你确认。
4. 确认后生成**稳定组合 Skill Bundle**（含 skills/scripts/rules/hooks/references），而不是单个 `SKILL.md`。
5. 内部走 CLI 后端做校验、生成 install-candidate、可选安装。

`.comet/skill-preferences.yaml` 支持 `prefer`/`require`/`advisory` 三类条目，确认后会计算 `preferenceHash` 绑定到产物。

<Note>
  普通用户不需要理解 Bundle、Factory、组合、Phase Recipe
  这些内部概念——它们只存在于实现和审计证据里。用户视角只有三个起点：
  <strong>定制 /comet-classic</strong>、<strong>创建新 Skill</strong>、
  <strong>升级已有 Skill</strong>。
</Note>

正常用户路径是：

```text
/comet-any -> comet eval -> comet creator status/next -> review/approve/run -> distribute
```

详见[组合任意 Skill 快速上手](/zh/skill-creator/getting-started)。

## Engine：进阶内容

如果你用 `/comet-any` 创建可复用 Skill，或用 `comet skill` 做本地调试和 Engine Run，你需要理解 Skill Engine——Comet 的确定性运行时。Engine 涉及 Skill 包结构、pending action/resume 循环、不可变快照、guardrails 和 runtime checks。

只用内置工作流 Skill 的用户**不需要理解 Engine**。想深入了解时，看[Skill 与 Engine（进阶）](/zh/skill-creator/engine)——完整的 Engine 机制详解，位于组合任意 Skill tab。
