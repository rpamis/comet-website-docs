<Update label="0.4.0-beta.18" description="2026-08-12" rss={{ title: "Comet 0.4.0-beta.18", description: "2026-08-12 发布记录" }}>
Beta 18 将 Eval 扩展为可以直接评估任意本地 Skill 的独立入口，同时加入 Native 大型需求编排和跨 worktree 的变更查看能力。

### Added（新增）

- **独立 Skill 评估入口**：可以直接运行 `comet eval ./my-skill` 评估本地 Skill，不需要先创建 `comet/eval.yaml`；完整使用流程见[快速上手：评估一个 Skill](/zh/eval/quickstart)。
- **任务发现与离线预检查**：支持 inline task、Skill 包内任务以及没有 manifest 时自动生成并缓存的 2–4 个任务；`--collect` 只做静态发现和配置检查，不启动 Agent 或 Docker。
- **可选择的评估 Agent 与独立 Judge**：评估可以选择 Claude Code、Codex、Qoder 或 CodeBuddy，并为主 Agent 与 LLM-as-Judge 分别配置模型、API 地址和凭据。
- **Langfuse 评估套件**：`comet eval --suite langfuse` 会同步 task trace、rubric score、pass 指标和实验摘要，同时保留本地报告。
- **Native 父子 Change**：大型需求可以在 Shape 阶段确认父子结构，Runtime 会按依赖推进 child，并在最终集成分支上验证父 Change 的完整目标。
- **跨 worktree 的 Dashboard**：Dashboard 会发现注册的 Git worktree，独立 Change 保持为根条目，Native 父 Change 可以展开查看 child 的状态和进度。
- **WorkBuddy 平台支持**：`comet init` 和 `comet update` 现在会把 Comet Skill 安装并更新到项目级 `.workbuddy/skills/` 或用户级 `~/.workbuddy/skills/`；项目级安装还会把 Comet Hook 合并到 `.workbuddy/settings.json`，同时保留已有配置。

### Changed（变更）

- **项目内 Hook 写入白名单**：项目可以在 `.comet/config.yaml` 的 `hook.allow_paths` 中配置项目相对目录，让共享规则或笔记在 Native Shape 或 Classic 非编码阶段仍可写入；Comet Runtime 和工作流自己的产物仍受保护。Hook 本身不会拦截项目外的写入，因此项目外路径无需配置白名单。
- **Classic 工作区路由**：创建或恢复 Classic change 时会根据当前分支和 worktree 绑定到对应工作目录，并在可用时复用已有 worktree。
- **Native 工作区复用**：Native 并行 Change 会复用匹配的 linked worktree；分支仍存在但 worktree 缺失时，恢复流程会重新创建它。

### Fixed（修复）

- **Classic Guard 项目根路径解析**：即使从项目内的嵌套工作目录运行，Classic design Guard 也会从已发现的项目根目录读取 delta spec，不再因当前工作目录不同而报路径不存在。

</Update>

<Update label="0.4.0-beta.17" description="2026-08-10" rss={{ title: "Comet 0.4.0-beta.17", description: "2026-08-10 发布记录" }}>
Beta 17 重构 Native 的完成与恢复路径：用户可读状态和文档可以跨设备继续，Runtime 负责必要检查和 Loop，Dashboard 直接展示同一份状态。

### Added（新增）

- **独立 Native Subagent 验收**：Builder 提交实现交接后，Runtime 运行必要检查，并分派全新的只读 Verifier 逐项检查 A1…An。Builder 自报“完成”不能直接归档；Skill 协调模式在归档前还需要一次明确的用户确认。
- **Trae Hook 支持**：`comet init`、`comet update`、`comet doctor` 和 `comet uninstall` 支持 Trae 与 Trae CN 的项目级、全局 Hook Router 配置，同时保留用户自己的 Hook 设置。

### Changed（变更）

- **更快的 Native Verify**：正常检查只执行一次并复用完成结果，输出流入本机日志；Verify 不再扫描或指纹化整个项目，Archive 正常路径也不重复验收。长 Maven、Gradle、npm 或 Python 输出不会仅因长度使有效结果失效。
- **可移植的 Native 状态**：`comet-state.yaml` 保存阶段、Loop、验收结果、交接、阻塞和下一步；`verification.md` 是可重建的用户报告，本机执行状态和日志留在 `.comet/runtime/native/`。
- **Native Dashboard**：Native 详情展示 Build/Verify 阶段、迭代、尝试、验收项、检查、阻塞、历史和用户可读产物；机器 Runtime 文件不出现在产物列表，旧归档通过只读适配器查看。
- **澄清与工作区选择**：新项目默认使用 Batch 澄清，先整理问题依赖再提问；创建 change 时会展示 `current`、`branch`、`worktree` 选择，并在恢复和链接 worktree 时保持正确归属。
- **Skill 与 CLI 指引**：Native 的公开命令和中英文 Skill 以 Runtime 返回的下一步为准，正常流程不要求手工拼接内部状态；阶段 Skill 的调用策略也更明确。

### Fixed（修复）

- **工作区与恢复路由**：链接 worktree、跨设备恢复、错误 checkout 和中断的 Archive 都会先检查当前状态，不会静默复用旧的通过结果或把 change 路由到另一个工作目录。
- **跨平台 Native 检查**：Windows 可正确执行 npm、pnpm 等命令 shim，超时会停止子进程树，减少平台相关的 Verify 失败。
- **Hook 与工作流隔离**：没有可信项目上下文的遗留全局 Hook 保持中性；Classic 专用参考只随 Classic 安装和加载；`comet doctor` 也能识别插件目录中的 Superpowers。

### Removed（移除）

- **旧 Native Runtime验收链**：新 change 不再生成旧的项目扫描、checkpoint、check、evidence、receipt 链。旧的 active change 会在需要时保守迁移，已经归档的旧 change 保持只读。

</Update>

<Update label="0.4.0-beta.15" description="2026-08-05" rss={{ title: "Comet 0.4.0-beta.15", description: "2026-08-05 发布记录" }}>
Beta 15 新增全局项目激活与 Native 并行 change，重构 Dashboard 变更浏览器和 Hook 生命周期，并修复验证、并行恢复与 Hook 相关的多项问题。

### Added（新增）

- **全局项目激活**：全局的 Native 或 Classic 默认值现在可以在未配置项目首次明确调用 `/comet` 时激活该项目；项目产物仍保留在项目内，已有的工作流归属会被保留，项目级初始化仍可用于本地覆盖。
- **Native 并行 change**：进入 Shape 前，Native 会检测活跃 change，并可自动创建隔离的 Git worktree；安全时仍保留 `current`、`branch` 和 `worktree` 选择，隔离的 change 会记住起始目标分支以便后续完成。

### Changed（变更）

- **Dashboard 变更浏览器**：Dashboard 现在加载轻量的 change 行，对活跃、归档和全部 change 分页显示，并只在选中后才获取完整详情；Native 和 Classic 在加载时保持所选详情面板稳定，详情加载失败时可重试，让大型项目保持响应。
- **Hook 生命周期与路由**：已激活的项目和隔离的 Native worktree 现在会自动获得一个项目级 Router；Setup、Update 和 Doctor 会迁移历史全局与遗留 Comet Hook，同时保留用户拥有的 Hook 配置，并在清理未完成时明确报告，而非静默继续。

### Fixed（修复）

- **全局 Native Skill 更新**：全局 `comet update` 现在只刷新已安装的工作流（包括 Native），不会新增用户未选择的工作流。
- **Native Verify 重试**：无效的验证报告会在必需检查运行前被拒绝；重试时未变化的成功必需检查回执会被复用，避免不必要的昂贵检查重复执行。
- **Native 并行恢复**：Ambient Resume 现在只对明确指定、已选中或唯一的 Native change 执行完整恢复检查，其他无关的活跃 change 不再触发无关的 Runtime 错误。
- **Subagent 工作流分发**：Classic Build 直接运行选定的创作工作流；Comet Any 让每条创作 lane 保持在指定工作流上，而不再根据平台特有的 Agent 标签替换。
- **Native scope 一致性**：Native 现在能检测 Git 修改文件视图下被隐藏的文件，避免误判 Build 与 Verify 的 scope 不一致而阻塞验证和归档。
- **Hook 写入处理**：没有活跃 Comet change 拥有目标时，项目 Hook 允许普通写入；对未知或外部目标（包括通过 symlink 或 junction 重定向的路径）保持中性，同时仍评估项目内写入。
- **Hook 配置安全**：Hook 安装不再覆盖用户拥有的 Kiro 文件或留下无效 Copilot 条目；Doctor 在报告 Router 健康前会检测过时遗留文件以及被禁用或结构不匹配的处理器。
- **Native receipt scope 恢复**：项目文件在 Build 后发生变化时，验证回执会在执行前停下，报告变化路径，并提供返回 Build 刷新实现 scope 的命令。
- **Classic build 恢复**：完整 Classic 工作流在上下文恢复后若没有有效实现计划，会回到计划创建阶段，并在计划恢复并关联前阻止项目源码写入。
- **Ambient Resume 清理**：禁用 Ambient Resume 时会从 `AGENTS.md` 和 `CLAUDE.md` 中移除 Comet 管理的指令，同时保留用户自己编写的内容。
- **Eval workspace Dockerfile**：workspace 没有根目录 Dockerfile 时，Eval 镜像准备现在会使用 `environment/Dockerfile`，这些 workspace 无需移动文件即可构建。

</Update>

<Update label="0.4.0-beta.14" description="2026-08-02" rss={{ title: "Comet 0.4.0-beta.14", description: "2026-08-02 发布记录" }}>
Beta 14 修复项目级更新、初始化与卸载中的配置兼容性和作用域问题，使现有项目更容易安全维护。

### Fixed（修复）

- **不完整项目配置**：`comet update` 和 Classic 根目录命令会补齐缺失的 Native 默认字段，而不是拒绝其他配置仍可用的项目。
- **更新作用域**：选择“仅当前项目”后，`comet update` 只刷新该项目；没有可更新的索引项目时会明确说明，而不会改动全局安装。
- **Classic 初始化兼容性**：为已有 Native 项目添加 Classic 时会保留已有根目录 `openspec/` 布局；在不支持硬链接的 exFAT 等文件系统上也能完成初始化。
- **Codex OpenSpec Skills**：项目初始化会将为 Codex 生成的 OpenSpec Skills 安装到其规范的 `.agents/skills/` 目录。
- **卸载选择与完成状态**：项目级卸载采用与初始化一致的平台批量选择；未选择的平台会被保留。选中的 Superpowers 配套 Skills 会被清理，保留用户工作目录内容不会再被误报为卸载失败，真实清理失败会显示原因，并按所选语言输出。

</Update>

<Update label="0.4.0-beta.13" description="2026-08-02" rss={{ title: "Comet 0.4.0-beta.13", description: "2026-08-02 发布记录" }}>
Beta 13 让日常工作流操作更快，并让卸载和 Dashboard 状态更容易判断。

### Added（新增）

- **Native 验证回执刷新**：新增 `comet native receipt refresh <change> [--apply]`，可检查失效的验证回执，并在可安全更新时重新生成手工回执；需要真实重跑的自动检查会明确列出，不会被误标为已通过。

### Changed（变更）

- **选择性工作流卸载**：交互式 `comet uninstall` 现在可按安装目标选择移除 Native、Classic 或两者。移除其中一个时会保留另一个工作流及其共用配置；移除 Classic 时可选是否清理 OpenSpec 与 Superpowers Skill，默认保留它们。
- **日常操作响应**：CLI 启动、Classic 与 Native 工作流命令、写入前检查以及 Native 快照更新均更快；Native 会优先复用未变化文件的已有结果，同时继续检查实际变更。
- **高频公共工作流命令**：高频 Native、Classic 与工作流解析命令保持稳定的 `comet` CLI 接口，同时在内部转入包内 runtime bundle；无需依赖宿主特有的 Skill 路径即可降低冷启动开销。
- **Dashboard 工作区**：Dashboard 提供更清晰的项目切换、搜索和 change 详情查看体验；从仓库子目录启动时能发现项目，并在独立、只读的 Native 工作区旁呈现 legacy 与 docs 布局中的 Classic change。

### Fixed（修复）

- **Classic 配置兼容性**：初始化和更新能够保留已有 Classic 项目的目录选择，并在旧项目配置不完整时更可靠地识别可继续使用的目录。
- **可移植的工作流执行**：Native 与 Classic Skill 现在调用公共 `comet` CLI，而不再搜索特定平台的 Skill 目录或调用内部 bundle。未安装 CLI 时会清晰停止；工作流路由仍会立即通过 Skill 工具加载选中的 Skill。
- **Classic 执行选择**：Classic 现在展示工作流支持的全部隔离与执行选择；用户选定后直接运行对应动作，失败时报告原错误，不再预先筛除选项。
- **Dashboard 状态提示**：Classic change 的验证状态现在使用通过（绿）、失败（红）、待验证（琥珀）和中性颜色区分；无效端口会在启动前给出明确错误。

### Security（安全）

- **Classic 阶段保护**：宿主配置目录和 worktree 不再绕过 Classic 阶段限制，避免在非 Build 阶段通过 `.claude/` 等路径隐藏源码写入。
- **Dashboard 构建依赖**：更新 Dashboard 的 CSS 构建依赖，修复可能经由不可信 source map 引用读取非预期映射文件的风险。

</Update>

<Update label="0.4.0-beta.12" description="2026-07-30" rss={{ title: "Comet 0.4.0-beta.12", description: "2026-07-30 发布记录" }}>
Beta 12 简化 Classic 目录迁移与 Dashboard 定位，并收敛 Native 的验证证据、修复交互和恢复指引。

### Changed（变更）

- **Classic 根目录迁移**：`comet classic root move docs --dry-run` 直接报告当前状态、冲突与阻塞项，不再生成 plan ID；`--apply` 无需 plan ID 即可迁移完整 `openspec/` 目录，包括活跃和未完整归档的 change。输出遵循 `classic.language`，已使用 `docs/openspec/` 的项目会得到明确的无需操作结果。
- **Native 工作流指引**：Native 会先识别当前 change 与阶段，再加载对应阶段的参考；进入实现前始终完成 Shape 分类、静默假设检查与共享理解确认。Build 中出现新的用户决定时，会暂停实现、重新澄清并确认更新后的需求，再继续推进。项目级和 change 级命令按任务组织，减少与当前阶段无关的信息。
- **Native 验证与修复**：Verify 通过时自动运行并绑定内置必需检查。验收证据可以来自人工观察或由 Runtime 执行的项目命令；命令执行支持 Windows shim，并在保存摘要前清理疑似凭据。Runtime 从失败证据推导修复缺口；仍有一次 override 时由 Agent 提出新的具体修复假设，override 或验证预算耗尽后才返回一次明确的用户决策。

### Fixed（修复）

- **Classic Dashboard 定位**：从仓库子目录启动 Dashboard 时会自动定位项目根目录，并按 `classic.artifact_layout` 读取 Classic change；采集失败会显示错误，不再伪装为空工作区。
- **显式 Comet Skill 路由**：`/comet` 只在你明确调用它，或明确要求使用 Comet 但未指定 Native 或 Classic 时进入。入口会直接按项目配置进入 Native 或 Classic，并保留原始请求，不再重新判断任务是否相关或按任务规模改选工作流。
- **失效的当前 change 选择**：当当前选择指向已不存在或已归档的 change 时，Comet 会重新检查活跃 change：没有候选时可正常处理其他工作；唯一候选仅用于只读恢复；多个候选时仍要求你明确选择。
- **Native baseline 恢复提示**：baseline 不完整时的诊断会同时提示 `native.snapshot.max_files`、总字节与时长预算，文件数超限可以直接定位到对应配置。

### Removed（移除）

- **Native 密码学审查**：移除 controller trust、签名身份、实现声明、独立审查和 waiver receipt 及其 CLI/Eval 交接路径。Native 现在只依赖绑定到当前 revision、contract、scope、snapshot 与产物的完整验收证据和内置必需检查。
- **冗余 Native CLI 输入**：移除 `comet native list` 别名、manual receipt 的 `--responsible` 与 `--confirmed`，以及由调用方传入的 `next --receipt`、`--evidence-receipt`、`--failure-category` 和 `--failed-check`。使用不带 change 名称的 `status` 查看列表，并在 `verification.md` 中引用验收 receipt；仍持有 v2 receipt 的 active change 需要重新记录 schema v3 证据。

</Update>

<Update label="0.4.0-beta.11" description="2026-07-29" rss={{ title: "Comet 0.4.0-beta.11", description: "2026-07-29 发布记录" }}>
Beta 11 简化 Native change 创建，并补齐项目配置的默认值和升级迁移。

### Changed（变更）

- **项目配置默认值**：新 Classic 配置默认使用 `classic.artifact_layout: docs`。`comet update` 会补齐缺失的 Native 与 Classic 托管字段；只有检测到需要保留的根目录 `openspec/` 项目时才继续写入 `legacy`。
- **按风险触发 Native 审核**：独立审核由真实 implementation scope 与风险决定，不再由 change 创建时的签名模式决定。普通 change 可以直接开始，高风险验证仍保持失败闭合。

### Removed（移除）

- **Native 创建授权**：`comet native new` 不再要求 `--creation-authorization`；`signed-v2` 创建协议和 `comet native trust authorize` 已删除。

</Update>

<Update label="0.4.0-beta.10" description="2026-07-28" rss={{ title: "Comet 0.4.0-beta.10", description: "2026-07-28 发布记录" }}>
Beta 10 重点引入 Native Loop，为 Classic 提供可选择、可迁移的文档目录布局，并修复本地 workflow Eval 与 Creator Bundle 的兼容链路。

### Added（新增）

- **定向平台安装与更新**：`comet init` 和 `comet update` 新增 `--platform <platform>`。需要修复或刷新单个平台时，不必重新处理项目中的其他平台；未指定该参数时，仍沿用现有的自动检测与回退行为。
- **CodeGraph 索引生命周期**：非交互项目初始化可以显式选择 `comet init --codegraph init|skip`。`comet doctor` 会区分 CLI 缺失、索引缺失、不完整、过期和可用状态；只有经过授权的 `comet doctor --repair --yes` 才会执行初始化、重建或同步（[#245](https://github.com/rpamis/comet/issues/245)）。

- **Native 证据化验收**：每条强制验收项都必须绑定当前 snapshot 和 scope 下的有效证据。Native 可以分别记录自动检查、人工观察、实现声明、独立审查和经批准的结构化豁免；失败、跳过、阻塞、过期或覆盖不完整的证据不能产生通过结果，高风险变更还需要独立复核（[#240](https://github.com/rpamis/comet/issues/240)）。

### Changed（变更）

- **Classic 文档目录**：新建的 Classic 或双工作流项目默认把 OpenSpec 产物放在 `docs/openspec/`，与 `docs/comet/`、`docs/superpowers/` 组成统一文档目录。已有项目继续使用当前的根目录 `openspec/`，除非显式迁移；所有 Classic 命令都会遵循所选布局（[#173](https://github.com/rpamis/comet/issues/173)）。

- **Native 归档确认**：`native.archive_confirmation: required` 会在最终 Archive 候选上要求一次明确决定；保持默认配置时继续自动归档。中间修复轮次不会触发归档确认，选择暂不归档也会保留当前 active change（[#238](https://github.com/rpamis/comet/issues/238)）。
- **Native 渐进式指引**：Native 入口优先呈现当前阶段、验收缺口和下一动作，只有在需要时才加载澄清、命令、产物与恢复细节。

### Fixed（修复）

- **本地 Eval 执行环境**：本地任务镜像现在包含评估所需的 Claude Code，并以非 root 用户运行，quick 和 full Eval 可以稳定识别执行环境并启动 runner（[#229](https://github.com/rpamis/comet/issues/229)）。

### Security（安全）

- **Native 审批隔离**：签名工作流的审批凭据保存在项目和实现者之外，项目内的变更不能自行取得批准权限（[#240](https://github.com/rpamis/comet/issues/240)）。

- **Comet Native 工作流**：新增独立的 `/comet-native` 工作流，不依赖 OpenSpec、Superpowers 或其他外部 Skill。它使用 Shape、Build、Verify、Archive 四个阶段，支持可恢复 checkpoint、完整目标规格和独立的 change 状态。需求澄清默认使用 `sequential`，每轮只处理一个最上游问题；你也可以切换到 `batch`，一次回答当前所有独立问题。参见 [Native 工作流](https://docs.comet.rpamis.com/zh/concepts/native-workflow)和 [Native 快速开始](https://docs.comet.rpamis.com/zh/native/quickstart)。

- **CodeBuddy Hook 支持**：CodeBuddy Code 的项目级和全局安装现在会把 Comet PreToolUse hook 非破坏性合并到 `.codebuddy/settings.json`，保留用户已有插件、设置和 hook；配置无效时会保持原文件不变并明确报告失败（[#193](https://github.com/rpamis/comet/issues/193)）。

### Changed（变更）

- **混合 change 状态**：`comet status` 现在区分 Comet 管理的 change 与普通 OpenSpec change，并只为已就绪的条目推荐对应归档命令（[#187](https://github.com/rpamis/comet/issues/187)）。

- **生成式 Eval manifest**：`comet eval` 会在运行时把 Skill Factory manifest 中的 `draftHash` 占位值解析为当前版本绑定值，因此 `/comet-any` 的产物可以直接评估，且不会改写生成的 Bundle 文件（[#183](https://github.com/rpamis/comet/issues/183)）。
- **Eval harness 定位**：通过 npm 安装的 `comet eval` 现在默认使用同版本随包分发的 harness，并把“harness 缺失”与“`uv` 不可用”分别报告，便于准确定位环境问题。
- **跨项目更新结果**：`comet update --all-projects` 会把 npm 包更新失败计入对应项目的失败结果；项目索引不可读时会明确失败，不再把问题报告成成功或空索引。
- **Dashboard 响应式工作区**：`comet dashboard` 在显示左侧导航时会把 change 工作区保持在视口内；打开 artifact preview 会保留滚动位置，已归档 change 会显示为完成状态，而不是再次建议 verify（[#170](https://github.com/rpamis/comet/issues/170)）。

- **OpenSpec CLI 安装范围**：即使选择项目级 Comet 安装，`comet init` 也会把 OpenSpec CLI 作为全局工具安装或升级，不再因为该选择在项目中创建 `node_modules/`（[#175](https://github.com/rpamis/comet/issues/175)）。

- **归档最终确认**：`/comet-archive` 会把用户最终批准记录到机器管理的 Classic 状态；在确认 transition 成功前，真实归档命令拒绝修改，避免直接调用脚本绕过确认。
- **归档注释格式**：Classic 归档注释会保留正常的 Markdown 文件结尾，并可安全重复执行，避免产生 `git diff --check` 格式错误（[#185](https://github.com/rpamis/comet/issues/185)）。
- **全局产物语言**：全局 `comet init` 和 `comet update` 会把所选产物语言保存到 `~/.comet/config.yaml`。Classic workflow 优先读取项目配置，再回退到全局默认；项目仍可覆盖该设置（[#174](https://github.com/rpamis/comet/issues/174)）。

<Update label="0.4.0-beta.1" description="2026-07-06" rss={{ title: "Comet 0.4.0-beta.1", description: "2026-07-06 发布记录" }}>
这是 0.4.0 线的第一个 beta。相对于 0.3.9，Comet 从一个依赖 Bash 的 `/comet` 工作流包，变成了一个跨平台 Node 运行时，覆盖工作流、Skill 创建、评估和可视化四大能力。下面的条目描述的是最终用户可见的发布形态，不是分支开发历史。

### 重点变化

- **纯 Node 运行时**：所有 Comet 脚本通过 Node.js 运行，macOS、Linux、Windows 用同一套命令，不再需要 Bash、Git Bash 或 WSL。
- **`/comet-any` Skill Creator**：从"生成一个 `SKILL.md`"升级为生成稳定的组合 Skill Bundle，带可评审的创作内容、发布证据链和平台原生文件。
- **`comet eval` 评估系统**：可量化任意本地 Skill 和 Comet 工作流的质量，含 pass@k/pass^k 可靠性指标和 HTML 报告。
- **配置化产物语言**：`comet init` 现在记录项目级产物语言，OpenSpec 和 Superpowers 产物按配置语言输出。
- **`comet dashboard`**：本地只读浏览器面板，可视化每个变更的阶段、产物、任务和风险。
- **路由上下文**：`/comet` 用结构化路由上下文做可解释路由，风险信号优先于口头流程。

### Added（新增）

- **跨平台 Classic 运行时**：随包分发的 `/comet` 工作流脚本现在通过 Node `.mjs` 启动器运行，背后由 TypeScript Classic 运行时支撑。同一套工作流在 Windows、macOS 和 Linux 上运行，不再需要 Git Bash、WSL 或兼容 shell 的脚本。
- **`comet dashboard`**：新增本地只读浏览器面板，展示进行中和已归档的变更，包括阶段进度、产物分组、任务进度、verify 状态、下一步指引、风险信号、Git 上下文、带元数据的产物预览，以及亮色/暗色 UI。`--json`、`--port`、`--no-open` 和 `GET /api/dashboard` 把同一份快照暴露给脚本和 CI。
- **`/comet-any` Skill Creator**：新增创建或升级可复用 Skill 的主流程。流程覆盖候选发现、可确认的方案、生成的 Skill Bundle、创作决策/指导区、创作车道、当前 draft 的评估就绪、评审批准、发布、分发，以及 Claude Code custom agents 等平台原生文件。
- **Skill Creator CLI**：新增 `comet creator` 用于常规创建/恢复指引，`comet publish` 用于评审、批准、发布和分发预览，后端 Bundle 命令保留为高级工具。
- **本地 Skill 工具**：新增 `comet skill add|show|run|continue|check`，用于安装、检查、运行、恢复和确定性校验本地 Skill 包（带快照）。
- **`comet eval` harness**：新增仓库本地评估，支持 Comet 工作流和任意本地 Skill，含 task profile、生成的 manifest、HTML 报告、token/cost 归因、pass@k/pass^k 可靠性指标、工作流专用评分、Skill 调用证据检查、可配置的模拟器提示词、Anthropic 兼容代理认证、Windows/WSL 友好执行、UTF-8 日志和回归门禁。
- **Comet workflow 评估任务**：内置 Comet workflow benchmark 扩展到 20 个任务，新增 dependency-confusion、layered streaming、persistence、approval、noise-resistance、cross-file refactor、observability config、graph execution review、agent memory routing、framework selection 等场景，用于更稳地比较 CONTROL、0.3.9 和 0.4.0。
- **Hotfix/tweak 范围决策**：为 hotfix 和 tweak 工作流新增定性升级信号；文件数量阈值现在会暂停询问用户确认，而不是强制自动升级到完整工作流（[#121](https://github.com/rpamis/comet/issues/121)）。
- **支持的平台**：新增 ZCode、MimoCode、Trae CN 和 Antigravity 2.0 支持。Antigravity 2.0 全局安装在 `~/.gemini/config/skills/`；ZCode 和 MimoCode 使用 OpenCode 兼容布局；Trae CN 使用 `.trae-cn/skills`。
- **符号链接安装模式**：`comet init` 和 `comet update` 现在可以选择用复制或符号链接/junction（从共享的 `.comet/skills/` 存储）安装 Skill。
- **项目 Skill 偏好**：新增 `.comet/skill-preferences.yaml`，让项目可以引导首选 Skill、排序和 Skill Creator 方案，而不必手改 bundle 文件。
- **配置化产物语言**：`comet init` 现在把项目级产物语言（`en` 或 `zh-CN`）写入 `.comet/config.yaml`，每个新 change 会把该语言快照到 `.comet.yaml`。OpenSpec 和 Superpowers 产物按配置语言输出，不再按触发请求临时判断；Comet guard 会拒绝明显主语言不匹配的工作流产物，对无效 `language` fail closed，并忽略 fenced code block，避免命令、路径或 hash 干扰判断。

### Changed（变更）

- **Comet 产品定位**：README、CLI 帮助和 Skill 指引现在把 Comet 呈现为一个工作流和 Skill 平台：运行引导式工作流、创建 Skill、评估它们、发布它们，以及诊断卡住的变更。
- **Comet Skill 语言指令**：中英文 Comet Skill 现在读取配置化产物语言（仅 `en` / `zh-CN`，不接受别名）来约束 OpenSpec prompt、Superpowers 参数、subagent 调度、验证报告和归档说明，而不是从触发请求语言推断。
- **Eval judge provider**：LLM-as-judge 现在必须显式设置 `BENCH_JUDGE_MODEL`，并使用独立的 `BENCH_JUDGE_*` provider 配置；配置 judge endpoint 和凭证时优先走 Anthropic 兼容 HTTP。配置不完整时报告 skipped，不再静默复用被测模型、endpoint 或凭证。
- **LangSmith eval 配置**：LangSmith eval 现在从主要 `LANGSMITH_*` 配置派生 Claude Code tracing plugin 设置，trace 保持在配置的 base project，hook logs 保存到 artifacts，并可按需自动构建官方 Claude Code tracing plugin 到 eval cache。
- **Eval 对比报告**：报告现在区分 raw、analysis-set、flagged、excluded runs；把 CONTROL 作为 business-only baseline；拆分 overall、business、workflow 的 pass@k/pass^k；并输出论文风格 Markdown/HTML，含指标说明、rubric 维度说明、证据、失败归因、居中表格、中英文切换、Python 优先图表和 inline SVG fallback。

- **README 格式化策略**：根 README 文件从 Prettier 检查中排除，避免 formatter 改写用户可见 prose 和精确文档措辞。
- **Classic 工作流状态**：机器管理的运行检查点从 `.comet.yaml` 移到 `.comet/run-state.json`，而用户可编辑的工作流字段保持 YAML 可读。Classic 阶段转换现在还会写入 `.comet/state-events.jsonl`，形成可审计的状态历史。
- **Classic 运行时打包**：Classic 控制元数据现在放在 `comet/runtime/classic` 下，命令启动器拆成独立的 Node bundle（`comet-state.mjs`、`comet-guard.mjs`、`comet-archive.mjs` 等），同时保持现有 `/comet*` 命令行为不变。
- **工作流诊断**：`comet status` 和 `comet doctor` 现在共享同一条运行时证据路径，报告当前步骤、运行时模式、畸形状态、缺失证据和推荐恢复动作。
- **工作流路由**：`/comet` 现在对 full、hotfix、tweak、resume 和歧义请求使用显式的路由上下文模型。`/comet-tweak` 现在是 tweak 专用的 OpenSpec action 路径，而完整 `/comet` 仍走 Superpowers 的 design/plan/build 路径。
- **评审工作流**：`review_mode` 现在对 full 工作流默认为 `standard`。`off`、`standard`、`thorough` 形成更清晰的评审梯度，由 Comet 接管评审派发策略，用户不必为重叠的 Superpowers 和 Comet 评审循环买单。
- **交互式决策点**：Comet 决策点现在在可用时优先使用 Claude Code 的结构化提问 UI，其他平台降级为文本。
- **调试工作流**：Debug Gate 可以在按配置的评审流串行应用修复之前，先并行调查独立的失败组。
- **仓库布局**：源码移入 `app/`、`domains/`、`platform/` 和 `scripts/`，测试移到对应的 `test/app/`、`test/domains/`、`test/platform/`、`test/scripts/` 和 `test/repository/` 根目录，让贡献者的职责边界更清晰。

- **`review_mode` field for code review control**: 在 `.comet.yaml` 中新增字段 `review_mode`（`off` / `standard` / `thorough`），控制 build 和 verify 阶段的自动代码评审。`comet-build` 要求在执行之前由用户选择；`comet-verify` 和子 agent 调度根据模式调整行为；`comet-hotfix` 默认为 `off`。由 `comet-state.sh`、`comet-guard.sh` 和 `comet-yaml-validate.sh` 校验。

- **Hook guard cross-change false positives**: 修复了 `comet-hook-guard.sh` 让一个 change 的阶段错误地阻止对另一个 change 写入的问题。写入到 `openspec/changes/<name>/` 的操作现在由该 change 自己的 `.comet.yaml` 阶段控制，而不是由目录中找到的第一个活跃 change 控制。这涵盖了此前阻止全新 change 产物写入的两种情况：（1）一个标记为 `archived: true` 但尚未物理移到 `archive/` 子目录的旧 change，以及（2）一个停滞在 `archive` 阶段且 `archived: false`（尚未运行归档脚本）的旧 change。此外，`.comet.yaml` 尚不存在的新 change 目录（在 `/comet-open` 期间，产物在状态文件之前写入）被视为 `open`，因此 `proposal/design/tasks/specs` 的写入是被允许的。

- **Phase guard auto-transition handoff**: 修复了注入的 Comet 阶段守卫规则在 `guard --apply` 之后硬编码下一个 skill 的问题，这可能绕过 `auto_transition: false`。该规则现在将守卫后的交接委托给 `comet-state next <change-name>`，并遵循 `NEXT: auto|manual|done`，从而尊重手动阶段边界。
- **Executable permission loss on macOS after update**: `bin/comet.js` 和 `assets/skills/comet/scripts/` 下的所有 shell 脚本此前以 git 模式 `100644`（不可执行）提交。npm 更新后，macOS 用户丢失了 `comet` CLI 入口点的执行权限。已将所有 8 个文件在 git 中改为 `100755`，使 npm 安装始终保留可执行位。

- **comet-tweak missing debug handling**: `comet-tweak/SKILL.md` 缺少 `comet-hotfix` 已有的 systematic-debugging 要求——当 tweak 执行期间测试或构建失败时，该 skill 现在明确要求在提出源码修复之前加载 `systematic-debugging` skill，与 hotfix 行为保持一致。
- **OpenSpec per-artifact instructions compliance**: 中英文 `comet-open` 现在对每个标准产物应用 OpenSpec 的逐产物指令（`openspec instructions proposal/design/tasks --change "<name>" --json`），从 JSON 载荷中加载 `context`、`rules`、`template`、`instruction`、`resolvedOutputPath` 和 `dependencies`，替代了硬编码的产物文案。在指令失败时停止产物生成，而不是静默绕过项目规则（[#66](https://github.com/rpamis/comet/issues/66)）。
- **CI Windows path escaping in skill verification**: `init-e2e` 工作流的 Pi 设置验证步骤将 Windows `$RUNNER_TEMP` 路径（包含反斜杠）直接插入 `node -e "require('...')"` 的 JS 字符串字面量中，其中 `\a`/`\_` 被解析为转义字符并破坏了路径（`D:\a\_temp` → `D:a_temp`），导致 Node 20 和 22 上 `init-e2e (windows-latest)` 运行器失败。现在该路径通过环境变量（`process.env`）传递，使其永远不进入 JS 字符串字面量；Linux/macOS 不受影响。
- **OpenSpec source formatting**: 重新格式化了 `src/core/openspec.ts`（长行换行），以满足 `prettier --check`，解除对 `format:check` CI 步骤的阻塞。
- **Symlink-safe removal during uninstall**: `removeFile`/`removeDir` 在删除之前不再解析符号链接。此前，符号链接的 skill、规则或 hooks 目录的解析目标会被 `comet uninstall` 递归删除；现在符号链接目录会被直接 unlink。`isDirEmpty` 也不再将不可读的目录报告为空，因此清理操作不会删除它无法检查的目录。
- **`comet update --json` output corruption**: npm 继承的 stdio 此前会混入 JSON 文档；现在在 JSON 模式下会丢弃 npm 的 stdout/stderr，使机器可读的输出保持可解析。
- **`comet update --json` no-targets shape**: 当不存在已安装目标时发出的提前返回 JSON 现在包含 `codegraph: 'skipped'`，与正常输出结构一致，使消费者无需对空路径做特殊处理。
- **JSON-mode version-check latency**: `comet init` 和 `comet update` 现在在 JSON 模式下跳过 npm registry 的版本检查，无需网络往返即可输出。
- **Malformed hook settings resilience**: 手工编辑的设置文件将 hook 分组存储为非数组值时，不再在 init/update 的 hook 合并期间抛出异常；格式不正确的分组会被强制转换为空。
- **Markdown code-fence language tags**: 在 `file-structure.md` 和 `subagent-dispatch.md`（中英文）的围栏代码块中添加了 `text` 语言标签，以满足 MD040 lint 检查，与现有的 OpenSpec 格式化 CI 修复保持一致。
- **Skills manifest version drift**: 将 `assets/manifest.json` 版本从 `0.3.3` 提升到 `0.3.8`，以与 `package.json` 保持一致。

### Added

- **Auto-transition config**: 在 `.comet.yaml` 和 `.comet/config.yaml` 项目默认配置中新增了 `auto_transition`（`true`|`false`），让团队可以选择 Comet 是自动推进到下一阶段 Skill，还是暂停等待手动切换。当 `auto_transition: false` 时，build/design/open/verify skill 在满足退出条件后会停止，并打印下一步的手动操作指引，而不是直接调用下一个 skill。包含状态机白名单、枚举校验以及 schema（`comet-yaml-validate.sh`）覆盖（[#74](https://github.com/rpamis/comet/pull/74)）。
- **Deterministic next-step resolver**: 新增 `comet-state next <change-name>`，根据 `.comet.yaml`（`phase`、`workflow`、`auto_transition`）解析 guard 之后的路由逻辑，并输出结构化结果：`NEXT: auto|manual|done`、`SKILL: <skill-name>` 和 `HINT`（手动模式下）。这将下一步 skill 的路由逻辑集中到脚本中，避免在各 skill 文案中重复编写。
- **Workflow output language**: Comet 工作流现在通过显式的输出语言规则，将触发用户请求的语言传播到 OpenSpec 和 Superpowers 步骤中，确保生成的提案、设计、计划、验证报告和归档说明都能以用户的语言呈现，保持可读性。恢复已有的 change 时，会保留产物的主要语言，除非用户明确要求切换（[#53](https://github.com/rpamis/comet/pull/53)、[#37](https://github.com/rpamis/comet/issues/37)）。
- **Execution benchmark (Claude Code)**: 新增 `benchmark:execution`，一个包含三个测试阶段的基准测试框架：L1（基于交接上下文生成设计文档）、L2（基于交接上下文构建 note-board 模块并运行测试）和 L3（完整工作流——根据规格实现一个 dictionary 模块并运行 10 个 vitest 测试）。调用 Claude Code（`claude -p`），并测量实际的测试通过率、token 用量、重试次数、耗时和成本。在小/中/大规模下对比 `off` 与 `beta` 上下文压缩模式。支持 `--phase l1|l2|l3|both|all` 和 `--dry-run` 用于确定性验证。将共享工具函数（`spawnCapture`、`parseClaudeJson`、`buildClaudeArgs` 等）抽取到 `scripts/benchmark-utils.mjs`。

- **Token optimization: TDD skill single load**: build skill 现在在第一个任务之前只加载一次 `test-driven-development` skill（而不是每个任务都加载），在 10 个任务的工作流中可减少约 44K token。包含上下文压缩后的恢复指引，恢复时重新加载一次。
- **Token optimization: brainstorming checkpoint**: design skill 现在在用户确认设计方案后会写入 `brainstorm-summary.md`，提供一个上下文压缩恢复点，在上下文窗口压缩过程中保留已确认的决策。
- **Token optimization: incremental brainstorming checkpoint**: design skill 现在在头脑风暴过程中增量更新 `brainstorm-summary.md`，在平台驱动的上下文压缩发生之前，保留已确认的事实、候选决策、风险、测试说明和待解决问题。
- **Token optimization: active compaction gate**: design skill 现在在 `brainstorm-summary.md` 定稿之后、创建设计文档之前，要求一个主动的上下文压缩检查点，优先使用宿主平台的原生压缩机制，不可用时回退为手动提示用户。
- **Token optimization: plan creation subagent offload**: build skill 将 `writing-plans` 的执行卸载给子 agent，释放主会话的上下文。子 agent 从文件中读取设计文档和 tasks.md，并返回计划文件路径。子 agent 失败时回退为内联执行。
- **Token optimization: verification skill dedup**: verify skill 现在在 light/full 分支判断之前只加载一次 `verification-before-completion`，而不是在每个分支中都加载，消除了冗余的 skill 内容。
- **Token optimization: tasks.md incremental scan**: build skill 现在用 `grep` 查找未完成的任务，而不是在每次任务完成后重新读取整个 `tasks.md` 文件。
- **Token optimization: hash on-demand read in verify**: verify skill 在重新读取 OpenSpec 产物之前先检查 `handoff_hash`。当哈希匹配时，仅跳过 `tasks.md`（proposal.md 和 design.md 仍会读取以进行比较检查）。使用新增的 `comet-handoff.sh --hash-only` 标志。
- **`--hash-only` flag for comet-handoff.sh**: 新增向后兼容的标志，仅输出上下文哈希而不生成交接文件，供 verify 阶段进行哈希比对使用。在计算哈希之前会校验必需的文件是否存在。
- **CodeGraph integration in comet init**: `comet init` 现在提供一个可选步骤来安装和配置 CodeGraph（`@colbymchenry/codegraph`），用于语义化代码智能。它会自动检测受支持的平台（Claude Code、Cursor、Codex、OpenCode、Gemini、Kiro、Antigravity），若 CLI 缺失则自动安装，运行 `codegraph install` 进行 agent 接线，并初始化项目索引。在 `--json` 模式下会优雅跳过。
- **Stale PR automation**: 新增了一个定时触发且可手动运行的 GitHub Actions 工作流，将 90 天未活动的 pull request 标记为 stale，再过 30 天后关闭，帮助管理长期闲置的评审队列。
- **TDD mode field**: 在 `.comet.yaml` 状态机中新增 `tdd_mode`（`tdd`|`direct`），让用户选择在构建时是否强制执行 TDD。当 `tdd_mode: tdd` 时，子 agent 调度时会注入显式的 TDD 硬约束，绕过 implementer-prompt.md 中的条件触发。解决 [#67](https://github.com/rpamis/comet/issues/67)。
- **subagent_dispatch field**: 在 `.comet.yaml` 状态机中新增 `subagent_dispatch`（`null`|`confirmed`），确保 `build_mode: subagent-driven-development` 只有在平台真实的后台调度能力得到确认后，才能离开 build 阶段。
- **Verify retry limit**: verify skill 现在在连续 3 次验证失败循环后强制要求用户决策，防止无限自动重试。
- **Manual verify_mode override**: 当自动检测的模式不合适时，用户可通过 `comet-state set <name> verify_mode <light|full>` 覆盖自动验证规模评估。
- **Local context compression benchmark**: 新增 `benchmark:context`，一个本地 Codex 基准测试框架，会创建匹配的 `context_compression: off` 和 `beta` Comet 测试用例，针对每种模式运行 `codex exec`，并报告 token 节省量、规格漂移率、任务完成率、解析成功率和耗时。使用 `--dry-run` 进行确定性的非 Codex 验证。
- **Beta-gated context compression switch**: 项目安装现在会创建带有 `context_compression: off` 的 `.comet/config.yaml`，让团队可以通过设置 `context_compression: beta` 让新的 change 启用 beta 规格投影。此开关仅控制 OpenSpec 交接投影路径（`spec-context.*`）；上述工作流 token 优化默认开启，无需 beta 模式。
- **Beta spec projection handoff**: `/comet-design` 现在可以使用 beta 上下文压缩来生成 `spec-context.json` 和 `spec-context.md`，保留 OpenSpec 的需求和场景标题及源哈希，使精简的设计交接在降低 token 负担的同时不削弱验收覆盖度。

### Changed

- **executing-plans review gate**: 当 `build_mode` 为 `executing-plans` 时，build 阶段现在要求在 build→verify 阶段守卫之前至少加载一次 Superpowers 的 `requesting-code-review` skill 并请求一次代码评审。CRITICAL 级别的问题必须在 verify 之前修复；已接受的非 CRITICAL 问题必须在持久产物中记录接受理由。build 退出检查清单会强制执行此关卡（[#76](https://github.com/rpamis/comet/pull/76)、[#41](https://github.com/rpamis/comet/issues/41)）。
- **Phase advancement vs handoff wording**: 中文和英文 Comet skill 现在一致地区分守卫驱动的阶段推进（`--apply`，始终更新 `phase`）与下一步 skill 调用控制（`auto_transition`）。open/design/build/verify/hotfix/tweak 的指引现在统一通过 `comet-state next` 来路由自动/手动交接。
- **预设连续性措辞**: hotfix 和 tweak 指引现在明确记录连续执行模式下的 `auto_transition: false` 例外情况，移除了围绕 "always continue" 行为的矛盾措辞。
- **Verify hash-skip scoped to tasks.md only**: 完整验证即使哈希匹配也始终读取 `proposal.md` 和 `design.md`，确保目标满足度和设计一致性检查拥有完整上下文。
- **Design Doc creation stays in main session**: 设计文档以内联方式创建（不卸载给子 agent），以保留完整的头脑风暴对话上下文，防止复杂需求下信息丢失。
- **Subagent failure fallback**: 计划创建的子 agent 卸载包含显式的降级回退——如果子 agent 失败，主会话会内联加载 `writing-plans`。
- **Beta spec verbatim projection**: beta 上下文压缩现在按原样投影整个 spec 文件（`cat`），而不是按英文关键词（GIVEN/WHEN/THEN/AND/BUT）过滤。这消除了语言相关的匹配，确保中文或非英文 spec 的验收标准零漂移，并彻底移除了脆弱的 AWK 过滤器。
- **JSON structural validation**: `comet-guard.sh` 现在校验 `spec-context.json` 的结构（必需字段：`change`、`phase`、`mode`、`files`、`context_hash`）以及源文件引用覆盖度，替代了之前基于英文标题的 markdown 检查。守卫会在阶段转换之前捕获损坏或不完整的 JSON。
- **JSON file roles**: `spec-context.json` 的 `files` 数组现在包含 `role` 字段（spec 文件为 `spec`，proposal/design/tasks 为 `supporting`），彻底移除了依赖语言的 `projection` 数组。
- **--full warning in beta mode**: 在 beta 模式下运行 `comet-handoff.sh --full` 现在会发出明确的警告，而不是静默忽略该标志。
- **CodeGraph step in comet update**: `comet update` 现在会在更新 skill 文件的同时提示安装/更新 CodeGraph，使用与初始化相同的平台检测和 CLI 安装流程。
- **Rules and hooks distribution in comet update**: `comet update` 现在会在更新 skill 文件的同时，将防漂移阶段守卫规则和 hook 分发到所有已安装的平台，确保 Comet 升级后规则和 hook 保持同步。
- **Archive confirmation gate**: 中文 `/comet-archive` 现在在运行归档脚本之前会暂停以获取用户的明确确认，让用户在主 spec 合并和 change 归档之前有最后的机会进行调整或重新验证。
- **English archive confirmation parity**: 英文 Comet skill 现在与已确认的中文归档确认工作流保持一致，包括 `/comet-archive`、`/comet-verify`、`/comet`、hotfix 和 tweak 指引。
- **Archive reopen transition**: 新增 `comet-state transition <change-name> archive-reopen`，让拒绝最终归档确认的用户可以从 `phase: archive` 返回 `phase: verify` 进行调整或重新验证，无需手动编辑 `.comet.yaml`。
- **OpenSpec clarification gate**: 中文和英文 `/comet-open` 现在要求在创建 proposal、design 或 tasks 产物之前，先确认一份需求澄清摘要，防止一轮问答就立即生成完整的 OpenSpec change。
- **PRD split preflight**: 中文和英文 `/comet-open` 现在会在创建 OpenSpec 产物之前对大型 PRD 进行分拣，允许用户将独立的功能拆分为多个 Comet change，同时让每个被接受的拆分项保持在 `/comet-open` 的状态机路径上。解决 [#62](https://github.com/rpamis/comet/issues/62)。
- **Skill invocation wording guidance**: 在 `CLAUDE.md` 中新增了仓库指引，要求新的 skill 触发描述使用既有的 "use the Skill tool to load..." 措辞，并在 skill 加载之后再放置上下文细节。
- **Anti-drift phase guard rule**: 新增 `.claude/rules/comet-phase-guard.md`，在每轮对话中重新注入 Comet 阶段感知、skill 调用要求、脚本执行要求、用户确认关卡和上下文压缩恢复指引，防止长上下文注意力漂移破坏 5 阶段工作流。在所有平台上作为软提醒生效。
- **Anti-drift phase guard hook**: 新增 `comet-hook-guard.sh` PreToolUse hook（配置在 `.claude/settings.local.json`），当当前 Comet change 处于 `open`、`design` 或 `archive` 阶段时硬性阻止文件写入，提供模型无法绕过的、平台特定的硬性执行层。将 `openspec/*`、`docs/superpowers/*`、`.claude/*` 和 `.comet/*` 路径加入白名单。
- **Platform rules/hooks distribution in comet init**: `comet init` 现在在初始化期间将防漂移阶段守卫规则和 hook-guard 脚本分发到所有受支持的平台。修正了平台定义：Cline 使用项目根目录下的 `.clinerules/`（而非 `.cline/rules/`），GitHub Copilot 使用带 `applyTo` frontmatter 的 `.github/instructions/*.instructions.md`，Kiro 使用 `.kiro/steering/`，Gemini CLI 没有规则目录（使用 GEMINI.md 文件）。为 8 个缺少规则配置的平台新增了 `rulesDir`/`rulesFormat`，为 7 个平台新增了 `supportsHooks`/`hookFormat`。hook 安装支持 7 种格式变体：Claude Code、Gemini、Windsurf、Copilot、Qwen、Kiro 和 Qoder。
- **Systematic debugging gate**: 中文和英文 build 及 hotfix skill 现在要求在实现阶段出现崩溃、意外行为、测试失败或构建失败时加载 Superpowers 的 `systematic-debugging`，确保在修复源码之前先进行根因分析并在当前 change 中编写回归测试。
- **Verification-before-completion gate**: 中文和英文 `/comet-verify` 现在要求在执行轻量或完整验证检查之前加载 Superpowers 的 `verification-before-completion`，在任何完成声明之前强制执行基于证据的确认。
- **Platform-neutral confirmation gates**: 中文和英文 Comet skill 及恢复消息现在引用当前平台的用户输入/确认机制，而不是硬编码 `AskUserQuestion`，避免 Codex 用户被指引去使用可能不存在的工具，同时保留阻塞性的用户决策。
- **预设升级路径**: hotfix 和 tweak skill 现在在升级到 full workflow 时包含 `set <name> phase design` 步骤，避免 workflow 切换后触发 comet-design 入口检查失败。
- **Build-complete conditional field reset**: `build-complete` 转换在前一次 verify_result 为 `fail` 时会保留 `verification_report` 和 `branch_status`，使 verify-fail→build→build-complete 的重新验证循环不丢失数据。
- **Open phase recovery granularity**: open 阶段恢复现在区分三种状态（所有产物完成 / 无产物完成 / 部分完成），并为每种状态提供具体的恢复操作。
- **50% scope threshold option**: build skill 现在在改动超过 50% 范围时提供"在当前 change 中继续"作为第三个选项，避免强制拆分 change。
- **Worktree plan commit**: build skill 现在明确指示在使用 worktree 隔离时，先提交计划文件再创建 worktree。

### Removed

### Fixed
