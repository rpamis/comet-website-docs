<Update label="0.4.0-beta.7" description="2026-07-20" rss={{ title: "Comet 0.4.0-beta.7", description: "2026-07-20 发布记录" }}>
### Added（新增）

- **Comet Native 工作流**：新增面向强模型的自包含工作流。需求澄清支持默认的 `sequential` 模式和可配置的 `batch` 模式：前者每轮询问一个最上游问题，后者一次提出本轮所有可回答问题，并在 Build 前要求最终共享理解确认。Claude Code 在整轮可由一次调用完整表达时优先使用 `AskUserQuestion`；否则整轮降级为编号文本，不拆分问题轮次。单 Skill 持续推进、可配置产物根、默认语言、完整目标规格、checkpoint 和有界状态都不依赖 OpenSpec、Superpowers 或其他外部 Skill。
- **证据绑定的自主执行**：新增 Git-owned 项目 snapshot，只纳入 tracked 与未被 ignore 的 untracked 文件并把 submodule/gitlink 作为原子条目；非 Git 项目使用带前后枚举围栏的有界物理树 snapshot。同时加入有界 overflow evidence、contract-hash-bound approval、Acceptance ID、不可变验证报告快照、可选内置只读 check receipt、证据失效回退、partial scope 授权和 repair episode。新建 change 或旧 schema migration 在提交状态前必须取得完整 baseline；不完整的当前 snapshot 不会伪造删除。没有真实 scope 进展时会停止重复失败。
- **可恢复的 Native 安全边界**：新增 schema 迁移、revision/CAS 与 live mutation 串行化、受保护 Run/文件 I/O、workspace identity、当前 root 冲突检查、两步 Archive、exactly-once 事务恢复、安全 root move、显式陈旧锁接管、有界 evidence retention 和只读 Dashboard projection。
- **稳定工作流入口**：新增永久 `/comet-native`、`/comet-classic` 与 `comet workflow resolve`。`/comet` 是配置驱动别名，只选择一套工作流，不转换或混合两边的 change、状态与产物；Skill-only 安装在 CLI 不可用时仍可使用随包 resolver。
- **Native 基线评估**：对齐 0.4.0 基线的 16 个任务与重复运行，按 `task_id + repetition` 配对并修正多轮调用耗时；Wave A–F fixture/validator 单独验证机械契约，不把静态覆盖包装成真实模型性能。
- **可选 Eval suite**：新增 `comet eval --suite local|langsmith`。Local 保持默认；LangSmith 模式复用同一任务语料和评分逻辑，由 CLI 启动 tracing-aware runner、报告目录与 Claude Code tracing plugin。
- **统一工作流保护**：每个平台只安装一个跨工作流 Rule，支持 Hook 的平台只安装一个 Router；共享 current-change selection 把一次原子多文件写入最多路由给一个 Guard，避免 Native 与 Classic 双重阻塞，并迁移已有 Classic selection 与旧托管 Hook/Rule。

### Changed（变更）

- **Node.js 运行时要求**：Comet 现在要求 Node.js 22 或更高版本。
- **对齐的 Eval 效率指标**：Native 对比报告现在从 raw trace 重新计算配对的模型启动/恢复、turn、tool call、累计耗时、token、成本与上下文压力，并使用严格成功交集，避免缺失 telemetry 或未完成任务夸大效率。
- **可选项目工作流**：项目级 `comet init` 会说明并提供 Native、Classic 或同时启用两者；新项目默认 `/comet` 进入 Native，Native 产物默认位于 `docs/comet/`。`--workflow both` 安装两套独立能力，共享 `.comet/config.yaml` 但不合并状态；完成摘要只展示实际初始化的工作目录。
- **明确的 Native 状态文件**：Active 与 archived Native change 统一使用 `comet-state.yaml`，同时保持与 Classic `.comet.yaml` 的 schema 和生命周期独立。
- **分区状态与恢复**：`comet status` 展示配置入口，并分别报告 Native、Classic 与未托管 OpenSpec change；`comet resume-probe` 返回 workflow-aware v2 结果，只从 `/comet-native` 或 `/comet-classic` 恢复，并在配置或状态损坏时失败关闭。
- **可配置环境感知恢复**：`.comet/config.yaml` 新增 Native 与 Classic 共用的 `ambient_resume` 开关；生成的配置注释跟随 init/update 语言，旧配置默认保持启用。
- **Classic 配置命名空间**：Classic 的 `language`、`context_compression`、`review_mode` 和 `auto_transition` 默认值迁入 `.comet/config.yaml` 的 `classic:` 块。`comet init` 与 `comet update` 会迁移旧顶层值，优先保留明确的新格式配置。
- **显式 npm 自更新**：current-project `comet update` 默认只刷新托管资产，不修改任何 npm 安装；需要更新 CLI 时必须传入 `--self-update`。显式 `--scope global` 也确定性使用 current-project 资产范围且不会隐式更新包；较宽更新可用 `--skip-self-update` 跳过包更新。自更新比较包含预发布版本的完整 semver、拒绝降级、隔离验证精确候选 CLI，并在安装失败时尝试恢复原精确版本。

### Fixed（修复）

- **初始化与更新错误报告**：`comet init` 与 `comet update` 对 incomplete 工作返回非零退出码，在 JSON 中保留 npm 诊断，标出批量更新中的失败与未尝试项目，并在组件失败后不再显示成功横幅或隐藏清理错误。
- **OpenSpec 安装诊断**：已安装的 OpenSpec CLI 版本过旧且未选择升级时，初始化会明确说明版本不满足要求，不再误报为 CLI 不可用。
- **Windows 交互式 Eval**：Docker 交互评估优先使用 Git Bash，保留容器 prompt 路径，按真实 driver turn 计数，并正确区分用户决定、完成状态和环境失败。
- **并行 Eval 协调**：Windows xdist worker 会等待共享 Docker build lock，不再把正常并发报告为资源死锁。
- **npm 发布缓存清理**：发布预检会在文件系统检查前排除嵌套和平台特有的 pytest cache，避免不可读的本地 Eval 派生目录阻塞发布或进入 npm 包。

</Update>

<Update label="0.4.0-beta.6" description="2026-07-20" rss={{ title: "Comet 0.4.0-beta.6", description: "2026-07-20 发布记录" }}>
### Added（新增）

- **`comet state rebind`**：用户明确确认当前分支应接管 change 后，可以用新命令重新绑定工作分支并记录审计事件；尚未建立首次绑定或处于 detached HEAD 时会拒绝执行。

### Changed（变更）

- **工作区分支绑定**：`current`、`branch` 和 `worktree` 三种隔离方式都会记录建立时的 Git 分支。后续切换分支会被 build、verify、archive 入口检查和源码写入守卫阻止；选择漂移的 change 也会失败，而不会静默覆盖绑定。旧 change 会在下一次 select 或 check 时补齐绑定，非 Git worktree 项目不受影响。
- **工作区隔离选择**：full、hotfix 和 tweak 都会让用户显式选择继续使用当前分支、创建新分支或创建 worktree，不再替用户静默决定。full workflow 现在也支持 `isolation: current`（[#190](https://github.com/rpamis/comet/issues/190)）。
- **状态与归档提示**：`comet status` 的文本和 JSON 输出会显示隔离方式与绑定分支；`current` 隔离归档时只询问推送当前分支或保留本地，不再提供面向功能分支的合并/PR 选项。

### Fixed（修复）

- **Skill 发现容错**：无关本地 Skill 的 YAML frontmatter 格式错误不再中断 Bundle Factory 指引或候选发现，Comet 会跳过损坏的描述并继续扫描。
</Update>

<Update label="0.4.0-beta.5" description="2026-07-14" rss={{ title: "Comet 0.4.0-beta.5", description: "2026-07-14 发布记录" }}>
### Changed（变更）

- **Skill 触发与决策创作**：内置阶段 Skill 和 Creator 生成的内部 Node Skill 明确入口与 Runtime 边界；Creator 在生成暂停点前区分自动处理、停止条件和人工交接，减少不必要的内部 Skill 调用与用户提问。
- **工作流 checkpoint**：清晰请求跳过多余命名确认；Build 预检可执行能力并合并相邻配置决定；大型 PRD 使用可恢复批次 manifest，恢复不再依赖未写入磁盘的对话状态。
- **验证修复与归档归属**：前三次可执行验证失败自动返回 Build，并跨恢复保存连续失败次数；Verify 只记录证据，Archive 在分支处理前只提交归属路径，确保最终分支包含规格和归档元数据。
- **Preset 执行语义**：Hotfix/Tweak 会如实记录当前工作区隔离，直接模式仍保留回归测试，升级完整工作流后清除轻量执行设置。
- **Dashboard 产物预览**：Markdown 预览支持表格、引用、任务列表、语法高亮和 Mermaid；全屏目录、重复标题锚点、长路径复制以及 YAML/JSON 结构化表格也得到统一处理。

### Fixed（修复）

- **OpenSpec 兼容性**：要求 OpenSpec 1.5+，并从 live schema 驱动 `/comet-open`，校验项目相对路径与具体输出，恢复 split batch 时不重建已完成 change。
- **Codex Hook 配置**：项目级和全局 Codex 安装写入受支持的 `.codex/hooks.json`，并安全迁移旧的 Comet 管理配置（[#199](https://github.com/rpamis/comet/issues/199)）。
- **标准 Superpowers 产物**：Classic 写入守卫接受标准目录中的首次设计、计划和验证产物，同时保留阶段、选择和重复占位检查。
- **Skill 生命周期完整性**：初始化、更新、Doctor 和卸载会一致报告 Skill、Rule、Hook 失败，保留损坏的用户 Hook 配置，并避免把部分安装登记成成功。

### Security（安全）

- **Dashboard 预览 XSS 防护**：Markdown/YAML/JSON 预览使用 DOMPurify，阻止危险 URL 与属性注入；Mermaid 使用严格安全模式，避免不可信产物执行脚本。

</Update>

<Update label="0.4.0-beta.4" description="2026-07-11" rss={{ title: "Comet 0.4.0-beta.4", description: "2026-07-11 发布记录" }}>
### Added（新增）

- **自然语言恢复探测**：新增低噪声的恢复探测机制和项目说明。继续处理已有工作时，即使没有显式输入 `/comet`，Agent 也可以先探测当前请求是否适合恢复活跃 workflow；存在歧义、未提交改动或需要用户决策时仍会暂停确认。
- **项目安装索引**：项目级安装会登记到用户级索引。交互式 `comet update` 和 `comet uninstall` 可以在当前项目与所有已登记项目之间选择；`--json` 或显式 `--current-project` 会限定当前项目，`comet uninstall --force` 也保持当前项目，跨项目操作需要显式使用 `--all-projects`。
- **稳定的 Classic 命令**：新增顶层 `comet state`、`comet guard`、`comet handoff` 和 `comet archive` 命令，Agent 和自动化不再需要依赖安装目录中的内部脚本路径（[#186](https://github.com/rpamis/comet/issues/186)）。
- **自定义项目命令证据**：无法自动推断 npm、Maven 或 Cargo 命令的项目，现在可以记录真实执行的 build/verify 命令及退出结果，形成可审计证据，而不必使用未文档化的跳过路径（[#192](https://github.com/rpamis/comet/issues/192)）。
- **CodeBuddy Hook 支持**：CodeBuddy Code 的项目级和全局安装现在会把 Comet PreToolUse hook 非破坏性合并到 `.codebuddy/settings.json`，保留用户已有插件、设置和 hook；配置无效时会保持原文件不变并明确报告失败（[#193](https://github.com/rpamis/comet/issues/193)）。

### Changed（变更）

- **混合 change 状态**：`comet status` 现在区分 Comet 管理的 change 与普通 OpenSpec change，并只为已就绪的条目推荐对应归档命令（[#187](https://github.com/rpamis/comet/issues/187)）。

### Fixed（修复）

- **并行 active change 守卫**：当多个 change 同时活跃时，源码写入会绑定到显式选择的当前 change。合法的 build 工作不再被另一个处于 open、design 或 archive 的 change 误阻塞；选择不明确时会给出可执行的选择提示（[#196](https://github.com/rpamis/comet/issues/196)）。
- **Codex CLI Skill 发现路径**：Codex 的项目级和全局安装现在把 Comet Skill 放在当前的 `.agents/skills` 发现目录中，Codex 专属配置仍保留在 `.codex`。更新和卸载会迁移 Comet 管理的旧 `.codex/skills` 内容，并保留无关 Skill。
- **生成式 Eval manifest**：`comet eval` 会在运行时把 Skill Factory manifest 中的 `draftHash` 占位值解析为当前版本绑定值，因此 `/comet-any` 的产物可以直接评估，且不会改写生成的 Bundle 文件（[#183](https://github.com/rpamis/comet/issues/183)）。
- **Eval harness 定位**：通过 npm 安装的 `comet eval` 现在默认使用同版本随包分发的 harness，并把“harness 缺失”与“`uv` 不可用”分别报告，便于准确定位环境问题。
- **跨项目更新结果**：`comet update --all-projects` 会把 npm 包更新失败计入对应项目的失败结果；项目索引不可读时会明确失败，不再把问题报告成成功或空索引。
- **Dashboard 响应式工作区**：`comet dashboard` 在显示左侧导航时会把 change 工作区保持在视口内；打开 artifact preview 会保留滚动位置，已归档 change 会显示为完成状态，而不是再次建议 verify（[#170](https://github.com/rpamis/comet/issues/170)）。
- **已有 Skill 目录的符号链接安装**：`comet init` 与 `comet update --install-mode symlink` 会保留平台现有的 `skills/` 目录，并只链接 Comet 管理的 Skill，本地或第三方 Skill 不再导致安装失败（[#171](https://github.com/rpamis/comet/issues/171)）。
- **OpenSpec CLI 安装范围**：即使选择项目级 Comet 安装，`comet init` 也会把 OpenSpec CLI 作为全局工具安装或升级，不再因为该选择在项目中创建 `node_modules/`（[#175](https://github.com/rpamis/comet/issues/175)）。
- **已归档 Dashboard 产物**：Dashboard 会从已归档 change 正确回到项目根解析 `docs/superpowers/` 路径，归档后的设计、计划和验证报告仍可查看（[#176](https://github.com/rpamis/comet/issues/176)）。
- **归档最终确认**：`/comet-archive` 会把用户最终批准记录到机器管理的 Classic 状态；在确认 transition 成功前，真实归档命令拒绝修改，避免直接调用脚本绕过确认。
- **归档注释格式**：Classic 归档注释会保留正常的 Markdown 文件结尾，并可安全重复执行，避免产生 `git diff --check` 格式错误（[#185](https://github.com/rpamis/comet/issues/185)）。
- **全局产物语言**：全局 `comet init` 和 `comet update` 会把所选产物语言保存到 `~/.comet/config.yaml`。Classic workflow 优先读取项目配置，再回退到全局默认；项目仍可覆盖该设置（[#174](https://github.com/rpamis/comet/issues/174)）。

</Update>

<Update label="0.4.0-beta.3" description="2026-07-08" rss={{ title: "Comet 0.4.0-beta.3", description: "2026-07-08 发布记录" }}>
### Fixed（修复）

- **Doctor 范围诊断**：`comet doctor` 现在会报告 auto scope 行为、Node/平台环境信息；当全局 Comet 安装可用但当前项目没有本地 Skill 副本时，会给出不惊扰的项目级提示，让用户区分"项目级安装可选"和"安装损坏"。
- **PowerShell 初始化输出**：`comet-state.mjs init` 现在把成功初始化信息写到 stdout，Windows PowerShell 不再把成功创建 `.comet.yaml` 误报成 `NativeCommandError`（[#167](https://github.com/rpamis/comet/issues/167)）。
- **版本短参数**：`comet -v` 现在等同于 `comet --version`，符合常见 CLI 习惯（[#167](https://github.com/rpamis/comet/issues/167)）。
- **Classic runtime 兜底**：Classic 阶段脚本现在保留内嵌 runtime 包兜底，即使某个平台安装缺少内部 `runtime/classic` 资产，`comet-guard.mjs`、handoff 和 archive 流程仍能运行（[#168](https://github.com/rpamis/comet/issues/168)）。
- **项目配置查找**：Classic guard 现在只从 `.comet/config.yaml` 读取项目默认配置；工作流状态仍只属于每个 change 的 `.comet.yaml`，根目录 `.comet.yaml` / `comet.yaml` 不再参与配置或状态解析（[#158](https://github.com/rpamis/comet/issues/158)）。

### Removed（移除）

- **自定义 guard 命令字段**：Classic 工作流状态不再接受 `build_command` 和 `verify_command`。guard 改为使用内置项目构建探测路径，旧字段会作为未知字段被拒绝。

</Update>

<Update label="0.4.0-beta.2" description="2026-07-07" rss={{ title: "Comet 0.4.0-beta.2", description: "2026-07-07 发布记录" }}>
### Fixed（修复）

- **单语言规则安装**：`comet init` 和 `comet update` 现在只安装与所选/检测到的 Skill 语言匹配的 Comet 阶段守卫规则文件（例如 `.claude/rules/comet-phase-guard.md`），不再无论语言选择都同时安装中英文两个规则变体。
- **符号链接安装安全性**：`comet init` 和 `comet update` 在符号链接安装模式下，如果目标平台的 `skills/` 目录包含 Comet 管理清单之外的文件，现在会拒绝把该目录替换成符号链接，避免删除本地或第三方 Skill（[#159](https://github.com/rpamis/comet/issues/159)）。
- **并行 change 的产物写入**：Classic 阶段守卫现在会把 `docs/superpowers/` 写入路由到匹配的 design/build/verify change，不再因为另一个更早创建的活跃 change 阻塞共享的 Design Doc 和计划产物（[#160](https://github.com/rpamis/comet/issues/160)）。

</Update>

<Update label="0.4.0-beta.1" description="2026-07-06" rss={{ title: "Comet 0.4.0-beta.1", description: "2026-07-06 发布记录" }}>
这是 0.4.0 线的第一个 beta。相对于 0.3.9，Comet 从一个依赖 Bash 的 `/comet` 工作流包，变成了一个跨平台 Node 运行时，覆盖工作流、Skill 创建、评估和可视化四大能力。下面的条目描述的是最终用户可见的发布形态，不是分支开发历史。

### 重点变化

- **纯 Node 运行时**：所有 Comet 脚本通过 Node.js 运行，macOS、Linux、Windows 用同一套命令，不再需要 Bash、Git Bash 或 WSL。
- **`/comet-any` Skill Creator**：从"生成一个 `SKILL.md`"升级为生成稳定的组合 Skill Bundle，带可评审的创作内容、发布证据链和平台原生文件。
- **`comet eval` 评估系统**：可量化任意本地 Skill 和 Comet 工作流的质量，含 pass@k/pass^k 可靠性指标和 HTML 报告。
- **配置化产物语言**：`comet init` 现在记录项目级产物语言，OpenSpec 和 Superpowers 产物按配置语言输出。
- **`comet dashboard`**：本地只读浏览器面板，可视化每个变更的阶段、产物、任务和风险。

- **Subagent dispatch Comet extensions**: 将 `comet-build/SKILL.md` 中内联的子 agent 调度协议重写为 `comet/reference/subagent-dispatch.md`（中英文），作为叠加在 Superpowers `subagent-driven-development` skill 之上的 Comet 专属扩展。该 skill 提供核心调度循环；Comet 扩展增加了真正的后台调度、持久的逐任务检查点（`subagent-progress.md`）、仅协调者执行源码、由后台 agent 负责 TDD、有界的评审-修复轮次（最多 3 轮）、无暂停的连续任务执行，以及从检查点阶段的精确上下文恢复。
- **`task-checkoff` subcommand**: 新增 `comet-state task-checkoff <file> <task-text>`，用于验证特定任务在 markdown 文件中是否被唯一勾选。供子 agent 调度协议在双重评审通过后进行针对性的完成验证。包含路径遍历防护、CRLF 处理和精确匹配校验。
- **`comet uninstall` command**: 新增 `comet uninstall [path]` CLI 命令，可安全地移除 Comet 分发到所有 29 个受支持 AI 编码平台的 skill、规则和 hook。支持 `--scope`（project/global）、`--force`（跳过确认）和 `--json` 输出。自动检测已安装的目标，仅移除 Comet 管理的产物，同时保留用户自定义的 hook 和非 Comet 配置，清理空目录和工作目录（`.comet/`、`docs/superpowers/`），并处理所有 7 种 hook 格式（Claude Code、Qwen、Qoder、Gemini、Windsurf、GitHub Copilot、Kiro）和所有 3 种规则格式（md、mdc、copilot instructions）（[#95](https://github.com/rpamis/comet/issues/95)）。
- **Progressive loading reference docs**: 从内联 skill 内容中抽取了四份参考文档以实现按需加载，降低每次调用的 token 成本（中英文）：`auto-transition.md`（自动阶段推进协议，替代各子 skill 中 7 × 约 10 行的重复内容）、`context-recovery.md`（上下文压缩恢复，替代 4 × 约 8 行）、`comet-yaml-fields.md`（`.comet.yaml` 字段表，约 40 行）和 `file-structure.md`（目录结构，约 20 行）。主 `comet/SKILL.md` 内联保留了关键的状态机硬约束，同时指向参考文档以获取详细的字段说明。预计每次调用节省：600–1500 token（取决于 skill）；完整工作流累计节省约 4100 token。
- **Pre-commit formatting hook**: 新增 `husky` + `lint-staged` 的 pre-commit hook，在每次 `git commit` 时自动对 `src/` 目录下的暂存源文件运行 `prettier --write`（范围与 CI 的 `format:check` 对齐）。与编辑器无关——对所有贡献者强制执行，无论使用何种 IDE 或 agent——防止 Prettier 格式问题进入 CI。`prepare` 脚本会在 `pnpm install` 时安装该 hook，且 `.husky/` 通过 `files` 白名单从发布的包中排除。

- **Pi slash command discovery**: `comet init` 和 `comet update` 现在会生成一个 Pi 扩展，将所有内置的 `/comet*` 工作流注册为原生斜杠命令并转发到 `/skill:*`。Pi 设置以非破坏性方式合并，启用 skill 命令；全局资源现在使用 Pi 官方文档记载的 `~/.pi/agent/` 目录，会检测旧的 `~/.pi/skills/` 安装以进行更新和清理，且 `comet uninstall` 仅移除 Comet 管理的资源，同时保留共享设置和无关的扩展（[#89](https://github.com/rpamis/comet/issues/89)）。
- **OpenCode plugin-installed Superpowers detection**: `comet init` 现在能正确检测通过 OpenCode 插件系统（在 `opencode.json` 中配置）已安装的 Superpowers，防止重复安装。此前只能检测直接放在 `~/.config/opencode/skills/` 下的 skill，遗漏了 `~/.config/opencode/superpowers/skills/` 的插件源目录以及 `opencode.json` 中的 `plugin` 数组。新增了 `hasOpenCodePluginSuperpowers()` 回退检测，类似于现有的 Claude Code 插件缓存检查（[#105](https://github.com/rpamis/comet/issues/105)）。
- **Lightweight verification consistency**: hotfix 文档现在描述了 6 项轻量验证路径，验证失败处理将 CRITICAL 和 IMPORTANT 发现视为阻塞项，使评审通过标准和失败决策保持一致。
- **Hook configuration merging during init and update**: Claude Code、Codex、Amazon Q、Qwen、Qoder、Gemini 和 Windsurf 的共享 hook 配置文件，现在在 Comet 为同一 matcher 或事件安装/更新 hook 时会保留用户自定义的 hook。现有的 Comet 命令通过其清单脚本路径识别并原地替换，防止过时的安装路径、重复的 matcher 分组和重复的 hook 累积，同时不影响无关的设置。
- **Subagent-driven task isolation and continuity**: `comet-build` 现在加载成熟的 Superpowers `subagent-driven-development` 循环，并应用更严格的 Comet 扩展，要求每个任务使用全新的后台实现者、全新的后台评审者和修复 agent、仅协调者执行源码，以及任务之间自动连续执行而不产生进度摘要或"continue?"提示。TDD 模式要求每个实现者/修复 agent 加载 TDD skill，并在评审前返回可审计的 RED/GREEN 证据。持久的逐任务检查点在上下文压缩过程中保留实现提交、评审阶段、反馈和三轮重试预算；任务勾选在两轮评审都通过之前保持阻塞（[#94](https://github.com/rpamis/comet/issues/94)、[#96](https://github.com/rpamis/comet/issues/96)、[#97](https://github.com/rpamis/comet/issues/97)）。
- **npm shebang line ending issue on macOS**: 当 npm 在 Windows 上打包项目时，`bin/comet.js` 的 shebang 行获得 CRLF 行尾，导致 macOS 将 `#!/usr/bin/env node\r` 解释为 `#!/usr/bin/env node` 之外的内容，在 `npm install -g @rpamis/comet` 后出现 "command not found"。在 `.gitattributes` 中为所有文本文件扩展名（`.js`、`.mjs`、`.ts`、`.json`、`.md`、`.yaml`、`.yml`）添加了显式的 `eol=lf` 规则，并为图片文件添加了二进制标记（[#82](https://github.com/rpamis/comet/issues/82)）。
- **CodeGraph Codex CLI skip on project scope**: 项目范围的 `comet init` 会向 `codegraph install` 传入 `--target` 和 `--location=local`，导致 Codex CLI（无项目本地配置）被跳过并显示令人困惑的消息。简化为 `codegraph install --yes`，不传 `--target` 或 `--location` 标志，让 CodeGraph 自动检测并配置所有已安装的 agent。移除了 `filterSupportedPlatforms` 和 `CODEGRAPH_SUPPORTED_TARGETS`（[#98](https://github.com/rpamis/comet/issues/98)）。
- **OpenSpec CLI upgrade and --profile fallback**: `ensureOpenSpecCli` 现在始终安装/升级 openspec 到最新版本，即使已存在旧版本，确保用户获得 `--profile` 支持和其他改进。新增了回退逻辑：如果 `openspec init` 在 stderr 中报 "unknown option --profile"，则不带该标志重试，以应对升级失败但残留旧 openspec 的边缘情况（[#84](https://github.com/rpamis/comet/issues/84)）。
- **Symlink resolution for skill file copies**: 当 skill 目录是符号链接时（例如 `~/.claude/skills/comet -> ~/.agents/skills/comet`），`copyFile` 和 `ensureDir` 会写入字面路径而不是跟随符号链接目标。损坏的符号链接会导致静默的复制失败。在 `file-system.ts` 中新增 `resolveSymlinkPath()`，沿路径树向上遍历并对损坏的符号链接跟随 `readlink` 目标。已应用于 `ensureDir`、`copyFile` 和 `writeFile`（[#85](https://github.com/rpamis/comet/issues/85)）。
- **comet-tweak missing debug handling**: `comet-tweak/SKILL.md` 缺少 `comet-hotfix` 已有的 systematic-debugging 要求——当 tweak 执行期间测试或构建失败时，该 skill 现在明确要求在提出源码修复之前加载 `systematic-debugging` skill，与 hotfix 行为保持一致。
- **OpenSpec per-artifact instructions compliance**: 中英文 `comet-open` 现在对每个标准产物应用 OpenSpec 的逐产物指令（`openspec instructions proposal/design/tasks --change "<name>" --json`），从 JSON 载荷中加载 `context`、`rules`、`template`、`instruction`、`resolvedOutputPath` 和 `dependencies`，替代了硬编码的产物文案。在指令失败时停止产物生成，而不是静默绕过项目规则（[#66](https://github.com/rpamis/comet/issues/66)）。
- **CI Windows path escaping in skill verification**: `init-e2e` 工作流的 Pi 设置验证步骤将 Windows `$RUNNER_TEMP` 路径（包含反斜杠）直接插入 `node -e "require('...')"` 的 JS 字符串字面量中，其中 `\a`/`\_` 被解析为转义字符并破坏了路径（`D:\a\_temp` → `D:a_temp`），导致 Node 20 和 22 上 `init-e2e (windows-latest)` 运行器失败。现在该路径通过环境变量（`process.env`）传递，使其永远不进入 JS 字符串字面量；Linux/macOS 不受影响。
- **OpenSpec source formatting**: 重新格式化了 `src/core/openspec.ts`（长行换行），以满足 `prettier --check`，解除对 `format:check` CI 步骤的阻塞。
- **Symlink-safe removal during uninstall**: `removeFile`/`removeDir` 在删除之前不再解析符号链接。此前，符号链接的 skill、规则或 hooks 目录的解析目标会被 `comet uninstall` 递归删除；现在符号链接目录会被直接 unlink。`isDirEmpty` 也不再将不可读的目录报告为空，因此清理操作不会删除它无法检查的目录。
- **`comet update --json` output corruption**: npm 继承的 stdio 此前会混入 JSON 文档；现在在 JSON 模式下会丢弃 npm 的 stdout/stderr，使机器可读的输出保持可解析。
- **`comet update --json` no-targets shape**: 当不存在已安装目标时发出的提前返回 JSON 现在包含 `codegraph: 'skipped'`，与正常输出结构一致，使消费者无需对空路径做特殊处理。
- **JSON-mode version-check latency**: `comet init` 和 `comet update` 现在在 JSON 模式下跳过 npm registry 的版本检查，无需网络往返即可输出。
- **Malformed hook settings resilience**: 手工编辑的设置文件将 hook 分组存储为非数组值时，不再在 init/update 的 hook 合并期间抛出异常；格式不正确的分组会被强制转换为空。
- **Markdown code-fence language tags**: 在 `file-structure.md` 和 `subagent-dispatch.md`（中英文）的围栏代码块中添加了 `text` 语言标签，以满足 MD040 lint 检查，与现有的 OpenSpec 格式化 CI 修复保持一致。
- **Skills manifest version drift**: 将 `assets/manifest.json` 版本从 `0.3.3` 提升到 `0.3.8`，以与 `package.json` 保持一致。

### Added

- **Auto-transition config**: 在 `.comet.yaml` 和 `.comet/config.yaml` 项目默认配置中新增了 `auto_transition`（`true`|`false`），让团队可以选择 Comet 是自动推进到下一阶段 Skill，还是暂停等待手动切换。当 `auto_transition: false` 时，build/design/open/verify skill 在满足退出条件后会停止，并打印下一步的手动操作指引，而不是直接调用下一个 skill。包含状态机白名单、枚举校验以及 schema（`comet-yaml-validate.sh`）覆盖（[#74](https://github.com/rpamis/comet/pull/74)）。
- **Deterministic next-step resolver**: 新增 `comet-state next <change-name>`，根据 `.comet.yaml`（`phase`、`workflow`、`auto_transition`）解析 guard 之后的路由逻辑，并输出结构化结果：`NEXT: auto|manual|done`、`SKILL: <skill-name>` 和 `HINT`（手动模式下）。这将下一步 skill 的路由逻辑集中到脚本中，避免在各 skill 文案中重复编写。
- **Workflow output language**: Comet 工作流现在通过显式的输出语言规则，将触发用户请求的语言传播到 OpenSpec 和 Superpowers 步骤中，确保生成的提案、设计、计划、验证报告和归档说明都能以用户的语言呈现，保持可读性。恢复已有的 change 时，会保留产物的主要语言，除非用户明确要求切换（[#53](https://github.com/rpamis/comet/pull/53)、[#37](https://github.com/rpamis/comet/issues/37)）。
- **Execution benchmark (Claude Code)**: 新增 `benchmark:execution`，一个包含三个测试阶段的基准测试框架：L1（基于交接上下文生成设计文档）、L2（基于交接上下文构建 note-board 模块并运行测试）和 L3（完整工作流——根据规格实现一个 dictionary 模块并运行 10 个 vitest 测试）。调用 Claude Code（`claude -p`），并测量实际的测试通过率、token 用量、重试次数、耗时和成本。在小/中/大规模下对比 `off` 与 `beta` 上下文压缩模式。支持 `--phase l1|l2|l3|both|all` 和 `--dry-run` 用于确定性验证。将共享工具函数（`spawnCapture`、`parseClaudeJson`、`buildClaudeArgs` 等）抽取到 `scripts/benchmark-utils.mjs`。

- **Token optimization: TDD skill single load**: build skill 现在在第一个任务之前只加载一次 `test-driven-development` skill（而不是每个任务都加载），在 10 个任务的工作流中可减少约 44K token。包含上下文压缩后的恢复指引，恢复时重新加载一次。
- **Token optimization: brainstorming checkpoint**: design skill 现在在用户确认设计方案后会写入 `brainstorm-summary.md`，提供一个上下文压缩恢复点，在上下文窗口压缩过程中保留已确认的决策。
- **Token optimization: incremental brainstorming checkpoint**: design skill 现在在头脑风暴过程中增量更新 `brainstorm-summary.md`，在平台驱动的上下文压缩发生之前，保留已确认的事实、候选决策、风险、测试说明和待解决问题。
- **Token optimization: active compaction gate**: design skill 现在在 `brainstorm-summary.md` 定稿之后、创建设计文档之前，要求一个主动的上下文压缩检查点，优先使用宿主平台的原生压缩机制，不可用时回退为手动提示用户。
- **Token optimization: plan creation subagent offload**: build skill 将 `writing-plans` 的执行卸载给子 agent，释放主会话的上下文。子 agent 从文件中读取设计文档和 tasks.md，并返回计划文件路径。子 agent 失败时回退为内联执行。
- **Token optimization: verification skill dedup**: verify skill 现在在 light/full 分支判断之前只加载一次 `verification-before-completion`，而不是在每个分支中都加载，消除了冗余的 skill 内容。
- **Token optimization: tasks.md incremental scan**: build skill 现在用 `grep` 查找未完成的任务，而不是在每次任务完成后重新读取整个 `tasks.md` 文件。
- **Token optimization: hash on-demand read in verify**: verify skill 在重新读取 OpenSpec 产物之前先检查 `handoff_hash`。当哈希匹配时，仅跳过 `tasks.md`（proposal.md 和 design.md 仍会读取以进行比较检查）。使用新增的 `comet-handoff.sh --hash-only` 标志。
- **`--hash-only` flag for comet-handoff.sh**: 新增向后兼容的标志，仅输出上下文哈希而不生成交接文件，供 verify 阶段进行哈希比对使用。在计算哈希之前会校验必需的文件是否存在。
- **CodeGraph integration in comet init**: `comet init` 现在提供一个可选步骤来安装和配置 CodeGraph（`@colbymchenry/codegraph`），用于语义化代码智能。它会自动检测受支持的平台（Claude Code、Cursor、Codex、OpenCode、Gemini、Kiro、Antigravity），若 CLI 缺失则自动安装，运行 `codegraph install` 进行 agent 接线，并初始化项目索引。在 `--json` 模式下会优雅跳过。
- **Stale PR automation**: 新增了一个定时触发且可手动运行的 GitHub Actions 工作流，将 90 天未活动的 pull request 标记为 stale，再过 30 天后关闭，帮助管理长期闲置的评审队列。
- **TDD mode field**: 在 `.comet.yaml` 状态机中新增 `tdd_mode`（`tdd`|`direct`），让用户选择在构建时是否强制执行 TDD。当 `tdd_mode: tdd` 时，子 agent 调度时会注入显式的 TDD 硬约束，绕过 implementer-prompt.md 中的条件触发。解决 [#67](https://github.com/rpamis/comet/issues/67)。
- **subagent_dispatch field**: 在 `.comet.yaml` 状态机中新增 `subagent_dispatch`（`null`|`confirmed`），确保 `build_mode: subagent-driven-development` 只有在平台真实的后台调度能力得到确认后，才能离开 build 阶段。
- **Verify retry limit**: verify skill 现在在连续 3 次验证失败循环后强制要求用户决策，防止无限自动重试。
- **Manual verify_mode override**: 当自动检测的模式不合适时，用户可通过 `comet-state set <name> verify_mode <light|full>` 覆盖自动验证规模评估。
- **Local context compression benchmark**: 新增 `benchmark:context`，一个本地 Codex 基准测试框架，会创建匹配的 `context_compression: off` 和 `beta` Comet 测试用例，针对每种模式运行 `codex exec`，并报告 token 节省量、规格漂移率、任务完成率、解析成功率和耗时。使用 `--dry-run` 进行确定性的非 Codex 验证。
- **Beta-gated context compression switch**: 项目安装现在会创建带有 `context_compression: off` 的 `.comet/config.yaml`，让团队可以通过设置 `context_compression: beta` 让新的 change 启用 beta 规格投影。此开关仅控制 OpenSpec 交接投影路径（`spec-context.*`）；上述工作流 token 优化默认开启，无需 beta 模式。
- **Beta spec projection handoff**: `/comet-design` 现在可以使用 beta 上下文压缩来生成 `spec-context.json` 和 `spec-context.md`，保留 OpenSpec 的需求和场景标题及源哈希，使精简的设计交接在降低 token 负担的同时不削弱验收覆盖度。

### Changed

- **executing-plans review gate**: 当 `build_mode` 为 `executing-plans` 时，build 阶段现在要求在 build→verify 阶段守卫之前至少加载一次 Superpowers 的 `requesting-code-review` skill 并请求一次代码评审。CRITICAL 级别的问题必须在 verify 之前修复；已接受的非 CRITICAL 问题必须在持久产物中记录接受理由。build 退出检查清单会强制执行此关卡（[#76](https://github.com/rpamis/comet/pull/76)、[#41](https://github.com/rpamis/comet/issues/41)）。
- **Phase advancement vs handoff wording**: 中文和英文 Comet skill 现在一致地区分守卫驱动的阶段推进（`--apply`，始终更新 `phase`）与下一步 skill 调用控制（`auto_transition`）。open/design/build/verify/hotfix/tweak 的指引现在统一通过 `comet-state next` 来路由自动/手动交接。
- **预设连续性措辞**: hotfix 和 tweak 指引现在明确记录连续执行模式下的 `auto_transition: false` 例外情况，移除了围绕 "always continue" 行为的矛盾措辞。
- **Verify hash-skip scoped to tasks.md only**: 完整验证即使哈希匹配也始终读取 `proposal.md` 和 `design.md`，确保目标满足度和设计一致性检查拥有完整上下文。
- **Design Doc creation stays in main session**: 设计文档以内联方式创建（不卸载给子 agent），以保留完整的头脑风暴对话上下文，防止复杂需求下信息丢失。
- **Subagent failure fallback**: 计划创建的子 agent 卸载包含显式的降级回退——如果子 agent 失败，主会话会内联加载 `writing-plans`。
- **Beta spec verbatim projection**: beta 上下文压缩现在按原样投影整个 spec 文件（`cat`），而不是按英文关键词（GIVEN/WHEN/THEN/AND/BUT）过滤。这消除了语言相关的匹配，确保中文或非英文 spec 的验收标准零漂移，并彻底移除了脆弱的 AWK 过滤器。
- **JSON structural validation**: `comet-guard.sh` 现在校验 `spec-context.json` 的结构（必需字段：`change`、`phase`、`mode`、`files`、`context_hash`）以及源文件引用覆盖度，替代了之前基于英文标题的 markdown 检查。守卫会在阶段转换之前捕获损坏或不完整的 JSON。
- **JSON file roles**: `spec-context.json` 的 `files` 数组现在包含 `role` 字段（spec 文件为 `spec`，proposal/design/tasks 为 `supporting`），彻底移除了依赖语言的 `projection` 数组。
- **--full warning in beta mode**: 在 beta 模式下运行 `comet-handoff.sh --full` 现在会发出明确的警告，而不是静默忽略该标志。
- **CodeGraph step in comet update**: `comet update` 现在会在更新 skill 文件的同时提示安装/更新 CodeGraph，使用与初始化相同的平台检测和 CLI 安装流程。
- **Rules and hooks distribution in comet update**: `comet update` 现在会在更新 skill 文件的同时，将防漂移阶段守卫规则和 hook 分发到所有已安装的平台，确保 Comet 升级后规则和 hook 保持同步。
- **Archive confirmation gate**: 中文 `/comet-archive` 现在在运行归档脚本之前会暂停以获取用户的明确确认，让用户在主 spec 合并和 change 归档之前有最后的机会进行调整或重新验证。
- **English archive confirmation parity**: 英文 Comet skill 现在与已确认的中文归档确认工作流保持一致，包括 `/comet-archive`、`/comet-verify`、`/comet`、hotfix 和 tweak 指引。
- **Archive reopen transition**: 新增 `comet-state transition <change-name> archive-reopen`，让拒绝最终归档确认的用户可以从 `phase: archive` 返回 `phase: verify` 进行调整或重新验证，无需手动编辑 `.comet.yaml`。
- **OpenSpec clarification gate**: 中文和英文 `/comet-open` 现在要求在创建 proposal、design 或 tasks 产物之前，先确认一份需求澄清摘要，防止一轮问答就立即生成完整的 OpenSpec change。
- **PRD split preflight**: 中文和英文 `/comet-open` 现在会在创建 OpenSpec 产物之前对大型 PRD 进行分拣，允许用户将独立的功能拆分为多个 Comet change，同时让每个被接受的拆分项保持在 `/comet-open` 的状态机路径上。解决 [#62](https://github.com/rpamis/comet/issues/62)。
- **Skill invocation wording guidance**: 在 `CLAUDE.md` 中新增了仓库指引，要求新的 skill 触发描述使用既有的 "use the Skill tool to load..." 措辞，并在 skill 加载之后再放置上下文细节。
- **Anti-drift phase guard rule**: 新增 `.claude/rules/comet-phase-guard.md`，在每轮对话中重新注入 Comet 阶段感知、skill 调用要求、脚本执行要求、用户确认关卡和上下文压缩恢复指引，防止长上下文注意力漂移破坏 5 阶段工作流。在所有平台上作为软提醒生效。
- **Anti-drift phase guard hook**: 新增 `comet-hook-guard.sh` PreToolUse hook（配置在 `.claude/settings.local.json`），当当前 Comet change 处于 `open`、`design` 或 `archive` 阶段时硬性阻止文件写入，提供模型无法绕过的、平台特定的硬性执行层。将 `openspec/*`、`docs/superpowers/*`、`.claude/*` 和 `.comet/*` 路径加入白名单。
- **Platform rules/hooks distribution in comet init**: `comet init` 现在在初始化期间将防漂移阶段守卫规则和 hook-guard 脚本分发到所有受支持的平台。修正了平台定义：Cline 使用项目根目录下的 `.clinerules/`（而非 `.cline/rules/`），GitHub Copilot 使用带 `applyTo` frontmatter 的 `.github/instructions/*.instructions.md`，Kiro 使用 `.kiro/steering/`，Gemini CLI 没有规则目录（使用 GEMINI.md 文件）。为 8 个缺少规则配置的平台新增了 `rulesDir`/`rulesFormat`，为 7 个平台新增了 `supportsHooks`/`hookFormat`。hook 安装支持 7 种格式变体：Claude Code、Gemini、Windsurf、Copilot、Qwen、Kiro 和 Qoder。
- **Systematic debugging gate**: 中文和英文 build 及 hotfix skill 现在要求在实现阶段出现崩溃、意外行为、测试失败或构建失败时加载 Superpowers 的 `systematic-debugging`，确保在修复源码之前先进行根因分析并在当前 change 中编写回归测试。
- **Verification-before-completion gate**: 中文和英文 `/comet-verify` 现在要求在执行轻量或完整验证检查之前加载 Superpowers 的 `verification-before-completion`，在任何完成声明之前强制执行基于证据的确认。
- **Platform-neutral confirmation gates**: 中文和英文 Comet skill 及恢复消息现在引用当前平台的用户输入/确认机制，而不是硬编码 `AskUserQuestion`，避免 Codex 用户被指引去使用可能不存在的工具，同时保留阻塞性的用户决策。
- **预设升级路径**: hotfix 和 tweak skill 现在在升级到 full workflow 时包含 `set <name> phase design` 步骤，避免 workflow 切换后触发 comet-design 入口检查失败。
- **Build-complete conditional field reset**: `build-complete` 转换在前一次 verify_result 为 `fail` 时会保留 `verification_report` 和 `branch_status`，使 verify-fail→build→build-complete 的重新验证循环不丢失数据。
- **Open phase recovery granularity**: open 阶段恢复现在区分三种状态（所有产物完成 / 无产物完成 / 部分完成），并为每种状态提供具体的恢复操作。
- **50% scope threshold option**: build skill 现在在改动超过 50% 范围时提供"在当前 change 中继续"作为第三个选项，避免强制拆分 change。
- **Worktree plan commit**: build skill 现在明确指示在使用 worktree 隔离时，先提交计划文件再创建 worktree。

### Removed

- **openspec/config.yaml**: 移除了未使用的示例 OpenSpec 配置文件（仅包含占位注释）。

### Fixed

- **Subagent task persistence**: `/comet-build` 现在要求每个子 agent 调度提示在提交之前，将已完成的任务勾选持久化到 Superpowers 计划中，并在映射时更新对应的 OpenSpec `tasks.md` 条目。build 守卫会阻止未勾选的 Superpowers 计划任务，build 恢复在检查最近的 git 历史/diff 或调度更多工作之前，会同时报告 OpenSpec 和计划的进度，防止在打断或上下文压缩后恢复时重新运行已完成的子 agent 工作（[#79](https://github.com/rpamis/comet/issues/79)）。

- **skip-all skipping uninstalled components**: `comet init` 不再将之前跳过的组件视为已安装。选择 skip-all 现在只跳过实际存在的组件，因此未安装的 OpenSpec、Superpowers、Comet 或 CodeGraph 组件仍会被提示安装，而不是被静默跳过（[#73](https://github.com/rpamis/comet/pull/73)）。

- **Update JSON output for rules/hooks**: `comet update --json` 现在在 skill 更新结果之外还包含规则和 hook 的分发结果，并具有针对每个目标的错误隔离，使单个平台失败不会破坏整个更新输出。

- **Duplicate YAML fields**: `comet-state.sh` 中的 `replace_yaml_field` 现在在替换后对所有字段去重，仅保留每个键的最后一次出现。此前，对同一字段多次调用 `cmd_set`（例如在 verify-fail → 重新验证循环中）可能在 `.comet.yaml` 中留下重复行，干扰下游解析器。修复 [#77](https://github.com/rpamis/comet/issues/77)。

- **Hook config format**: `installClaudeCodeHooks` 和 `.claude/settings.local.json` 现在使用正确的 `matcher` + `hooks: [{ type, command }]` 数组格式，替代了扁平的 `{ matcher, command, description }` 格式，修复了 `/doctor` 的 schema 校验错误。

- **Archive delta merge**: `comet-archive.sh` 现在将归档 spec 更新委托给 OpenSpec 的 delta 合并语义，而不是将 change spec 复制覆盖主 spec，防止 `ADDED/MODIFIED/REMOVED/RENAMED` 章节标题泄漏到稳定 spec 中。解决 [#69](https://github.com/rpamis/comet/issues/69)。
- **Brainstorming depth**: 中文和英文 `/comet-design` 不再告诉 Superpowers 的 `brainstorming` 跳过上下文探索，因此不清晰的目标、范围、非目标、验收场景或约束必须在创建设计文档之前得到澄清。
- **Command injection prevention**: `comet-guard.sh` 中的 `run_command_string()` 现在拒绝包含 shell 元字符（`;`、`|`、`&`、`$`、反引号）的 build/verify 命令，防止通过 `.comet.yaml` 的命令字段进行命令注入。
- **Path traversal prevention**: `comet-state.sh cmd_set` 现在在写入之前校验路径字段（design_doc、plan、verification_report、handoff_context、handoff_hash）是否包含 `..` 遍历序列。
- **Design guard enforcement**: design 守卫现在要求 full workflow 必须有 `design_doc`（FAIL 而非 WARN），防止在没有设计文档的情况下推进阶段。
- **branch_status preservation on verify-fail**: `verify-fail` 转换不再重置 `branch_status`，在重新验证循环中保留分支处理状态。
- **UTC date consistency**: 所有脚本现在使用 `date -u +%Y-%m-%d` 来设置 `created_at`、`verified_at` 和归档命名，消除了本地/UTC 日期不一致问题。
- **macOS SCRIPT_DIR resolution**: 所有脚本使用可移植的 `$(cd "$(dirname "$0")" && pwd -P)` 替代 `readlink -f`，以保证跨平台兼容性。
- **Archive directory resolution fallback**: `comet-archive.sh resolve_archive_dir()` 现在在精确的基于 UTC 的路径不匹配时，按 `*-$CHANGE` 模式搜索，修复了不同时区下的测试可靠性问题。
- **Temp file permissions**: 所有 `mktemp` 调用现在在写入敏感数据之前对临时文件设置 `chmod 600`。
- **Pipe hash error propagation**: `comet-handoff.sh` 和 `comet-guard.sh` 中的哈希计算现在先将管道输出捕获到变量中，再管道传递给哈希流，防止在 `pipefail` 下静默失败。
