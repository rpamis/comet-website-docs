## What's Changed [0.2.4] - 2026-05-21

### Added

- **验证证据强制校验**: `verify-pass` 推进现在要求 `verification_report`（文件必须存在）和 `branch_status: handled` 才允许进入下一阶段。守卫将这些作为硬性前置条件进行检查
- **`.comet.yaml` 中的 `verification_report` 和 `branch_status` 字段**: 新增状态字段，用于跟踪验证报告路径和分支处理状态
- **comet-verify（中文）中的验证证据步骤**: 新增第 4 步，要求在守卫应用前创建报告文件并记录分支状态
- **`branch_status` 枚举校验**: `comet-state.sh set` 会将 `branch_status` 校验为 `pending` 或 `handled`
- **守卫 verify 检查**: `comet-guard.sh` 现在会在 verify 阶段检查 `verification_report 是否存在` 以及 `branch_status=handled`
- **Bats 测试 CRLF 修复**: Shell 测试在执行前会去除脚本中的 `\r`，修复了 Windows 兼容性
- **`test:shell` 运行器**: 用 `node scripts/run-bats.js` 替代直接调用 `bats`，以支持跨平台

### Changed

- **Hotfix 根因检查顺序调整**: 将根因消除检查移至加载 comet-verify **之前**（第 3a 步拆分为 3a/3b），防止在 verify 流程中被跳过
- **简化 Hotfix 标题描述**: 将含糊的"非独立并行流程"替换为直接的"快速 bug 修复工作流"，明确可独立调用
- **移除 comet-design 中的非操作步骤**: 删除了第 3 步（双规格划分表）和第 4 步（文档层级）——这些是纯参考资料，不包含 agent 操作
- **移除重复的脚本定位块**: comet-open（第 3 步）和 comet-archive（第 1 步）在变量已缓存时不再重复完整的 `COMET_SEARCH_ROOTS` find 块
- **移除 comet-build 中重复的 50% 阈值**: 仅在阈值判定表中提及一次，不再在表格和列表中重复
- **通用错误处理**: comet 主 Skill 中的错误表将"Maven compile/test"改为"Build/test"，使用语言无关的措辞
- **comet-state.sh 用法帮助**: 修复了帮助文本中 `check` 参数顺序（`check <change-name> <phase>`）

### Fixed

- **comet-state.sh `init` 变更目录解析**: `cmd_init` 现在会在检查 `.comet.yaml` 是否已存在之前解析 `change_dir`，修复了嵌套目录下的路径解析问题
- **verify 阶段守卫死锁**: `verify-pass` 推进现在在通过 `verify-fail` 回滚时会重置 `verification_report` 和 `branch_status`，防止过期的证据导致错误的推进

### Tests

- **`comet-scripts.test.ts` 中 +66 行**: 新增测试覆盖验证证据阻断、分支状态校验以及带证据的守卫 verify
- **`comet-state.bats` 中 +12 行**: 新增测试覆盖 `branch_status` 枚举校验、CRLF 去除以及 init 输出中新字段的存在性
