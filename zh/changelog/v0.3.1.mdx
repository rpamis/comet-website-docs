## What's Changed [0.3.1] - 2026-05-26

### Added

- **Workflow state metadata**: `.comet.yaml` 初始化现在会记录 `base_ref` 和 `created_at`，使规模评估和验证能够基于稳定的变更基线进行推断。

### Changed

- **Comet decision points**: 调整中英文 workflow skills，使 design 确认、build 配置、verify 失败、spec drift、分支处理和预设升级都会暂停并等待明确的用户选择，而不是依赖默认值或推荐项。
- **Build workflow selection**: 将工作区隔离和执行方式选择合并为一个 build 配置步骤，减少重复暂停，同时仍要求在实现继续之前确定 `isolation` 和 `build_mode`。
- **Hotfix verification flow**: 将 root-cause elimination 移到 build guard 之前，并要求预设升级把 `workflow` 切到 `full`，让失败的 hotfix 检查停留在 build 阶段，并让 full-flow 升级保持一致状态。
- **Verification scale assessment**: 规模检查现在回退到 `.comet.yaml` 的 `base_ref`，并使用四文件阈值进行完整验证，使已提交的 build 变更更不容易被漏算。
- **English skill parity**: 将英文 Comet Skill 与中文工作流规则同步，包括交接生成、脏工作树处理、spec drift 决策和验证失败阻断。

### Fixed

- **Windows npm update**: `comet update` 现在通过 shell 启动 npm，使包更新路径在 Windows 命令垫片下可靠工作。
- **Superpowers install diagnostics**: 失败的 Superpowers 安装现在会打印清理后的 stderr 详情，使网络或 GitHub 访问失败可见，而不是隐藏可操作的原因。

### Tests

- **Workflow safeguard coverage**: 为中文 Comet 决策点需求和 Superpowers 安装失败诊断添加了回归测试覆盖。
