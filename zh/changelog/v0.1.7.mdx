## What's Changed [0.1.7] - 2026-05-16

### Added

- **`comet-archive.sh` script**: 一键归档自动化 —— 校验入口状态、将 delta spec 同步到主 spec（覆盖）、为 design doc 和 plan 的 frontmatter 添加标注、将 change 移动到 archive 目录、更新 `archived: true`。支持 `--dry-run` 预览
- **`--apply` mode for `comet-guard.sh`**: 可选标志，在所有 guard 检查通过后自动更新 `.comet.yaml` 状态字段。阶段转换时无需手动编辑状态
- **Idempotent frontmatter annotation**: `annotate_frontmatter()` 会跳过已存在的 `archived-with:` 行，可安全重复执行

### Changed

- **Removed manual state editing**: 所有阶段转换（design → build → verify → archive）现在改用 `guard --apply`，不再手动更新 `.comet.yaml` 字段和写入校验循环
- **Removed write-verification blocks**: 从 comet-open、comet-design、comet-build、comet-verify 和 comet-archive 这些 Skill 中移除了所有 `【写入验证】` / `【Write verification】` 模式
- **Removed `## ADDED`/`## MODIFIED`/`## REMOVED` delta format**: delta spec 现在是完整的 spec；归档时直接覆盖主 spec，而不是合并片段
- **Removed step 2b from comet-open**: 对已有能力的增量修改就是一次新的 `/comet-open` —— brainstorming 会自然地把已有 spec 作为上下文读入
- **Simplified archive skill**: 第 1b–5 步替换为一次 `comet-archive.sh` 调用
- **Updated `comet/SKILL.md`**: 脚本位置章节现在同时记录了 `--apply` 模式和归档脚本

### Removed

- `isolation`、`build_mode`、`verify_mode` 字段的 few-shot YAML 示例（与 agent 判断重复）
- comet-archive 对 `openspec-archive-change` skill 的依赖（归档脚本已处理所有步骤）
