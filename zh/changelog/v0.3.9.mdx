## What's Changed [0.3.9] - 2026-06-17

### Added

- **CLI i18n shared module**: 将初始化时的翻译表抽取到 `src/commands/i18n.ts`，使 init、update 及未来的命令能够一致地共享英文字符串，而不是每个命令各自复制一份翻译表。
- **Optional npm dependency prompts in init/update**: `comet init` 和 `comet update` 现在对 OpenSpec CLI、Superpowers（通过 `npx skills add`）和 CodeGraph CLI 提供多选提示，而不是强制安装。系统上尚未检测到的项目默认勾选；已安装的项目默认不勾选，让用户可以选择升级而不被强制。Superpowers 选项还会推荐安装 v6.0.0+（速度约提升 2 倍，token 减少约 50%）。
- **`--language` option for `comet init`**: 新增 CLI 标志（`en`/`zh`），以非交互方式选择 skill 语言，与既有的 `comet update --language` 选项保持一致（[#109](https://github.com/rpamis/comet/pull/109)）。
- **`review_mode` field for code review control**: 在 `.comet.yaml` 中新增字段 `review_mode`（`off` / `standard` / `thorough`），控制 build 和 verify 阶段的自动代码评审。`comet-build` 要求在执行之前由用户选择；`comet-verify` 和子 agent 调度根据模式调整行为；`comet-hotfix` 默认为 `off`。由 `comet-state.sh`、`comet-guard.sh` 和 `comet-yaml-validate.sh` 校验。
- **Project-level review mode defaults**: `.comet/config.yaml` 现在可以设置 `review_mode: off|standard|thorough`，该值会被快照到新的 full workflow change 中，让团队可以选择项目范围的自动评审默认值，同时保留既有的逐 change 状态行为。新生成的配置文件包含 `context_compression`、`review_mode` 和 `auto_transition` 的枚举注释，用户无需查阅文档即可调整支持的值。
- **Uninstall by platform selection**: `comet uninstall` 现在在检测到多个平台时显示复选框提示，允许用户选择性地卸载特定平台，而不是一次性全部移除。单目标场景使用简单的 yes/no 确认。`--force` 和 `--json` 标志保留既有的全部一次性移除行为。
- **Codex plugin-installed Superpowers detection**: `comet init` 现在能检测通过 Codex 插件缓存（`~/.codex/plugins/cache/...`）已安装的 Superpowers，防止重复安装——与既有的 Claude Code 和 OpenCode 插件检测平行（[#115](https://github.com/rpamis/comet/pull/115)）。

### Changed

- **Tagline rebrand**: 将 `comet init` banner 以及 `package.json` / CLI `--description` 中的 Comet 标语从 "OpenSpec + Superpowers dual-star development workflow" 改为 "Agent Skill Harness Phase-Guarded Automation From Idea To Archive"，按核心价值（阶段守卫的 agent skill 框架）而非底层 OpenSpec + Superpowers 依赖来定位 Comet。
- **Change name confirmation as a blocking decision point**: `comet-open` SKILL.md（中英文）现在新增了专门的 Step 1c，在 `openspec new change` 之前暂停以确认 change 名称。agent 必须从澄清摘要中推导出 2-3 个 kebab-case 英文候选名，始终提供自定义输入选项，并警告中文（或任何非 kebab-case）输入将被转换为合规的 kebab-case 英文名称并回显确认——防止 agent 自动生成不合规的中文 change 名称。
- **Non-ASCII change name prevention**: 在 `comet-open` SKILL.md（中英文）中新增了显式的 ASCII 校验规则，防止 agent 自动生成包含中文、日文、韩文字符、空格或特殊字符的不合规 change 名称。agent 现在必须向用户请求一个符合 ASCII 的名称。
- **Chinese gate-term normalization**: 更新了中文 Comet 措辞，避免将 `gate` 直译为"门"：Design Step 1e 现在使用"主动式上下文压缩"，共享的调试指引现在使用"异常调试协议"，且 `CLAUDE.md` / `AGENTS.md` 现在将其定义为未来 skill 编辑的标准中文翻译规则。
- **Full i18n coverage for CLI prompts**: 将翻译覆盖范围从仅 `init` 扩展到也覆盖 `update`（banner、npm 更新进度、skill 复制进度、摘要、codegraph 提示）。所有面向用户的字符串现在都有英文和中文两种变体（[#109](https://github.com/rpamis/comet/pull/109)）。

### Fixed

- **Phase-skip enforcement across all guard layers**: 修复了 agent 从 `open` 直接跳到 `build`（跳过 `design`）而未被检测到的问题。`comet-state.sh` 现在在每个向前转换时强制要求证据；直接 `set phase` 被阻止（带有 `COMET_FORCE_PHASE=1` 逃生口）；`comet-hook-guard.sh` 在 `design_doc` 为 null 时阻止源码写入；`comet-phase-guard` 规则新增阶段入口自洽检查，要求在写入源码之前具备前置产物。
- **Hook guard cross-change false positives**: 修复了 `comet-hook-guard.sh` 让一个 change 的阶段错误地阻止对另一个 change 写入的问题。写入到 `openspec/changes/<name>/` 的操作现在由该 change 自己的 `.comet.yaml` 阶段控制，而不是由目录中找到的第一个活跃 change 控制。这涵盖了此前阻止全新 change 产物写入的两种情况：（1）一个标记为 `archived: true` 但尚未物理移到 `archive/` 子目录的旧 change，以及（2）一个停滞在 `archive` 阶段且 `archived: false`（尚未运行归档脚本）的旧 change。此外，`.comet.yaml` 尚不存在的新 change 目录（在 `/comet-open` 期间，产物在状态文件之前写入）被视为 `open`，因此 `proposal/design/tasks/specs` 的写入是被允许的。
- **CodeGraph setup detection**: 修复了即使项目已有 `.codegraph/` 索引，`comet init` 和 `comet update` 仍会提示进行 CodeGraph 设置的问题。现有的项目索引现在会跳过可选的 CodeGraph 提示和安装步骤，且 CodeGraph CLI 解析可以使用 pnpm 全局二进制文件，再回退到 npm 全局安装。
- **Phase guard auto-transition handoff**: 修复了注入的 Comet 阶段守卫规则在 `guard --apply` 之后硬编码下一个 skill 的问题，这可能绕过 `auto_transition: false`。该规则现在将守卫后的交接委托给 `comet-state next <change-name>`，并遵循 `NEXT: auto|manual|done`，从而尊重手动阶段边界。
- **Executable permission loss on macOS after update**: `bin/comet.js` 和 `assets/skills/comet/scripts/` 下的所有 shell 脚本此前以 git 模式 `100644`（不可执行）提交。npm 更新后，macOS 用户丢失了 `comet` CLI 入口点的执行权限。已将所有 8 个文件在 git 中改为 `100755`，使 npm 安装始终保留可执行位。

### Tests

- **Phase-skip enforcement coverage**: 新增了 shell 脚本测试，覆盖加固后的守卫层——当 open 产物缺失时阻止 `open-complete`、根据 `design_doc` 是否存在阻止/允许 `design-complete`、在 `verify_result: pass` 之前阻止 `archived`、阻止直接 `set phase` 同时允许 `COMET_FORCE_PHASE` 逃生口，以及在 `design_doc` 为 null 时阻止 full workflow 的 `build` 源码写入，同时仍允许预设工作流和带有效 `design_doc` 的 full workflow。
- **Project review mode default coverage**: 新增了回归测试覆盖 `.comet/config.yaml` 中 `review_mode` 快照到 full workflow change、拒绝无效的项目评审模式，以及生成的项目配置文件中的枚举注释。
- **CodeGraph setup coverage**: 新增了针对现有 `.codegraph/` 索引检测、跳过冗余 CodeGraph 安装、pnpm 全局 CLI 解析，以及在项目索引已存在时抑制更新时 CodeGraph 提示的回归测试。
- **Phase guard handoff coverage**: 新增了 skill 规则回归覆盖测试，确保阶段守卫委托给 `comet-state next`，不再嵌入可能忽略 `auto_transition` 的固定下一步 skill 映射。
- **`review_mode` integration coverage**: 新增了回归测试，验证 `review_mode` 贯穿状态、守卫和校验脚本，并在 `comet-build`/`comet-verify`/`comet-hotfix` 中具有正确的特定模式行为。
- **Uninstall platform selection coverage**: 新增了针对单目标自动选择、多目标复选框选择、用户取消、`--force` 跳过、`--json` 输出以及未找到目标处理的测试。
