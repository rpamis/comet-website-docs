这是 0.4.0 线的第一个 beta。相对于 0.3.9，Comet 从一个依赖 Bash 的 `/comet` 工作流包，变成了一个跨平台 Node 运行时，覆盖工作流、Skill 创建、评估和可视化四大能力。下面的条目描述的是**最终用户可见的发布形态**，不是分支开发历史。

## What's Changed [0.4.0-beta.1] - 2026-06-27

### 重点变化

- **纯 Node 运行时**：所有 Comet 脚本通过 Node.js 运行，macOS、Linux、Windows 用同一套命令，不再需要 Bash、Git Bash 或 WSL。
- **`/comet-any` Skill Creator**：从"生成一个 `SKILL.md`"升级为生成稳定的组合 Skill Bundle，带可评审的创作内容、发布证据链和平台原生文件。
- **`comet eval` 评估系统**：可量化任意本地 Skill 和 Comet 工作流的质量，含 pass@k/pass^k 可靠性指标和 HTML 报告。
- **`comet dashboard`**：本地只读浏览器面板，可视化每个变更的阶段、产物、任务和风险。
- **路由上下文**：`/comet` 用结构化路由上下文做可解释路由，风险信号优先于口头流程。

### Added（新增）

- **跨平台 Classic 运行时**：随包分发的 `/comet` 工作流脚本现在通过 Node `.mjs` 启动器运行，背后由 TypeScript Classic 运行时支撑。同一套工作流在 Windows、macOS 和 Linux 上运行，不再需要 Git Bash、WSL 或兼容 shell 的脚本。
- **`comet dashboard`**：新增本地只读浏览器面板，展示进行中和已归档的变更，包括阶段进度、产物分组、任务进度、verify 状态、下一步指引、风险信号、Git 上下文、带元数据的产物预览，以及亮色/暗色 UI。`--json`、`--port`、`--no-open` 和 `GET /api/dashboard` 把同一份快照暴露给脚本和 CI。
- **`/comet-any` Skill Creator**：新增创建或升级可复用 Skill 的主流程。流程覆盖候选发现、可确认的方案、生成的 Skill Bundle、创作决策/指导区、创作车道、当前 draft 的评估就绪、评审批准、发布、分发，以及 Claude Code custom agents 等平台原生文件。
- **Skill Creator CLI**：新增 `comet creator` 用于常规创建/恢复指引，`comet publish` 用于评审、批准、发布和分发预览，后端 Bundle 命令保留为高级工具。
- **本地 Skill 工具**：新增 `comet skill add|show|run|continue|check`，用于安装、检查、运行、恢复和确定性校验本地 Skill 包（带快照）。
- **`comet eval` harness**：新增仓库本地评估，支持 Comet 工作流和任意本地 Skill，含 task profile、生成的 manifest、HTML 报告、token/cost 归因、pass@k/pass^k 可靠性指标、工作流专用评分、Skill 调用证据检查、可配置的模拟器提示词、Anthropic 兼容代理认证、Windows/WSL 友好执行、UTF-8 日志和回归门禁。
- **Hotfix/tweak 范围决策**：为 hotfix 和 tweak 工作流新增定性升级信号；文件数量阈值现在会暂停询问用户确认，而不是强制自动升级到完整工作流（[#121](https://github.com/rpamis/comet/issues/121)）。
- **支持的平台**：新增 ZCode、MimoCode、Trae CN 和 Antigravity 2.0 支持。Antigravity 2.0 全局安装在 `~/.gemini/config/skills/`；ZCode 和 MimoCode 使用 OpenCode 兼容布局；Trae CN 使用 `.trae-cn/skills`。平台总数达到 **33** 个。
- **符号链接安装模式**：`comet init` 和 `comet update` 现在可以选择用复制或符号链接/junction（从共享的 `.comet/skills/` 存储）安装 Skill。
- **项目 Skill 偏好**：新增 `.comet/skill-preferences.yaml`，让项目可以引导首选 Skill、排序和 Skill Creator 方案，而不必手改 bundle 文件。

### Changed（变更）

- **Comet 产品定位**：README、CLI 帮助和 Skill 指引现在把 Comet 呈现为一个工作流和 Skill 平台：运行引导式工作流、创建 Skill、评估它们、发布它们，以及诊断卡住的变更。
- **Classic 工作流状态**：机器管理的运行检查点从 `.comet.yaml` 移到 `.comet/run-state.json`，而用户可编辑的工作流字段保持 YAML 可读。Classic 阶段转换现在还会写入 `.comet/state-events.jsonl`，形成可审计的状态历史。
- **Classic 运行时打包**：Classic 控制元数据现在放在 `comet/runtime/classic` 下，命令启动器拆成独立的 Node bundle（`comet-state.mjs`、`comet-guard.mjs`、`comet-archive.mjs` 等），同时保持现有 `/comet*` 命令行为不变。
- **工作流诊断**：`comet status` 和 `comet doctor` 现在共享同一条运行时证据路径，报告当前步骤、运行时模式、畸形状态、缺失证据和推荐恢复动作。
- **工作流路由**：`/comet` 现在对 full、hotfix、tweak、resume 和歧义请求使用显式的路由上下文模型。`/comet-tweak` 现在是 tweak 专用的 OpenSpec action 路径，而完整 `/comet` 仍走 Superpowers 的 design/plan/build 路径。
- **评审工作流**：`review_mode` 现在对 full 工作流默认为 `standard`。`off`、`standard`、`thorough` 形成更清晰的评审梯度，由 Comet 接管评审派发策略，用户不必为重叠的 Superpowers 和 Comet 评审循环买单。
- **交互式决策点**：Comet 决策点现在在可用时优先使用 Claude Code 的结构化提问 UI，其他平台降级为文本。
- **调试工作流**：Debug Gate 可以在按配置的评审流串行应用修复之前，先并行调查独立的失败组。
- **仓库布局**：源码移入 `app/`、`domains/`、`platform/` 和 `scripts/`，测试移到对应的 `test/app/`、`test/domains/`、`test/platform/`、`test/scripts/` 和 `test/repository/` 根目录，让贡献者的职责边界更清晰。

### Fixed（修复）

- **Windows 路径处理**：修复 OpenSpec init/update 在 Windows 上对含空格目录的路径引用，`comet init` 不再因为项目路径含空格而失败。
- **Git 子模块脚本查找**：当 agent 在 Git 子模块内工作时，Comet hook 和运行时脚本解析现在使用所在项目根，子模块内的编辑不再因为 `.claude/skills/comet/scripts/*` 只在父项目级别存在而失败（[#136](https://github.com/rpamis/comet/issues/136)）。
- **Doctor 诊断**：`comet doctor` 现在给出更清晰的版本、项目/全局范围、畸形状态、缺失证据和恢复指引，让用户能区分"真的缺少项目安装"和"有效的全局安装"，并理解当前 `.comet.yaml` 的状态问题（[#135](https://github.com/rpamis/comet/issues/135)）。
- **评审模式一致性**：英文、中文、共享规则和恢复指引现在对 `review_mode` 达成一致，已安装的 Skill 不再描述一个与运行时 guard/state 检查冲突的旧双评审流程（[#126](https://github.com/rpamis/comet/issues/126)）。
- **init/update 的项目配置合并**：`comet init` 和 `comet update` 现在对 `.comet/config.yaml` 做字段级合并，而不是文件存在就跳过。保留现有用户值、补齐缺失的管理字段、刷新注释、保留额外用户字段；损坏的 YAML 优雅回退到全部默认。
- **init 结果汇总**：`comet init` 现在把有任何组件失败的平台排除出 `Installed` 列表并点名失败组件，OpenCode 等平台不再同时显示为已安装和失败（[#128](https://github.com/rpamis/comet/issues/128)）。

### Removed（移除）

- **Bash 优先的 Classic 脚本**：移除了随包分发的 Classic 工作流脚本必须通过 Bash 兼容 shell 脚本运行的要求。

### Security（安全）

- **Dependabot 依赖告警**：把测试工具钉到打过补丁的 Vite 和 esbuild 版本（覆盖 npm 和 pnpm lockfile），清除了待处理的 Vite 路径穿越、launch-editor 和 esbuild dev-server 告警，且不改变 Comet 运行时依赖。
