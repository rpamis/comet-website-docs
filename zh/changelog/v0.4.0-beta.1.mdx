这是 master（`0.3.9`）之后的主要产品跃迁。Comet 现在是纯 Node 运行时，而不是依赖 Bash/WSL 的工作流层；新增稳定的 `comet skill` 和 `comet eval` 用户路径；并把 `/comet-any` 变成真正的 Skill Factory，带 next-action 指导、readiness 门禁、生成的 `comet/eval.yaml` 和更清晰的发布证据链。

## 重点变化

### 纯 Node 运行时

所有 Comet 脚本都通过 Node.js 运行，macOS、Linux、Windows 用同一套命令，不再需要 Bash、Git Bash 或 WSL。原来的 `.sh` 脚本变为 `.mjs` 入口，背后由共享 TypeScript 运行时支撑。

- `comet-guard.mjs`、`comet-state.mjs`、`comet-handoff.mjs`、`comet-archive.mjs`、`comet-env.mjs`、`comet-yaml-validate.mjs`、`comet-hook-guard.mjs` 全部迁移到 Node。
- Classic 运行时存储拆分：machine-owned Run state 从 `.comet.yaml` 移到 `.comet/run-state.json` 或 `.comet/runs/<run-id>`。
- `.comet.yaml` 现在保留用户可理解的工作流投影，并增加 `run_id` 链接。

### Comet Skill 平台

新增内部 Skill Engine 和面向用户的 `comet skill` 命令：

```bash
comet skill install ./my-skill --project .
comet skill validate my-skill --project .
comet skill inspect my-skill --json
comet skill run my-skill --change ./changes/demo
comet skill run my-skill --run-id demo-run --project .
comet skill resume --run-id demo-run --status succeeded --summary "Done"
comet skill eval --run-id demo-run --scope completion
```

- 项目 Skill 发现、不可变 Run 快照、runtime evals、独立 `.comet/runs/<run-id>` 执行。
- 项目 Skill 按名称覆盖内置 Skill；无效覆盖 fail closed 而不是静默回退。
- 文本模式直接打印 `Pending action` 和 `Next:` 恢复提示。

### `/comet-any` Skill Factory

`/comet-any` 现在生成稳定组合 Skill Bundle，而不是只产出一个 `SKILL.md`。普通用户路径是：

```text
/comet-any -> comet eval -> comet publish review/approve/run -> comet publish distribute --preview -> comet publish distribute
```

- 三种起点：改一版 `/comet`、做一个新 Skill、整理已有 Skill。
- 项目级偏好文件从 `.comet/skills.txt` 升级为 `.comet/skill-preferences.yaml`，支持 `advisory`/`strict` 模式。
- 生成前必须展示组合方案确认页，用户确认后才写 Bundle draft。
- 生成物包含 `reference/resolved-skills.json` 真实来源证据、Engine Package（`comet/skill.yaml`、`comet/guardrails.yaml`、`comet/checks.yaml`、`comet/eval.yaml`）和 required control plane（`scripts/rules/hooks`）。
- next-action 指导、readiness 门禁、生成的 `comet/eval.yaml`、分布预览和恢复摘要。

### 共享 eval 系统

新增可复用 eval harness，通过 `comet eval` 提供：

```bash
comet eval collect --manifest ./comet/eval.yaml
comet eval run --manifest ./comet/eval.yaml --html
comet eval run --skill-path ./my-skill --skill-name my-skill --quick
```

- profiles、生成的 Skill manifest、通用 smoke task（`generic-skill-smoke`）、HTML 报告。
- 失败归因（harness/workflow/task/model）、token/cost/duration 报告。
- `collect` 做发现预检查，`run` 执行真实评估。

### `comet publish` 发布门面

新增 `comet publish` 作为 `/comet-any` 产物的常规 readiness、approval、publish 和 distribute 路径，同时保留 `comet bundle` 作为高级后端。

- review 输出现在包含面向用户的 readiness 结论和下一步，而不是只暴露原始 blocker 证据。
- 分发前强制 preview，展示 planned files、unsupported capability、executable disclosures。
- readiness 门禁：未解决候选、旧 hash 的 eval 证据、缺失人工 approval、required capability gap、executable disclosure 未确认都会阻塞发布。

## 平台扩展

- 新增 ZCode 支持。
- 新增 MimoCode 原生平台支持（项目级 `.mimocode/`，全局 `.config/mimocode/`）。
- 新增 **Trae CN**（`trae-cn`）平台支持：Trae 国内版，独立目录 `.trae-cn/` 和 OpenSpec 工具 id。平台总数达到 **32** 个。
- 新增 **符号链接（symlink）安装模式**：`comet init`/`comet update` 可在各平台目录创建指向 `.comet/skills/` 的符号链接，所有平台共享同一份中央存储，节省磁盘空间。
- 跨平台 install/distribute 层继续扩展。

## 关键修复

- 修复仓库/运行时重组后打包命令（`comet doctor`、`status`、`init`、`update`）的 asset 查找问题。
- 畸形 `.comet.yaml` 不再导致整个扫描崩溃，`status`/`doctor`/`guard --json` 走统一证据路径。
- `comet doctor` 新增 Comet 和 Superpowers 环境状态，不再把无关平台 Skill 目录当作不完整的 Comet 安装。
- `/comet-any` 发布门禁收紧：缺失候选、过期 eval、缺失评审 approval、不支持的 required 能力、可执行披露都会在发布/分发前明确暴露。
- `/comet-any` proposal 确认门禁：确认 Factory proposal metadata 后才能生成、评审或发布 Skill Bundle。
- Windows 和路径可靠性：修复含空格目录的 OpenSpec init/update 路径引用，加固 eval/task harness 的 Windows UTF-8、Docker 和报告输出。
- 子模块 hook 执行：用绝对脚本路径和显式项目根安装 hook 命令，子模块里的 Agent 仍使用父工作区的 Comet 脚本和阶段状态。

## 详细变更

### Added

- **Node-only runtime foundation**: Classic workflow launchers 迁移到薄 `.mjs` 入口，背后由共享 TypeScript 运行时支撑，不再依赖 Bash、Git Bash 或 WSL。
- **Comet Skill platform**: 内部 Skill Engine 加面向用户的 `comet skill install|validate|inspect|run|resume|eval`、项目 Skill 发现、不可变 Run 快照、runtime evals、独立 `.comet/runs/<run-id>` 执行。
- **`/comet-any` Skill Factory backend**: 确定性 Bundle 创作后端，`/comet-any` 内部使用：`factory-init`、`factory-resolve`、`factory-generate`、生成的 `resolved-skills.json`、生成的 `comet/eval.yaml`、review summary、ready-state publish/distribute。
- **Bundle authoring recovery list**: `comet bundle list` 发现可恢复的 Skill Factory 创作会话。
- **Protocol-driven `/comet-any` authoring**: 创建 Skill 现在走显式创作协议（`reference/authoring-protocol.json`），含确定性 lane DAG、schema 校验的 lane 输出和真实多票 Skill 评审。LLM 创作内容（入口/节点 Skill 正文、决策点、恢复）通过 `comet bundle authoring-record` 合并进生成的包，而确定性骨架（workflow protocol、runtime 脚本、manifest）保持模板化和可复现。新增 `comet bundle authoring-plan` 和 `comet bundle authoring-record` 命令驱动流水线，记录的评审证据（不再是硬编码 approval）门禁发布就绪。
- **Authored content zones (Auto + Authored split)**: 生成的 SKILL.md 由确定性 **Auto zone**（frontmatter、路由表、Entry/Exit 检查、证据格式、恢复）加上 **Authored zone**（入口的 `## Decision Core`、节点的 `## Guidance`）组成。节点分类为 `delegates`（薄指导正确）vs `substance`（必须有富创作指导）。缺创作内容的 `substance` 节点会渲染 `AUTHORING PENDING` stub 并阻止发布。
- **Generic LLM judge**: `BENCH_LLM_JUDGE=1` 现在也覆盖 generic/authoring profile，用 `generic_llm_judge.py` 打分 `task_completion`、`output_quality`、`instruction_adherence` 三维度（外加 task 自定义 `rubric_criteria`）。
- **Dashboard 改进**: 产物按来源分组（OpenSpec / Superpowers / Comet）、亮色/暗色主题切换（持久化偏好）、产物预览显示文件大小和更新时间元数据、环形图动画从 0 开始。
- **Shared eval system**: 可复用 eval harness，含 profiles、生成的 Skill manifest、通用 smoke task、HTML 报告、失败归因、token/cost 报告，通过 `comet eval run|collect` 暴露。
- **Platform expansion**: ZCode 支持和 MimoCode 原生支持。
- **Stable composed Skill control plane**: 生成的 `/comet-any` Skill Bundle 包含 required scripts、rules、hooks、runtime checks、Eval manifest 和组合证据。
- **Factory Skill composition**: 创作时展开 source Skill 的 `comet/flow.yaml`，含 choice resolution 和 cycle detection。
- **Comet Any user guidance**: 首次使用 Factory guide、可确认的组合 proposal、resume summary、distribution preview。

### Changed

- **`review_mode` default changed to `standard`**: full workflow 初始化的默认 `review_mode` 和运行时 fallback 从 `null`（关闭）改为 `standard`。适用于 init 模板、`classic-state-command.ts` 运行时 fallback 和冻结的 0.3.9 契约 fixture。
- **Project config merge on init/update**: `comet init` 和 `comet update` 对 `.comet/config.yaml` 做字段级合并，而非文件存在就跳过。保留现有值、补齐缺失字段、刷新注释、保留自定义字段；损坏 YAML 优雅回退到全部默认。
- **Publish facade path**: `comet publish` 作为常规 readiness/approval/publish/distribute 路径，`comet bundle` 作为高级后端。
- **Comet product model**: 围绕纯 Node 运行时、可恢复工作流诊断、可复用 Skill 平台和 `/comet-any` 作为主 Skill 创建路径重新定位。
- **Repository and runtime layout**: 仓库重组为 `app/`、`domains/`、`platform/`、`scripts/` 和对应测试。
- **Classic runtime storage**: machine-owned Run state 从 `.comet.yaml` 拆出，更多 workflow facts 走共享 diagnostics/runtime-eval 路径。
- **Runtime checks naming**: 新 Engine-native 包使用 `comet/checks.yaml`，迁移期保留 legacy `comet/evals.yaml` 加载。
- **Bundle distribution disclosure**: publish distribute 输出现在暴露 planned files 和 executable hook disclosures。
- **Comet Any preferences**: 用项目级 `.comet/skill-preferences.yaml` 替代未发布的 `.comet/skills.txt`，含 inventory-backed 偏好设置、proposal preview、preference-aware review readiness。
- **Publish readiness**: review 输出现在包含面向用户的 readiness 结论和下一步，在原始 blocker 证据之前。
- **Comet Any Skill Maker language**: 围绕定制 `/comet`、创建新 Skill、升级已有 Skill 重构语言，Bundle 和 Factory 概念保留在内部审计层。

### Removed

- **Bash-first runtime assumptions**: 移除旧的 shell-script 运行时/测试假设；Node launcher 和跨平台 runtime check 成为默认契约。
