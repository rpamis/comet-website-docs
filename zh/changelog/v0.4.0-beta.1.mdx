这是 master（`0.3.9`）之后的主要产品跃迁。Comet 现在是纯 Node 运行时，而不是依赖 Bash/WSL 的工作流层；新增稳定的 `comet skill`、`comet eval` 和 `comet creator` 用户路径；并把 `/comet-any` 变成真正的 Skill Creator，带 `comet creator next` 用户恢复路径、readiness 门禁、生成的 `comet/eval.yaml` 和更清晰的发布证据链。

## 重点变化

### 纯 Node 运行时

所有 Comet 脚本都通过 Node.js 运行，macOS、Linux、Windows 用同一套命令，不再需要 Bash、Git Bash 或 WSL。原来的 `.sh` 脚本变为 `.mjs` 入口，背后由共享 TypeScript 运行时支撑。

- `comet-guard.mjs`、`comet-state.mjs`、`comet-handoff.mjs`、`comet-archive.mjs`、`comet-env.mjs`、`comet-yaml-validate.mjs`、`comet-hook-guard.mjs` 全部迁移到 Node。
- Classic 运行时存储拆分：machine-owned Run state 从 `.comet.yaml` 移到 `.comet/run-state.json` 或 `.comet/runs/<run-id>`。
- `.comet.yaml` 现在保留用户可理解的工作流投影，并增加 `run_id` 链接。

### Comet Skill 平台

新增内部 Skill Engine 和面向用户的 `comet skill` 命令：

```bash
comet skill add ./my-skill --project .
comet skill show my-skill --project .
comet skill show my-skill --json
comet skill run my-skill --change ./changes/demo
comet skill run my-skill --run-id demo-run --project .
comet skill continue --run-id demo-run --status succeeded --summary "Done"
comet skill check --run-id demo-run --scope completion
```

- 项目 Skill 发现、不可变 Run 快照、runtime checks、独立 `.comet/runs/<run-id>` 执行。
- 项目 Skill 按名称覆盖内置 Skill；无效覆盖 fail closed 而不是静默回退。
- 文本模式直接打印 `Pending action` 和 `Next:` 恢复提示。

### `/comet-any` Skill Creator

`/comet-any` 现在生成稳定组合 Skill Bundle，而不是只产出一个 `SKILL.md`。普通用户路径是：

```text
/comet-any -> comet eval -> comet creator status/next -> comet publish review/approve/run -> comet publish distribute --preview -> comet publish distribute
```

- 三种起点：改一版 `/comet`、做一个新 Skill、整理已有 Skill。
- 项目级偏好文件从 `.comet/skills.txt` 升级为 `.comet/skill-preferences.yaml`，支持 `advisory`/`strict` 模式。
- 生成前必须展示组合方案确认页，用户确认后才写 Bundle draft。
- 生成物包含 `reference/resolved-skills.json` 真实来源证据、Engine Package（`comet/skill.yaml`、`comet/guardrails.yaml`、`comet/checks.yaml`、`comet/eval.yaml`）和 required control plane（`scripts/rules/hooks`）。
- `comet creator status` / `comet creator next` 用户路径、readiness 门禁、生成的 `comet/eval.yaml`、分发预览和恢复摘要。

### 共享 eval 系统

新增可复用 eval harness，通过 `comet eval` 提供：

```bash
comet eval ./comet/eval.yaml --collect
comet eval ./comet/eval.yaml --html
comet eval ./my-skill --skill-name my-skill --quick
```

- profiles、生成的 Skill manifest、通用 smoke task（`generic-skill-smoke`）、HTML 报告。
- 失败归因（harness/workflow/task/model）、token/cost/duration 报告。
- `--collect` 做发现预检查，不带 `--collect` 时执行真实评估。

### `comet publish` 发布门面

新增 `comet publish` 作为 `/comet-any` 产物的常规 readiness、approval、publish 和 distribute 路径，同时保留 `comet bundle` 作为高级后端。

- review 输出现在包含面向用户的 readiness 结论和下一步，而不是只暴露原始 blocker 证据。
- 分发前强制 preview，展示 planned files、unsupported capability、executable disclosures。
- readiness 门禁：未解决候选、旧 hash 的 eval 证据、缺失人工 approval、required capability gap、executable disclosure 未确认都会阻塞发布。

## 平台扩展

- 新增 ZCode 支持。
- 新增 MimoCode 原生平台支持（项目级 `.mimocode/`，全局 `.config/mimocode/`）。

- 新增 **符号链接（symlink）安装模式**：`comet init`/`comet update` 可在各平台目录创建指向 `.comet/skills/` 的符号链接，所有平台共享同一份中央存储，节省磁盘空间。
- 跨平台 install/distribute 层继续扩展。

## 关键修复

- 修复仓库/运行时重组后打包命令（`comet doctor`、`status`、`init`、`update`）的 asset 查找问题。
- 畸形 `.comet.yaml` 不再导致整个扫描崩溃，`status`/`doctor`/`guard --json` 走统一证据路径。
- `comet doctor` 新增 Comet 和 Superpowers 环境状态，不再把无关平台 Skill 目录当作不完整的 Comet 安装。
- `/comet-any` 发布门禁收紧：缺失候选、过期 eval、缺失评审 approval、不支持的 required 能力、可执行披露都会在发布/分发前明确暴露。
- `/comet-any` proposal 确认门禁：确认 Factory proposal metadata 后才能生成、评审或发布 Skill Bundle。
- Windows 和路径可靠性：修复含空格目录的 OpenSpec init/update 路径引用，加固 eval/task harness 的 Windows UTF-8、Docker 和报告输出。
- 子模块 hook 执行：用绝对脚本路径和显式项目根安装 hook 命令，子模块里的 Agent 仍使用父工作区的 Comet 脚本和阶段状态。

## 详细变更

### Added

- **Node-only runtime foundation**: Classic workflow launchers 迁移到薄 `.mjs` 入口，背后由共享 TypeScript 运行时支撑，不再依赖 Bash、Git Bash 或 WSL。
- **Comet Skill platform**: 内部 Skill Engine 加面向用户的 `comet skill add|validate|inspect|run|resume|eval`、项目 Skill 发现、不可变 Run 快照、runtime checks、独立 `.comet/runs/<run-id>` 执行。
- **`/comet-any` Skill Creator backend**: 确定性 Bundle 创作后端，`/comet-any` 内部使用：`comet creator init`、`comet creator resolve`、`comet creator generate`、生成的 `resolved-skills.json`、生成的 `comet/eval.yaml`、review summary、ready-state publish/distribute。
- **Skill Creator recovery list**: `comet creator list` 发现可恢复的 Skill Creator 创作会话。
- **Protocol-driven `/comet-any` authoring**: 创建 Skill 现在走显式创作协议（`reference/authoring-protocol.json`），含确定性 lane DAG、schema 校验的 lane 输出和真实多票 Skill 评审。LLM 创作内容（入口/节点 Skill 正文、决策点、恢复）通过 `comet creator authoring-record` 合并进生成的包，而确定性骨架（workflow protocol、runtime 脚本、manifest）保持模板化和可复现。新增 `comet creator authoring-plan` 和 `comet creator authoring-record` 命令驱动流水线，记录的评审证据（不再是硬编码 approval）门禁发布就绪。
- **Authored content zones (Auto + Authored split)**: 生成的 SKILL.md 由确定性 **Auto zone**（frontmatter、路由表、Entry/Exit 检查、证据格式、恢复）加上 **Authored zone**（入口的 `## Decision Core`、节点的 `## Guidance`）组成。节点分类为 `delegates`（薄指导正确）vs `substance`（必须有富创作指导）。缺创作内容的 `substance` 节点会渲染 `AUTHORING PENDING` stub 并阻止发布。
- **Generic LLM judge**: `BENCH_LLM_JUDGE=1` 现在也覆盖 generic/authoring profile，用 `generic_llm_judge.py` 打分 `task_completion`、`output_quality`、`instruction_adherence` 三维度（外加 task 自定义 `rubric_criteria`）。
- **Dashboard 改进**: 产物按来源分组（OpenSpec / Superpowers / Comet）、亮色/暗色主题切换（持久化偏好）、产物预览显示文件大小和更新时间元数据、环形图动画从 0 开始。
- **Shared eval system**: 可复用 eval harness，含 profiles、生成的 Skill manifest、通用 smoke task、HTML 报告、失败归因、token/cost 报告，通过 `comet eval [target] --collect/--html` 暴露。
- **Platform expansion**: ZCode 支持、MimoCode 原生支持和 Antigravity 2.0 支持。
- **Trae CN 平台**：新增 Trae 国内版（`trae-cn`）独立平台支持，项目级 `.trae-cn/skills`，全局 `~/.trae-cn/skills`。
- **Antigravity 2.0 平台**：新增 Antigravity 2.0（`antigravity2`）独立平台支持，与 Antigravity 共享项目级 `.agents/`，全局走 `~/.gemini/config/skills/`，平台总数达 33 个。
- **符号链接安装模式**：`comet init` / `comet update` 新增 **copy**（传统，每平台独立副本）和 **symlink**（共享 `.comet/skills/` 中央存储）两种安装模式，节省磁盘并保证跨平台一致性；Windows 上用不需要管理员权限的 junction。
- **Debug Gate 并行失败排查**：Debug Gate 协议现在在四阶段流程前先做一次失败独立性评估——当 ≥3 个失败来自不同问题域（不同测试文件、不同根因、独立子系统），它会加载 Superpowers `dispatching-ai.ents` skill 并为每个失败派一个后台调查 agent 并行定位根因，而非逐个串行调试。调查保持并行，修复仍串行且走当前 `review_mode` 循环，并发 agent 永不编辑同一文件。
- **Stable composed Skill control plane**: 生成的 `/comet-any` Skill Bundle 包含 required scripts、rules、hooks、runtime checks、Eval manifest 和组合证据。
- **Factory Skill composition**: 创作时展开 source Skill 的 `comet/flow.yaml`，含 choice resolution 和 cycle detection。
- **Comet Any user guidance**: 首次使用 Skill Creator guide、可确认的组合 proposal、resume summary、distribution preview。
- **`comet creator next` 用户路径**：新增一条只输出单个推荐下一步的用户命令，把后端 Bundle next action 翻译成普通用户可直接执行的 `comet eval ...`、`comet creator ...` 或 `comet publish ...` 命令，适合恢复中断的 `/comet-any` 流程。
- **Classic 状态转换审计日志**：成功的 `comet-state transition`、`comet-guard --apply` 和 archive 更新会追加到 `.comet/state-events.jsonl`，记录 event、source、from/to 状态和字段 effects。

### Changed

- **Classic 运行时打包**：把内部 Classic 控制包移到 `comet/runtime/classic` 下并改为**纯 YAML**（`skill.yaml` / `guardrails.yaml` / `checks.yaml`），安装产物不再暴露一个顶层、像 Skill 的 `comet-classic` 目录，但所有 `/comet*` 命令行为不变。
- **`subagent-driven-development` 下不再重复 review**：子 Skill dispatch 参考现在明确指出 `review_mode` 接管 Superpowers `subagent-driven-development` 默认的"每个 task 后派 reviewer"，且每模式的 review 次数由整条流的 review-budget 表固定——一次 change 不再同时为 Superpowers 的逐 task review 和 Comet 自己的 review 买单。
- **三档 review 渐变**：`review_mode` 现在形成真正的梯度：`off` = 零 task 级 reviewer（用户自担风险，记录原因）；`standard` = 仅当一个 task 命中风险信号时派一个 task 级 reviewer（spec + quality）；`thorough` = 每个 task 都派 task 级 reviewer，取代旧的批量 review。
- **每条 dispatch 必须显式选模型**：子 Skill dispatch 参考现在要求每次 implementer / fixer / reviewer dispatch 都显式指定模型，而不是静默继承会话里最贵的模型。
- **`review_mode` 默认改为 `standard`**：full workflow 初始化的默认 `review_mode` 和运行时 fallback 从 `null`（关闭）改为 `standard`。
- **`/comet` 主入口渐进式加载**：脚本定位引导（env-var 解析、`--apply`/`transition`/`next`/`archive` 命令参考、输出格式）从主 `comet/SKILL.md` 移到新的 `comet/reference/scripts.md` 单一来源，主入口每次加载省掉约 45 行内联样板。
- **Comet 子 Skill 渐进式加载**：把 `/comet` 的引导重构扩展到所有阶段和预设 Skill。frontmatter description 现在只描述触发条件，共享的脚本定位设置放在 `comet/reference/scripts.md`，`comet/reference/context-recovery.md` 定义一条**任意入口恢复规则**——从 `/comet-open`、`/comet-build`、`/comet-hotfix`、`/comet-tweak` 或其他入口恢复都保持确定性，无需在每个 Skill 里重复同样的样板。
- **归档提交提示**：archive Skill 现在以一个明确的"提交归档变更"步骤收尾。归档脚本只移动文件、合并 spec——不自动 commit——新步骤会提示用户 `git add -A && git commit` 并完成 phase 4 的分支处理，避免归档结果留在工作树未提交。
- **停顿点提问体验**：Comet 决策点现在在 Claude Code 等支持结构化提问的平台优先展示可点击的单选/多选。若平台没有 `AskUserQuestion`，或第一次调用失败，本会话后续停顿点直接降级为编号文本选项，避免反复尝试失败的 UI。
- **Project config merge on init/update**：`comet init` 和 `comet update` 对 `.comet/config.yaml` 做字段级合并，而非文件存在就跳过。保留现有值、补齐缺失字段、刷新注释、保留自定义字段；损坏 YAML 优雅回退到全部默认。
- **Publish facade path**: `comet publish` 作为常规 readiness/approval/publish/distribute 路径，`comet bundle` 作为高级后端。
- **Comet product model**: 围绕纯 Node 运行时、可恢复工作流诊断、可复用 Skill 平台和 `/comet-any` 作为主 Skill 创建路径重新定位。
- **Repository and runtime layout**: 仓库重组为 `app/`、`domains/`、`platform/`、`scripts/` 和对应测试。
- **Classic runtime storage**: machine-owned Run state 从 `.comet.yaml` 拆出，更多 workflow facts 走共享 diagnostics/runtime-eval 路径。
- **Runtime checks naming**: 新 Engine-native 包使用 `comet/checks.yaml`，迁移期保留 legacy `comet/evals.yaml` 加载。
- **Bundle distribution disclosure**: publish distribute 输出现在暴露 planned files 和 executable hook disclosures。
- **Comet Any preferences**: 用项目级 `.comet/skill-preferences.yaml` 替代未发布的 `.comet/skills.txt`，含 inventory-backed 偏好设置、proposal preview、preference-aware review readiness。
- **Publish readiness**: review 输出现在包含面向用户的 readiness 结论和下一步，在原始 blocker 证据之前。
- **Comet Any Skill Creator language**: 围绕定制 `/comet`、创建新 Skill、升级已有 Skill 重构语言，Bundle 和 Factory 概念保留在内部审计层。

### Eval 增强

- **自定义用户模拟器提示词**：新增 `BENCH_SIMULATOR_PROMPT_FILE` 环境变量（默认 `eval/simulator-instruction.md`）。auto_user 评测里，用户模拟 Agent 的指令可由你指定的文件覆盖，相对路径从 `eval/` 解析。`--simulator-prompt` 命令行参数仍保留更高优先级。
- **Anthropic 兼容代理认证**：当 `ANTHROPIC_API_KEY` 未设置时，`claude` 可改用 `ANTHROPIC_AUTH_TOKEN` + `ANTHROPIC_BASE_URL`（BigModel / mimo / OpenRouter 等）认证。配套变量 `ANTHROPIC_MODEL`、`ANTHROPIC_DEFAULT_HAIKU/SONNET/OPUS_MODEL`、`ANTHROPIC_DEFAULT_*_MODEL_NAME`、`CLAUDE_CODE_SUBAGENT_MODEL` 让代理后端的模型路由可控。

### Fixed

- **Windows 路径处理**：修复 OpenSpec init/update 在含空格目录下的路径引用，`comet init` 不再因项目路径含空格而失败。
- **部分 init 失败汇总**：`comet init` 把有任何组件失败的平台归入 `Failed` 并点名失败组件，而不是把部分安装既显示为已安装又显示为失败。
- **Skill 文档 EN/ZH 同步**：补回英文 `comet-build` Skill 里缺失的 `review_mode` 选择表和 review-gate 条件，回填中文 verify Skill 的"重试上限"段落。
- **停顿点 UI 覆盖**：新增共享决策点协议覆盖，确认结构化提问优先路径、一次性降级行为，以及阶段 Skill 继续保持平台中立。
- **Lint 噪声清理**：修复 `domains/bundle/authoring.ts`、`domains/factory/package.ts`、`domains/skill/platform-install.ts` 的 lint 告警，并新增 `scripts/lint/gitignore-top-level.mjs` 防止顶层 artifact 被意外提交。

### Removed

- **Bash-first 运行时依赖**: 移除旧的 shell-script 运行时/测试假设；Node launcher 和跨平台 runtime check 成为默认契约。
- **无用的 boilerplate 版本标记**：从 `comet/SKILL.md` 的脚本定位块移除没人读取的 `boilerplate version: vN` 标注，git 已经追踪跨文件同步。
- **主 comet Skill 的最佳实践附录**：从 `comet/SKILL.md` 删除"Best Practices / 最佳实践"附录。每一条都在 Decision Core 或对应子 Skill（comet-build / comet-archive / comet-hotfix / comet-tweak）里有更精确的指引，附录只是重复，子 Skill 仍是唯一来源。
