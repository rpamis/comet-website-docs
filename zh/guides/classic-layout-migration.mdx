---

Classic 模式目前支持两种 OpenSpec 目录布局：历史遗留项目使用仓库根目录下的 `openspec/`，新建项目默认存放在 `docs/openspec/`。布局由 `.comet/config.yaml` 中的 `classic.artifact_layout` 控制，但**不能只修改这个配置项来搬迁目录**。

本文介绍如何迁移 Classic 目录布局，以及迁移中断后如何恢复。如果只是日常的会话中断、更换开发机或长上下文压缩，直接在 Agent 对话中重新输入 [`/comet`](/zh/guides/resuming-workflow) 即可。

## 首先确认是否确实需要迁移

在项目根目录运行：

```bash
comet classic root show
```

这条命令会打印当前识别出的布局和实际路径：`artifactLayout` 为 `legacy` 时，根目录指向 `openspec/`；为 `docs` 时，根目录指向 `docs/openspec/`。

| 当前识别的布局 | 建议处置方案                                                |
| -------------- | ----------------------------------------------------------- |
| `legacy`       | 想统一到新布局时，按本文先运行 `--dry-run` 预览   |
| `docs`         | 已经是新布局，无需迁移。直接使用 `/comet` 推进日常开发即可   |
| 命令报错       | 先运行 `comet doctor` 修复环境配置或未完成的事务，然后重试     |

`docs` 是新建 Classic 项目的推荐布局，但已有历史项目可以长期继续使用 `legacy`。两种布局都在官方长期支持范围内，没有团队统一要求时，不必中断手头任务去搬迁目录。

## 迁移前安全核查

迁移会一次性搬迁**整个** `openspec/` 目录树，包含所有活跃变更、历史归档、Spec 和全局配置。执行前，请通知团队成员暂停向 Classic 目录写入内容，并先把当前 Git 工作区的改动暂存或提交。

然后运行只读的预检：

```bash
comet classic root move docs --dry-run
```

预检不修改磁盘文件。它会详实报告源路径与目标路径、文件清单摘要、配置变更项、潜在文件冲突以及可用的恢复预案。只有当输出明确显示 `可执行迁移: 是` 时，才可继续下一步。

<Warning>
  在执行 dry-run 预览与正式 apply 之间，<strong>切勿对源码或文档做任何修改</strong>。迁移引擎在执行时会再次核验目录指纹；若检测到中途产生新改动，会主动终止以防覆盖内容。
</Warning>

### 常见阻断问题及应对方案

| 预检报错现象                   | 根本成因                                          | 正确应对方式                                             |
| ------------------------------ | ------------------------------------------------- | -------------------------------------------------------- |
| `docs` 目标目录已存在非空内容  | `docs/openspec/` 目录下原本就有文件，可能造成覆盖 | 先手动排查该目录内的已有文件，切勿强行覆盖               |
| 存在未完成的事务残留           | 上一次迁移意外中断留下了中间流水                  | 先根据后文“迁移中断恢复”处理完毕，再重新运行 dry-run     |
| Classic 未启用或配置不兼容     | 当前项目未正式初始化 Classic 模式                 | 先运行 `comet doctor` 诊断项目配置                       |
| 出现文件权限或路径冲突         | 文件只读或被其他进程占用                          | 解除文件占用后，重新运行预检                             |

## 正式执行迁移

预检确认无误后，在项目根目录执行：

```bash
comet classic root move docs --apply
```

当前版本的 `--apply` 无需手动输入 Plan ID。Comet 会在事务保护下，复制校验完整目录树、将 `classic.artifact_layout` 原子更新为 `docs`，随后安全清理历史旧目录。整个过程会完整保留所有变更的状态机、检查点、脑暴快照与归档证据。

命令提示“迁移已完成”后，再次验证根目录状态：

```bash
comet classic root show
```

若输出显示 `artifactLayout: "docs"` 且 `openSpecRoot: "docs/openspec"`，即表示迁移完成。此时重新在 Agent 中输入 `/comet`，系统会自动基于新路径识别并接管变更。

## 迁移意外中断后的恢复指引

若在执行 `--apply` 期间因断电、杀进程或磁盘异常导致中断，**切勿手动强行搬移目录、切勿手动删除 `.comet/classic-root-move.json` 事务文件，也不要直接改配置文件**。这些操作会破坏系统自动恢复所需的记录。

首先运行诊断命令：

```bash
comet doctor
```

诊断报告会明确指出当前停留在迁移事务的哪一步，并给出当前可用的恢复方式：

- 若确认希望**继续完成**原迁移流程，运行：

  ```bash
  comet doctor --repair --strategy continue
  ```

- 若确认希望**放弃本次迁移并彻底回滚**至原状（需在配置尚未切换前），运行：

  ```bash
  comet doctor --repair --strategy rollback
  ```

`continue` 与 `rollback` 策略受事务阶段严格约束，系统仅在安全的前提下放行对应操作。恢复完成后，再次运行 `comet classic root show` 确认最终状态。

## 迁移后的排障清单

迁移完成后若输入 `/comet` 提示找不到任务，请按以下顺序逐项核对：

1. 运行 `comet classic root show`，确认变更根目录已准确指向 `docs/openspec/changes/`；
2. 检查既有的活跃变更确实位于该目录下，归档记录位于 `docs/openspec/changes/archive/`；
3. 运行 `comet status`，查看变更的阶段状态与任务完成度；
4. 运行 `comet doctor`，排查是否有损坏的残留引用；
5. 在对话中重新输入 `/comet` 唤醒接管。

<Note>
  <code>classic.artifact_layout</code> 仅作用于 Classic 的 OpenSpec 产物目录。Native 工作流使用完全独立的 <code>native.artifact_root</code>，迁移 Classic 不会触碰 Native 的任何文件。
</Note>

## 禁止事项

- 禁止通过操作系统资源管理器或纯命令行 `mv` 手动搬移 `openspec/` 目录；
- 禁止仅在配置文件中将 `classic.artifact_layout` 单独改为 `docs`；
- 禁止在迁移事务未彻底完成前新建、归档或编辑变更；
- 禁止擅自删除迁移事务日志或临时文件。

只有通过官方提供的 `comet classic root move` 与 `comet doctor --repair`，才能确保元数据与状态机恢复完整。
