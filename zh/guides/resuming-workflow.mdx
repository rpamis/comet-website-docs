title: "恢复中断的工作"
description: "学习会话中断、上下文压缩或换平台后，如何让 Comet 从正确阶段继续。"
---

恢复时先不要让 Agent 猜。让 Comet 重新读取文件化状态。

## 最短路径

```bash
comet status
```

然后在 Agent 平台里输入：

```text
/comet
```

如果 `status` 显示诊断问题，再运行：

```bash
comet doctor
```

## 恢复判定顺序

```mermaid
flowchart TD
  A["重新打开项目"] --> B["comet status"]
  B --> C{"有活跃 change?"}
  C -->|没有| D["创建新 change"]
  C -->|有| E["检查 phase 和 evidence"]
  E --> F{"状态有效?"}
  F -->|有效| G["/comet 路由到当前阶段"]
  F -->|异常| H["comet doctor 诊断"]
  H --> I["按提示修复或恢复证据"]
```

## build 阶段恢复

如果 `phase: build`，重点看：

- `build_pause`
- `plan`
- `build_mode`
- `isolation`
- `subagent_dispatch`
- 未完成的 `tasks.md` 项

`build_pause: plan-ready` 表示计划已生成，下一步是选择隔离方式和执行方式。

## verify 失败恢复

如果 `verify_result: fail`，不要直接归档。先决定修复还是接受偏差。选择修复后回到 build。

## 有未提交改动时

Comet 会把未提交改动当作恢复风险。先检查这些改动属于当前 change、用户改动还是无关改动，再继续。
