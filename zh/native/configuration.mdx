Native 与 Classic 共用项目级 `.comet/config.yaml`。引入 Native 后，配置文件不再只保存 Classic 的四个默认值；它同时承担 `/comet` 入口路由、工作流启用范围和自动恢复策略，并把 Native 专属设置放在 `native` 命名空间中。

## 完整示例

同时启用 Native 与 Classic 的项目可以生成如下配置：

```yaml
schema: comet.project.v1
default_workflow: native
workflows:
  - native
  - classic
ambient_resume: true

native:
  artifact_root: docs
  language: zh-CN
  clarification_mode: sequential
  archive_confirmation: automatic
  max_verify_failures: 5
  # Native 内容快照使用的可审计项目范围与有界工作预算。
  snapshot:
    # 纳入的项目相对路径；支持 *、** 和 ?。
    include:
      - '**/*'
    # 明确排除不属于实现范围的数据或生成物。
    exclude: []
    # 单次快照最多捕获的文件数。
    max_files: 10000
    # 单次快照最多流式哈希的内容总字节数。
    max_total_bytes: 268435456
    # 单次快照的最长执行时间（毫秒）。
    max_duration_ms: 60000

classic:
  language: zh-CN
  context_compression: off
  review_mode: standard
  auto_transition: true
```

共享字段决定入口和恢复；`native.*` 只影响 Native，`classic.*` 只影响新建 Classic change。两套状态机、change 目录和 Guard 不会因为共用配置文件而合并。

## 共享入口字段

| 字段               | 允许值 / 默认值            | 作用                                                      |
| ------------------ | -------------------------- | --------------------------------------------------------- |
| `schema`           | `comet.project.v1`         | 当前结构化项目配置版本；由 Comet 管理                     |
| `default_workflow` | `native` \| `classic`      | 用户调用 `/comet` 时进入哪套永久 Skill                    |
| `workflows`        | `native`、`classic` 或两者 | 此项目已经启用并安装的工作流；必须包含默认工作流          |
| `ambient_resume`   | `true`（默认）\| `false`   | 是否允许 Agent 对普通自然语言续接请求自动运行只读恢复探测 |

`default_workflow` 只控制入口，不迁移已有 change。`workflows` 也不是安装命令：不要只在 YAML 中加入 `native` 或 `classic`，应使用 `comet init . --workflow native|classic|both` 安装对应 Skill、Rule 与 Hook Router。

## Native 字段

| 字段                              | 允许值 / 默认值                             | 作用                                                                    |
| --------------------------------- | ------------------------------------------- | ----------------------------------------------------------------------- |
| `native.artifact_root`            | 项目内相对路径；默认 `docs`                 | 决定 `<artifact-root>/comet/` 中规格、change、归档和 Runtime 数据的位置 |
| `native.language`                 | `en` \| `zh-CN`；默认 `en`                  | 新建 Native change 的需求简述、规格和报告语言                           |
| `native.clarification_mode`       | `sequential` \| `batch`；默认 `sequential`  | 每轮询问一个最上游问题，或一次提出本轮全部可回答问题                    |
| `native.archive_confirmation`     | `automatic` \| `required`；默认 `automatic` | 最终 Archive 候选自动归档，或要求一次明确确认                           |
| `native.max_verify_failures`      | 正整数；默认 `5`                            | 同一需求契约可以接受的 Verify 失败总次数                                |
| `native.snapshot.include`         | 项目相对匹配模式；默认 `["**/*"]`           | 定义基线快照和后续当前快照纳入的路径                                    |
| `native.snapshot.exclude`         | 项目相对 glob；默认 `[]`                    | 显式排除不属于实现范围的版本化数据或生成物                              |
| `native.snapshot.max_files`       | 正整数；默认 `10000`                        | 单次快照最多捕获的文件数                                                |
| `native.snapshot.max_total_bytes` | 正整数；默认 `268435456`                    | 单次快照最多流式哈希的文件内容总字节数                                  |
| `native.snapshot.max_duration_ms` | 正整数；默认 `60000`                        | 单次快照允许的最长执行时间                                              |

`artifact_root: .` 对应 `<project>/comet/`，`artifact_root: docs` 对应 `<project>/docs/comet/`。已有 Native 项目不能只改这个字段再手动移动目录；使用事务化命令：

```bash
comet native root show
comet native root move docs
```

修改后续新 change 的默认语言可以运行：

```bash
comet native init --language zh-CN
```

已有 change 会继续使用创建时写入的语言，不会被项目默认值追溯改写。

`clarification_mode` 只改变产品问题的组织方式，不新增阶段，也不改变共享写入保护或调用方停点。Sequential 每轮只问一个最上游决定，Batch 提出本轮所有可回答决定；两种模式都必须在进入 Build 前完成最终共享理解确认。切换模式不会清除需求简述中已保存的 `[blocking]` 问题；应先处理当前问题，再按新模式计算下一轮。

`archive_confirmation` 只在最终 Verify 通过后生效。`automatic` 继续完成归档；`required` 在最终 Archive 候选处停下等待一次明确决定。Verify 失败后的 Build ↔ Verify 修复轮次不会触发该确认。

`max_verify_failures` 是同一需求契约的总失败预算。缺口减少、检查转绿或证据恢复有效仍可继续下一轮；相同语义缺口第三次出现且没有进展时会更早停止。只有用户确认后的需求契约变化会开始新的预算周期。

### 内容快照范围与预算

Native 使用文件内容的流式 SHA-256 建立基线快照，不把 Git 对象哈希或 Git LFS 指针当作普通文件内容身份。Git 项目可以使用 Git 枚举已跟踪与未被忽略的未跟踪文件，但 Git 只是选择提供器；非 Git 项目使用物理树提供器，内容语义相同。

`include` 与 `exclude` 先规范化，再连同策略哈希写入新 change 的 `baseline-manifest.json`。后续 Build、Verify 和检查始终沿用基线快照的范围，所以不能在实现中途修改配置来隐藏变化。资源预算不是内容身份：仓库增长后可以提高 `max_files`、`max_total_bytes` 或 `max_duration_ms`，而不必改用 Git 哈希。

#### 路径模式匹配规则

所有路径模式都相对于项目根目录，并使用 `/`：

- `*` 匹配单个目录层级内的任意字符；
- `**` 可以跨越多个目录层级；
- `?` 匹配一个非 `/` 字符；
- 不允许绝对路径、反斜杠、空模式或 `..`；
- 不支持 `!pattern` 写法，排除项必须写入 `exclude`。

一个路径只有在匹配至少一个 `include` 且不匹配任何 `exclude` 时才会进入快照，因此 `exclude` 最终优先。路径模式会被去重、排序和规范化，再写入基线策略。

`.gitignore` 与 `exclude` 不是同一层：Git 提供器用 `.gitignore` 决定哪些未跟踪文件进入候选集合，Native 策略则记录一次 change 明确承诺观察的范围。非 Git 提供器没有 Git 忽略规则，所以对大型生成物和数据目录写出明确的排除模式，也能让不同提供器保持一致意图。

#### 如何选择范围与预算

先定义交付范围，再考虑性能：

- 文件属于实现或验证范围：提高总字节数和执行时间，让 Runtime 完整流式哈希。
- 大型数据或生成物不属于实现范围：用明确的 `exclude` 模式排除，并让该策略随基线快照留下审计记录。
- 不确定文件是否相关：先保留，查看 Runtime 返回的实际限制和受影响路径后再决定。

普通项目优先使用默认完整范围：

```yaml
native:
  snapshot:
    include:
      - '**/*'
    exclude: []
    max_files: 10000
    max_total_bytes: 268435456
    max_duration_ms: 60000
```

Monorepo 应同时包含目标应用、共享依赖、相关测试和根级构建身份文件：

```yaml
native:
  snapshot:
    include:
      - 'apps/web/**'
      - 'packages/ui/**'
      - 'packages/config/**'
      - 'package.json'
      - 'pnpm-lock.yaml'
      - 'pnpm-workspace.yaml'
    exclude:
      - 'apps/web/dist/**'
      - 'apps/web/coverage/**'
    max_files: 20000
    max_total_bytes: 536870912
    max_duration_ms: 90000
```

大型仓库可以保持广泛 include，明确排除与交付无关的重型内容：

```yaml
native:
  snapshot:
    include:
      - '**/*'
    exclude:
      - 'data/generated/**'
      - 'artifacts/benchmarks/**'
      - 'dist/**'
      - 'coverage/**'
      - '.cache/**'
    max_files: 50000
    max_total_bytes: 1073741824
    max_duration_ms: 120000
```

不要只纳入当前准备修改的源码目录。如果构建、测试或 Runtime 依赖共享包、根配置、锁文件或迁移脚本，也必须纳入。不要为了让快照通过而排除源码、测试或交付所需配置；这会让实现范围与真实风险脱节。

超出预算时，`comet native new` 继续失败关闭并删除未完成 change，但诊断会返回实际限制、策略哈希、受影响路径、配置文件位置和支持的修复方向，不再只给出无法执行的笼统动作。

更多可直接复制的场景和排障答案见 [Native 常见问题](/zh/native/faq#内容快照与实现范围)。

<Warning>
  <code>native.pending_root_move</code> 是产物根目录迁移
  中断恢复使用的机器字段，不是用户配置项。看到它时运行 <code>comet native doctor</code>
  ，不要手工删除或修改。
</Warning>

## Classic 字段

Classic Runtime 从 `.comet/config.yaml` 的 `classic:` 块读取以下默认值，并在新建 change 时写入该 change 的 `.comet.yaml`：

| 字段                  | 允许值                            | 默认值     |
| --------------------- | --------------------------------- | ---------- |
| `language`            | `en` \| `zh-CN`                   | `en`       |
| `context_compression` | `off` \| `beta`                   | `off`      |
| `review_mode`         | `off` \| `standard` \| `thorough` | `standard` |
| `auto_transition`     | `true` \| `false`                 | `true`     |

这些字段不会改变 Native 的执行方法；Native 没有 context compression、review mode 或按阶段 Skill 自动衔接配置。

## 常见配置

### 只启用 Native

```yaml
schema: comet.project.v1
default_workflow: native
workflows:
  - native
ambient_resume: true
native:
  artifact_root: docs
  language: zh-CN
  clarification_mode: sequential
  snapshot:
    include: ['**/*']
    exclude: []
    max_files: 10000
    max_total_bytes: 268435456
    max_duration_ms: 60000
```

### 两套工作流都启用，但默认进入 Classic

```yaml
schema: comet.project.v1
default_workflow: classic
workflows:
  - native
  - classic
ambient_resume: true
native:
  artifact_root: docs
  language: zh-CN
  clarification_mode: batch
  snapshot:
    include: ['**/*']
    exclude: []
    max_files: 10000
    max_total_bytes: 268435456
    max_duration_ms: 60000
classic:
  language: zh-CN
  context_compression: off
  review_mode: standard
  auto_transition: true
```

### 关闭普通请求的自动恢复探测

```yaml
ambient_resume: false
```

这只关闭 Agent 对自然语言续接请求的自动探测；显式 `/comet` 仍按 `default_workflow` 工作。

## 旧 Classic 配置迁移

只有顶层 `language`、`context_compression`、`review_mode` 和 `auto_transition` 的旧文件，入口解析仍会使用 `legacy-fallback` 进入 Classic，不会猜测 Native。Classic Runtime 不再直接读取这些顶层默认值。

运行 `comet init` 或 `comet update` 时，Comet 会把旧顶层值迁入 `classic:`，保留已经明确写在新块中的值，并移除旧字段。启用 Native 时使用 `comet init . --workflow native` 或 `--workflow both`，不要手工拼接两套配置。
