Native 与 Classic 共用项目级 `.comet/config.yaml`。引入 Native 后，配置文件不再只保存 Classic 的四个默认值；它同时承担 `/comet` 入口路由、工作流启用范围和自动恢复策略，并把 Native 专属设置放在 `native` 命名空间中。

## 完整示例

同时启用 Native 与 Classic 的项目可以生成如下配置：

```yaml
schema: comet.project.v1
default_workflow: native
workflows:
  - native
  - classic
ambient_resume: true

native:
  artifact_root: docs
  language: zh-CN
  clarification_mode: sequential
  # Native 内容快照使用的可审计项目范围与有界工作预算。
  snapshot:
    # 纳入的项目相对路径；支持 *、** 和 ?。
    include:
      - '**/*'
    # 明确排除不属于实现范围的数据或生成物。
    exclude: []
    # 单次快照最多捕获的文件数。
    max_files: 10000
    # 单次快照最多流式哈希的内容总字节数。
    max_total_bytes: 268435456
    # 单次快照的最长执行时间（毫秒）。
    max_duration_ms: 60000

classic:
  language: zh-CN
  context_compression: off
  review_mode: standard
  auto_transition: true
```

共享字段决定入口和恢复；`native.*` 只影响 Native，`classic.*` 只影响新建 Classic change。两套状态机、change 目录和 Guard 不会因为共用配置文件而合并。

## 共享入口字段

| 字段               | 允许值 / 默认值            | 作用                                                      |
| ------------------ | -------------------------- | --------------------------------------------------------- |
| `schema`           | `comet.project.v1`         | 当前结构化项目配置版本；由 Comet 管理                     |
| `default_workflow` | `native` \| `classic`      | 用户调用 `/comet` 时进入哪套永久 Skill                    |
| `workflows`        | `native`、`classic` 或两者 | 此项目已经启用并安装的工作流；必须包含默认工作流          |
| `ambient_resume`   | `true`（默认）\| `false`   | 是否允许 Agent 对普通自然语言续接请求自动运行只读恢复探测 |

`default_workflow` 只控制入口，不迁移已有 change。`workflows` 也不是安装命令：不要只在 YAML 中加入 `native` 或 `classic`，应使用 `comet init . --workflow native|classic|both` 安装对应 Skill、Rule 与 Hook Router。

## Native 字段

| 字段                              | 允许值 / 默认值                            | 作用                                                                       |
| --------------------------------- | ------------------------------------------ | -------------------------------------------------------------------------- |
| `native.artifact_root`            | 项目内相对路径；默认 `docs`                | 决定 `<artifact-root>/comet/` 中 specs、changes、archive 和 runtime 的位置 |
| `native.language`                 | `en` \| `zh-CN`；默认 `en`                 | 新建 Native change 的 brief、规格和报告语言                                |
| `native.clarification_mode`       | `sequential` \| `batch`；默认 `sequential` | 每轮询问一个最上游问题，或一次提出本轮全部可回答问题                       |
| `native.snapshot.include`         | 项目相对 glob；默认 `["**/*"]`             | 定义 baseline 和后续 current snapshot 纳入的路径                           |
| `native.snapshot.exclude`         | 项目相对 glob；默认 `[]`                   | 显式排除不属于实现范围的版本化数据或生成物                                 |
| `native.snapshot.max_files`       | 正整数；默认 `10000`                       | 单次快照最多捕获的文件数                                                   |
| `native.snapshot.max_total_bytes` | 正整数；默认 `268435456`                   | 单次快照最多流式哈希的文件内容总字节数                                     |
| `native.snapshot.max_duration_ms` | 正整数；默认 `60000`                       | 单次快照允许的最长执行时间                                                 |

`artifact_root: .` 对应 `<project>/comet/`，`artifact_root: docs` 对应 `<project>/docs/comet/`。已有 Native 项目不能只改这个字段再手动移动目录；使用事务化命令：

```bash
comet native root show
comet native root move docs
```

修改后续新 change 的默认语言可以运行：

```bash
comet native init --language zh-CN
```

已有 change 会继续使用创建时写入的语言，不会被项目默认值追溯改写。

`clarification_mode` 只改变产品问题的组织方式，不新增 phase，也不改变共享写入保护或调用方停点。Sequential 每轮只问一个最上游决定，Batch 提出本轮所有可回答决定；两种模式都必须在进入 Build 前完成最终共享理解确认。切换模式不会清除 brief 中已保存的 `[blocking]` 问题；应先处理当前问题，再按新模式计算下一轮。

### 内容快照范围与预算

Native 使用文件内容的流式 SHA-256 建立 baseline，不把 Git object hash 或 Git LFS pointer 当作普通文件内容身份。Git 项目可以使用 Git 枚举 tracked 与未被 ignore 的 untracked 文件，但 Git 只是选择 provider；非 Git 项目使用物理树 provider，内容语义相同。

`include` 与 `exclude` 先规范化，再连同策略 hash 写入新 change 的 `baseline-manifest.json`。后续 Build、Verify 和 check 始终沿用 baseline 的范围，所以不能在实现中途修改配置来隐藏变化。资源预算不是内容身份：仓库增长后可以提高 `max_files`、`max_total_bytes` 或 `max_duration_ms`，而不必改用 Git hash。

大型仓库通常有两种处理方式：

- 文件属于实现或验证范围：提高总字节数和执行时间，让 Runtime 完整流式哈希。
- 大型数据或生成物不属于实现范围：用明确的 `exclude` 模式排除，并让该策略随 baseline 留下审计记录。

```yaml
native:
  snapshot:
    include:
      - 'src/**'
      - 'test/**'
      - 'package.json'
    exclude:
      - 'data/generated/**'
    max_files: 50000
    max_total_bytes: 1073741824
    max_duration_ms: 120000
```

超出预算时，`comet native new` 继续失败关闭并删除未完成 change，但诊断会返回实际限制、策略 hash、受影响路径、配置文件位置和支持的修复方向，不再只给出无法执行的笼统动作。

<Warning>
  <code>native.pending_root_move</code> 是 root move
  中断恢复使用的机器字段，不是用户配置项。看到它时运行 <code>comet native doctor</code>
  ，不要手工删除或修改。
</Warning>

## Classic 字段

Classic Runtime 从 `.comet/config.yaml` 的 `classic:` 块读取以下默认值，并在新建 change 时写入该 change 的 `.comet.yaml`：

| 字段                  | 允许值                            | 默认值     |
| --------------------- | --------------------------------- | ---------- |
| `language`            | `en` \| `zh-CN`                   | `en`       |
| `context_compression` | `off` \| `beta`                   | `off`      |
| `review_mode`         | `off` \| `standard` \| `thorough` | `standard` |
| `auto_transition`     | `true` \| `false`                 | `true`     |

这些字段不会改变 Native 的执行方法；Native 没有 context compression、review mode 或按阶段 Skill 自动衔接配置。

## 常见配置

### 只启用 Native

```yaml
schema: comet.project.v1
default_workflow: native
workflows:
  - native
ambient_resume: true
native:
  artifact_root: docs
  language: zh-CN
  clarification_mode: sequential
  snapshot:
    include: ['**/*']
    exclude: []
    max_files: 10000
    max_total_bytes: 268435456
    max_duration_ms: 60000
```

### 两套工作流都启用，但默认进入 Classic

```yaml
schema: comet.project.v1
default_workflow: classic
workflows:
  - native
  - classic
ambient_resume: true
native:
  artifact_root: docs
  language: zh-CN
  clarification_mode: batch
  snapshot:
    include: ['**/*']
    exclude: []
    max_files: 10000
    max_total_bytes: 268435456
    max_duration_ms: 60000
classic:
  language: zh-CN
  context_compression: off
  review_mode: standard
  auto_transition: true
```

### 关闭普通请求的自动恢复探测

```yaml
ambient_resume: false
```

这只关闭 Agent 对自然语言续接请求的自动探测；显式 `/comet` 仍按 `default_workflow` 工作。

## 旧 Classic 配置迁移

只有顶层 `language`、`context_compression`、`review_mode` 和 `auto_transition` 的旧文件，入口解析仍会使用 `legacy-fallback` 进入 Classic，不会猜测 Native。Classic Runtime 不再直接读取这些顶层默认值。

运行 `comet init` 或 `comet update` 时，Comet 会把旧顶层值迁入 `classic:`，保留已经明确写在新块中的值，并移除旧字段。启用 Native 时使用 `comet init . --workflow native` 或 `--workflow both`，不要手工拼接两套配置。
