Native 和 Classic 共用项目根目录的 `.comet/config.yaml`。它决定 `/comet` 进入哪套工作流、项目启用了哪些工作流，以及 Native/Classic 各自的默认值。新 Native change 不需要配置项目级扫描范围。

## 完整示例

```yaml
schema: comet.project.v1
default_workflow: native
workflows:
  - native
  - classic
ambient_resume: true

native:
  artifact_root: docs
  language: zh-CN
  clarification_mode: batch
  archive_confirmation: automatic
  max_verify_failures: 5

classic:
  language: zh-CN
  context_compression: off
  review_mode: standard
  auto_transition: true

# hook:
#   allow_paths:
#     - src
```

共享字段管入口和恢复；`native.*` 只影响 Native，`classic.*` 只影响新建的 Classic change。两套工作流的目录和状态彼此独立。

## 共享入口字段

| 字段               | 允许值 / 默认值            | 作用                    |
| ------------------ | -------------------------- | ----------------------- | -------------------------------------- |
| `schema`           | `comet.project.v1`         | 配置版本，由 Comet 管理 |
| `default_workflow` | `native`                   | `classic`               | `/comet` 的默认入口                    |
| `workflows`        | `native`、`classic` 或两者 | 本项目已启用的工作流    |
| `ambient_resume`   | `true`（默认）             | `false`                 | 是否对自然语言续接请求运行只读恢复探测 |

`default_workflow` 只管入口，不会迁移已有 change。YAML 里增加 `native` 也不会安装 Skill；安装或更新请使用：

```bash
comet init --workflow native|classic|both
comet update
```

## Hook 写入放行

`hook.allow_paths` 列出在受保护阶段允许 Agent 写入的项目相对目录。它是 Native 和 Classic 共享的写入策略，默认为空。

不配置时，项目内（产物区之外）的写入按各工作流的阶段规则处理：Native 只在 Build 阶段允许实现写入，Classic 按自身阶段与守卫规则判定。把某个目录加入 `hook.allow_paths` 后，该目录及其子目录的写入会直接放行，不再受阶段检查约束——典型用途是让实现代码目录（如 `src/`、`apps/web/`）在任意阶段都能修改，避免在非 Build 阶段触发回退或拦截。

```yaml
hook:
  allow_paths:
    - src
    - apps/web
```

要点：

- 路径必须是项目相对路径，用 `/` 分隔，每项一个目录；按前缀匹配，`src` 会覆盖 `src/` 下所有文件。
- 以下区域永远受保护，无法通过本配置放行：`.comet`（Runtime 状态）、Native 产物根（如 `docs`）、Classic 的 openspec 与 superpowers 根。它们始终走专属写入规则。
- 路径越界或格式错误会在 `comet doctor` 检查时报错。

## Native 字段

| 字段                          | 允许值 / 默认值             | 作用                                  |
| ----------------------------- | --------------------------- | ------------------------------------- | ------------------------------------------------------ |
| `native.artifact_root`        | 项目内相对路径；默认 `docs` | 用户文档放在 `<artifact-root>/comet/` |
| `native.language`             | `en`                        | `zh-CN`；默认 `en`                    | 新 change 的 brief、Spec、报告语言                     |
| `native.clarification_mode`   | `batch`                     | `sequential`；新项目默认 `batch`      | 一轮询问所有已具备前提的问题，或每轮询问一个最上游问题 |
| `native.archive_confirmation` | `automatic`                 | `required`；默认 `automatic`          | 通过 Verify 后是否等待一次用户确认                     |
| `native.max_verify_failures`  | 正整数；默认 `5`            | 同一实现需求允许的失败轮次上限        |

### 修改产物根目录

`artifact_root: .` 对应 `<project>/comet/`，`docs` 对应 `<project>/docs/comet/`。已有项目不要只改 YAML 再手动移动目录：

```bash
comet native root show
comet native root move docs
```

### 修改语言和澄清模式

语言只影响之后新建的 change；已有 change 保留创建时的语言。Batch 是新项目默认值，也可以显式切换：

```yaml
native:
  language: zh-CN
  clarification_mode: sequential
```

两种模式都会先调查可查事实，并在进入 Build 前要求用户确认完整的共享理解。切换模式不会自动删除 brief 里的 `[blocking]` 问题。

### 归档确认和失败上限

`automatic` 在 Verify 通过后继续归档，`required` 会停下等待一次明确确认。`max_verify_failures` 只限制实现失败轮次；Runtime 执行错误和语义阻塞会以 `await-user`/`blocked` 返回，不会通过手改计数继续循环。

## 旧项目升级说明

旧版本可能留下 `native.snapshot`、change-local Runtime、旧 receipt 或 evidence 文件。它们不是 beta17 新 change 的配置项或验收输入。升级时由 `comet update`/`comet doctor` 处理迁移；不要为了让新 Verify 通过而继续添加这些字段，也不要手工复制旧 Runtime。

## 常见配置

### 只启用 Native

```yaml
schema: comet.project.v1
default_workflow: native
workflows:
  - native
ambient_resume: true
native:
  artifact_root: docs
  language: zh-CN
  clarification_mode: batch
  archive_confirmation: automatic
  max_verify_failures: 5
```

### 关闭普通请求的自动恢复探测

```yaml
ambient_resume: false
```

这只关闭自然语言续接时的只读探测；显式 `/comet` 仍按 `default_workflow` 工作。
