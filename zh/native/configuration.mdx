Comet 将项目级配置集中在根目录的 `.comet/config.yaml`。运行 `comet init` 时会自动生成默认配置，绝大多数项目无需手动调整；只有当你需要定制默认工作流、文档语言、澄清节奏、文档写入策略、并发上限、记忆/知识来源或自定义 PR 脚本时，才需要修改对应字段。

## 推荐的 Native 配置

适合中文交付文档项目的常用配置如下：

```yaml
# 配置格式版本，由 Comet 自动维护
schema: comet.project.v1
# /comet 默认进入 Native 工作流
default_workflow: native
# 当前项目启用的工作流（native、classic 或两者）
workflows:
  - native
# 在新会话用自然语言继续旧任务时，启用只读恢复探测
ambient_resume: true
# 是否支持生成独立 HTML 变更说明（Native 下仅在用户要求时生成）
change_walkthrough: true

# 个人记忆（Native 与 Classic 共用）
memory:
  learning: true
  retrieval: true

# 项目知识来源
knowledge:
  provider: local

# Native 核心配置
native:
  # change、Spec 与验证报告的根目录：<artifact_root>/comet/
  artifact_root: docs
  # 新建 change 的文档语言（en | zh-CN）
  language: zh-CN
  # 澄清方式：batch（每轮批量问） | sequential（逐题问）
  clarification_mode: batch
  # 归档确认：automatic（满足安全条件时自动归档） | required（人工确认后再归档）
  archive_confirmation: automatic
  # 同一确认目标允许的最大 Verify 失败次数
  max_verify_failures: 5
  # 多会话 Supervisor 模式下允许并发推进的子任务上限
  max_parallel_children: 2
  # 非 Build 阶段的普通文档写入策略：allow（保留并由 Agent 评估影响） | revert（严格拦截）
  document_writes: allow
```

<Tip>
  推荐通过 `comet init --workflow native` 生成初始配置，后续用 `comet update` 同步版本；常见选项也可以直接在 `comet dashboard` 的 **设置 → Comet 配置** 中可视化调整。
</Tip>

## 默认工作流与自然语言恢复

| 字段 | 默认值 | 行为说明 |
| --- | --- | --- |
| `schema` | `comet.project.v1` | 配置文件格式版本，请勿手动改动。 |
| `default_workflow` | 初始化时选定 | 决定 `/comet` 默认进入 `native` 还是 `classic`。 |
| `workflows` | 初始化时选定 | 声明项目启用的工作流（支持单独启用或同时启用 `native` 与 `classic`）。 |
| `ambient_resume` | `true` | 开启后，在对话中说“继续刚才的任务”会触发只读恢复探测；设为 `false` 可停用。 |

修改 `default_workflow` 只影响后续新建入口的路由，不会把已有的 Native change 改成 Classic，也不会反向迁移 Classic change。想在项目中同时启用两套工作流，运行 `comet init --workflow both` 即可。

## Native 核心参数

| 配置项 | 可选值 / 默认值 | 作用说明 |
| --- | --- | --- |
| `native.artifact_root` | 项目相对路径；默认 `docs` | 决定 change、Specs 与报告的存放根目录（`<artifact_root>/comet/`）。 |
| `native.language` | `en` \| `zh-CN`；默认 `en` | 决定后续新建 change 的文档语言；已有 change 沿用创建时的语言。 |
| `native.clarification_mode` | `batch` \| `sequential`；默认 `batch` | 控制 Shape 阶段按批提问还是逐题提问。详见 [Sequential 与 Batch 澄清](/zh/native/clarification-modes)。 |
| `native.archive_confirmation` | `automatic` \| `required`；默认 `automatic` | 控制 Verify 全部通过后是否自动进入归档。 |
| `native.max_verify_failures` | 正整数；默认 `5` | 同一确认目标允许的最大真实 Verify 失败次数，超限后暂停等待人工决定。 |
| `native.max_parallel_children` | 正整数；默认 `2` | Supervisor 多会话模式下的子任务并发上限；单会话模式固定为 `1`。 |
| `native.document_writes` | `allow` \| `revert`；默认 `allow` | 控制 Shape、Verify、Archive 阶段对普通文档类文件的写入处理策略。 |

### Supervisor 子任务并发上限

可以在 **Dashboard → 设置 → Comet 配置 → Native 工作流** 中调整，或直接编辑 `native.max_parallel_children`：

- 配额统计“已派发且尚未完成集成”的活跃子任务数量（包括 Build、Verify 和等待集成中的子任务）；Runtime 完成集成后自动释放名额。
- 修改后从下一轮派发生效；如果下调到当前活跃数量以下，系统会等已有子任务完成集成后再按新上限派发，不会中止正在运行的任务。
- 配置始终以主项目为准，子任务 worktree 中的配置不会反向影响主任务。详见 [Supervisor Change](/zh/native/supervisor-change)。

### 产物存储根目录

`artifact_root: docs` 对应 `<project>/docs/comet/`，`artifact_root: .` 对应 `<project>/comet/`，路径必须位于项目根目录内。

已有项目要迁移产物根目录时，不要手动改 YAML 或手搬目录。直接让 Agent 处理即可；你也可以自己在终端运行迁移命令（`show` 查看当前根目录，`move` 迁移到指定目录；迁移中断后可通过 `comet native doctor --repair --strategy <continue|rollback>` 恢复）：

```bash
comet native root show
comet native root move docs
```

### 归档确认策略（`native.archive_confirmation`）

- **`automatic`**：当 Verify 全部通过，且同时满足“接受验收是唯一待处理等待项、无待处理证据等待、无 `running` 或 `unknown` 动作”时，Runtime 自动接受并继续归档。
- **`required`**：Verify 全部通过后停下，等待你在对话中明确确认再归档。

注意：`automatic` 只决定是否跳过本地归档前的二次确认，**不会**未经同意自动执行 Git merge、push 或创建 PR。

### 验证失败上限（`native.max_verify_failures`）

限制同一确认目标允许的最大真实 Verify 失败次数（默认 `5`）。达到上限时，Native Loop 暂停并列出历次失败记录，由你决定换思路继续修、调整需求还是取消任务，避免在错误方向上反复消耗 Token。平台报错或缺少外部条件等阻塞会直接暂停报告，不要靠调大该上限来掩盖环境错误。

### 非 Build 阶段文档写入策略（`native.document_writes`）

- **`allow`（默认）**：在 Shape、Verify、Archive 阶段对仓库根目录及 `docs/`、`doc/`、`documentation/`、`.github/` 等目录下的普通 Markdown/文本/LICENSE 文件（位于 Native 产物根目录之外）和 `walkthrough.html` 的写入视为中性修改，保留原 Run 并由 Agent 读取差异评估影响。
- **`revert`**：切回严格拦截模式，非 Build 阶段的普通文档写入也会被 Hook Guard 拒绝。

## 变更说明页面（`change_walkthrough`）

`change_walkthrough` 对 Native 和 Classic 共用，默认 `true`。在 Native 模式下，**仅当你明确要求生成可视化变更说明时**才会生成 `walkthrough.html`（对比前后行为、展开关键代码并附可选流程图，Verify 同步测试结果，Archive 保存归档链接）；日常任务仍以简洁文字摘要收尾。如果希望彻底禁用以节省说明 Token，可在配置文件顶层设为 `change_walkthrough: false`（或在 Dashboard 设置中关闭）。

## 个人记忆（`memory`）

`memory` 对 Native 与 Classic 共用，默认全部开启：

| 字段 | 说明 |
| --- | --- |
| `memory.learning` | 允许在任务完成时自动记录可复用的个人开发偏好与协作经验。 |
| `memory.retrieval` | 允许在相关任务中自动检索并注入已有个人记忆。 |

如果只想读取已有记忆、不想自动新增，可设 `learning: false`、`retrieval: true`。

## 项目知识（`knowledge`）

`knowledge.provider` 默认为 `local`。除内置代码与文档语料外，可通过 `include` 追加项目内的 Markdown Glob（正斜杠、不越出项目根目录），并按需调整单文件与总语料大小上限：

```yaml
knowledge:
  provider: local
  local:
    include:
      - docs/architecture/**/*.md
      - packages/*/README.md
    max_file_mb: 1
    max_total_mb: 32
```

如果团队已有远程 RAG 知识库服务，可切换为 `remote`（必须使用 HTTPS，仅 `localhost`/回环地址允许 HTTP；Token 通过 `token_env` 指定环境变量名，不要明文写进配置文件；超时范围 `100`–`30000` 毫秒）：

```yaml
knowledge:
  provider: remote
  remote:
    endpoint: https://knowledge.example.com
    token_env: COMET_KNOWLEDGE_TOKEN
    scope: engineering
    timeout_ms: 5000
```

## Hook 写入白名单（`hook.allow_paths`）

Native 与 Classic 共用，默认为空数组。如果你的项目有自定义 Hook 或脚本需要在受保护阶段向某个专用目录写文件，可在此放行（仅支持项目相对目录，采用正斜杠 `/`）：

```yaml
hook:
  allow_paths:
    - .my-hook-output
    - docs/team-notes
```

<Warning>
  不要把业务源码目录加入 `allow_paths`，否则会绕过 Shape、Verify 和 Archive 的写入保护。`.comet/`、Native 正式产物目录及 Classic 产物目录始终受工作流保护，无法通过 `allow_paths` 豁免。
</Warning>

## 定制 Pull Request 创建脚本（`native.finish.pull_request`）

默认情况下，选择“推送并创建 PR”时会调用 `gh pr create --fill`。如果团队仓库对 PR 模板、标题或字段有专门校验，可以通过 `native.finish.pull_request` 接入仓库自带脚本，而底层的提交、推送、已有 PR 查重、分支核验和恢复仍由 Comet 处理：

```yaml
native:
  finish:
    pull_request:
      provider: repository-command
      command: [pwsh, -NoProfile, -File, scripts/comet-create-pr.ps1]
      timeout_ms: 120000
```

配置约束：

- `provider` 当前仅支持 `repository-command`。
- `command` 为非空参数数组；首项必须是 PATH 中的可执行程序或项目相对路径，不能用绝对路径。
- `timeout_ms` 默认 `120000` 毫秒（2 分钟），上限 `600000` 毫秒（10 分钟）。
- 脚本在项目根目录启动，通过 stdin 接收 `comet.native.pull-request-finish-input.v1` JSON，并通过 stdout 返回 `comet.native.pull-request-finish-result.v1` JSON。
- 本地仍需安装并登录 GitHub CLI（`gh`），供 Comet 独立核验远端分支与 PR 状态。
