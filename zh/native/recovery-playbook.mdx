遇到中断或错误，先读取 Runtime 返回的状态，再执行它给出的动作。Native 的恢复依据是 `.comet/config.yaml`、brief、Specs、`comet-state.yaml` 和必要的本机 Runtime；不是聊天记录，也不是 Agent 自述。

## 标准诊断顺序

```bash
comet status
comet native status <change-name> --details --json
comet native doctor <change-name>
```

按以下顺序判断：

1. artifact root、启用的 workflow 和澄清模式是否正确；
2. `status` 是否找到目标 change；
3. 当前 branch/worktree 是否与 change 绑定一致；
4. `status --details` 返回的 `status`、`phase`、Loop、acceptance、blockers 和 continuation；
5. doctor 是否报告迁移残留、未完成事务、锁或 active/archive 冲突。

不要手工编辑 YAML、selection 或 `.comet/runtime/native/`。当输出有分页时，按 continuation 或 cursor 继续读取，不要把未读的验收项当成不存在。

## 跨设备找不到 change

同步项目代码、`.comet/config.yaml`、brief、Specs 和 `comet-state.yaml`。如果 `verification.md` 已存在也同步它；缺失报告可以重建。目标设备运行：

```bash
comet status
comet native status <change-name> --details --json
```

如果 artifact root、branch/worktree 不匹配，先修复项目上下文或明确选择目标，不要新建第二个 change，也不要把同一份文档复制到两个 root。

## 执行中断和本机 Runtime 缺失

`.comet/runtime/native/changes/<name>/state.json`、日志和锁属于本机 overlay。进程被终止、设备切换或 overlay 缺失时：

1. 运行 `comet native status <name> --details --json`；
2. 让 Runtime 按 YAML 标记 running 为 interrupted，并重建匹配的 overlay；
3. 若处于 Shape/Build，继续当前阶段；
4. 若处于 Verify，按 continuation 重新执行必要的中断检查，再分派新的 Verifier；
5. 若处于 `archive-ready`，先重新确认 Verify，再运行 Archive；正常 Archive 不会另外重跑已完成检查。

## 迁移和 doctor

升级中的旧 active change 可能有 change-local Runtime、旧状态或旧报告。首次 `comet update` 后，必要时运行：

```bash
comet native doctor <change-name> --repair
```

迁移只继承能够从旧 brief、Spec 和状态证明的事实；旧的通过结论不会直接变成新 v4 pass。无法确定的旧进度会保守回到 Build 或等待用户。普通新 change 不应运行 legacy-only 修复策略。

## Archive 中断和并行冲突

Archive 可能经历写入 Spec、更新最终 YAML、生成报告、移动目录和清理本机 Runtime。中断后再次运行同一个 Archive 命令会按事务继续；不要删除事务目录或手工把状态改成 done。若 active 和 archive 同时存在、事务丢失但目录已经部分移动，doctor 会停下要求人工处理。

两个 change 要修改同一 capability 时，Archive 会返回需要串行顺序的 blocker。先选择哪个 change 归档，再按新的 continuation 继续；不会自动覆盖另一个 change 的 Spec。

## 常见状态与处理

| 现象                             | 正确处理                                                                        |
| -------------------------------- | ------------------------------------------------------------------------------- |
| `await-user`                     | 阅读 blocker 和 `resolution_action`，向用户展示选项；确认后按 continuation 继续 |
| `blocked`                        | 先处理损坏、执行错误、冲突或停滞原因；不要直接增加计数或伪造结果                |
| branch/worktree mismatch         | 回到正确 checkout，或由用户明确选择新的工作区；不要在错误目录写入               |
| Verify 失败                      | 按失败 acceptance 和检查修复，提交新的 Builder handoff，再让新的 Verifier 验收  |
| 报告缺失/过期                    | 让 Runtime 从 YAML 重建；不要手工复制一份“通过”报告                             |
| 旧 Runtime/receipt/evidence 残留 | 运行 update/doctor 迁移或只读检查；不要把它们加入新 change                      |
