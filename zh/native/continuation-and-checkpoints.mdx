会话中断后，让 Agent 继续原 change。Runtime 在 Run 中保存当前阶段、用户决定和任务结果。恢复时先核对当前工作区和待处理的动作，再按最新命令响应继续。

## 查看当前进度和下一步

回到该 change 的工作区，运行 `comet native status <change-name> --json`。如果不知道名称，先用 `comet native status --json` 查看当前工作区的任务。若 change 使用独立 Git worktree，进入那个 worktree 再查看。需要完整的动作和决策记录时，在具名查询中加上 `--details`。

`status` 用于查看。Agent 按响应中的下一步推进流程，执行后以新响应为准。若提示状态已变，重新查询后再提交决定。如果响应给出了状态版本、预期动作或提案标识，提交确认时保留这些参数。

| `continuation.mode` | 当前情况 | 如何继续 |
| --- | --- | --- |
| `execute` | 有明确的下一步。 | Agent 在响应指定的工作区执行返回的操作。 |
| `ask` | 流程在等待你的决定。 | 查看当前提案，确认、要求修改或补充缺少的信息。 |
| `wait` | 原任务已经领取，尚未返回结果。 | 查看或等待原任务，使用原领取信息提交结果。 |
| `reconcile` | 需要核对执行结果或排除阻塞。 | 按提示核对原任务、路径或事务，再执行返回的恢复操作。 |
| `done` | 流程已结束。 | 查看最终状态。若已归档，再核对约定的 Git 交付是否完成。 |

## 恢复正在执行的任务

新会话先核对原任务是否已经领取，以及原执行会话是否还在运行。等待工具超时后，Agent 应到原平台查看任务进度。如果任务仍在运行，继续等待这次执行。若任务已结束，先取回真实结果，并用原任务的领取信息提交。

如果结果不明，先核对原执行和已经产生的文件或外部结果，避免重复运行可能已经生效的操作。只有确认原任务失败、丢失、超时终止或结束后没有可用结果时，才按 Runtime 返回的下一步处理失败或重试。详见 [SDK 失败恢复与未知结果](/zh/sdk/recovery)。

## 恢复缺失的本机 Run

如果本机记录缺失，先执行 `comet native doctor <change-name> --json` 查看诊断。Runtime 可以从 `comet-state.yaml` 中有效的检查点和配套材料恢复原 Run。按 Doctor 返回的命令恢复。缺少有效检查点或材料不一致时，先保留工作区，核对可用的原始记录。

换设备前，停止在原设备上推进任务，同步当前代码、`comet-state.yaml`、`brief.md`、相关 Specs、引用的产物和项目配置。检查点保存已记录的进度，未同步的代码需要从原工作区找回。仍有执行结果不明时，先核对原任务。若是正在执行的 Supervisor 子任务，还需要单独处理子任务和集成 worktree。文件和恢复边界见 [Native Runtime 的组成](/zh/native/runtime)与 [Supervisor Change](/zh/native/supervisor-change)。

## 恢复中断的归档

如果 Archive 命令仍在后台运行，等待原命令返回，避免再次启动归档。如果命令已中断，查看当前状态和诊断，再按 Runtime 返回的恢复指引继续原归档事务。归档完成后，单独核对 Git 提交、推送或 Pull Request 是否已经执行。见 [归档与交付](/zh/native/archive-and-delivery)。
