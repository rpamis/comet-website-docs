AI 编程工具在复杂仓库里最容易出两类事故：一是在需求还没确认、或者正在验收时直接修改了业务代码；二是在多分支、多任务并存时把文件写进了错误的目录，或者把状态文件改坏。

Native 通过清晰的分工控制这些风险：**Agent 负责理解需求、运行平台检查和评估改动影响；Runtime 和 Hook Guard 在后台把守任务归属、阶段写入边界、正式状态保护和归档事务。** 这些保护全程自动生效，你不需要手动运行命令去开关或维护状态。

## 任务归属与临时退出工作流

同一个项目可以同时启用 Native 和 Classic，但每个具体 change 只属于其中一套工作流。当前工作区的选中记录保存在 `.comet/current-change.json` 中，Hook Router 读取归属后，只调用对应工作流的 Guard。

- **自动归属**：当前工作区只有一个活跃 change 且未显式指定时，自动关联到该任务。
- **存在多个活跃任务或归属不清**：主动暂停并列出候选项让你选择，不会猜一个默认值直接写入。
- **切换当前任务**：在对话里直接说“切换到 `<change-name>`”，Agent 会在后台更新工作区归属。
- **临时做与 Comet 无关的普通修改**：在对话里说“先临时改个无关文件，不走当前 Comet 任务”，Agent 会在后台取消当前工作区的任务选中（对应 `comet native select --none`）：
  - 该设置对同一工作区内的所有会话生效，放行普通项目代码修改，并暂停被动恢复探测；
  - 工作流正式目录和状态文件依然受保护，不会因为取消选中而被误改；
  - 需要回到原任务时，在对话里说继续原任务即可恢复归属。

## Hook Guard 的七类写入拦截保护

在支持 Hook 的 Agent 平台上，Agent 的每次文件写入工具调用都会先经过 Hook Guard 检查；一旦拦截，Guard 会返回明确原因和可直接执行的修正动作，让 Agent 自动纠偏。除了最基本的阶段控制外，Guard 在底层还会拦截七类常见误操作：

### 1. 按阶段控制代码写入边界

| 阶段 | 允许写入范围 | 拦截行为 |
| --- | --- | --- |
| **Shape** | 当前 change 的 `brief.md`、草拟 Specs 和 `children.yaml`。 | 需求确认前禁止修改业务源码（若你明确要做无关修改，提示先退出当前任务选中）。 |
| **Build** | 当前 change 绑定工作区内的业务代码与测试。 | 禁止写进未准备 Build worktree 的共享规划目录，也禁止 Supervisor 父任务在 Build 阶段直接改代码。 |
| **Verify** | 只读核验（`native.document_writes: allow` 下保留人工微调由 Agent 评估影响）。 | 禁止验收过程中越过流程私自修改实现，发现问题应按 `continuation` 退回 Build。 |
| **Archive** | 由 Runtime 按事务完成 Spec 合并与目录归档。 | 禁止从 Archive 执行 Verify 专属修订或手工改动归档控制文件。 |

### 2. 六类常见路径与归属误操作防护

1. **禁止手改 Runtime 控制文件**：直接编辑 `.comet/current-change.json`、工作区运行态目录，或 change 内的 `comet-state.yaml`、`verification.md`、`capability-association.yaml` 会被立即拒绝。
2. **拦截未登记的正式文件与错误根目录**：还没通过正常流程登记就手工创建 `changes/<name>/brief.md`，或者把文件写进错误的 `.comet/comet/changes/` 目录而偏离项目配置的 `native.artifact_root`（默认 `docs/comet/changes/`）时，Guard 会直接拦截并给出正确的登记动作或目标路径。
3. **保护已发布的项目正式 Specs**：直接修改项目已发布的 `specs/<capability>/spec.md` 会被拦截，并引导把改动合并到当前 change 目录下的草拟 Spec，待 Archive 时统一合入。
4. **禁止单次操作混改正式需求与代码**：一次写入调用如果同时修改 `brief.md`/`specs/` 和业务源码或普通文档，会被拒绝，要求将正式需求修改与代码实现分步进行。
5. **拦截跨 change 误写**：试图修改属于另一个活跃 change（或未登记 change）的正式文件时，Guard 会提示先切换目标任务，或为新需求创建独立 worktree。
6. **共享规划与交接后防错写**：多个活跃 change 共享同一规划分支时，在准备独立 Build worktree 之前禁止直接写代码；change 交接到新 worktree（`executionCwd`）后，继续在旧规划目录写该 change 的文件会被拦截并指出新路径。

## 文档写入策略与 Hook 边界

Hook Guard 会根据 `.comet/config.yaml` 中的以下两项配置控制非 Build 阶段的放行范围（完整字段与 YAML 示例见 [Native 配置](/zh/native/configuration)）：

- **非 Build 阶段文档写入（`native.document_writes`）**：默认 `allow` 会放行 `walkthrough.html`、`.comet/config.yaml` 以及产物目录外的普通文档编辑，保留原 Run 并交由 Agent 读取差异评估影响，不机械清空批准或验收记录；设为 `revert` 时，非 Build 阶段的普通文档写入也会被 Guard 拒绝。
- **自定义 Hook 白名单（`hook.allow_paths`）**：为项目自定义脚本放行指定的项目相对目录及其子路径（项目目录外目标默认放行）。`.comet/`、Native 正式产物目录与 Classic 产物目录无法通过白名单绕过；单次写入同时命中白名单目录和受保护目录时，未放行目标仍会被拦截。

### Hook 的安全边界

Hook Guard 只拦截 Agent 平台公开暴露的文件写入工具调用，**不是操作系统级别的硬沙箱**。通过外部编辑器直接保存、第三方后台进程或平台未暴露通道修改的文件不会触发 Hook。另外，部分 Agent 平台需要你在设置中显式开启或信任 Hook，单纯安装插件不代表 Hook 已生效。因此，Verify 阶段的改动核对以及 Archive 阶段的候选与工作区校验仍然是最终底线。

## 无 PID 锁机制与并发隔离

- **平台工具直跑命令**：开发构建、测试和静态检查直接由 Agent 平台工具执行，Runtime 不托管这些进程，也不维护命令 PID 或停止回执。
- **单写者与 worktree 隔离**：同一个工作区同一时刻只允许单一写入者更新状态；并行任务通过独立的 Git worktree 物理隔离。
- **进程退出即释放锁**：本机事务锁随进程退出自动释放，不再依赖历史 PID 判定进程是否存活，也不需要手工清理残留的锁文件。

## 只读环境感知恢复探针（`comet resume-probe`）

在新会话里用自然语言说“继续刚才的改动”“把验证跑完”时，后台的只读恢复探针 `comet resume-probe` 会检查当前工作区是否有可恢复的活跃任务，**不会修改选中 change，也不会私自切换 Git 分支**。

探针具备句级否定与排除识别能力，减少误触发：

- **识别否定子句**：它会按标点和“但是 / but”切分句子，如果某个 change 名称或恢复动词出现在“不要 / 别 / 暂不 / don't”等否定子句中（例如“别恢复 auth-fix，先回答个问题”），不会被误判为恢复意图。
- **区分拒绝新建与恢复旧任务**：说“不用开新流程，继续刚才那个”仍能正确识别为恢复已有任务。
- **显式退出探测**：说“不走 comet”“直接解释”“只回答”或“without comet”时直接跳过工作流路由。
- **配置开关**：在 `.comet/config.yaml` 中设置 `ambient_resume: false`（或让 Agent 取消当前任务选中）可停用被动探测。

## 事务保护与离线诊断入口

Archive 归档和产物根目录迁移均由事务记录保护，中途断电或崩溃后可按事务状态继续，已完成的步骤不会重复执行。日常排查直接问 Agent 即可；如果你想自己查看现场，可以在终端运行下面的只读诊断命令（不修改任何状态）：

```bash
comet status
comet native status <change-name> --details --json
comet native doctor <change-name> --json
```

切换或取消任务选中由 Agent 在后台调用 `comet native select` 完成，下面的命令供你在终端排障时查阅：

<Accordion title="底层命令参考：手动切换或取消任务归属（日常由 Agent 自动调用）">

```bash
# 切换当前工作区的选中任务
comet native select <change-name>

# 取消任务选中，允许当前工作区做与 Comet 无关的普通编辑
comet native select --none
```

</Accordion>

各故障场景的详细排障指南，见 [Native 任务恢复](/zh/native/recovery-playbook)。
