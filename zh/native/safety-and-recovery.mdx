Native 通过阶段守卫、任务身份和可恢复事务约束流程。Agent 负责理解需求、执行检查和判断编辑影响；Runtime 负责记录用户决定、推进原任务并完成归档交付。

## 写入归属于哪个 change

`.comet/current-change.json` 指定当前 workflow 和 change。项目可以启用多套工作流，但同一需求只能归属于一个流程。Hook Router 确认当前归属后，只调用对应的 Guard。

选择缺失且只有一个有效任务时，可以推断当前归属。存在多个候选、选择损坏或工作区绑定不匹配时，先按提示明确目标，不根据默认工作流猜测。需要手工选择时使用 `comet native select <change-name>`。

## 阶段感知的变更控制

- **Shape**：整理目标、方案与验收，等待你确认后才能实现。
- **Build**：在当前任务的工作区完成实现。Supervisor 的子任务只在各自 worktree 中写入，主会话负责协调与串行提交结果。
- **Verify**：验收者对照原始请求和全部验收项核查，不在验收中直接实现修复；发现问题先返回 Build。
- **Archive**：按已接受的结果与实际交付决定归档，不能借归档扩大修改或执行范围。

普通编辑按 `native.document_writes` 处理。默认保留编辑，由 Agent 判断影响：措辞调整不自动撤销批准；需求或验收变化重新确认；实现变化修订候选；检查变化只补缺失或受影响的证据。使用 `revert` 策略时，按 Guard 的拒绝与恢复指引处理。详见[编辑后继续当前任务](/zh/guides/mid-workflow-changes#编辑后继续当前任务)。

## 可观察写入的前置保护

Hook 只能处理平台提供的事件和目标路径，不是操作系统级沙箱。IDE、后台进程或平台未暴露给 Hook 的写入，可能无法即时拦截。后续 Agent 审查与 Runtime 的任务、工作区和交付检查仍需完成。

平台需要启用或信任 Hook 时，应先完成平台要求；安装了插件不代表 Hook 已获得信任。

## Agent 执行检查

普通开发命令和测试通过 Agent 平台工具运行，记录实际命令、目录、结果和限制。Runtime 不再托管这些进程，不绑定 PID，不等待停止回执，也不计算项目文件指纹来决定是否复用检查。

Agent 判断旧检查是否适用于当前候选和执行环境，保留仍有效的结果，只补必要验证。测试通过不等于验收完成；Verify 仍须覆盖原始请求和全部验收项。明确要求独立审查时仍须满足要求。详见[验证与修复](/zh/native/verification-and-repair)。

## 工作区写入与未完成事务

每个 workspace 同一时间由一个执行者维护状态，子任务通过独立 worktree 隔离。普通工作流不再创建协调锁或要求恢复旧锁记录。

目录迁移和 Archive 仍会检查真实的未完成事务。存在待恢复的步骤、来源不明的目录或工作区冲突时，先处理原事务。不要删除状态或事务记录来绕过阻塞。

## 路径与文件身份校验

正式文档和状态必须位于 Runtime 返回的路径中。目录迁移、符号链接、归档目标和工作区归属仍由相应入口检查。文档增长不再受内置字节上限阻塞，读取失败则报告实际错误，不用旧内容冒充完整材料。

文件路径、实际写入与业务事务检查不代表 Runtime 会为普通编辑保存内容快照。不要手工重建本机状态、修改执行身份或复制其他任务的记录。

## 可恢复的事务式归档

Archive 保留原 Run、已接受结果、批准范围和实际交付进度。中断后先核对原事务，再按返回的恢复动作继续；已完成的步骤不应重复执行，结果未知的外部操作先核对现场。

active 与 archive 同时存在、事务损坏、目录被占用或多个任务冲突时，保留现场并处理具体阻塞。主 Spec 更新与 Git 交付仍受检查，不能通过重新创建任务覆盖未完成事务。详见[归档与交付](/zh/native/archive-and-delivery)。

## 基于原任务的断点恢复

恢复时继续推进同一 change 和 Run。正式文档与有效检查点用于跨设备恢复，本机执行数据按 checkout 与 worktree 隔离；目录路径以 Runtime 返回的实际地址为准，不再依赖旧版 `.comet/runtime/native/` 目录布局。

若原 Agent 任务仍在运行，应继续等待原任务完成。工具等待超时不代表任务执行失败，切勿重复派发。遇到明确失败、任务丢失或结果不可用时，先记录失败原因，再按标准流程恢复。详见[任务推进与中断恢复](/zh/native/continuation-and-checkpoints)。

## 零写入的自动恢复探测

`comet resume-probe` 以只读方式识别当前选择与可恢复任务，不会修改 change，也不会自动切换分支。若存在多个候选或归属不明确，会提示用户进行选择；若未发现匹配任务，则不进入工作流，保持普通对话。配置 `ambient_resume: false` 可关闭普通自然语言请求的自动恢复探测。

## 统一诊断与恢复入口

日常推进使用 Runtime 返回的最新任务和命令。需要排查时读取：

```bash
comet status
comet native status <change-name> --details --json
comet native doctor <change-name>
```

若工作区不匹配，先切换回指定目录；若历史命令被拒绝，重新读取最新动作；若迁移或归档流程中断，沿用诊断明确给出的恢复路径。若诊断未提供可用修复指令，应保留现场，切勿手工拼接状态。

继续阅读[恢复手册](/zh/native/recovery-playbook)。
