title: '归档与交付'

---

你接受验收结果后，Native 会执行 Archive：将已确认的 Spec 变更合入项目正式 Specs，并把 change 目录移入归档历史目录。代码和归档文档如何进入 Git（保留在本地、提交、合并、推送或提 PR），由你在对话中明确指定的交付范围决定。日常归档由 Agent 在后台自动完成，不需要手动输入命令；收尾时请分别核对“归档完成”和“Git 交付完成”。

## 接受当前验收结果

Verify 全部通过后，查看 `verification.md`（或 Agent 转述的摘要）中的逐项验收结论、检查证据和已知限制。你确认的是这一版实现及其验收结论：

- 发现需要继续修的问题时，直接在对话里告诉 Agent 修复实现，回到 Build；
- 需要调整需求或验收标准时，说明新要求回到 Shape 重新确认；
- 如果你已经明确告诉 Agent“全部通过后直接接受并归档”（或在项目配置中开启了 `native.archive_confirmation: automatic` 且满足安全条件），Runtime 会在通过后自动接受并推进归档。

接受结果时可以一并说明交付方式，例如：“接受当前结果，归档后在当前分支提交，先不推送”。

## 后台检查条件并执行 Archive

接受结果后，Agent 会在后台自动推进归档流程（依次完成归档预检、应用 Specs 和目录搬迁）：

- **预检未通过（`ready: false`）**：Runtime 会列出具体阻塞原因（例如结果尚未接受、工作区与绑定不一致、或项目正式 Spec 出现冲突），且不会修改任何 Specs 或目录。先按提示解决阻塞再继续。
- **预检通过**：Runtime 将本次确认的 Spec 变更合入项目正式 Specs（例如 `docs/comet/specs/authentication/spec.md`），将 change 目录连同 `brief.md`、`comet-state.yaml` 和 `verification.md` 移入 `docs/comet/archive/` 下的归档目录。使用自定义产物目录时以项目配置为准。

如果另一个并行 change 刚刚更新了同一份能力 Spec，Archive 会暂停并提示冲突；按提示先同步最新项目 Spec、补跑受影响检查后再归档。详见 [多 Change 并行与冲突控制](/zh/native/multi-change-and-conflicts)。

## 核对归档结果

Archive 完成后，Run 状态变为 `completed`、业务状态变为 `done`。你可以一并确认以下三项：

- 归档目录可读，且保留了 `brief.md`、`comet-state.yaml` 和 `verification.md`；
- 项目正式 Specs 已包含本次批准的新增或修改内容；
- 如果归档中途发生中断，在对话中让 Agent 查诊断并恢复原事务——已完成的写入不会重复执行。详见 [Native 任务恢复](/zh/native/recovery-playbook)。

## 完成并核对 Git 交付

执行 Git 操作前，Agent 会先核对当前分支、目标分支和本次 change 涉及的文件。暂存范围只包含本次实现代码、更新后的项目 Specs 和正式归档材料，提交前查看暂存差异（staged diff）并遵守项目的提交规范与 Git Hook；工作区里与本次任务无关的改动会原样保留。

| 你确认的交付范围 | 需要核对的结果 |
| --- | --- |
| 仅归档，保留工作区。 | 确认归档路径以及工作区仍保留的改动。 |
| 提交到当前分支。 | 确认提交 SHA、所在分支和提交内容。 |
| 本地合并到目标分支。 | 确认目标分支包含已交付的改动（若采用 squash 等方式，核对实际合并提交）。 |
| 推送到远端。 | 确认远端名称、目标分支和远端提交与预期一致。 |
| 创建 Pull Request。 | 确认 PR 链接、来源分支、目标分支和包含的提交。 |

如果推送或创建 PR 中途中断，先查远端分支和 PR 实际状态，确认哪些动作已经生效后再补做剩余步骤，不要盲目重复提交。

日常归档由 Agent 在后台完成，不需要你手动运行命令。想自己确认归档前的就绪状态时，可以在终端运行下面的只读预览命令，它不会修改任何文件。

<Accordion title="终端只读预览命令（日常由 Agent 自动执行，想在终端手动检查就绪状态时可用）">

```bash
# 仅做只读预检，查看 ready、blockers 与待应用的 Spec 预览，不写入任何文件
comet native archive <change-name> --dry-run --json
```

</Accordion>
