关于 Native 的适用场景、四阶段工作流、portable 状态、验证、恢复和冲突处理的常见问题。

## 基础概念

<AccordionGroup>
  <Accordion title="Native 和 Classic 应该怎么选">
    主力模型是 Fable 5、GPT-5.6 及同档强模型时优先 Native：这类模型能自主规划和实现，强加方法论约束反而浪费它的能力，Native 把方法选择权交给它，只锁住结果与证据。模型能力档更低、需要更明确过程约束时用 Classic，它通过 OpenSpec 与 Superpowers 提供 open、design、build、verify、archive 五阶段治理。两套工作流由 `.comet/config.yaml` 选择。
  </Accordion>

<Accordion title="Native 是否依赖 OpenSpec、Superpowers 或其他外部 Skill">
  不依赖。Native 自带 Shape、Build、Verify、Archive 和 Runtime。只有 Classic 才安装并使用
  OpenSpec、Superpowers 等 Classic 参考。
</Accordion>

<Accordion title="为什么 Builder 说完成还不能归档">
  Builder 只提交实现 handoff。Runtime 先运行必要检查，再分派新的只读 Verifier 覆盖全部 A1…An。Skill
  协调但没有独立 Verifier execution 时，归档前还需要一次明确用户确认，并会在报告中标明降级。
</Accordion>

<Accordion title="Verify 为什么会回到 Build">
  验收失败、检查失败、Verifier 漏项或结果无效都会写入下一步 continuation，并把 change 返回
  Build。下一轮修复明确缺口后，由新的 Builder 和新的 Verifier 重新开始。
</Accordion>

<Accordion title="没有 verification.md 可以恢复吗">
  可以。Shape 和 Build 只需要同步的 brief、Specs 和 `comet-state.yaml`；`verification.md`
  是可重建报告。Verify 或 archive-ready
  在另一台设备上会重建本机执行状态并重新确认，不会直接复用旧的本机结果。
</Accordion>

<Accordion title="Native 的 portable 状态和本机 Runtime 有什么区别">
  `comet-state.yaml` 保存阶段、Loop、验收、handoff、检查摘要、Verifier
  结论、阻塞和下一步，是跨设备稳定边界。`.comet/runtime/native/` 只保存本机
  `state.json`、日志、锁和事务，缺失或版本不匹配时可以重建。
</Accordion>

<Accordion title="为什么新项目默认 Batch">
  Batch 会先整理问题依赖，再一次询问当前前提已具备的问题，减少重复往返。Sequential
  仍可配置，按轮次询问一个最上游问题；两者都要在 Build 前确认共享理解。
</Accordion>

<Accordion title="需要额外检查怎么办">
  当前 Verifier 通过 `request-checks` 请求 Runtime 执行。Runtime
  会去重等价计划、限制请求轮数并返回结果；不要自行创建“检查回执”或在状态文件里填通过。
</Accordion>

  <Accordion title="多个 Native change 可以并行吗">
    可以。创建 change 时会在适用时展示 `current`、`branch`、`worktree` 选择；`.comet/current-change.json` 只选择下一次写入归属，不限制 active change 数量。两个 change 要修改同一 capability 时，Archive 会要求明确顺序。
  </Accordion>
</AccordionGroup>

## 恢复和排障

先运行：

```bash
comet status
comet native status <change-name> --details --json
comet native doctor <change-name>
```

不要手工修改 `comet-state.yaml`、`.comet/current-change.json` 或 `.comet/runtime/native/`。如果代码、artifact root、branch/worktree 未同步，或 active/archive 目录混合，Runtime 会返回具体的 `await-user`/`blocked` 动作。

旧版本留下的 change-local Runtime、旧 receipt/evidence 或 `native.snapshot` 配置只用于迁移和只读兼容。新 beta17 change 不会创建它们；升级时运行 `comet update`，必要时运行 `comet native doctor <change-name> --repair`。
