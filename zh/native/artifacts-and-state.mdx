Native 把需求、目标 Specs、状态文件和验收报告保存在项目中。当前阶段、用户批准和执行结果由本机的 Run 保存。查看一个 change 时，可以从 `brief.md` 了解约定，从 `verification.md` 查看验收证据，从 CLI 确认当前还能做什么。

## 找到 change 的实际目录

以下以 `login-error-message` 为例。默认产物根目录是 `docs`，可以通过 `.comet/config.yaml` 中的 `native.artifact_root` 配置。目录随项目而异，以 `show` 返回的路径为准。

```text
docs/comet/
  changes/login-error-message/
    brief.md
    specs/authentication/spec.md
    specs/authentication/delta.yaml
    comet-state.yaml
    verification.md
  specs/authentication/spec.md
  archive/
```

这里的 `delta.yaml` 用于已关联现有 capability 的变更。验收通过前，`verification.md` 可能尚未生成。Supervisor Change 还可能有 `children.yaml`。

```bash
comet native show login-error-message --json
```

在返回的 `artifacts` 中查看 change 目录、brief、Specs、状态文件和报告的位置。路径与预期不符时，先核对当前工作区和项目配置。已归档的材料请查看 Archive 返回的目录。

## 在 Shape 中维护需求与目标 Specs

<span id="briefmd" />

### `brief.md`

`brief.md` 记录目标、范围、明确排除的内容、约束、影响交付的用户决定和验收依据。描述工程范围时，列出要新增、修改、删除的模块与关键文件，以及明确不建的部分。目录树或列表均可。

例如，`login-error-message` 的 brief 可以约定只修改登录失败提示，保留服务端返回码和原有的限流规则。把密码错误和请求限流写成可分别检查的验收项。涉及用户决策的未决问题用 `[blocking]` 标记，解决后更新材料，再请用户确认完整 Shape。

### 目标 Spec 与 Delta

change 目录里的 `specs/<capability>/spec.md` 描述归档后这项能力应有的完整行为。本次修改的内容要写清，同时保留该能力仍然有效的既有规则。

- 新能力由 Agent 编写完整目标 Spec。
- 已关联现有能力时，Agent 在 `delta.yaml` 中维护本次变更，引用稳定的需求标识。Runtime 基于当前项目 Spec 生成完整目标 Spec，供 Shape 评审和 Verify 验收。
- 要移除已有能力，按 [Native 命令概览](/zh/scripts/comet-native) 提交能力移除。直接删除文件无法记录这个决定。

以登录提示为例，项目的 `specs/authentication/spec.md` 是已经生效的规范。change 里的目标 Spec 用来评审新增的提示规则，归档时 Runtime 才会把已确认的变更应用到项目 Specs。

### `children.yaml`

Supervisor Change 用它记录子任务、依赖关系和每个子任务覆盖的验收项。子任务用验收项的编号引用原文，父 change 仍保留全部验收要求。并行执行见 [Supervisor Change](/zh/native/supervisor-change)。

## 查看由 Comet 维护的状态与报告

| 文件或记录 | 存放位置 | 用途 |
| --- | --- | --- |
| `comet-state.yaml` | change 目录。 | 展示阶段和验收状态。在关键节点保存恢复检查点，供恢复原 Run。 |
| `verification.md` | change 目录，归档后随 change 保存。 | 查看逐项结论、实际检查、审查方式和已知限制。 |
| `.comet/current-change.json` | 当前项目的 `.comet/`。 | 记录当前工作区选中的 change，用于无名称调用与 Hook 路由。通过 `comet native select` 修改。 |
| 本机 Run 和执行记录 | 默认位于 `~/.comet/workspaces/<workspace-id>/runtime/`。 | 保存执行进度、动作和用户决定，以及事务处理所需的本机记录。主工作区与各 Git worktree 分开保存。 |

通过 `comet native status` 查看当前进度，通过返回的操作提交决定与结果。直接修改状态文件或报告无法推进 Run。需要处理缺失或损坏的记录时，见 [任务推进与中断恢复](/zh/native/continuation-and-checkpoints)。

## 判断哪些内容需要随项目同步

评审和交付时，把本次实现和对应的正式材料一起审查。归档后的 change 与更新后的项目 Specs 一起交付。按项目规则把状态文件和验收报告随该 change 保存，方便其他人核对决定与证据。

换设备继续同一个任务时，同步实际代码、正式材料、含有效检查点的 `comet-state.yaml`、相关产物与项目配置。检查点保存的是记录下来的进度。未提交且未同步的代码、独立子任务 worktree 和原平台的后台任务需要分别核对。

当前 change 的选择和本机 Runtime 目录由各工作区维护。无需把本机 Run 目录提交到 Git。还在执行的任务应保留本机记录，以便核对原结果和未完成的事务。
