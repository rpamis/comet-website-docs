---
title: 'Native 命令概览'
description: 'Native 工作流的公开命令：创建、查看、选择、推进、恢复和归档。'
---

`comet native` 是 Native Runtime 的命令入口。大多数用户只需在 Agent 中输入 `/comet` 或 `/comet-native`，Skill 会根据 Runtime 返回的 continuation 调用命令。

## 命令一览

| 命令                          | 做什么                                                     |
| ----------------------------- | ---------------------------------------------------------- |
| `comet native init`           | 初始化或整理 Native 项目配置                               |
| `comet native root show/move` | 查看或事务化移动产物根目录                                 |
| `comet native new`            | 创建 change 并准备 `current`、`branch` 或 `worktree`       |
| `comet native show`           | 查看 brief、Specs 和 portable 状态                         |
| `comet native status`         | 查看 change、Loop、验收、检查和下一步                      |
| `comet native select`         | 多个 change 并存时选择写入归属                             |
| `comet native spec remove`    | 记录 capability 删除意图                                   |
| `comet native next`           | 按 continuation 确认或恢复边界、提交 handoff/Verifier 输入 |
| `comet native archive`        | 预览或执行归档和工作区收口                                 |
| `comet native doctor`         | 诊断、迁移和重建本机 Runtime                               |

新的 Native 流程不再公开 `checkpoint`、`check`、`evidence` 或 `receipt` 命令；检查由 Runtime 在 Verify 中执行，结果进入 portable 状态和用户报告。

## 创建和查看

```bash
comet native new add-user-avatar --isolation current
comet native status --json
comet native status add-user-avatar --details --json
comet native show add-user-avatar
```

`new` 创建 brief、Specs 和 `comet-state.yaml`，本机执行目录放在 `.comet/runtime/native/`。`status`/`show` 是只读的，不会偷偷改变 selection。

## 推进和 Verify

`next` 不接受 Agent 自填通过结果。它只确认 Shape、返回 Build、重试允许的 Verifier，或通过 `--runner-input` 提交 Runtime 定义的 handoff、检查计划和 Verifier 响应：

```bash
comet native next add-user-avatar --summary "Shape confirmed" --confirmed
comet native next add-user-avatar --summary "Implementation changed" --return-to-build
comet native next add-user-avatar --runner-input <temporary-json-file>
```

正常输入模板和字段以 `comet native status <name> --details --json` 返回的 `continuation.inputOptions.template` 为准。`request-checks` 只能由当前 Verifier 请求 Runtime 执行；Builder 自报通过不会直接进入 Archive。

## 归档

先查看 Runtime 返回的 archive-ready continuation，再按需预览或执行：

```bash
comet native archive add-user-avatar --dry-run
comet native archive add-user-avatar --confirmed
```

Archive 应用完整 target Specs、生成 `verification.md`、移动 change 并清理本机 Runtime；正常路径不重新执行 Verify。并行 capability 冲突时，根据 `continuation` 先选择串行顺序。

## 诊断、迁移和恢复

```bash
comet native doctor
comet native doctor add-user-avatar
comet native doctor add-user-avatar --repair
```

`doctor --repair` 只做可确定的迁移、事务收口和本机 overlay 重建，不替用户改需求、Spec 或代码。跨设备恢复缺少 `verification.md` 不会阻止 Shape/Build；错误 branch/worktree 或混合 active/archive 布局会等待用户。

用户可读产物是 brief、Specs、`comet-state.yaml` 和 `verification.md`；`.comet/runtime/native/` 只放本机 state、日志、锁和事务。
