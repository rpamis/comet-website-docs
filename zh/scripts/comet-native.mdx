`comet native` 是 Agent 推进 Native 任务时使用的命令：创建 change、查看状态、确认 Shape、提交实现与验收结果、取消、归档和诊断。你在对话里提需求、回答 Agent 的提问、确认决策，Agent 负责在两次回复之间调用这些命令。

<Note>
  本页命令由 Agent 在后台调用，你不需要手动运行。日常开发只需在对话中输入 <code>/comet</code> 提需求、回答 Agent 的提问，或说“继续”。本页供你在终端排查问题、编写脚本或接入其他 Agent 平台时查阅。
</Note>

从 0.5.5 起，新建的 Native change 使用 SDK。已有的 Compat change 仍可用 `comet native next <change-name>` 继续推进，并按原流程归档。Agent 以命令返回的 `runtimeFormat`、`workspace` 和 `continuation` 为准决定下一步；旧 Runner 输入和 `--finish` 交付参数只用于 Compat 任务。

## 批准 Shape 后等待实施

你可以在确认方案时告诉 Agent“确认方案，但先不开始写代码”。Agent 会在 Runtime 返回的 Shape 确认命令后追加 `--defer-build`，并保留 `--confirmed` 和全部预期状态参数。等你要求开工时，接收任务的会话再执行 `comet native next <change-name> --session <实际会话标识> --json`，进入返回的 `executionCwd` 所指的目录开始实现。完整规则见[多 Change 并行与冲突控制](/zh/native/multi-change-and-conflicts)。

## SDK 常用命令

Agent 在任务各阶段调用的主要命令：

```bash
comet native new <change-name> --json
comet native status <change-name> --details --json
comet native next <change-name> --json
comet native archive <change-name> --dry-run --json
comet native doctor <change-name> --json
```

你的确认、Builder 与独立 Verifier 的结果，必须用当前任务的原身份提交。不要照示例自己填写状态版本、候选或确认哈希。完整流程见 [任务推进与中断恢复](/zh/native/continuation-and-checkpoints)。

## 取消未完成任务

在对话里告诉 Agent“取消当前任务”并说明原因，Agent 会先预览、再执行取消：

```bash
comet native cancel <change-name> --dry-run --json
comet native cancel <change-name> --json
```

取消后，这个 change 不再计入活动任务，实现、提交、分支和工作区都会保留。受管理的检查会停止；结果还没核对过的执行，要先确认已经停止，之后才释放当前选择。已完成或旧的 Compat 任务会返回各自适用的处理方式，取消不能当作归档验收。

<Note>下面保留 Compat 命令、状态字段和旧版本机目录参考。SDK 的可用参数以当前 `comet native <command> --help` 与返回的下一步为准。</Note>

`comet native` 是 Native Runtime 的命令入口。大多数用户只需在 Agent 中输入 `/comet` 或 `/comet-native`，Skill 会根据 Runtime 返回的 continuation 调用命令。

## 命令一览

| 命令                          | 做什么                                                                                    |
| ----------------------------- | ----------------------------------------------------------------------------------------- |
| `comet native init`           | 初始化或整理 Native 项目配置                                                              |
| `comet native root show/move` | 查看或以事务方式移动产物根目录                                                            |
| `comet native show`           | 查看 brief、Specs 和可跨设备同步的状态（portable 状态）                                   |
| `comet native status`         | 查看 change、Loop、验收、检查和下一步（`--cursor` 分页、`--details` 看完整 continuation） |
| `comet native select`         | 多个 change 并存时选择写入目标                                                            |
| `comet native spec remove`    | 记录 capability 删除意图                                                                  |
| `comet native spec sync`      | 修正已确认 Spec 中的本地链接（语义修改返回 Shape）                                        |
| `comet native next`           | 按 continuation 确认或恢复边界、提交 handoff/Verifier 输入                                |
| `comet native archive`        | 预览或执行归档和工作区收尾                                                                |
| `comet native check`          | 对指定 change 运行只读的 Native 验证检查                                                  |
| `comet native doctor`         | 诊断、迁移和重建本机 Runtime                                                              |

新的 Native 流程不再公开 `checkpoint`、`evidence` 或 `receipt` 命令。验收检查由 Runtime 在 Verify 中执行（可用 `comet native check` 随时只读重跑），结果进入可跨设备同步的状态和用户报告。

## 查看已有任务

`status` 和 `show` 是只读命令，不改变当前工作区的选择，你也可以在终端自己运行：

```bash
comet native status --json
comet native status add-user-avatar --details --json
comet native show add-user-avatar
```

## 推进和 Verify

`next` 不接受 Agent 自己填写的通过结果。它只做这几件事：确认 Shape、接受或修订 Verify 结果、重试允许的 Verifier，或通过 `--runner-input` 提交 Runtime 定义的 handoff、检查计划和 Verifier 响应：

```bash
comet native next add-user-avatar --summary "Shape confirmed" --confirmed
comet native next add-user-avatar --summary "Current result accepted" --accept-result
comet native next add-user-avatar --summary "Implementation needs revision" --revise-implementation
comet native next add-user-avatar --summary "Acceptance criteria changed" --revise-requirements
comet native next add-user-avatar --runner-input <temporary-json-file>
```

Verify 之后由你决定下一步，Agent 用 `--accept-result`、`--revise-implementation` 和 `--revise-requirements` 提交你的决定。`--confirmed` 只用于确认 Shape，或确认明确降级的 verifier-unavailable 回退，不能用来接受通过结果。Verifier 不可用时有两个选择：

```bash
comet native next add-user-avatar --summary "Retry verifier" --retry-verifier
comet native next add-user-avatar --summary "Accept degraded result" --confirmed
```

`--retry-verifier` 保留当前候选和已完成的检查，只发起新的验收尝试。Supervisor 并行推进时，`next` 还带 `--coordination-mode` 和 `--max-parallel`（默认 2）；带恢复上下文的调用需要 `--expected-state-version` / `--expected-action`，防止旧响应覆盖新状态。

正常的输入模板和字段，以 `comet native status <name> --details --json` 返回的 `continuation.inputOptions.template` 为准。`request-checks` 只能由当前 Verifier 请求 Runtime 执行；Builder 自己报告通过时，change 不会直接进入 Archive。

当前命令已经返回所需模板或 Verifier 任务包时，直接使用该响应，不必再查一次 status。Supervisor 可以用 `--confirmed --coordination-mode multi-session|single-session` 同时确认完整方案和推进方式；接受结果时可以加 `--finish keep|merge|push|pull-request` 一起保存交付选择。实际执行时，保留最新 continuation 给出的状态版本与预期动作参数。

## 归档

Agent 先读取 Runtime 返回的 archive-ready continuation，再按需预览或执行：

```bash
comet native archive add-user-avatar --dry-run
comet native archive add-user-avatar --confirmed
```

项目对提交说明有要求时，在预览和执行命令里带上相同的说明参数。例如只保留隔离工作区：

```bash
comet native archive add-user-avatar --dry-run --finish keep --commit-message "chore: archive add-user-avatar"
comet native archive add-user-avatar --confirmed --finish keep --commit-message "chore: archive add-user-avatar"
```

`--commit-message` 设置归档提交说明，`--merge-message` 设置本地合并说明，后者只用于 `--finish merge`。两者都支持中文和多行文本，传入时按当前 Shell 的规则引用。项目 Hook 照常执行；说明被拒绝后的恢复见 [恢复手册](/zh/native/recovery-playbook#archive-事务恢复)。

Archive 应用完整的 target Specs、生成 `verification.md`、移动 change 并清理本机 Runtime，正常路径不重新执行 Verify。branch/worktree 隔离的交付方式用 `--finish keep|merge|push|pull-request` 指定，各选项的含义见[归档与交付](/zh/native/archive-and-delivery)。并行的 capability 冲突时，按 `continuation` 先用 `--serial-first` 选择串行顺序。

## 诊断、迁移和恢复

`comet native doctor` 是只读诊断命令，你也可以在终端自己运行；加上 `--repair` 会执行修复：

```bash
comet native doctor
comet native doctor add-user-avatar
comet native doctor add-user-avatar --repair
```

`doctor --repair` 只做能确定的迁移、未完成事务的收尾和本机 overlay 重建，不会替你改需求、Spec 或代码。跨设备恢复时缺少 `verification.md` 不会阻止 Shape/Build；遇到错误的 branch/worktree 或 active 与 archive 混在一起的目录时，它会暂停并等你处理。

供你阅读的文件是 brief、Specs、`comet-state.yaml` 和 `verification.md`；`.comet/runtime/native/` 只存放本机的 state、日志、锁和事务。
