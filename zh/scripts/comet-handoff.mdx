Classic 默认直接交接原始材料。`comet handoff` 用于查看已有设计交接来源；明确需要集中阅读时，再生成 Markdown 视图。它不会替你批准方案或推进尚未确认的设计。

## 查看已有交接

```bash
comet handoff <change-name> design --write
```

命令在 design 或 build 阶段核对当前 change 和原任务的交接引用。默认报告正式来源，不复制正文，也不重算文件 hash。

SDK 任务尚未建立设计提案时，应先继续原工作流，由 Agent 准备具体方案并请求确认；不能用 handoff 命令替代提案和用户决定。

## 生成集中阅读视图

```bash
comet handoff <change-name> design --write --full
```

视图写入当前 change 的 `.comet/handoff/design-context.md`，包含可用的 proposal、design、tasks 和 delta Specs 原文。实际 change 目录以 Runtime 返回的路径为准。

视图只方便阅读。后续需求与任务完成情况仍以正式源文件为准；修改源文档后由 Agent 判断影响，需要更新视图时再生成。

## 旧项目与旧命令

`off`、`beta` 和旧派生文件可以作为兼容记录保留，不再表示两套 hash 交接格式。`--hash-only` 已移除；不用检查文件摘要来决定是否读取文档或允许阶段推进。

安装包保留 `comet-handoff.mjs` 兼容入口，普通操作使用公开命令 `comet handoff`。更多说明见[上下文交接与原文复用](/zh/concepts/context-compression)和[修改设计后继续](/zh/guides/mid-workflow-changes)。
