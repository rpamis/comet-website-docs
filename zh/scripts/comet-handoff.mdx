Classic 默认直接交接原始材料，不复制正文。`comet handoff` 用于查看已有的设计交接来源；需要集中阅读时，再生成 Markdown 视图。它不会替你批准方案，也不会推进尚未确认的设计。

<Note>
  本页命令由 Agent 在后台调用，你不需要手动运行。日常开发只需在对话中输入 <code>/comet</code> 提需求、回答 Agent 的提问，或说“继续”。本页供你在终端排查问题、编写脚本或接入其他 Agent 平台时查阅。
</Note>

## 查看已有交接

Agent 在 design 或 build 阶段用下面的命令，核对当前 change 与原任务的交接引用：

```bash
comet handoff <change-name> design --write
```

默认只报告正式来源，不复制正文，也不重算文件 hash。

SDK 任务还没有建立设计提案时，应先继续原工作流，由 Agent 准备具体方案并请你确认；handoff 命令不能代替提案和你的决定。

## 生成集中阅读视图

```bash
comet handoff <change-name> design --write --full
```

视图写入当前 change 的 `.comet/handoff/design-context.md`，包含可用的 proposal、design、tasks 和 delta Specs 原文。实际 change 目录以 Runtime 返回的路径为准。

视图只方便阅读。后续需求与任务完成情况仍以正式源文件为准；修改源文档后由 Agent 判断影响，需要更新视图时再生成。

## 旧项目与旧命令

`off`、`beta` 和旧派生文件可以作为兼容记录保留，不再表示两套 hash 交接格式。`--hash-only` 已移除；不用检查文件摘要来决定是否读取文档或允许阶段推进。

安装包保留 `comet-handoff.mjs` 兼容入口，Agent 指令、脚本集成或终端排障应优先使用公开命令 `comet handoff`。更多说明见[上下文交接与原文复用](/zh/concepts/context-compression)和[修改设计后继续](/zh/guides/mid-workflow-changes)。
