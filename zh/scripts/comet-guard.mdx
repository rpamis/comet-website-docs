title: "comet guard"
description: "检查 open、design、build、verify 和 archive 阶段是否满足推进条件。"
---

`comet guard` 是稳定的阶段检查命令。它会检查当前 phase 需要的文件、字段和验证证据。

## 基本形式

```bash
comet guard <change-name> <phase>
comet guard <change-name> <phase> --apply
```

不带 `--apply` 时只检查。带 `--apply` 时，检查通过后会委托状态脚本推进 phase。

## 常见检查

- open: proposal、design、tasks 和 delta spec 是否完整。
- design: Design Doc 是否存在。
- build: `build_mode`、`isolation`、`tdd_mode`、`review_mode` 等是否满足约束，并运行自动探测到的项目构建检查。
- verify: 验证报告和验证结果是否可用。
- archive: 是否已通过验证并完成最终确认。

## 构建检查

build 阶段不再读取 `build_command` 或 `verify_command` 配置字段。guard 会根据项目文件自动探测构建方式，例如 `package.json` 中的 `npm run build`、Maven 或 Cargo。

如果 change 的 `.comet.yaml` 里仍然保留 `build_command` / `verify_command`，guard 会把它们当作未知字段拒绝。需要固定团队级验证命令时，建议放在项目自己的脚本体系里。无法自动推断入口时，真实运行命令后使用 `comet state record-check` 记录证据；guard 会验证记录，而不是要求跳过检查。

<Warning>
  guard 失败时不要硬改状态绕过。先修复缺失证据或回到对应阶段。
</Warning>

<Note>
  安装包仍包含 <code>comet-guard.mjs</code> 兼容 launcher，但普通使用和 Agent 指令应优先采用 <code>comet guard</code>。
</Note>
