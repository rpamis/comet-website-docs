关于 Personal Memory、Project Knowledge 和 Agent Learning Loop 如何形成、选择、使用和管理长期上下文的常见问题。

## 内容归属

<AccordionGroup>
  <Accordion title="个人记忆、项目知识和项目策略有什么区别">
    个人记忆归当前用户所有，保存语言、表达方式、验证习惯和个人协作经验。项目知识归当前项目，保存项目结构、依赖、决策、流程、约束和已经复验的故障解决方式。

    Project Policy（项目策略）是项目知识中的一类记录，用于描述项目决策、稳定模式、操作流程和约束。它不是新的 Rule 文件，也不会覆盖 `AGENTS.md`、其他平台 Rule、源码、配置或测试。

  </Accordion>

  <Accordion title="Agent Learning Loop 会记录哪些内容">
    Native、Classic、Hotfix 和 Tweak 会提供结构化的任务结果、用户反馈、验证、Review、故障复验和 Archive 事件。Learning Loop 从这些事件中提取可复用候选，再按所有者和来源分别交给个人记忆或项目知识。

    明确要求“以后都这样”可以直接形成个人记忆。系统归纳出的经验通常先以较低优先级试用，经过成功应用或确定性证据后再提升状态。

  </Accordion>

  <Accordion title="Comet 会保存完整聊天、工具日志或代码 diff 吗">
    不会。长期记录只保留必要的情境、动作摘要、结果和证据引用，不保存完整聊天、完整任务轨迹、完整 diff、原始工具日志、命令输出或模型隐藏推理。可以直接从当前仓库取得的普通项目事实也不会写入个人记忆。
  </Accordion>
</AccordionGroup>

## 上下文选择

<AccordionGroup>
  <Accordion title="Dashboard 有相关记录，为什么当前任务没有直接使用">
    Context Director 会根据当前项目、路径、任务、操作和阶段筛选内容。少量关键画像和直接相关的稳定记录可以完整进入上下文；其他候选只进入 Context Manifest，提供摘要、应用原因和稳定 ID，Agent 需要时再展开正文和来源。

    记录存在不代表每次任务都应注入。作用域不匹配、来源已经变化、记录被替代或当前任务相关性较低时，Comet 会跳过它。

  </Accordion>

  <Accordion title="个人记忆或项目知识会覆盖当前要求吗">
    不会。当前用户要求、系统约束、仓库 Rule、源码、配置、测试和 Runtime 状态保持更高优先级。长期上下文只帮助 Agent 更快理解协作偏好和项目背景，不会扩大提交、推送、删除或发布权限。
  </Accordion>
</AccordionGroup>

## 管理与故障

<AccordionGroup>
  <Accordion title="发现错误记录后怎么处理">
    个人记忆可以在 Dashboard 或通过 `comet memory correct`、`forget` 和 `rollback` 纠正、遗忘或回滚。遗忘默认保留恢复能力；永久删除需要显式选择。

    项目知识应先核对来源。来源变化会让旧记录失效；需要保留修正时，通过项目知识的管理入口记录纠正，不要通过修改个人记忆来覆盖项目事实。

  </Accordion>

  <Accordion title="插件或后台 Reflection 失败会阻塞工作流吗">
    后台采集、Reflection、检索或单个 Learner 失败时，Comet 会记录诊断并继续当前 Native、Classic、Hotfix 或 Tweak 流程。个人记忆和项目知识使用独立 Provider，一个插件故障不会中断另一类上下文。

    你正在等待的显式新增、纠正、遗忘、回滚或展开操作失败时，Comet 会返回实际错误并保持原状态，不会把失败操作报告为成功。

  </Accordion>
</AccordionGroup>
