本页描述普通用户视角的 `/comet-any` 流程。

## 1. 准备偏好

可选地创建：

```text
.comet/skills.txt
```

一行一个 Skill，顺序表示偏好调用顺序。

```text
brainstorming
writing-plans
requesting-code-review
verification-before-completion
```

## 2. 调用 `/comet-any`

```text
/comet-any
```

示例目标：

```text
请基于 .comet/skills.txt 创建一个 PR 评审助手。
它要先澄清范围，再制定检查计划，再做代码审查，最后要求验证证据。
```

## 3. 处理候选

如果候选缺失或有多个来源，`/comet-any` 必须暂停询问你。它不能静默忽略，也不能替你选择。

## 4. 生成产物

常见产物：

```text
SKILL.md
reference/resolved-skills.json
comet/skill.yaml
comet/guardrails.yaml
comet/evals.yaml
comet/eval.yaml
```

## 5. 评估并发布

```bash
comet eval collect --manifest ./generated-skill/comet/eval.yaml
comet eval run --manifest ./generated-skill/comet/eval.yaml --html
comet publish status my-skill
comet publish review my-skill --platform claude
comet publish approve my-skill --reviewer alice
comet publish run my-skill --platform claude
```

分发前，`/comet-any` 或 `comet publish distribute` 会展示平台能力缺口和可执行披露。
