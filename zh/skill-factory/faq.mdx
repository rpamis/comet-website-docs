关于 `/comet-any` Skill Factory 的创建流程、偏好配置、发布和分发的常见问题。

## 基础概念

<AccordionGroup>
  <Accordion title="我不懂 Bundle、Factory、composition 这些词">
    普通用户不需要懂。这些是 `/comet-any` 的内部后端概念。你只需要调用 `/comet-any`，它会在内部调用 CLI 维护确定性状态。第一层只有三种起点：改一版 `/comet`、做一个新 Skill、整理已有 Skill。
  </Accordion>

  <Accordion title="/comet-any 和 /comet 有什么区别">
    `/comet` 是经典 Spec 模式入口，驱动五阶段项目变更流程。`/comet-any` 是 Skill Factory，用来创建、优化、组合可复用的 Skill Bundle。详见[Skill Factory 概览](/zh/skill-factory/overview)。
  </Accordion>

  <Accordion title="为什么要生成 Bundle 而不是只生成一个 SKILL.md">
    多步骤、需要恢复、需要 guardrails、需要 runtime evals 或包含脚本副作用的 Skill，必须生成稳定组合 Skill Bundle（包含 SKILL.md + Engine Package + control plane）。只生成 SKILL.md 会失去 Run 恢复和 runtime eval。
  </Accordion>
</AccordionGroup>

## 偏好与组合

<AccordionGroup>
  <Accordion title=".comet/skill-preferences.yaml 和 .comet/skills.txt 是什么关系">
    0.4.0-beta.1 用项目级 `.comet/skill-preferences.yaml`（支持 advisory/strict 模式、prefer/require、策略）替代了旧的 `.comet/skills.txt`。详见[Skill 偏好与真实来源](/zh/skill-factory/preferences)。
  </Accordion>

  <Accordion title="advisory 和 strict 模式有什么区别">
    `advisory`（默认）可以补充目标需要的 Skill，但必须解释偏离原因。`strict` 是团队标准化模式，required Skill 缺失、歧义或禁止 scripts/hooks 时阻塞。
  </Accordion>

  <Accordion title="为什么组合方案要等我确认才生成">
    `/comet-any` 不能直接写 Bundle draft。它必须先展示"Skill Maker 方案确认页"，说明复用哪些 Skill、偏离原因、scripts/hooks 披露，你确认后才写 draft。这避免生成不符合预期的产物。
  </Accordion>

  <Accordion title="候选缺失或有多个来源怎么办">
    `/comet-any` 会暂停询问你，不会静默忽略或替你选择。你选择明确来源、移除缺失项或更新偏好后，它才会更新 Factory metadata 继续。
  </Accordion>
</AccordionGroup>

## 评估与发布

<AccordionGroup>
  <Accordion title="生成物会被自动分发到平台吗">
    不会。`/comet-any` 发布后会询问你是否分发，并先展示预览。只有你确认后才会真正写入平台。
  </Accordion>

  <Accordion title="为什么发布被阻塞了">
    常见阻塞原因：还有 unresolved candidate、Eval 没跑或对应旧 hash、缺少人工 approval、required capability gap、executable disclosure 未确认。`comet publish status` 会直接展示 `Blockers:`。详见[发布和分发 Skill](/zh/skill-factory/publishing)。
  </Accordion>

  <Accordion title="分发前为什么要先跑 preview">
    preview 是强制检查，展示 planned files、unsupported capability、executable disclosures 和 `No files were written`。确认预览后才能移除 `--preview` 执行真实分发，避免误写文件。
  </Accordion>

  <Accordion title="Eval 通过了就能直接发布吗">
    不能。Eval 通过只是 readiness 的一个条件，还需要人工批准（`comet publish approve`）。Eval 通过且 hash 匹配、人工批准后才算 publishable。详见[发布和分发 Skill](/zh/skill-factory/publishing)。
  </Accordion>
</AccordionGroup>

## 恢复与排障

<AccordionGroup>
  <Accordion title="做到一半中断了怎么办">
    直接对 Agent 说"继续上次的 Skill 创建"。`/comet-any` 会扫描可恢复状态，展示名称、状态、next action 和上次确认的组合方案摘要，让你选择继续哪一个。
  </Accordion>

  <Accordion title="偏好文件改了，旧组合方案还能用吗">
    `advisory` 模式会给 warning，让你选择继续旧组合方案或重新生成。`strict` 模式默认阻塞，要求你确认继续或重新生成。
  </Accordion>

  <Accordion title="resolved-skills.json 是什么，为什么要看它">
    `reference/resolved-skills.json` 记录组合方案基于哪些真实 Skill、它们的 hash 和从真实 SKILL.md 提炼的内容摘要（sourceSummaries）。它是"不是按名字猜的"的证据。准备发布或审查时优先看它。
  </Accordion>
</AccordionGroup>
