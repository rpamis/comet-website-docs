在本轮相同任务的评估中，Native 0.5.3 与 Native 0.4.0-rc.1 均取得 48/48 严格通过。0.5.3 的平均累计 Agent 执行耗时为 159.8 秒，rc.1 为 235.2 秒，低 32.1%。

比较双方均为 Native 工作流。0.4.0-rc.1 使用冻结的已发布包，保留该版本自己的确认、验证与归档要求。

两组实际遥测均报告了 `deepseek-flash[1m]` 和 `deepseek-v4-flash` 标签。完整报告保留这些标签，不将不同标签合并成单一模型身份。

<h2 id="通过率与重复运行稳定性">通过率与重复运行稳定性</h2>

严格通过要求业务检查与对应版本的 Native 流程检查同时通过。

| 指标         | Native 0.5.3 | Native 0.4.0-rc.1 |
| ------------ | -----------: | ----------------: |
| 严格 pass@1  |  48/48，100% |       48/48，100% |
| pass@3       |  16/16，100% |       16/16，100% |
| pass^3       |  16/16，100% |       16/16，100% |
| 业务检查通过 |        48/48 |             48/48 |

`pass@3` 表示每题三次尝试至少一次成功，`pass^3` 表示三次全部成功。本轮两个版本在这两个指标上持平。

<h2 id="全部通过时的执行开销">全部通过时的执行开销</h2>

下表使用双方都严格通过的全部 48 对样本。耗时累计模型调用、工具执行和续行，不包含镜像准备。

| 每次任务的平均值              | Native 0.5.3 | Native 0.4.0-rc.1 | 0.5.3 相对变化 |
| ----------------------------- | -----------: | ----------------: | -------------: |
| 累计 Agent 执行耗时           |     159.8 秒 |          235.2 秒 |         −32.1% |
| 工具调用                      |        53.44 |             86.54 |         −38.3% |
| 可观测 Token 总量，含缓存读取 |    2,314,560 |         2,633,238 |         −12.1% |
| 模型启动 / 恢复次数           |         2.96 |              2.71 |          +9.2% |
| 非缓存输入 Token              |       66,456 |            63,978 |          +3.9% |

本轮 0.5.3 在保持全部通过的同时，累计执行耗时、工具调用和可观测 Token 总量更低；启动 / 恢复次数与非缓存输入 Token 更高。完整报告同时列出这些变化。

<h2 id="结果适用范围">结果适用范围</h2>

两组在不同时间窗口运行，服务负载没有受控，因此不能把全部耗时差异归因于某项特性移除。结果只覆盖本批固定任务。

Token 是保存的受测 Agent 调用可观测量，独立子 Agent 的完整总量可能不可观测。报告中的成本是 CLI 估算，不能作为 DeepSeek 账单。

模型启动前的准备失败没有记成模型答错；未启动模型的位置按原计划补齐，有效评分没有被重复计入。报告附录保留的 MiMo 历史结果仅作参考，不与本轮 DeepSeek 样本合并比较。
