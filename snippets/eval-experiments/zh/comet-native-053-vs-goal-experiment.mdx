<h2 id="原题得分、满分率与重复运行稳定性">原题得分、满分率与重复运行稳定性</h2>

原题得分范围为 0–1，reward 达到 1.0 才算满分。平均得分保留部分完成的表现，满分率统计完整成功。

| 数据集 / 执行方式        | 平均得分 | 总体满分率 |      pass@3 |     pass^3 |
| ------------------------ | -------: | ---------: | ----------: | ---------: |
| WorkBuddy-Bench / Native |    0.778 | 6/9，66.7% |  2/3，66.7% | 2/3，66.7% |
| WorkBuddy-Bench / Goal   |    0.750 | 6/9，66.7% |  2/3，66.7% | 2/3，66.7% |
| SkillsBench / Native     |    0.667 | 6/9，66.7% | 3/3，100.0% | 1/3，33.3% |
| SkillsBench / Goal       |    0.444 | 4/9，44.4% | 3/3，100.0% |  0/3，0.0% |

`pass@3` 表示每题三次至少一次满分；`pass^3` 表示三次全部满分。两个数据集分别报告，不将其混成一个总体得分。

Goal 在 SkillsBench 的每题都出现过满分，所以 pass@3 为 100%；没有一题三次全部满分，所以 pass^3 为 0%。这不代表每次都答错。

每个题目、每种模式展示三次结果。完整批次先比较满分次数，再比较平均原题得分；对指定零分位置，若额外单次得分更高则替换，全部来源保留。指标是择优展示的观察值；两组可选记录数量不同，结果不代表同等运行预算下的随机对照。

WorkBuddy-Bench 与 SkillsBench 的结果按原题得分统计。满分率、三次内至少一次成功与三次全部成功分别反映完成质量、成功覆盖与重复运行稳定性。

<h2 id="评分与比较边界">评分与比较边界</h2>

全部得分来自同一原题与原评分器。评分环境失败时，对保存的原候选评分，不修改候选、不再次调用模型，也不推断缺失的自然退出码或 Native 流程状态。

Native 实际执行的 CLI 使用冻结的 0.5.3。缓存题一次运行查看过与该包不同的本地脚本，但没有执行它们；这项上下文差异保留在执行记录中。

这是低、中、高难度的分层代表题选样，且采用结果择优展示，不代表完整官方榜单。所选批次的成功率不能直接推广到全部任务。Token 仅覆盖可观测记录，CLI 估价不等于模型账单。
