Native 0.5.3 and Native 0.4.0-rc.1 each strictly passed 48/48 runs on the same tasks. Mean cumulative Agent execution time was 159.8 seconds for 0.5.3 and 235.2 seconds for rc.1, a 32.1% reduction.

Both treatments use Native workflows. Version 0.4.0-rc.1 uses a frozen published package with its original confirmation, verification, and Archive requirements.

<h2 id="experiment-setup">Experiment setup</h2>

| Item                | Shared setup                                                                    |
| ------------------- | ------------------------------------------------------------------------------- |
| Tasks               | The same 16 Comet workflow tasks                                                |
| Repetitions         | 3 per task; 48 per treatment; 96 model scores in total                          |
| Agent               | Claude Code 2.1.318                                                             |
| Model               | DeepSeek-V4.1-Flash-1017; invocation alias `deepseek-flash[1M]`                 |
| Task validation     | The same task definitions, original instructions, business data, and assertions |
| Workflow validation | Each version follows its own actual Native protocol                             |

Both treatments' telemetry reports `deepseek-flash[1m]` and `deepseek-v4-flash` labels. The full report retains those labels rather than merging them into one model identity.

<h2 id="success-rates-and-repeat-run-stability">Success rates and repeat-run stability</h2>

A strict pass requires both task checks and the corresponding version's Native workflow checks to pass.

| Metric             | Native 0.5.3 | Native 0.4.0-rc.1 |
| ------------------ | -----------: | ----------------: |
| Strict pass@1      |  48/48, 100% |       48/48, 100% |
| pass@3             |  16/16, 100% |       16/16, 100% |
| pass^3             |  16/16, 100% |       16/16, 100% |
| Task checks passed |        48/48 |             48/48 |

`pass@3` means at least one success in three attempts per task; `pass^3` means all three succeed. The versions tie on both metrics in this cohort.

<h2 id="execution-overhead-when-both-pass">Execution overhead when both pass</h2>

These averages use all 48 matched pairs that strictly passed in both treatments. Time includes model calls, tools, and resumptions, excluding image preparation.

| Mean per run                                 | Native 0.5.3 | Native 0.4.0-rc.1 | Relative change |
| -------------------------------------------- | -----------: | ----------------: | --------------: |
| Cumulative Agent execution time              |      159.8 s |           235.2 s |          −32.1% |
| Tool calls                                   |        53.44 |             86.54 |          −38.3% |
| Observed total tokens, including cache reads |    2,314,560 |         2,633,238 |          −12.1% |
| Model starts / resumptions                   |         2.96 |              2.71 |           +9.2% |
| Uncached input tokens                        |       66,456 |            63,978 |           +3.9% |

Version 0.5.3 retained all passes with lower cumulative execution time, tool calls, and observed total tokens. Model starts / resumptions and uncached input tokens increased. The full report includes both directions.

<h2 id="interpretation-limits">Interpretation limits</h2>

Runs used different time windows without controlling service load. The entire timing difference cannot be attributed to one removed feature. Results cover this fixed cohort only.

Tokens are observable quantities from saved subject-Agent calls; complete independent-subagent totals may be unavailable. CLI cost estimates are not DeepSeek bills.

Preparation failures before model startup were not scored as model errors. Unstarted positions were completed within the original plan without counting valid scores twice. Historical MiMo results in the appendix are reference only and are not pooled with DeepSeek runs.
