失败归因

RC1：parser 误报已校正

原始快照中的 Skill * 来自 find 命令的 shell glob；修复后的 parser 只识别显式的 comet-native 调用。

beta16：1 次纯 workflow 失败

cross-file-refactor r3 缺少预期产物、终态状态和完整 trajectory，但业务验证通过。

beta16：1 次业务与 workflow 同时失败

noise-distractor r2 的 invoice 税率计算失败，同时缺少产物/状态/trajectory 证据。

Judge 不替代硬检查

本报告采用确定性验证器、最终通过状态和原始 result 耗时，不用定性 Judge 文本替代它们。

比较边界

对齐的部分

相同 16 个业务任务、验证器、模型选择、交互模式和 3 次重复。

版本特有的部分

RC1 和 beta16 分别检查自己的 Native 产物、状态、loop 与 trajectory 契约。

分析集

每个版本 48 个唯一报告，全部 included、high confidence；4 个 exit-125 恢复壳作为 harness 噪声排除。

时间窗口限制

beta16 是复用的历史运行，因此耗时只能作为方向性证据，不是受控因果估计。

结论

在这组对齐样本中，RC1 保留了完整的任务级 pass@3 覆盖，提高了 strict 稳定性并缩短了原始模型耗时。但配对效率视图同时显示轮次、工具调用、总 Token 和成本上升，因此它是一个 trade-off，而不是全面的效率胜利。
