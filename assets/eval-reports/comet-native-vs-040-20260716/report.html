其余失败来自依赖 Skill 未观测到、主 Comet Skill 未调用，或只完成 3/5 个 Classic 阶段。

比较边界

对齐的部分

相同 16 个业务任务、相同业务验证器、相同 3 次重复规模，并都使用 Mimo 2.5 Pro 作为主模型。

刻意不同的部分

Native 检查 Shape—Build—Verify—Archive 证据；Classic 检查五阶段、OpenSpec 和依赖 Skill 契约。

提示词去偏

任务中的 Classic 术语被明确映射到 Native 工作流，保留业务要求，但不要求 Native 模仿 Classic 产物。

时间窗口限制

0.4.0 来自历史运行，Native 来自当前并发运行。耗时差异是强方向性信号，不是完全受控的因果结论。

结论

在这组对齐样本中，Native 保留了 100% 的任务级 pass@3，同时提高了单次严格通过率和三次全通过率，并显著缩短累计模型耗时。它说明面向强模型的轻执行路径是可行的；它不意味着 Classic 应被移除。Classic 仍服务于需要更强过程约束和分步引导的模型与任务。
